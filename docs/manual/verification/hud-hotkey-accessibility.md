# HUD、複数画面、ホットキー、アクセシビリティ

ホットキーでの切り替え、HUD の寸法・位置・表示時間・画面の移り方、視差効果などの表示設定への追従、VoiceOver とキーボードだけの操作を確かめる。確かめる仕様は `SPEC-HUD-001`、`SPEC-HUD-002`、`SPEC-HUD-003`、`SPEC-HUD-004`、`SPEC-HUD-005`、`SPEC-HUD-006`、`SPEC-HUD-007`、`SPEC-HUD-008`、`SPEC-KEY-001`、`SPEC-KEY-002`、`SPEC-UI-007`、`SPEC-UI-008` である。

この手順はこのファイルだけで完結する。最初の1回の準備（[`prepare.md`](prepare.md)）を除き、ほかの検証ファイルの手順は行わない。共通の決まりは [`README.md`](README.md) にある。

正式アイコンの `SPEC-UI-009`・`SPEC-UI-010` は正式素材が用意された後の検査であり、代替シンボルで合格にしない。表示言語の `SPEC-UI-011` は `localization.md` で確かめる。ヘルパーの削除を含む VoiceOver の試験はこの手順に含めない。

## 始める前に

- 準備（`prepare.md`）を終え、退避先 `B` の絶対パスを控えている。
- 外部ディスプレイを1台用意する（操作3）。60 Hz と 120 Hz の画面があれば比べる。
- HUD の寸法と位置は画面録画から測る。録画のフレームレートが分かっていれば、消えるまでの時間も同じ録画から数える。目分量しかできない場合は、その旨を書いて判定不能に寄せる。

リポジトリのルートで devShell に入る。

```sh
cd <リポジトリのルート>
nix develop
```

devShell の中で退避先を入れ、足場を確かめる。`OK` が出なければ、退避先かチェックアウトが違うので止める。試験する CLI のパスも入れる（操作5で使う）。

```sh
B='控えた退避先の絶対パスに置き換える'
test "$(cat "$B/repository-path.txt")" = "$PWD" && echo OK
CLI="$PWD/.build/xcode/Build/Products/Debug/Capsaicin.app/Contents/Helpers/capsaicin"
just status
```

アプリが動いていなければ起動し、メニューでスリープ防止がオフであることを確かめる。

```sh
just start
just status
```

次の開始値を `"$B/result-hud-hotkey-accessibility.txt"` に控えてから変える。

- 設定の「フィードバック」の「スリープ防止中にCaps LockのLEDを点灯」をオフ、「スリープ」の「ディスプレイを閉じたとき」を「Macをスリープ（標準）」（MacBook 以外の Mac では「メニューからのスリープも防ぐ」をオフ）にする。「バッテリー残量が少ないときに自動解除」「タイマーで自動解除」「指定時刻に自動解除」をオフにする。
- 「フィードバック」の「切り替え時にHUDを表示」をオンにする。「操作」の「CLIからの操作を許可」をオンにする。
- システム設定の「視差効果を減らす」「透明度を下げる」「コントラストを上げる」、VoiceOver、フルキーボードアクセスの値。

## 操作と期待

1. 設定の「操作」の「スリープ防止の切り替え」の「キーを記録」を押し、⌃⌥⌘C を割り当てる。別のアプリで文字を入力している最中に2回押し、開始・解除と HUD を見る。記録中の Esc、Delete と、ほかで使われている組み合わせによる登録の失敗も試す。実際に重なる安全な組み合わせを用意できなければ、その確認だけ判定不能とする。

   期待: 1回目で開始して「スリープ防止 オン」、2回目で解除して「スリープ防止 オフ」の HUD が出る。入力中のアプリのフォーカスは奪わない。重なる組み合わせでは「このショートカットは他の機能で使用されています。」が出て登録されない。

2. HUD が出る位置に別のウインドウを置き、表示中に入力とクリックを続ける。3秒間に10回切り替える。

   期待: HUD は1枚だけ表示され、フォーカスを奪わず、最後の状態を示す。

3. 外部ディスプレイにカーソルを置いて切り替え、表示中に内蔵ディスプレイへカーソルを移して切り替える。消えた後にもう一度切り替える。表示中に外部ディスプレイを外す。

   期待: 表示中の更新は同じ画面にとどまり、次の新しい表示でカーソルのある画面へ移る。画面を外すと HUD は消える。

4. システム設定で「視差効果を減らす」「透明度を下げる」「コントラストを上げる」を1つずつオンにし、HUD を録画・撮影する。各項目を開始値に戻してから次へ進む。

   期待: 「視差効果を減らす」では移動・拡大の動きをしない。HUD は高さ48 pt、横は内容に合わせて最大420 pt、画面の下端から64 pt の位置で、約2.1秒で消える。

5. VoiceOver とフルキーボードアクセスをオンにし、マウスを使わずにメニュー、設定、(i)、入力パネルを操作する。「切り替え時にHUDを表示」をオフにして、ホットキーで切り替えたときの読み上げを聞く。CLI で切り替えて比べる。

   ```sh
   "$CLI" on
   printf 'exit=%s\n' "$?"
   "$CLI" off
   printf 'exit=%s\n' "$?"
   ```

   期待: キーボードだけで操作できる。HUD がオフでもホットキーでの切り替えの内容を読み上げ、中黒は読まない。読み上げが重ならない。CLI での切り替えは読み上げない。

6. スリープ防止中に10分作業し、アイコンの点滅や不要な通知がないかを記録する。60 Hz・120 Hz の画面があれば録画し、HUD のコマ落ちを比べる。Accessibility Inspector が使える場合、明るい壁紙と暗い壁紙で HUD の文字のコントラストを測る。

   期待: 点滅や不要な通知がない。コントラストは 4.5:1 以上である。

## 中止するとき

操作できなくなる、フォーカスを奪う、読み上げが重なる、開始値へ戻せない場合は止める。メニューの「スリープ防止をオフにする」で解除し、VoiceOver とフルキーボードアクセスをオフにして、表示設定を開始値へ戻す。

## 元に戻す

メニューの「スリープ防止をオフにする」で解除する。設定の「スリープ防止の切り替え」の試験用のホットキーを消す。VoiceOver、フルキーボードアクセス、3つの表示設定、外部ディスプレイの接続、アプリの設定を控えた値へ戻す。

## 記録

`"$B/result-hud-hotkey-accessibility.txt"` に次を書く。

- ホットキーの登録と失敗の表示
- HUD の寸法と位置（測り方も）、消えるまでの時間、画面ごとの表示と移り方
- 表示設定ごとの見え方、読み上げの内容、コントラストの測定値
- 録画・撮影の絶対パス、戻した設定、成功／失敗／判定不能、未実施の操作と理由
