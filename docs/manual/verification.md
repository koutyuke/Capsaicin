# 実機で Capsaicin を確認して元に戻す手順

オーナーが承認済みの検証用 Mac で、Debug アプリの起動、抑止、復旧、画面を確認する手順である。システム設定と管理者権限を使い、ログアウト・再起動で作業を中断する。全項目の所要時間は未実測である。

本文のコマンドはまだ実行しておらず、ソースとの静的照合だけを行っている。実際に走らせた記録が残るまでは、ここに書いた期待値を「確かめた事実」として扱わない。独立した LED 復旧手段がない場合は、1節の起動前ゲートで止める。

実行するのはオーナーだけである。`scripts/manual/verify.sh` はアプリの起動とプロセスの停止を行うので、エージェントは実行しない。

## この手順の読み方

各小節は「目的 → 前提 → 操作 → 期待 → 中止 → 復元 → 記録」の順に並ぶ。操作の番号と期待の番号は対応する。上から順に実行し、前提がそろわない項目は飛ばして判定不能とする。飛ばした項目を成功に数えない。

失敗を無視して次へ進む一括実行はしない。異常が出たら後続の試験を止め、9節へ進む。

記録は、生の出力を貼るのではなく「期待と照らした結論」で書く。たとえば `2.2-3: ログイン後 state=not running、pid なし` のように、どの操作の、何が、期待どおりだったかを残す。生の出力、画面写真、録画は `B` に置き、結果欄にはその絶対パスを書く。

確認に使うコマンドは操作ごとに示す。メニュー、システム設定、蓋の開閉、目視だけの項目にはコマンドがなく、本文でその旨を書く。

### 用語

| 言葉 | この手順での意味 |
| --- | --- |
| ジョブ | `~/Library/LaunchAgents/io.github.koutyuke.capsaicin.debug.plist` を launchd に読み込ませたもの。`launchctl print "$JOB"` で状態を見る |
| 引き渡し | 手で起動したアプリが plist を書いて `bootstrap` と `kickstart` を投げ、成功したら自分は終了して launchd 起動の個体にバトンを渡す仕組み |
| `RunAtLoad` | plist の中の値。`true` ならログイン時に起動する。設定画面の「ログイン起動」がこれを書く |
| `SleepDisabled` | `pmset -g` に出るシステム全体の値。`1` ならスリープしない。この手順では開始時は `0` を前提にする |
| `B` | 1.2 で作る退避先。設定、記録、plist、画面写真、結果をここに置く。最後まで消さない |

「期待」と実測が違ったら、まず実測をそのまま残す。そのうえで、期待の書き方が悪いのか、製品が期待と違うのかを切り分ける。判断がつかなければ、その項目を判定不能として PM に渡す。

### 判定不能と中止の使い分け

- **判定不能**: 前提がそろわない、測る手段がない、結果が他の要因と区別できない。試験そのものは安全に続けられる。
- **中止**: 状態が期待から外れ、このまま進むと復元できなくなるおそれがある。後続を止め、9節で戻す。

中止したときは、どの操作の直後に、何が、どう違ったかを書く。中止した試験を「失敗」と混ぜない。製品の不具合が疑われる場合だけ失敗とし、根拠になる出力を添える。

## 全体の流れ

```text
[1. 記録・退避] ──復旧手段なし／既存の常駐処理あり──▶ [中止・保存物を保管]
│
▼
[2〜4. 起動・抑止・ヘルパー] ──異常──▶ [9. 復元・PMへ報告]
│
▼
[5〜8. LED・再開・CLI・画面] ──異常──▶ [9. 復元・PMへ報告]
│
▼
[9. 開始前の状態へ復元・結果をPMへ渡す]
```

## 0. 毎回の始め方

1節は最初の1回だけ行う。1節を終えていれば、ここから2節以降の確認に入る。止める、ビルドする、起動する、変数を入れる、の手順は `scripts/manual/verify.sh` にまとめてある。このスクリプトはアプリを起動し、プロセスを止める。そのため、オーナーだけが実行する。

```sh
cd <リポジトリのルート>
eval "$(scripts/manual/verify.sh env)"   # B・ID・JOB・PLIST・RECORD・APP・CLI・HELPER・RULE・DAEMON を入れる
scripts/manual/verify.sh restart         # 動いている Debug アプリを止め、ビルドし、Finder と同じ経路で起動する
```

各小節を始める前に、次の2つで足場を確かめる。

```sh
printf 'B=%s\nJOB=%s\n' "$B" "$JOB"
scripts/manual/verify.sh status
```

- `env` の `B` は、1節で作った `~/Capsaicin-verification.*` のうち、いちばん新しいものである。ログアウトや再起動の後も、`env` をもう一度実行すれば変数が戻る。`B` が空なら、1節がまだ終わっていない。
- `status` は、ジョブの状態、Debug アプリのプロセス、`SleepDisabled`、Capsaicin のアサーションを表示する。期待する状態は、ジョブが `state = running` で、プロセスが1つだけ動き、その PID がジョブの `pid` と一致することである。
- `restart` と `stop` は、まずアプリに quit を送る。この終了は「終了理由を判定できない」終了になり、抑止を停止中の状態に戻してから終わる（`SPEC-LCY-002`）。10秒たっても残るプロセスだけに、`SIGTERM` を送る。`SIGTERM` で止めたプロセスは後片付けを通らない。そのため、抑止中に残ったときは `status` で `SleepDisabled` とアサーションを確かめる。
- コードを直してもらった後は、`restart` だけで新しいビルドに入れ替わる。

## 1. 準備し、開始前の状態を保存する

この節で「元に戻せる状態」を作る。ここを通せない環境では、2節以降を実施しない。1.1〜1.3 は状態を読むだけで、1.4 でビルドし、起動前ゲートを通る。

### 1.1 実行者と検証環境を固定する

- **目的**: `SPEC-LCY-005`、`SPEC-LCY-007`、`SPEC-HLP-005` の確認で既存環境を失わない。
- **前提**: 実行者はオーナーである。エージェントは本文のコマンドを実行しない。Apple Silicon、macOS 26 以上、Xcode 27.2、Nix の flakes、有効な管理者認証を用意する。未保存の作業を保存する。
- **操作**:
  1. Release と Debug の Capsaicin が両方停止している検証用 Mac を使う。既存のアプリが動作中なら、本手順では終了させず中止する。Release を検証中に起動しない。
  2. ターミナルでリポジトリのルートを開き、以後のコマンドを同じ Bash で実行する。

     ```sh
     bash
     /usr/bin/xcode-select -p
     /usr/bin/sw_vers
     /usr/bin/uname -m
     /bin/ps -axo pid,ppid,comm | /usr/bin/grep '[C]apsaicin.app/Contents/MacOS/Capsaicin'
     ```

- **期待**: Developer ディレクトリが Xcode 内を指し、CPU は `arm64` である。最後の検索でアプリが見つからない。
- **中止**: アプリが動作中、環境が非対応、承認がない場合。Xcode の選択は変更しない。
- **復元**: まだ状態を変更していないので不要である。
- **記録**: macOS の版とビルド番号、機種、`xcode-select -p` の出力を `B` の結果用メモに写す。

### 1.2 読み取り結果と退避先を残す

- **目的**: `SPEC-HLP-005`、`SPEC-LCY-007` の開始前の状態を後から比較できるようにする。
- **前提**: 1.1 が完了している。`trash` が使えることを `command -v trash` で確かめる。なければ削除操作を始めず PM に相談する。
- **操作**:
  1. 所有者だけが読める退避先と、共通変数を作る。

     ```sh
     umask 077
     ROOT="$PWD"
     B="$(/usr/bin/mktemp -d "$HOME/Capsaicin-verification.XXXXXX")"
     ID='io.github.koutyuke.capsaicin.debug'
     JOB="gui/$(id -u)/$ID"
     PLIST="$HOME/Library/LaunchAgents/$ID.plist"
     RECORD="$HOME/Library/Application Support/$ID/resume-record.json"
     APP="$ROOT/.build/xcode/Build/Products/Debug/Capsaicin.app"
     CLI="$APP/Contents/Helpers/capsaicin"
     HELPER='/Library/PrivilegedHelperTools/io.github.koutyuke.capsaicin.helper.debug'
     RULE='/etc/sudoers.d/capsaicin_debug'
     DAEMON='/Library/LaunchDaemons/io.github.koutyuke.capsaicin.helper.debug.plist'
     printf '%s\n' "$B"
     printf '%s\n' "$ROOT" > "$B/repository-path.txt"
     ```

  2. 表示した `B` の絶対パスを、別のメモにも保存する。再ログイン後は、0節の `eval "$(scripts/manual/verify.sh env)"` で変数を戻す。`mktemp` を再実行しない。
  3. 開始前の状態を保存する。

     ```sh
     /usr/bin/pmset -g > "$B/pmset.before.txt"
     /usr/bin/pmset -g custom > "$B/pmset-custom.before.txt"
     /usr/bin/pmset -g assertions > "$B/assertions.before.txt"
     /bin/launchctl print "$JOB" > "$B/agent.before.txt" 2>&1
     printf '%s\n' "$?" > "$B/agent-print.exit.txt"
     /bin/launchctl print-disabled "gui/$(id -u)" > "$B/disabled.before.txt"
     /bin/launchctl print "gui/$(id -u)/io.github.koutyuke.capsaicin" > "$B/release-agent.before.txt" 2>&1
     printf '%s\n' "$?" > "$B/release-agent-print.exit.txt"
     /usr/sbin/sysctl kern.boottime > "$B/boottime.before.txt"
     /bin/date '+%Y-%m-%dT%H:%M:%S%z' > "$B/date.before.txt"
     /usr/bin/awk '$1 == "SleepDisabled" {print $2}' "$B/pmset.before.txt" > "$B/sleep-disabled.before.txt"
     cat "$B/sleep-disabled.before.txt" "$B/agent-print.exit.txt" "$B/agent.before.txt"
     ```

- **期待**: `SleepDisabled` は1行の `0` または `1`。LaunchAgent の照会は「サービスが見つからない」旨で失敗する。
- **中止**: `SleepDisabled` が欠落・重複・不明の場合。Debug・Release いずれかの LaunchAgent が読み込み済みの場合も止める。`release-agent.before.txt` と終了コードを読み、`~/Library/LaunchAgents/io.github.koutyuke.capsaicin.plist` が存在する場合も、ログイン時の同時起動を避けるため止める。読み込み済みジョブは plist だけでは完全復元できないので、この手順で `bootout` しない。権限不足を「存在しない」とみなさない。
- **復元**: 読み取りと退避先の作成だけなので、システムの復元は不要である。開始値が `1` の場合も、この時点では下ろさない。
- **記録**: `SleepDisabled` の開始値、2つの `launchctl print` の終了値と本文、`boottime`、`date` を写す。文言は macOS の版で変わるので、終了値と本文の両方を残し、片方だけで判断しない。

### 1.3 設定、再開用の記録、未読込の plist を退避する

- **目的**: `SPEC-SET-002`、`SPEC-LCY-007` の既存データを保存する。
- **前提**: アプリとジョブが停止している。次の対象がシンボリックリンクなら止める。
- **操作**:
  1. 既存の Debug 設定をドメイン全体で保存する。ホットキーの値もこの退避に含める。

     ```sh
     /usr/bin/defaults read "$ID" > "$B/defaults.before.txt" 2> "$B/defaults-read.error.txt"
     printf '%s\n' "$?" > "$B/defaults-read.exit.txt"
     cat "$B/defaults-read.exit.txt" "$B/defaults-read.error.txt"
     ```

     終了コードが `0` なら、次を実行する。

     ```sh
     /usr/bin/defaults export "$ID" "$B/defaults.before.plist"
     /usr/bin/plutil -lint "$B/defaults.before.plist"
     ```

     ドメインが存在しない旨だけが出た場合は、次を実行する。他のエラーなら止める。

     ```sh
     touch "$B/defaults.absent"
     ```

  2. 再開用の記録と plist を、存在しなかったことも含めて保存する。

     ```sh
     if [ -L "$RECORD" ] || [ -L "$PLIST" ]; then
       printf '%s\n' '中止: シンボリックリンクがある'
     else
       if [ -f "$RECORD" ]; then cp -p "$RECORD" "$B/resume-record.before.json"; else touch "$B/record.absent"; fi
       if [ -f "$PLIST" ]; then cp -p "$PLIST" "$B/agent.before.plist"; else touch "$B/agent.absent"; fi
     fi
     ```

  3. 既存の記録があれば、`cat "$B/resume-record.before.json"` で `session`、`ownsSleepDisabled`、`isRunning`、`misalignments` を読む。抑止・所有・実行中・未復元の制御が残っていたら、そのまま保管して止める。壊れた記録も消さない。
  4. Release・Debug 両方のヘルパー構成を読む。

     ```sh
     /bin/ls -ld /Library/PrivilegedHelperTools/io.github.koutyuke.capsaicin.helper{,.debug}
     /bin/ls -ld /etc/sudoers.d/capsaicin{,_debug}
     /bin/ls -ld /Library/LaunchDaemons/io.github.koutyuke.capsaicin.helper{,.debug}.plist
     ```

- **期待**: 退避に成功し、ヘルパー構成6ファイルはすべて存在しない。既存 plist があっても読み込まれておらず、元ファイルを保存できている。
- **中止**: ヘルパー構成が1つでも存在する、アクセス拒否、退避失敗、既存記録の意味を判断できない場合。既存ヘルパーは修復・削除せず、構成のない別の検証用 Mac を PM と選ぶ。
- **復元**: 元ファイルは変更していない。`B` を残す。以降で消すのは今回の検証で作ったデータだけとする。
- **記録**: `defaults` の終了値、`record.absent`／`agent.absent`／`defaults.absent` のどれができたか、ヘルパー構成6ファイルの有無。既存データがあった場合は、その中身を要約して写す（認証情報は写さない）。

### 1.4 ビルドし、起動前ゲートを通る

- **目的**: `SPEC-LCY-005`、`SPEC-LED-001` の確認を、復旧可能な状態で始める。
- **前提**: 1.3 が完了している。外観、アクセントカラー、アクセシビリティ、VoiceOver、バックグラウンド項目の開始値を画面写真で `B` に保存する。外付け機器の製品名と接続方式も記録する。
- **操作**:
  1. リポジトリのルートからビルドする。

     ```sh
     nix develop --command just build
     /usr/libexec/PlistBuddy -c 'Print :CFBundleIdentifier' "$APP/Contents/Info.plist"
     /bin/ls -l "$APP/Contents/Helpers/"
     ```

  2. 結果用メモを `B` に置き、実行日、macOS のビルド番号、Mac の機種、承認者、各手順の実測値を書く。認証情報や全プロセスの環境変数は保存しない。
  3. PM に、独立したプロセスから各対象キーボードへ `"Auto"` を書ける復旧用実行ファイルと、その実行・成功判定の手順を用意してもらう。承認済みの手順を `B` に保管する。

- **期待**: bundle ID が `io.github.koutyuke.capsaicin.debug`、埋め込み実行ファイルが `capsaicin` と `capsaicin-helper` である。独立した LED 復旧手段と実行者が決まっている。
- **中止**: 復旧手段がない場合はここで止め、2〜8節を実施しない。リポジトリには独立した復旧 CLI がない。LED 設定をオフにするだけでは、起動時の `"Auto"` 書き込みを防げない。既存の LED 上書きモードを保つ必要がある環境でも止める。
- **復元**: ビルドだけならシステムの復元は不要である。動的確認を始めなかったことを結果に書く。
- **記録**: bundle ID、埋め込み実行ファイル2つ、承認済み復旧手順の置き場所。

ここから先は、各節の前提がそろった項目だけを上から順に実行する。飛ばした項目は判定不能にする。

**結果欄**: 成功／失敗／判定不能: ____。環境・承認・退避先: ____。未実施項目と理由・気づいたこと: ____。

## 2. 起動と LaunchAgent を確認する

この節では、手で開いても最終的に launchd の管理下で動くこと（2.1）、ログイン起動の設定が効くこと（2.2）、クラッシュしたときだけ起こし直されること（2.2）、バックグラウンド項目を無効にしたときの表示（2.3）を見る。

2.1 と 2.2 は `RunAtLoad` とシステム設定を変える。2.3 の後で元に戻す。

### 2.1 Finder 起動から引き渡しを確認する

- **目的**: `HYP-LCY-003`、`SPEC-LCY-005`。
- **前提**: 1.4 のゲートを通った。`SleepDisabled` の開始値が `0` である。開始値が `1` なら変更せず、動的確認を中止する。
- **操作**:
  1. `scripts/manual/verify.sh restart` を実行する。`open` は、Finder のダブルクリックと同じ経路でアプリを起動する。

     ```sh
     scripts/manual/verify.sh restart
     ```

  2. 出力された状態を読む。

     ```sh
     /bin/launchctl print "$JOB"
     /bin/ps -axo pid,ppid,comm | /usr/bin/grep '[C]apsaicin.app/Contents/MacOS/Capsaicin'
     /usr/bin/plutil -p "$PLIST"
     ```

  3. メニューから終了し、ジョブとプロセスを別々に見る。ジョブは読み込まれたままで、実行だけが止まるのが正しい。

     ```sh
     /bin/launchctl print "$JOB"
     /usr/bin/pgrep -fx "$APP/Contents/MacOS/Capsaicin"
     ```

  4. `open "$APP"` でもう一度起動し、5秒待ってから2と同じ3つのコマンドを実行する。終了した後にもう一度開けることも、この手順で確かめる。

     ```sh
     /usr/bin/open "$APP"
     sleep 5
     /bin/launchctl print "$JOB"
     /bin/ps -axo pid,ppid,comm | /usr/bin/grep '[C]apsaicin.app/Contents/MacOS/Capsaicin'
     /usr/bin/plutil -p "$PLIST"
     ```

  5. 期待から外れたら、もう一度だけ `scripts/manual/verify.sh status` で読み直す。それでも外れていれば中止する。

- **期待**: Debug ジョブが実行中で、その `pid` のアプリだけが残る。`ProgramArguments` が `$APP/Contents/MacOS/Capsaicin` を指す。3のあとは `pid` がなく、プロセスも残らない。
- **中止**: 複数起動、引き渡しの繰り返し、Release の起動、登録失敗の場合。
- **復元**: メニューの終了操作で止める。ジョブと plist の除去は9節で行う。
- **記録**: 起動経路、各段階の `state` と `pid`、プロセスの本数、`ProgramArguments`、`KeepAlive`、`RunAtLoad`。

起動した直後の一瞬だけ2プロセスが見えることがある。手で開いた個体が引き渡してから終了するまでの間であり、数秒後に1本へ戻れば正常である。5秒たっても2本残るときは、引き渡しの失敗として扱う。

これは引き渡しの結果の確認である。`XPC_SERVICE_NAME` 自体を起動経路別に記録する機能はないので、`HYP-LCY-003` の直接測定は判定不能とする。`ps e` で他の秘密情報を含む環境を採取しない。

### 2.2 ログイン設定とクラッシュ後の再起動を確認する

- **目的**: `HYP-LCY-002`、`SPEC-LCY-001`、`SPEC-LCY-003`。
- **前提**: 停止中で、「一般」の再開設定は「再開しない」である。以後、画面の項目は機能名で指す。文言は `Sources/Capsaicin/Settings/` の String Catalog を正本とする。
- **操作**:
  1. 「一般」のログイン起動をオフにし、`plutil -p "$PLIST"` で `RunAtLoad = false` と `KeepAlive.Crashed = true` を確かめる。

     ```sh
     /usr/bin/plutil -p "$PLIST" | /usr/bin/grep -E 'RunAtLoad|KeepAlive'
     ```

  2. メニューから終了し、`pgrep` でプロセスが消えたことを確かめてから、ジョブを外して読み込み直す。

     ```sh
     /usr/bin/pgrep -fx "$APP/Contents/MacOS/Capsaicin"
     /bin/launchctl bootout "$JOB"
     /bin/launchctl bootstrap "gui/$(id -u)" "$PLIST"
     /bin/launchctl print "$JOB"
     ```

  3. ジョブに実行中の `pid` がないことを、次のコマンドで確かめる。

     ```sh
     /bin/launchctl print "$JOB" | /usr/bin/grep -E '^\s*(state|pid|runs|last exit code) ='
     ```

     Apple メニューからログアウトして再ログインする。変数を0節の `eval` で戻し、同じ照会を行う。

     ```sh
     eval "$(scripts/manual/verify.sh env)"
     /bin/launchctl print "$JOB" | /usr/bin/grep -E '^\s*(state|pid|runs|last exit code) ='
     /usr/bin/pgrep -fx "$APP/Contents/MacOS/Capsaicin"
     ```

  4. `launchctl kickstart "$JOB"` で起動する。次のコマンドで PID を得る。

     ```sh
     /bin/launchctl kickstart "$JOB"
     PID="$(/bin/launchctl print "$JOB" | /usr/bin/awk '$1 == "pid" && $2 == "=" {print $3}')"
     /bin/ps -p "$PID" -o pid=,comm=
     ```

     出力が Debug アプリの絶対パスと一致した場合だけ、クラッシュさせる。

     ```sh
     /bin/kill -SEGV "$PID"
     ```

  5. 30秒を観測の上限として待ち、`launchctl print "$JOB"` で別の PID になったことを記録する。

     ```sh
     /bin/launchctl print "$JOB" | /usr/bin/grep -E '^\s*(state|pid|runs|last exit code) ='
     /usr/bin/pgrep -fx "$APP/Contents/MacOS/Capsaicin"
     ```

  6. ログイン起動をオンにし、ログアウト・再ログインする。オンにした直後に plist を確かめる。

     ```sh
     /usr/bin/plutil -p "$PLIST" | /usr/bin/grep -E 'RunAtLoad|KeepAlive'
     ```

     再ログイン後は次の2つで、ジョブが実行中でプロセスが1本だけであることを確かめる。

     ```sh
     eval "$(scripts/manual/verify.sh env)"
     scripts/manual/verify.sh status
     ```

- **期待**: 2・3では起動しない。4ではクラッシュ後に別の PID で起動する。6ではメニューバーに表示される。
- **中止**: PID が空・複数・別アプリの場合はシグナルを送らない。再起動しない場合も連続して送らない。3でジョブ自体が見つからない場合も、起動しなかったと混ぜずに中止する。
- **復元**: ログイン起動を次の試験に必要な値へ戻す。最終的な開始値の復元は9節で行う。
- **記録**: `RunAtLoad` の前後、2・3での `state` と `pid` の有無、4で撃った PID と5で戻った PID、`runs`、`last exit code`。

読み方の補足を4つ置く。

- ログイン起動の切り替えは plist を書き換えるだけで、読み込み済みのジョブを外さない。オフにしても今動いているアプリは止まらないのが正しい。効くのは次のログインからである。
- 2の `bootout` はジョブを外すだけで、plist は消さない。アプリが動いたままだと後片付けを通らずに終わるので、必ず先に終了して `pgrep` が空であることを確かめる。`bootstrap` が失敗したときは、同じコマンドを繰り返さず `print` で残存を確かめる。
- 3のあと、ジョブは「読み込まれているが実行されていない」が期待である。`launchctl print` が「見つからない」と答えるのは別の異常であり、起動しなかったこととは区別する。
- 5の30秒はこの手順の中止基準であり、製品の保証時間ではない。

`KeepAlive` は `Crashed` だけなので、メニューからの終了や `SIGTERM` では再起動しない。これも 2.1 の3と合わせて確認できる。

### 2.3 バックグラウンド項目が無効の表示を確認する

- **目的**: `SPEC-LCY-005`。
- **前提**: システム設定の「一般」→「ログイン項目と機能拡張」で Debug の項目を識別できる。
- **操作**:
  1. メニューから終了し、`pgrep` が空であることを確かめる。

     ```sh
     /usr/bin/pgrep -fx "$APP/Contents/MacOS/Capsaicin"
     ```

  2. 該当項目を無効にする。アプリの終了を求められたら従う。
  3. Finder から起動する。

     ```sh
     /usr/bin/open "$APP"
     sleep 3
     /usr/bin/pgrep -fx "$APP/Contents/MacOS/Capsaicin"
     /bin/launchctl print "$JOB"
     ```

  4. アプリの設定ウィンドウで「一般」を開いて表示を撮る。警告の行が出ていたら、その文言をそのまま写す。システム設定の「一般」には警告は出ない。
  5. 確認後は該当項目を元の許可状態に戻し、アプリを終了して `open "$APP"` で起動し直す。ジョブが実行中に戻り、アプリの設定ウィンドウの「一般」で警告の行が消えたことを確かめる。

     ```sh
     /usr/bin/open "$APP"
     sleep 3
     /bin/launchctl print "$JOB" | /usr/bin/grep -E '^\s*(state|pid) ='
     /usr/bin/pgrep -fx "$APP/Contents/MacOS/Capsaicin"
     ```

- **期待**: アプリは動作し、アプリの設定ウィンドウの「一般」に、バックグラウンド項目が無効、またはクラッシュ時の自動再起動が使えない旨の警告の行が出る。
- **中止**: Release や別アプリの項目と区別できない場合は無効にしない。5で警告が消えない場合は、再起動試験へ進まない。
- **復元**: 開始前の写真と `disabled.before.txt` を参照し、同じ項目だけを戻す。
- **記録**: 無効にした項目の表示名、アプリが動いたこと、`launchctl print` の結果、アプリの設定ウィンドウの「一般」に出た警告の行の文言、戻したあとに警告が消えたこと。

項目の見分けがつかないときは、無効にしないで止める。Debug と Release は表示名が同じ "Capsaicin" になりうる。1.3 の6ファイル照会で Release の構成がないことを確認済みでも、システム設定の一覧に他のアプリの項目が並ぶため、名前だけで決めない。

警告の行は2種類ある。コード上は、LaunchAgent の状態が `ready` のときだけ「再起動される」とみなす。無効にしてから `open` しても登録と起動は成功しうる。実測では `launchctl print-disabled` に項目が現れず、ジョブは実行中のまま `runs` が増えた。その場合は launchd から起動された個体が承認待ちを返すため「バックグラウンド項目が無効です」が出る。「クラッシュ時に自動再起動できません」は、登録か起動が実際に失敗したときに出る。どちらが出たかを結果に残し、期待の「または」を実測で具体化する。

## 3. 抑止の基本とハードウェア検出を確認する

この節では、自動スリープを常に止めるアサーションと画面の追加抑止（3.1）、画面消灯・スクリーンセーバーと蓋・バッテリーの検出（3.2）、「ディスプレイを閉じたとき」の設定（3.3）を見る。

### 3.1 設定ごとのアサーションを比較する

- **目的**: `SPEC-BLK-001`。
- **前提**: 「ディスプレイを閉じたとき」は「スリープ」（蓋のない Mac では「メニューから選んでもスリープさせない」はオフ）である。「スリープ」の「自動でオフにする」にあるタイマー・指定時刻・バッテリー残量をオフにする。電源アダプターを接続する。試験後はバッテリー条件を戻す。
- **操作**:
  1. 「スリープ」で「ディスプレイを自動でオフにしない」をオフにし、メニューから開始する。
  2. アサーションを読み、Capsaicin の行を写す。

     ```sh
     /usr/bin/pmset -g assertions | /usr/bin/grep -i -A2 capsaicin
     ```

  3. 解除後、「ディスプレイを自動でオフにしない」をオンにして開始し、同じコマンドを実行する。
  4. 解除してもう一度同じコマンドを実行し、Capsaicin の行が消えたことを確かめる。
- **期待**: どちらでも `Capsaicin` の `PreventUserIdleSystemSleep` があり、「ディスプレイを自動でオフにしない」がオンのときだけ `PreventUserIdleDisplaySleep` もある。解除後は Capsaicin のアサーションがない。別アプリのアサーションは消さない。
- **中止**: 開始拒否や解除後の残留がある場合。
- **復元**: メニューで解除する。「ディスプレイを自動でオフにしない」を開始前の値に戻す。残留があれば9節で復旧する。
- **記録**: 各段階の Capsaicin の行を丸ごと写す（アサーションの種類と数を後から比較する）。他のアプリの行は数だけ数える。

アサーションの存在だけでは実際のスリープ抑止の合格にしない。システム設定の画面消灯までの既存の時間を `/usr/bin/pmset -g custom | /usr/bin/grep -i displaysleep` で記録し、その時間を超えて操作せずに待つ。「ディスプレイを自動でオフにしない」がオフなら画面は消灯でき、オンなら消灯しないことを比較する。OS 側の自動スリープ条件を特定できない場合、実際の自動スリープは判定不能とし、`pmset` のタイマー設定を変更しない。

### 3.2 画面消灯と蓋・バッテリーの検出を確認する

- **目的**: `HYP-BLK-001`、`HYP-BLK-008`、`HYP-BLK-009`、`HYP-SET-001`、`HYP-SET-002`、`SPEC-SET-006`。
- **前提**: 抑止を解除している。画面が消えてもキーボード・トラックパッドで復帰できる。
- **操作**:
  1. 管理者ユーザーと一般ユーザーのそれぞれで、`sudo` なしで実行する。

     ```sh
     /usr/bin/pmset displaysleepnow
     printf 'exit=%s\n' "$?"
     ```

  2. 蓋のある Mac とない Mac で次を実行し、設定の蓋関連行の有無と照合する。

     ```sh
     /usr/sbin/ioreg -r -c IOPMrootDomain -d1 -w0 | /usr/bin/grep AppleClamshellState
     /usr/bin/pmset -g batt
     ```

  3. 各 Mac で「スリープ」の「自動でオフにする」にあるバッテリー残量のカードの有無を記録する。UPS がある場合はその有無と製品名も書く。
  4. 「システム設定 > ロック画面」でスクリーンセーバの自動起動までの時間を最短にし、ディスプレイを自動でオフにするまでの時間をそれより長くする。変更前の値を控える。「ディスプレイを自動でオフにしない」をオンにして抑止を開始し、スクリーンセーバの時間より長く操作せずに待つ。解除して同じだけ待ち、対照の結果を記録する。
- **期待**: 1は終了コード `0` で消灯する。蓋のある Mac だけで `AppleClamshellState` があり、「ディスプレイを閉じたとき」のポップアップが表示され、アイコンが `laptopcomputer` になる。蓋のない Mac では「メニューから選んでもスリープさせない」のスイッチが表示され、アイコンが `powersleep` になる。バッテリー残量のカードは内蔵バッテリーのある Mac だけにある。4では抑止中にスクリーンセーバが自動起動せず、解除後には起動する。
- **中止**: 消灯から復帰できない、想定外の権限要求がある場合。1台の結果を他機種の合格にしない。
- **復元**: メニューで抑止を解除し、手動操作で画面を復帰させる。接続機器と「システム設定 > ロック画面」の変更した値を開始前に戻す。
- **記録**: 実行したユーザーの種類（管理者・一般）、終了値、`AppleClamshellState` の有無、バッテリーグループの有無、機種名。スクリーンセーバーと画面の時間の開始値、抑止中と解除後の自動起動の有無、復元した値。

`pmset -g batt` は IOPS の型の直接測定ではない。`HYP-SET-002` の UPS と内蔵バッテリーの型の区別は、型を出す試作プログラムがないので判定不能とする。`HYP-BLK-008` の通知時刻もアプリが記録しないので、4節の画面消灯は間接確認にとどめる。

### 3.3 ディスプレイを閉じたときの設定を確認する

- **目的**: `SPEC-SET-002`、`SPEC-SET-005`、`SPEC-SET-006`。
- **前提**: 抑止を解除している。蓋のある Mac を使い、ヘルパーの状態を確認してある。ヘルパーの設置や蓋を閉じる試験は4節で行う。
- **操作**: 「スリープ」を開き、「ディスプレイを閉じたとき」の選択肢と (i) を見る。ヘルパーが設置済みなら「スリープ（標準）」「ディスプレイをオフ」「オンのまま」を順に選ぶ。ヘルパーが正しく設置されていない状態で、それを要する設定が保存されている場合は、表示と (i) の先頭を記録する。その状態を安全に用意できなければ注意の表示の確認だけ判定不能にする。
- **期待**: 独立した子の行がなく、1つのポップアップに4つの選択肢がある。ヘルパーが要る設定が保存されているのに正しく設置されていないときは、ポップアップは無効にならず、保存した選択肢を表示し、アイコンが注意の記号に替わる。(i) の先頭から、この設定を適用できない理由と「ヘルパー」の修復先を読める。通常の説明には、ディスプレイを閉じる操作とアップルメニューの「スリープ」などを個別に設定できないこと、ヘルパーと管理者パスワードが要ることがある。
- **中止**: 「スリープ」以外を選ぶ操作が設置・修復を求めたら、その場では承認せず、取り消して「スリープ」のままになることを確かめ、4節の設置手順に進む。
- **復元**: 試した設定を開始前の値に戻す。ヘルパーの状態は変えない。
- **記録**: ポップアップの表示・選択肢・(i) の内容、注意の記号の有無、ヘルパーの状態、元の設定値。

**結果欄**: 成功／失敗／判定不能: ____。設定とアサーション・機種別の検出値: ____。未実施項目と理由・気づいたこと: ____。

## 4. ヘルパーを設置し、抑止・修復・削除を確認する

この節では、管理者認証の取り消しと設置（4.1）、ヘルパーの on・off（4.2）、部分欠落からの修復（4.3）、起動時の後片付け（4.4）、削除のときの扱い（4.5）、Daemon のない状態での値の永続性（4.6）を見る。

この節だけはシステム領域に3ファイルを置く。**設置したことを示すマーカー `B/helper-created` は、所有者・権限・plist がすべて期待どおりだと確かめてから作る。** マーカーがない状態で削除の操作をしない。

3ファイルの意味は次のとおり。

| 変数 | パス | 役割 |
| --- | --- | --- |
| `HELPER` | `/Library/PrivilegedHelperTools/io.github.koutyuke.capsaicin.helper.debug` | root で `pmset disablesleep` を呼ぶ実行ファイル |
| `RULE` | `/etc/sudoers.d/capsaicin_debug` | このヘルパーだけを `sudo -n` で許可するルール |
| `DAEMON` | `/Library/LaunchDaemons/io.github.koutyuke.capsaicin.helper.debug.plist` | 起動時に `off` を1回実行する LaunchDaemon |

### 4.1 管理者認証の取り消しと設置を確認する

- **目的**: `SPEC-HLP-001`、`SPEC-HLP-004`、`SPEC-HLP-005`。
- **前提**: 1節で Release・Debug の既存ヘルパーがないことを確認済みで、`SleepDisabled = 0` である。
- **操作**:
  1. 停止中に「ディスプレイを閉じたとき」で「ディスプレイをオフ」を選ぶ（蓋のない Mac では「メニューから選んでもスリープさせない」をオンにする）。設置確認を一度取り消し、ポップアップが「スリープ」（蓋のない Mac ではスイッチがオフ）のままであることを確かめる。同じ操作をして設置確認を承認し、OS の管理者認証ではキャンセルする。
  2. ポップアップが「スリープ」（蓋のない Mac ではスイッチがオフ）に戻り、「ヘルパー」が未インストールであることを確かめる。3ファイルが作られていないことも見る。

     ```sh
     /bin/ls -l "$HELPER" "$RULE" "$DAEMON"
     ```

  3. 同じ操作を繰り返し、今度は管理者認証を承認する。

     **この承認でシステム領域に3ファイルを設置する。既存ファイルが現れていたら承認せず止める。**

  4. 次を実行する。

     ```sh
     /bin/ls -l "$HELPER" "$RULE" "$DAEMON"
     /usr/bin/plutil -p "$DAEMON"
     ```

- **期待**: 取り消しでは設定が保存されず、3ファイルとも作られない。設置後は選んだ動作（蓋のない Mac ではオン）が保存され、ヘルパーが `root:wheel`・755、sudoers が `root:wheel`・440、plist が `root:wheel`・644 である。plist のラベルは `io.github.koutyuke.capsaicin.helper.debug`、引数はヘルパーの絶対パスと `off` である。
- 所有者・権限・plist がすべて期待どおりの場合だけ、`touch "$B/helper-created"` を実行する。
- **中止**: 認証を取り消しても設定やファイルが残る、設置失敗、所有者・権限が異なる場合。設置成功を確認できるまでマーカーを作らない。
- **復元**: 設置した3ファイルは4.5か9節でアプリの削除操作により除去する。sudoers を手で編集しない。
- **記録**: 取り消し時の3ファイルの有無、設置後の3行の所有者・権限、`plutil` のラベルと引数、マーカーを作ったかどうか。

### 4.2 on・off と手動・蓋閉じスリープを確認する

- **目的**: `SPEC-HLP-002`、`HYP-BLK-006`、`SPEC-BLK-001`、`SPEC-BLK-002`、`HYP-BLK-008`。
- **前提**: 今回設置したヘルパーだけがある。アプリは起動済みで抑止は停止中、`SleepDisabled = 0`。MacBook は電源接続、外部ディスプレイなしで机上に置く。閉じた Mac をかばんに入れない。
- **操作**:
  1. ヘルパーを直接呼び、各呼び出しの終了値と状態を読む。

     ```sh
     /usr/bin/sudo -n "$HELPER" on
     printf 'exit=%s\n' "$?"
     /usr/bin/pmset -g
     /usr/bin/sudo -n "$HELPER" off
     printf 'exit=%s\n' "$?"
     /usr/bin/pmset -g
     ```

  2. 不正引数は、sudoers が許可しないので、未設置のバンドル内コピーを権限なしで呼ぶ。

     ```sh
     "$APP/Contents/Helpers/capsaicin-helper" invalid
     printf 'exit=%s\n' "$?"
     "$APP/Contents/Helpers/capsaicin-helper" on extra
     printf 'exit=%s\n' "$?"
     ```

  3. 「ディスプレイを閉じたとき」を「ディスプレイをオフ」にし（蓋のない Mac では「メニューから選んでもスリープさせない」をオンにする）、メニューで開始する。状態を読んでから、Apple メニューのスリープを選び、蓋のある Mac では続けて蓋を1分閉じてから開ける。

     ```sh
     /usr/bin/pmset -g | /usr/bin/awk '$1 == "SleepDisabled" {print $2}'
     ```

  4. 開く前後の時刻と `pmset -g log` の該当区間を記録する。閉じている間の消灯を安全に目視できなければ、消灯は判定不能とする。「ディスプレイを閉じたとき」を「オンのまま」にした場合とも比較する。

     ```sh
     /bin/date '+%Y-%m-%dT%H:%M:%S%z'
     /usr/bin/pmset -g log | /usr/bin/grep -iE 'sleep|wake'
     ```

  5. メニューで解除し、`pmset -g` を読む。もう一度蓋を閉じてスリープし、開けると復帰することを確かめる。

     ```sh
     /usr/bin/pmset -g | /usr/bin/awk '$1 == "SleepDisabled" {print $2}'
     ```

- **期待**: 1では終了値 `0`、`SleepDisabled` が `1`→`0`。2は終了値 `64` で状態を変えない。3は `SleepDisabled = 1` で手動・蓋閉じスリープを止める。5では `0` に戻る。
- **中止**: `sudo -n` が認証を要求する、状態が不明、異常発熱、解除後もスリープできない場合。
- **復元**: まずメニューで解除する。直接 `on` したものはアプリの所有ではないので、直接 `off` して `0` を確認する。戻せなければ9.1の緊急復旧を使う。
- **記録**: 各呼び出しの終了値と `SleepDisabled`、`pmset -g log` の該当行、蓋を閉じていた時刻、復帰にかかった時間。

`sudo -n` が「パスワードが必要」と言ったら、sudoers のルールが効いていない。認証を求められた時点で止め、パスワードを入れて続けない。`sudo -n` の失敗は、ヘルパーの不具合とルールの不備を区別する材料になる。

ネットワーク応答はスリープの断定に使わない。別端末から ping を使う場合は、開蓋時に疎通する宛先 IP を記録してから `ping -c 3 IP_ADDRESS` を使う。`IP_ADDRESS` は記録した検証 Mac の IP に置き換える。応答だけで、または無応答だけで判定せず、スリープログと突き合わせる。`HYP-BLK-006` の「片方だけは指定できない」という仕組みの主張は、実測とは別のソース調査である。

### 4.3 部分欠落から修復する

- **目的**: `SPEC-HLP-004`。
- **前提**: 抑止を解除し、`SleepDisabled = 0`。`B/helper-created` があり、3ファイルとも今回作ったものと分かる。
- **操作**:
  1. sudoers のルールだけを削除せず退避する。

     ```sh
     /usr/bin/sudo /bin/mv "$RULE" "$B/sudoers.test-backup"
     ```

  2. 「ヘルパー」を開き、部分欠落の表示と「修復」「削除」を記録する。「スリープ」で保存した選択肢（蓋のない Mac ではオンのスイッチ）が表示されたまま、アイコンが注意の記号に替わり、(i) の先頭で適用できない理由と修復先を読めることを確かめる。蓋のある Mac では「ディスプレイを閉じたとき」を「スリープ」にしてから「オンのまま」を選び、修復の確認と管理者認証を承認する。蓋のない Mac では「ヘルパー」の「修復」から管理者認証を承認する。

### 4.4 起動時の後片付けを確認する

### 4.5 削除と外部の disablesleep の保持を確認する

### 4.7 「明るさを0」の開閉・解除・利用者の変更を確認する

- **目的**: `SPEC-BLK-013`。閉じた間は暗くして画面収録を続け、閉じている間に上がった輝度は1分以内に0に戻し、開いたときと解除時に閉じる前の輝度へ戻す。
- **前提**: オーナーが操作する。未保存の作業を片付け、ヘルパーを設置済みにする（4.6まで終えていたら4.1で再設置する）。蓋のある Mac を電源接続・外部ディスプレイなしで机上に置く。開始前の輝度、自動輝度調節、True Tone、「スリープ」画面と再開の設定を控える。自動輝度調節をオフにし、明るさのキーで画面を十分明るくする。「ディスプレイを閉じたとき」は「明るさを0」、「ディスプレイを自動でオフにしない」はオン、バッテリーと指定時刻の解除条件はオフにする。**暗いだけの画面はロックされないので、席を離れない。** 輝度の判定は目視で行い、`ioreg` の値は使わない（`EVID-BLK-008`）。
- **操作**:
  1. 秒表示の時計を映して画面収録を始め、タイマーをオフにして抑止を開始する。蓋を1分閉じ、隙間から光が漏れるかを見る。開けた直後の明るさ、ロック画面の有無、すぐ操作できるかを確かめる。収録を停止して再生し、閉じた区間も時計が進んでいることを見る。再開用の記録を `plutil -p "$RECORD"` で読み、`savedBrightness` が残っていないことを確かめる。

  3. タイマーをオフにして開始し、蓋を閉じる。閉じている間に、接続した外付けキーボードの明るさのキーで画面を明るくする。隙間の光で変化を確認し、1分以内に光が消えるかを見る。明るくしてから1分以上待って蓋を開け、閉じる前の明るさに戻るかを見る。記録に `savedBrightness` が残っていないことを読む。閉じたまま明るさを変える手段がなければ、この操作は未実施として理由を残す。
- **期待**: 1は閉じている間に光が漏れず、開けると元と同じくらいの明るさになり、ロックされずすぐ操作できる。収録の描画は続く。2は閉じたまま解除され、開けても暗い画面が残らない。3は明るくしてから1分以内に輝度が0に戻って隙間の光が消え、開けると閉じる前と同じくらいの明るさになる。いずれも復元後に輝度の記録は残らない。`disablesleep` より先に戻す呼び出し順は自動テストで確かめ、目視だけで順序を断定しない。
- **中止**: 異常発熱、解除後も暗いまま、収録停止、予期しないロックがある場合。安全に隙間を見られなければ光漏れは判定不能とする。
- **復元**: 蓋を開けて抑止を解除する。暗いままなら明るさのキーで戻す。収録中なら停止し、輝度・自動輝度調節・True Tone・「スリープ」画面と再開の設定を控えた値へ戻す。この節のために再設置したヘルパーは4.5で削除する。戻らなければ後続を止め、記録を保管して PM に渡す。
- **記録**: Mac と macOS の版、各回の設定、閉じた時刻と開いた時刻、目視の明るさと光漏れ、ロックの有無、収録ファイルと該当区間、復元後の記録と `SleepDisabled`、未実施・判定不能の項目と理由。

## 5. LED と Caps Lock の入力状態を確認する

この節では、LED が点灯すること（5.1）、入力状態が変わらないこと（5.1）、機器の抜き差しと復帰で点灯が戻ること（5.1）、キー配列を変更するアプリの案内と入力への影響（5.2）を見る。

この節は目視が主になる。判定は「LED と入力の両方」で行い、読み戻した値や画面の表示だけで合格にしない。

### 5.1 点灯、入力、接続変更、復帰を確認する

- **目的**: `HYP-LED-001`、`HYP-LED-003`、`HYP-LCY-001`、`SPEC-LED-001`、`SPEC-LED-002`、`SPEC-LED-003`。
- **前提**: 1.4の独立復旧手順が承認済みである。入力監視を新たに許可しない。「ディスプレイを自動でオフにしない」と時間・バッテリーの解除条件をオフにし、「ディスプレイを閉じたとき」を「スリープ」にする（蓋のない Mac では「メニューから選んでもスリープさせない」をオフにする）。自動スリープの抑止は常に働く。Caps Lock は利用者が手動でオフにする。
- **操作**:
  1. LED の通知をオンにしてメニューで開始する。内蔵キーボードと、USB・Bluetooth・2.4 GHz レシーバーの各外付けキーボードで `abc` を入力する。
  2. 利用者が Caps Lock をオン・オフする。抑止を解除し、同じ操作を繰り返す。
  3. 再び開始し、外付けキーボードを接続・切断・再接続する。
  4. Apple メニューでスリープし、復帰する。LED を見る。続けて `pmset displaysleepnow` で画面だけをスリープさせ、10秒後に Shift キーで復帰させて LED を見る。`open -a ScreenSaverEngine` でスクリーンセーバーを起動して戻ったときと、Control + Command + Q でロックして解除したときも LED を見る。ロックでは、ロック画面の間と解除の後の両方を見る。
  5. 抑止中に LED の通知をオフにする。通常の Caps Lock 連動を確かめ、解除する。
- **期待**: 1は LED だけが点灯し、入力は小文字である。2は抑止中は点灯を保ち、解除後は通常連動に戻る。3・4は対象へ再適用する。5は通常連動に戻る。
- **中止**: 入力状態が勝手に変わる、入力監視の許可要求、復旧失敗の場合。
- **復元**: まずメニューで解除する。各対象の `"Auto"` 書き込みと目視確認ができなければ、承認済みの独立復旧手順を実行する。読み戻し値だけを合格条件にしない。
- **記録**: キーボードごとに、接続方式、LED の点灯、入力した文字の大小、解除後の戻り。スリープ復帰の所要時間も書く。

1.4 で控えた機器名と、3の抜き差しで反応した機器が同じかを照合する。名前が同じ機器が2台ある環境では、3の結果を機器ごとに分けて書く。

`HYP-LCY-001` の「書いたプロセスの終了後も残る」は、自動再起動する製品では復元と競合して測れない。独立した試作プロセスがないため判定不能とする。利用者が Caps Lock を操作する場合も、ソフトウェアから入力状態を変更する操作は使わない。

### 5.2 キー配列を変更するアプリの案内と入力への影響を確認する

- **目的**: `SPEC-LED-002`、`SPEC-LED-005`。
- **前提**: Karabiner-Elements を既に使える検証環境である。新たなインストールや設定変更はこの手順に含めない。修飾キーを厳密に照合する Karabiner-Elements のルール（`from.modifiers` に `optional` がないもの）を1つ用意している。
- **操作**: Karabiner-Elements が動作中に設定の「LED」を開き、案内を撮る。LED の通知をオンにして開始し、用意したルールを試す。解除してから Karabiner-Elements をメニューバーから終了し（「Quit Karabiner-Elements」）、案内が消えるか見る。
- **期待**: 動作中だけ設定の「LED」に案内がある。抑止中もルールが成立する。Karabiner-Elements が既定の設定で占有するキーボードでは、抑止中に Caps Lock をオンにしてオフにすると LED が消える（`DEC-LED-006` で受け入れた振る舞い、`EVID-LED-012`）。Caps Lock に触れない間は点いていてよい。終了後、10秒以内に案内が消える。
- **中止**: ルールが抑止中だけ成立しない、通常連動へ復元できない場合。
- **復元**: 抑止を解除し、承認済みの LED 復旧手順を実行する。Karabiner-Elements の稼働状態を開始前へ戻す。
- **記録**: 設定の「LED」の案内、ルールの成否、LED の目視、案内が消えるまでの秒数、Karabiner-Elements の稼働状態。

`HYP-LED-004` は製品が使わない `IOHIDDeviceSetValue` の試験である。専用試作と復旧手順がないので実施しない。`SPEC-LED-006` の関数欠落も通常ビルドでは模擬できないため判定不能とする。チケットの LED 番号範囲のうち、仕様に存在しない番号は割り当てない。

## 6. 終了と再開用の記録を確認する

     ```sh
     /bin/kill -SEGV "$PID"
     ```

  5. 再起動後に記録を読み、元の解除時刻を過ぎるまで待つ。

     ```sh
     /usr/bin/plutil -p "$RECORD" | /usr/bin/grep -E 'isRunning|lastUpdated|misalignments'
     /bin/date '+%Y-%m-%dT%H:%M:%S%z'
     ```

- **期待**: 2は `isRunning = false`、`exitReason = userQuit`、`session` がない。アサーションは解放済みである。3は再開しない。4は再開し、5は元の期限で解除し、タイマーを数え直さない。
- **中止**: 記録保存失敗の警告、解除時刻の延長、PID の不一致の場合。
- **復元**: 解除し、再開を「再開しない」に戻す。記録を消して不具合を隠さず、9節まで保管する。
- **記録**: 2と5で読んだ記録の中身、アサーションの有無、解除した時刻、再開までにかかった時間。

クラッシュさせる前に、2.2の4と同じく PID が Debug アプリの絶対パスと一致することを確かめる。`kill -SEGV` は1回だけ行い、再起動しないときに撃ち直さない。

輝度のクラッシュ復旧は別の回で4.7の前提を整え、「アプリの再起動時だけ」で暗くした後、この節の4の PID 照合とクラッシュを行う。蓋を閉じたまま再起動を待ってから開け、元と同じくらいの明るさ、抑止の再開、`savedBrightness` の消去を確認し、4.7の復元を行う（`SPEC-BLK-013`）。

### 6.2 ログアウト・再起動・連続クラッシュを確認する

- **目的**: `HYP-LCY-004`、`HYP-LCY-005`、`SPEC-LCY-004`、`SPEC-LCY-006`、`SPEC-LCY-007`。
- **前提**: 6.1が成功し、ログイン起動をオンにしている。LED とヘルパーを使わない。
- **操作**:
  1. 次の表の各行で新しく抑止を開始し、記載の終了操作を行う。再ログイン後、状態と `RECORD` を保存する。各行の間に解除する。

     | 再開設定 | 終了操作 | 期待する状態 |
     | --- | --- | --- |
     | 再開しない | Apple メニューの再起動 | 停止中 |
     | アプリの再起動時だけ | ログアウト、続けて別の試行で再起動 | 両方とも停止中 |
     | アプリと Mac の再起動時 | ログアウト、続けて別の試行で再起動 | 両方とも抑止中 |
     | アプリと Mac の再起動時、タイマー1分 | システム終了して2分以上待って起動 | 期限切れなので停止中 |

     再ログイン後は次で状態と記録を保存する。

     ```sh
     scripts/manual/verify.sh status
     /usr/bin/plutil -p "$RECORD" | /usr/bin/grep -E 'isRunning|exitReason|lastUpdated|crashLaunches'
     ```

  2. 再起動直前と直後に `sysctl kern.boottime` と `date '+%Y-%m-%dT%H:%M:%S%z'` を保存する。`lastUpdated` は Swift の `Date` の標準 JSON 表現で、2001-01-01 UTC からの秒数である。UNIX 秒と直接比較しない。

     ```sh
     /usr/sbin/sysctl kern.boottime
     /bin/date '+%Y-%m-%dT%H:%M:%S%z'
     ```

  3. 再開を「アプリの再起動時だけ」にして開始する。10分以内に、2.2の PID 照合→クラッシュ→別 PID の起動確認を3回、1回ずつ行う。途中で手動の解除や開始をしない。1回分は次のとおりで、これを3回繰り返す。

     ```sh
     PID="$(/bin/launchctl print "$JOB" | /usr/bin/awk '$1 == "pid" && $2 == "=" {print $3}')"
     /bin/ps -p "$PID" -ww -o pid=,comm=
     /bin/kill -SEGV "$PID"
     sleep 5
     /bin/launchctl print "$JOB" | /usr/bin/grep -E '^\s*(state|pid|runs|last exit code) ='
     ```

- **期待**: 表のとおりである。同じ Mac 起動中の `kern.boottime` は変わらず、Mac 再起動後は保存した更新時刻より後になる。連続クラッシュは1・2回目だけ再開し、3回目は停止中となる。`crashLaunches` に3件が残る。
- **中止**: ログインしても起動しない、再開条件と結果が違う、3回目でも再開する場合。追加のシグナルを送らない。
- **復元**: 起動していれば解除し、再開を「再開しない」に戻す。再起動・ログアウトで失われる他アプリの未保存データは戻せないので事前保存を必須とする。
- **記録**: 表の行ごとの再開設定と結果、`kern.boottime`、`lastUpdated`、`crashLaunches` の件数、3回のクラッシュで撃った PID と再起動後の PID。

表の各行は独立した試行である。行をまたいで抑止を続けない。行の途中で期待と違う結果が出たら、その行だけを止めて記録し、次の行へ進んでよいかは PM が決める。

`HYP-LCY-005` の Apple Event の生値、終了処理の意図的な引き延ばし、ログアウト取り消し後の内部判定は通常ビルドで採取・注入できない。表による間接確認と区別して判定不能とする。`HYP-LCY-004` の時計を戻す試験は、他サービスにも影響するため実施しない。起動処理途中の中断、起動時刻の取得不能、記録保存失敗、ヘルパーの期限超過は専用の偽物を使う自動テストに任せ、実機の権限や時計を壊して模擬しない。

## 7. CLI の起動・書式・終了コードを確認する

この節では、停止したアプリを CLI が起こせること（7.1）、返す終了コードとソケットの所有者（7.1）、受け付けない入力と設定を拒むこと（7.2）を見る。

終了コードの意味は次のとおり。数字だけを覚えるより、どの状態を表すかで読む。

| 終了コード | 意味 |
| --- | --- |
| `0` | 成功。開始、解除、状態の取得ができた |
| `1` | `status` で停止中 |
| `64` | 使い方の誤り（引数の形が違う） |
| `69` | 要求を完了できなかった。アプリに接続できないときもこれ |

### 7.1 停止したアプリを CLI から起動する

- **目的**: `SPEC-CLI-001`、`SPEC-CLI-002`、`SPEC-CLI-003`、`SPEC-CLI-004`、`SPEC-CLI-006`、`SPEC-CLI-007`。
- **前提**: CLI を受け付ける設定がオンで、「ディスプレイを閉じたとき」は「スリープ」（蓋のない Mac では「メニューから選んでもスリープさせない」はオフ）、LED はオフである。バッテリーの解除条件もオフにする。メニューからアプリを終了する。
- **操作**: 1コマンドずつ出力を記録する。`set -e` は使わない。

  ```sh
  "$CLI" on --for 1m
  printf 'exit=%s\n' "$?"
  "$CLI" status
  printf 'exit=%s\n' "$?"
  "$CLI" on --for 2m
  printf 'exit=%s\n' "$?"
  "$CLI" off
  printf 'exit=%s\n' "$?"
  "$CLI" status
  printf 'exit=%s\n' "$?"
  ```

  設定の「操作」で CLI パスをコピーし、`$CLI` と同じ絶対パスか比較する。ソケットも読む。

  ```sh
  /bin/ls -ld "/private/tmp/io.github.koutyuke.capsaicin-$(id -u)"
  /bin/ls -l "/private/tmp/io.github.koutyuke.capsaicin-$(id -u)/ipc.debug.sock"
  ```

- **期待**: 最初の `on` でその CLI を含む Debug アプリが起動する。終了コードは順に `0, 0, 0, 0, 1`。2回目の `on` は、その要求を受けた時点から2分後に解除の時刻を置き換え、置き換えたことと新しい解除の時刻を伝える。CLI 操作では HUD が出ない。ソケットの親は当該ユーザー所有で700、Debug ソケットは `ipc.debug.sock` である。
- **中止**: Release の起動、接続失敗、所有者違いの場合。ソケットの権限を変えて回避しない。
- **復元**: CLI の `off`、またはメニューで解除する。ソケットは共有ディレクトリごと消さない。
- **記録**: 各コマンドの標準出力・標準エラー・終了コード、アプリが起動したか、コピーした CLI パスと `$CLI` の一致、ソケットの所有者と権限。

### 7.2 不正な書式と受け付けない設定を確認する

## 付録 A. つまずいたときの切り分け

状態が期待から外れたときは、次の順で見る。当てはまらないときは、そのまま中止して記録する。

| 症状 | まず確かめること |
| --- | --- |
| プロセスが0本、または2本以上 | `launchctl print "$JOB"` を読み直し、`ps -p <pid>` で pid が実在するか見る。5秒待って再確認 |
| `launchctl bootstrap` が失敗する | `print` で残存ジョブを確認する。同じコマンドを繰り返さない |
| ログイン後にジョブが見つからない | plist の有無、`launchctl print-disabled` の該当行、`RunAtLoad` の値 |
| `sudo -n` がパスワードを要求する | sudoers のルールの有無。認証を入れずに中止 |
| `SleepDisabled` が戻らない | 9.1の緊急復旧。戻らなければ 9.4 で報告 |
| LED が通常連動に戻らない | 承認済みの独立復旧手順。読み戻し値で合格にしない |
| 設定画面の警告行が消えない | アプリを終了して `open` で起動し直す。それでも消えなければ 2.3 で止める |

## 付録 B. 結果のまとめ方

節末の結果欄は、次の形で埋めると読み手が追いやすい。空欄を残したまま次へ進まない。

```text
成功／失敗／判定不能: 成功（2.2-4のクラッシュ再起動まで）
観測値: kickstart→pid 2345、SEGV→pid 2456（runs 2、last exit code -11）
      再ログイン後 state=not running、pid なし
復元: SleepDisabled 0、ヘルパー3ファイルなし、LED 通常連動
未実施と理由: HYP-LCY-003 は経路別の環境記録機能がないため判定不能
気づいたこと: 2.2-3 のログイン後は loaded/not running で期待どおり
写真・ログ: /Users/<user>/Capsaicin-verification.ab12cd/general-warning.png
```

この手順自体を直すときは、実測と食い違った箇所を先に記録する。期待値を実測に合わせて書き換えるのではなく、製品が違うのか手順が違うのかを PM が判断してから直す。
