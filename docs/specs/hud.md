# 画面表示（HUD）の仕様

## 対象範囲

抑止を切り替えたときに画面に出す表示（HUD）の、表示する場面、内容、出し方、寸法、動き、アクセシビリティを定める。HUD を自前で描く判断は `DEC-HUD-001`、素材と動きの判断は `DEC-UI-007`、設定がオフでも VoiceOver で読み上げる判断は `DEC-UI-005` にある。文言の正本は String Catalog にある（`SPEC-UI-011`）。

受け入れ例の共通の前提は、`specs/blocking.md` の「受け入れ例の共通の前提」にある。

## SPEC-HUD-001 表示する場面

関連要件: `REQ-HUD-001`、`REQ-HUD-003`

「切り替えたときに画面に表示する（HUD）」がオンのとき、次の場面で HUD を表示する。

- ホットキーまたはメニューで、抑止を開始または解除したとき。
- ホットキーまたはメニューで開始しようとして、開始を拒否したとき（`SPEC-BLK-010`）。
- タイマー、指定時刻、バッテリー残量によって、抑止が自動で解除されたとき。抑止中に設定を変えて、バッテリー残量の条件が成り立った場合も含む。

CLI で切り替えたとき、抑止中に設定を変えたとき（`SPEC-BLK-009`。解除に至った場合を除く）は表示しない。設定がオフのときは、どの場面でも表示しない（VoiceOver の読み上げは `SPEC-HUD-008`）。

### 受け入れ例: CLI では表示しない

1. HUD の設定をオンにし、バッテリー残量の条件が成り立たない状態にする。
2. ホットキーで抑止を開始し、続けて `capsaicin off` を実行する。
3. ホットキーのときは HUD が表示され、`capsaicin off` のときは表示されない。

### 受け入れ例: 設定がオフなら表示しない

1. HUD の設定をオフにする。
2. メニューで抑止を開始する。
3. HUD は表示されない。

## SPEC-HUD-002 表示する内容

関連要件: `REQ-HUD-001`

HUD には、アイコン、状態、解除の条件（または理由）を、この順に1行で表示する。

| 場面 | アイコン | 状態 | 解除の条件・理由 |
| --- | --- | --- | --- |
| 開始した | `capslock.fill` | 止め始めたこと | 先に来る時間の条件（時刻か時間）。なければ出さない |
| 手動で解除した | `capslock` | 止めるのをやめたこと | 出さない |
| 時間の条件で解除した（由来がタイマー） | `capslock` | 止めるのをやめたこと | タイマーが終わったこと |
| 時間の条件で解除した（由来が指定時刻） | `capslock` | 止めるのをやめたこと | その時刻になったこと |
| バッテリー残量で解除した | `capslock` | 止めるのをやめたこと | バッテリーがしきい値を下回ったこと |
| 開始を拒否した | `capslock` | 開始できないこと | 理由（バッテリーがしきい値を下回っていること、ヘルパーで止められなかったことなど） |
| 解除したが、合わせられていない制御が残った（`SPEC-BLK-007`） | `capslock` | 止めるのをやめたこと | 一部を元に戻せなかったこと。上の解除の行の代わりに表示する |

時間の条件による解除の理由は、抑止のセッションの由来（`SPEC-BLK-003`）から決める。解除の条件・理由を出さないときは、状態だけを表示し、区切りも出さない。

### 受け入れ例: 開始したとき

1. 指定時刻を 4:00 にする。
2. メニューで、指定せずに抑止を開始する。
3. HUD に、`capslock.fill`、止め始めたこと、4:00 までであることが表示される。

### 受け入れ例: 手動で解除したとき

1. 抑止中にする。
2. ホットキーで解除する。
3. HUD に、`capslock` と、止めるのをやめたことだけが表示され、区切りと解除の条件は表示されない。

## SPEC-HUD-003 ウインドウの性質

関連要件: `REQ-HUD-002`

- `NSPanel` を `.nonactivatingPanel` と `.borderless` で作り、`ignoresMouseEvents = true` にしてクリックを下のウインドウに通す。キーウインドウにもメインウインドウにもならない。
- レベルは `.statusBar`。`collectionBehavior` に `.canJoinAllSpaces`、`.fullScreenAuxiliary`、`.stationary`、`.ignoresCycle` を付け、フルスクリーンのアプリの上にも表示し、ウインドウの切り替えの対象にしない。
- スクリーンショットや画面共有には写ってよい。

### 受け入れ例

1. テキストエディタで入力している状態で、パネルが出る位置の下にほかのウインドウを置く。
2. ホットキーで抑止を開始し、入力を続け、パネルの上をクリックする。
3. 入力はテキストエディタに入り続け、クリックはパネルの下のウインドウに届く。

## SPEC-HUD-004 寸法と素材

関連要件: `REQ-HUD-001`

| 項目 | 値 |
| --- | --- |
| 形 | カプセル。高さ 48 pt、角丸 24 pt |
| 幅 | 内容に合わせる。最大 420 pt。超えた分は解除の条件・理由の文字列を末尾で省略する。状態の文字列は省略しない |
| 左右の余白 | 左 17 pt、右 20 pt。SF Symbols が形の外側に持つ約 3 pt の空白を左で差し引き、見える余白を左右で揃える |
| アイコン | SF Symbols、`.title3` に合わせた大きさ、Monochrome、`labelColor` |
| アイコンと文字の間隔 | 10 pt |
| 状態の文字 | `.title3`、`.semibold`、`labelColor` |
| 区切り | 中黒（·）。前後に 6 pt。`tertiaryLabelColor` |
| 解除の条件・理由の文字 | `.title3`、`secondaryLabelColor` |
| 素材 | SwiftUI の `glassEffect(.regular, in: Capsule())`（Liquid Glass の Regular）。影はガラスの既定に任せ、独自の影を足さない |
| 位置 | マウスカーソルがある画面の `visibleFrame` の水平中央、下端から 64 pt 上 |

### 受け入れ例

1. Dock を画面の下に表示した状態にする。
2. ホットキーで抑止を開始する。
3. HUD は Dock より上、画面の水平中央に、高さ 48 pt のカプセルとして表示される。

## SPEC-HUD-005 出入りの動き

関連要件: `REQ-HUD-001`

| 段階 | 変化 | 時間 | カーブ |
| --- | --- | --- | --- |
| 入る | 不透明度 0 → 1、拡大率 0.96 → 1、下から 8 pt 上へ | 0.20 秒 | ease-out（`cubic-bezier(0.2, 0, 0, 1)` 相当） |
| 留まる | 変化なし | 1.6 秒 | — |
| 出る | 不透明度 1 → 0、拡大率 1 → 0.98 | 0.30 秒 | ease-in（`cubic-bezier(0.4, 0, 1, 1)` 相当） |

表示から消えるまでは約 2.1 秒である。バネによる揺れ（オーバーシュート）は使わない。

### 受け入れ例

1. HUD の設定をオンにする。
2. ホットキーで抑止を開始し、画面を録画する。
3. HUD は約 0.2 秒で現れ、約 1.6 秒留まり、約 0.3 秒で消える。揺れは見られない。

## SPEC-HUD-006 続けて切り替えたとき

関連要件: `REQ-HUD-001`

- HUD は常に1枚だけにし、並べたり積み重ねたりしない。
- 入る・留まる段階で次の切り替えがあったら、同じパネルの内容を置き換え、留まる時間を最初から数え直す。
- 置き換えの動きは次のとおりにする。時間はどれも 0.20 秒、カーブは ease-out（`cubic-bezier(0.2, 0, 0, 1)` 相当）である。
  - 幅が変わるときは、カプセルが中央の位置を保ったまま左右に伸び縮みする。
  - アイコンと文字は1行として左端を揃え、カプセルの左端の動きに合わせて横に移る。伸び縮みの途中でも、内容はカプセルの外に見えない。
  - アイコンは SF Symbols の置き換えアニメーション（`.contentTransition(.symbolEffect(.replace))`）で切り替える。
  - 文字（状態、区切り、解除の条件・理由）は、古い文字をぼかしながら消し、新しい文字をぼかした状態から現す。拡大・縮小は加えない。新旧の文字が両方読める瞬間を作らない。
- 出る段階で次の切り替えがあったら、その時点の不透明度から 0.15 秒で不透明に戻し、内容を置き換える。いったん消してから出し直さない。
- 短い間に何度も切り替えたら、最後の状態を表示する。途中の状態を順番に見せない。

### 受け入れ例: 何度も切り替える

1. HUD の設定をオンにする。
2. ホットキーを 3 秒間に 10 回押す。
3. HUD は1枚のまま、ちらつかずに最後の状態を表示し、最後の切り替えから約 1.6 秒留まってから消える。

### 受け入れ例: 幅の違う内容に置き換える

1. HUD の設定をオンにし、解除しても一部の制御を元に戻せない状態にする（`SPEC-BLK-007`）。
2. ホットキーで抑止を開始し、HUD が留まっている間にもう一度押して解除し、画面を録画する。
3. カプセルは中央の位置を変えずに左右へ伸び、アイコンと文字はカプセルの左端と一緒に左へ移る。文字はカプセルからはみ出さず、「オン」と「オフ」の文字が重なって読める瞬間がない。

## SPEC-HUD-007 複数のディスプレイ

関連要件: `REQ-HUD-001`

- 表示を始める時点でマウスカーソルがある画面（`NSEvent.mouseLocation` を含む `NSScreen`）に出す。
- 表示中に内容を置き換えるときは、カーソルが別の画面に移っていても、表示中の画面のまま更新する。次に新しく表示するときは、そのときのカーソルの画面に出す。
- 表示中にディスプレイの構成が変わったら、HUD をすぐに消す。

### 受け入れ例

1. 外部ディスプレイを接続し、マウスカーソルを外部ディスプレイに置く。
2. ホットキーで抑止を開始し、表示中にカーソルを内蔵ディスプレイへ移して、もう一度ホットキーを押す。
3. HUD は外部ディスプレイに出て、2回目も外部ディスプレイのまま内容が変わる。

## SPEC-HUD-008 アクセシビリティ

関連要件: `REQ-HUD-004`

- 視差効果を減らす: 拡大と移動をやめ、不透明度の変化だけにする（入る 0.20 秒、出る 0.30 秒）。アイコンの置き換えはクロスフェードにする。
- 透明度を下げる: ガラスを不透明な背景（`windowBackgroundColor`）に置き換え、`separatorColor` の 1 pt の枠線を付ける。ガラスが自動で不透明にならない場合は、この置き換えをアプリが行う。
- コントラストを上げる: `separatorColor` の 1 pt の枠線を付け、解除の条件・理由の文字を `labelColor` にする。
- VoiceOver: 表示と同時に、同じ内容を1文にして `NSAccessibility.post(element:notification:userInfo:)` の `.announcementRequested` で読み上げる。区切りの中黒は読ませない。HUD の設定がオフでも、VoiceOver が動いていれば、HUD を表示する場面で読み上げる。

### 受け入れ例: 視差効果を減らす

1. 「視差効果を減らす」をオンにする。
2. ホットキーで抑止を開始し、録画する。
3. HUD は拡大も移動もせず、不透明度だけが変わる。

### 受け入れ例: 設定がオフでも読み上げる

1. VoiceOver をオンにし、HUD の設定をオフにする。
2. ホットキーで抑止を開始する。
3. HUD は表示されず、止め始めたことと解除の条件が読み上げられる。
