# 設定画面の仕様

## 対象範囲

設定ウインドウの構成、設定項目と既定値、(i) の説明、「このアプリについて」のアップデートとリンク、ライセンス、「スリープ」の見せ方、その Mac にない機能の項目の扱いを定める。各項目が変える振る舞いは、表の「振る舞い」の列が指す仕様にある。すべての項目を個別に切り替える判断は `DEC-SET-001`、設定の保存は `DEC-SET-002`、セクションとカードの構成は `DEC-SET-006`、「このアプリについて」の構成は `DEC-UI-014`、スリープとディスプレイの用語は `DEC-UI-012` にある。画面をまたぐ規則（文字、色、コントロールの種類）は `specs/ui.md` にある。項目名はここでは項目を指す呼び名であり、文言の正本は String Catalog にある（`SPEC-UI-011`）。

受け入れ例の共通の前提は、`specs/blocking.md` の「受け入れ例の共通の前提」にある。

## SPEC-SET-001 ウインドウとサイドバー

関連要件: `REQ-SET-002`、`REQ-MENU-005`

- AppKit の `NSWindow` に SwiftUI の `NavigationSplitView` を載せる。左はサイドバー（`List`、`.sidebar` スタイル）、右は選んだセクションの `Form`（`.grouped` スタイル）。
- ウインドウは幅 720 pt × 高さ 500 pt でサイズを固定する。サイドバーの幅は 200 pt で固定する。行の高さ、角丸、余白はシステム既定にする。ただし、右側の内容の上の余白は下の規則に従う。
- ウインドウの上端に、全幅のタイトルバーの帯を置かない。サイドバーはウインドウの上端から下端まで伸ばし、閉じる・最小化・ズームのボタンはサイドバーの上に重ねる（`DEC-UI-006`）。
- 上端は、標準のツールバー（`.unified`）にする。閉じるボタンなどはその縦の中央に乗る。各セクションの最上段では、項目を置かず、選んだセクション名を標準のタイトルとして右側の最上段に出す。右側の内容にはセクション名の大きな見出しを置かない。ツールバーの背景と区切り線は標準のものをそのまま使う。ライセンスのシート（`SPEC-SET-008`）を開いて閉じても、設定ウインドウのタイトルとタイトルバーの高さ、閉じるボタンの位置は変えない。
- 右側の内容の最初のグループ（見出しがあるときは見出し）は、ツールバーの下端から 12 pt に置く。「このアプリについて」では、最初のグループの代わりにアプリアイコンの上端をこの位置に置く。macOS 26 のシステム設定と同じ間隔である。
- 最小化とズームのボタンは無効にする。
- 前回開いていたセクションを開く。初めて開くときや、保存されたセクションが存在しないときは「一般」を開く。
- 開くと、ほかのアプリが前面にあってもアプリを前面に出し、ウインドウをキーウインドウにする（`DEC-SET-003`）。
- 設定画面が別のデスクトップ（Space）に表示されていれば、そのデスクトップへ移って前面に出す。移るかどうかは、システム設定の「アプリケーションの切り替えで、アプリケーションのウインドウが開いているスペースに移動」に従う。設定画面を閉じていれば、いま見ているデスクトップに開く。フルスクリーンのアプリを見ているときは、その上に開く。
- アプリが動いている間に、Finder、Launchpad、Spotlight、Dock のアイコン（`SPEC-MENU-007`）などからアプリをもう一度開くと、設定画面を開く。初めて起動したときは開かない。
- 設定の変更はその場で反映し、「適用」ボタンは置かない。
- ⌘W で閉じる。サイドバーは ↑↓ で移動し、Tab で右側に移る。

サイドバーには、アイコンとセクション名を並べる。上の4つは閉じるボタンなどの下から並べ、下の2つはサイドバーの下端に寄せる。選択の表示と ↑↓ キーでの移動は、6 項目を通して連続させる。

| 位置 | セクション | アイコン |
| --- | --- | --- |
| 上 | 一般 | `gearshape` |
| 上 | スリープ | `moon.zzz` |
| 上 | LED | `custom.capsaicin.led`（独自シンボル） |
| 上 | 操作 | `keyboard` |
| 下 | ヘルパー | `lock.shield` |
| 下 | このアプリについて | `info.circle` |

### 受け入れ例: 構成

1. 設定画面を開く。
2. サイドバーを見て、「スリープ」を選ぶ。
3. 上端を横切るタイトルバーの帯がなく、サイドバーがウインドウの上端まで伸び、閉じるボタンなどがサイドバーの上に乗る。サイドバーの上に4つ、下端に「ヘルパー」と「このアプリについて」が、表のアイコンとともに並ぶ。右側の最上段のタイトルが「スリープ」に相当する名前になり、右側に項目が、左にアイコンと項目名、右にコントロールの形で並ぶ。

### 受け入れ例: サイドバーをキーボードで移動する

1. サイドバーの「一般」にフォーカスを置く。
2. ↓ で順に「このアプリについて」まで移り、↑ で「一般」まで戻る。
3. 上の4項目と下の2項目の境目でも移動が途切れず、選んだ項目に選択の表示が移る。

### 受け入れ例: 前回のセクションを開く

1. 設定画面で「LED」を開いてから閉じる。
2. メニューから設定画面を開き直す。
3. 「LED」が選ばれた状態で開き、ウインドウが前面のキーウインドウになる。最小化とズームのボタンは押せない。

### 受け入れ例: 起動中にアプリを開き直す

1. 設定画面を閉じた状態で、Finder からアプリを起動する。設定画面は開かない。
2. Finder からもう一度アプリを開く。
3. 設定画面が前面のキーウインドウとして開く。ほかのアプリを前面にしてから同じ操作をしても、設定画面が前面に出る。

### 受け入れ例: ほかのデスクトップとフルスクリーン

1. システム設定の「アプリケーションの切り替えで、アプリケーションのウインドウが開いているスペースに移動」をオンにする。デスクトップ1で設定画面を開いたまま、デスクトップ2に移り、ほかのアプリを前面にする。
2. ステータスアイコンのメニューから設定画面を開く。
3. デスクトップ1へ移り、設定画面が前面のキーウインドウになる。
4. 設定画面を閉じ、デスクトップ2に移ってから、もう一度開く。
5. 設定画面がデスクトップ2に、前面のキーウインドウとして開く。
6. 設定画面を閉じ、ほかのアプリをフルスクリーンにしてから、もう一度開く。
7. 設定画面がフルスクリーンのアプリの上に、前面のキーウインドウとして開く。

## SPEC-SET-002 設定項目と既定値

関連要件: `REQ-SET-001`

設定項目は次のとおりで、すべて個別に切り替えられる。ある項目を変えても、ほかの項目の保存値は変わらない。(i) の列は、(i) で伝えることを示す（`SPEC-SET-003`）。

カードは `Form` の `Section` で作り、各セクションの表の順に並べる。表の「カード」が同じ行は1枚にまとめ、グループの見出しは最初のカードだけに付ける。親の行と子の行は同じカードにまとめ、子は親のすぐ下に置く。子の行（親の値がオンのときだけ意味を持つ行）は、親がオフなら無効になり、値を保つ。無効の子の行は字下げと OS のグレーの表示で示し、(i) は置かない。

親の行と子を持たない行には、項目名の左に SF Symbols のアイコン（LED の項目は独自シンボル）を置く。アイコンは `secondaryLabelColor` で幅をそろえた列に置く。子の行にはアイコンを付けず、項目名の始まりを親の項目名にそろえる。注意の案内のアイコンは `exclamationmark.triangle.fill`（`systemOrange`）にし、案内の右側には何も置かない。ヘルパーが要る行の注意の表示は `SPEC-SET-005` に従う。

## SPEC-SET-003 項目名と説明

関連要件: `REQ-SET-003`

各項目には説明文を付けず、項目名だけで内容が伝わるようにする。項目名から分からない連動や制約がある行だけに (i) を置く（`DEC-SET-006`）。伝える内容は `SPEC-SET-002` の (i) の列、`SPEC-SET-005`、`SPEC-SET-007` にある。項目名の言い換えや、親がオフのため子が無効になる理由だけの説明には (i) を置かない。

(i) は項目名の右に `info.circle`（`secondaryLabelColor`、小さめ）で置く。クリックするか VoiceOver で操作すると、ポップオーバーで説明を開く。同じ文をツールチップにも設定し、ポインタを合わせても読めるようにする（`DEC-UI-002`）。(i) は、コントロールの有効・無効によらず押せる。抑止中の動作を説明するときの書き出しは `DEC-UI-012` に従う。

### 受け入れ例: キーボードで説明を開く

1. 設定画面で「スリープ」を開く。
2. Tab で「ディスプレイを自動でオフにしない」の (i) にフォーカスを移し、Space を押す。
3. ポップオーバーで説明が開く。行の下に説明文は表示されていない。

### 受け入れ例: ポインタを合わせて読む

1. 設定画面で「スリープ」を開く。
2. 「ディスプレイを自動でオフにしない」の (i) にポインタを合わせる。
3. ツールチップで同じ説明が表示される。

### 受け入れ例: 説明が必要な行だけに (i) を置く

1. 設定画面で「スリープ」を開く。
2. タイマー・指定時刻・バッテリー残量をオフにして、各行を見る。
3. (i) は「ディスプレイを自動でオフにしない」、ヘルパーが要る行、「指定時刻」にだけある。継続時間、時刻、しきい値、電源アダプタの子の行は、字下げとグレーで無効と分かり、(i) はない。

## SPEC-SET-004 このアプリについて

関連要件: `REQ-SET-004`、`REQ-MENU-005`、`REQ-SET-007`

右側は、ほかのセクションと同じ `Form`（`.grouped`）にする。スクロールは `SPEC-SET-002` に従い、次の順に並べる。

| 順 | まとまり | 内容 |
| --- | --- | --- |
| 1 | 見出し | アプリアイコン、アプリ名、バージョンとビルド番号 |
| 2 | アップデート | `SPEC-SET-007` の2行 |
| 3 | リンク | Web サイト、ライセンス |
| 4 | 終わりの部分 | 「Capsaicin を終了」ボタン、著作権の表示 |

見出しと終わりの部分はカードにせず、右側の幅の中央にそろえる。縦の中央にはそろえず、内容と一緒にスクロールさせる。グループの見出しとカードは標準の見た目にする。文字のスタイルは `SPEC-UI-002` に従う。

アプリアイコンは 96 × 96 pt にし、VoiceOver でアプリアイコンと分かるラベルを付ける。アプリ名には見出しの trait を付ける。バージョンとビルド番号は、実行中のアプリの値を表示し、選択してコピーできる。

自前で配置する間隔は次のとおりとする。上端の位置は `SPEC-SET-001` に従う。

| 場所 | 間隔 |
| --- | --- |
| アイコンとアプリ名の間 | 12 pt |
| アプリ名とバージョンの間 | 4 pt |
| バージョンと「アップデート」の見出しの間 | 24 pt |
| 「リンク」のカードと終了ボタンの間 | 24 pt |
| 終了ボタンと著作権の表示の間 | 12 pt |
| 著作権の表示とスクロールの内容の下端の間 | 24 pt |

「リンク」は、`SPEC-SET-002` の設定の行と同じアイコンと項目名の配置にする。

| 行 | 左のアイコン | 右側 | 操作 |
| --- | --- | --- | --- |
| Web サイト | `globe` | 装飾の `arrow.up.right` | 既定のブラウザで `https://github.com/koutyuke/Capsaicin` を開く |
| ライセンス | `doc.text` | 装飾の `chevron.right` | `SPEC-SET-008` のシートを開く |

どちらも行全体を押せるようにし、文字は `labelColor` にする。「Web サイト」にはリンクの trait と、ブラウザでリポジトリを開くことが分かるヒントを付ける。右の矢印は VoiceOver の対象から外す。「ライセンス」はボタンとして読み上げ、操作できるようにする。

終了ボタンは `SPEC-UI-005` の標準の枠付きボタンにし、色を付けない（`DEC-UI-010`）。押すと、メニューの「終了」と同じ処理でアプリを終了する（`SPEC-LCY-002`）。著作権の表示は、Info.plist の `NSHumanReadableCopyright` から読み、翻訳しない。

### 受け入れ例: 構成とスクロール

2. 内容を下端までスクロールし、VoiceOver の見出しの移動も使う。

2. 表示を見て、バージョンとビルド番号を選択してコピーする。

## SPEC-SET-005 「スリープとディスプレイ」の保存値と注意の表示

関連要件: `REQ-SET-005`

「スリープ」の「スリープとディスプレイ」は `SPEC-SET-002` のとおり、その Mac に合う2行を並べる。抑止中に止まる範囲は `SPEC-BLK-001`、保存値を抑止に使う規則は `SPEC-BLK-012` にある。設定の操作で行を消したり、並びを動かしたりしない。

「ディスプレイを閉じたとき」は、次の対応で保存値を表示し、選んだ値を保存する。ポップアップはヘルパーの状態によって無効にしない。MacBook 以外の Mac のスイッチは、手動スリープの保存値をそのまま表示する。

| 選択肢 | 手動スリープの保存値（`blocksManualSleep`） | 閉じたときのディスプレイの保存値（`lidCloseDisplay`） |
| --- | --- | --- |
| スリープ（標準） | オフ | 変更しない |
| ディスプレイをオフ | オン | `turnOff` |
| 明るさを0 | オン | `zeroBrightness` |
| オンのまま | オン | `keepOn` |

「スリープ」以外を選んだとき、ヘルパーが使えなければ、確認のうえ設置する（承認待ちなら、システム設定を開く）。設置が完了したら選んだ値を保存する。システム設定での許可を待つ間は、選んだ値を表示したまま保存値を変えず、行のアイコンを `exclamationmark.triangle.fill`（`systemOrange`）に置き換え、(i) の先頭に、システム設定で Capsaicin の項目を許可すると有効になることを示す。確認を断った場合、失敗した場合、許可を待つ間に選んだ値を捨てた場合は保存値を変えず、保存値に対応する選択肢に戻る。流れは `SPEC-HLP-001` にある。抑止中の反映に失敗したときは `SPEC-BLK-009` に従う。

ヘルパーが要る設定が保存されているのに、ヘルパーが使えないとき（未インストール、承認待ち、このビルドでは使えない。`SPEC-HLP-004`）は、保存した選択肢（MacBook 以外の Mac ではオンのスイッチ）を表示したままにする。その行のアイコンを `exclamationmark.triangle.fill`（`systemOrange`）に置き換え、(i) の先頭に、ヘルパーを使えないためこの設定を適用できないことと、直し方（未インストールなら「ヘルパー」セクションで設置すること、承認待ちならシステム設定で Capsaicin の項目を許可すること）を示す。ヘルパーの状態は、抑止の判定（`SPEC-BLK-012`）には影響しない。削除の扱いは `SPEC-HLP-004` にある。

「明るさを0」が選ばれていて（上の対応表）、DisplayServices で内蔵ディスプレイの輝度を変えられないと分かったとき（判定は `SPEC-BLK-013`）も、保存値に対応する選択肢を表示したまま操作できるようにする。行のアイコンは上と同じ注意の記号にし、(i) の先頭で、輝度を変えられないため閉じても画面が点いたままになることを伝える。ヘルパーの注意もあるときは、(i) の先頭で両方を伝える。

### 受け入れ例: 選択と保存値の対応

1. ヘルパーを設置し、「ディスプレイを閉じたとき」で「オンのまま」を選ぶ。
2. 「スリープ」を選び、設定画面を閉じて開き直す。続けて「ディスプレイをオフ」を選ぶ。
3. 各選択で保存値が表の対応になり、開き直しても保存値に対応する選択肢が表示される。行の数と並びは変わらない。

### 受け入れ例: ヘルパーの設置を断る

1. ヘルパーが未インストールの状態で、「ディスプレイを閉じたとき」は「スリープ」にしておく。
2. 「オンのまま」を選び、設置の確認を取り消す。
3. 保存値は変わらず、ポップアップは「スリープ」に戻る。

### 受け入れ例: ヘルパーを使えなくなった場合

1. ヘルパーを設置して「ディスプレイを閉じたとき」で「オンのまま」を選んでから、システム設定の「ログイン項目と機能拡張」で Capsaicin の項目をオフにする。
2. 設定画面で「スリープ」を開き、ヘルパーが要る行と (i) を見る。
3. ポップアップは「オンのまま」を表示し、操作できるままである。アイコンが注意の記号に置き換わり、(i) の先頭で設定を適用できない理由と直し方を読める。

### 受け入れ例: MacBook 以外の Mac でヘルパーを使えなくなった場合

1. MacBook 以外の Mac でヘルパーを設置して「メニューから選んでもスリープさせない」をオンにし、システム設定の「ログイン項目と機能拡張」で Capsaicin の項目をオフにする。
2. 設定画面で「スリープ」を開き、ヘルパーが要る行と (i) を見る。
3. スイッチはオンのまま表示され、アイコンが注意の記号に置き換わる。(i) の先頭で設定を適用できない理由と直し方を読める。

### 受け入れ例: 「明るさを0」を使えない Mac

1. ヘルパーを設置して「ディスプレイを閉じたとき」を「明るさを0」にする。DisplayServices で内蔵ディスプレイの輝度を変えられないことが分かる試験用の環境にする。
2. 設定画面で「スリープ」を開き、その行と (i) を見る。続けてヘルパーも使えない状態にし、もう一度見る。
3. どちらも「明るさを0」が表示され、ポップアップは操作できる。アイコンは注意の記号になり、(i) の先頭で、輝度を変えられず閉じても画面が点いたままになることを読める。ヘルパーも使えない場合は、その理由と直し方も読める。

## SPEC-SET-007 アップデートの設定と操作

関連要件: `REQ-SYS-008`

「このアプリについて」の「アップデート」には、「自動アップデート」と「ソフトウェアアップデート」の2行を、この順に置く。行の配置とアイコンの色は `SPEC-SET-002` に従う。更新の方式、配信元、署名の検証は `DEC-SYS-019` に従う。

| 行 | アイコン | コントロール |
| --- | --- | --- |
| 自動アップデート | `arrow.triangle.2.circlepath` | 右側にポップアップと、項目名の横に (i) |
| ソフトウェアアップデート | `arrow.down.circle` | 項目名の下に状態、右側に操作のボタン |

### 自動アップデート

選択肢と Sparkle の設定の対応は次のとおりとし、選ぶと2つの値をこの組み合わせにする。既定は「確認のみ」で、自動の確認の許可を求めない。

| 選択肢 | `automaticallyChecksForUpdates` | `automaticallyDownloadsUpdates` |
| --- | --- | --- |
| オフ | `false` | `false` |
| 確認のみ | `true` | `false` |
| ダウンロードしてインストール | `true` | `true` |

確認がオフでダウンロードがオンの値は、「オフ」と表示する。保存の責務は `SPEC-SET-002` に従う。Sparkle の画面で値が変わったときも、ポップアップをその値に合わせる。「オフ」でも、手動の確認はできる。

(i) は `SPEC-SET-003` の方法で開く。自動の確認は1日に1回ほど行うこと、「ダウンロードしてインストール」では抑止を止めているときにインストールして起動し直すこと、対象は安定版だけであることを伝える。インストールを待つ条件は `SPEC-LCY-008` にある。自動の確認がオンなら、初めて起動したときにも確認する。

### ソフトウェアアップデート

行には、次の4つの状態だけを持たせる。インストールを待つ版がある場合を優先し、次に新しい版がある場合、最後に確認日時の有無で表示を決める。

| 状態 | 項目名の下で伝えること | ボタンの操作 |
| --- | --- | --- |
| 確認したことがある | 最終確認の日時 | 今すぐ確認する |
| まだ確認していない | まだ確認していないこと | 今すぐ確認する |
| 新しい版がある | 利用できる版の番号 | その版のアップデートの画面を開く |
| インストールを待っている版がある | 版の番号と、インストールを待っていること | 無効。自動でダウンロードした版は `SPEC-LCY-008` の条件がそろうとインストールされる |

抑止中の確認でインストールを取り消した版（`SPEC-LCY-008`）も、「新しい版がある」状態で示す。「新しい版がある」状態は、メニューの知らせ（`SPEC-MENU-009`）と同じときに終わる。利用者がその版の Sparkle の画面を見て後の通知を選んだときや、更新の処理が終わったときは、確認日時の状態に戻る。

確認や更新の処理中で、新たな確認を受け付けない間はボタンを無効にする。インストールを待っている間も、Sparkle は新たな確認を受け付けないので、ボタンは無効になる。処理中を5つ目の状態にはせず、表の状態を表示したままにする。ラベルが変わっても、ボタンは右寄せを保ち、行の高さとほかの行の位置を動かさない。状態の切り替えに動きや読み上げの通知を付けない。

最終確認の日時は Sparkle が持つ値を使う。今日と昨日は相対の表記にし、それより前は日付と時刻を示す。日付の表現はアプリの表示言語に従い、時刻は `SPEC-UI-012` に従う。ページを開いたときと更新の処理が終わったときに、状態を読み直す。

ボタンを押すと、アプリを前面に出して Sparkle の標準の画面を開く。最新の版であることやエラーは、この画面で伝え、行の状態にはしない。ボタンの VoiceOver のラベルは、確認する操作か、表示した版へアップデートする操作かを区別する。状態は別の静的テキストとして読めるようにする。定期の確認での知らせ方は `SPEC-MENU-009`、インストールと抑止の関係は `SPEC-LCY-008` に従う。

更新の配信元か公開鍵を持たないビルドでは更新を確かめず、両方の行を残したまま、ポップアップと操作のボタンを無効にする。Debug 構成は既定で配信元も公開鍵も持たない。試験のために両方をビルドの設定で渡した Debug 構成は、Release 構成と同じく更新を確かめる（`HYP-SYS-002`）。ポップアップは「オフ」、状態は「まだ確認していない」に相当する表示とし、理由の説明は追加しない。

### 受け入れ例: 既定値と選択の保存

1. Sparkle の設定を保存していない Release 構成のアプリを起動する。
2. 「このアプリについて」を開き、3つの選択肢を順に選んで、アプリを起動し直す。
3. 初めは「確認のみ」で、許可を求める画面は出ない。選ぶと表の組み合わせになり、起動し直しても最後に選んだ値が表示される。Capsaicin の設定には値が追加されない。

### 受け入れ例: Sparkle 側で値が変わる

1. Release 構成の試験用の環境で、「このアプリについて」を開く。
2. Sparkle の画面から自動ダウンロードの値を変える。続けて、試験用の設定で確認をオフ、ダウンロードをオンにする。
3. ポップアップは Sparkle 側の値にその場で合い、後者では「オフ」と表示される。

### 受け入れ例: 自動をオフにしても手動で確認できる

1. Release 構成で自動アップデートを「オフ」にし、ほかのアプリを前面にする。
2. 「ソフトウェアアップデート」のボタンを押す。
3. Capsaicin が前面になり、Sparkle の画面が開く。確認中は行のボタンが無効になる。最新の版であることやエラーは Sparkle の画面だけが伝え、行に結果専用の状態は増えない。

### 受け入れ例: 4つの状態と日時

1. Release 構成の試験用の環境で、未確認、今日確認済み、新しい版あり、インストール待ちの版ありを順に用意する。
2. それぞれでページを開く。確認済みでは OS の時刻の設定を12時間制と24時間制に変える。
3. 行は表の対応する状態と操作を示す。確認日時には今日であることと OS の設定に合う時刻が出る。新しい版と待っている版には版の番号があり、ボタンの読み上げでも操作と版を区別できる。

### 受け入れ例: Debug 構成

1. 配信元と公開鍵を渡さずにビルドした Debug 構成のアプリを起動する。
2. 「このアプリについて」を開き、更新の2行を操作しようとする。
3. ポップアップとボタンは無効で、更新の確認は行われない。無効の理由の説明は表示されない。

## SPEC-SET-008 ライセンスのシート

関連要件: `REQ-SET-007`

「このアプリについて」の「ライセンス」を選ぶと、設定ウインドウに標準のシートを開く。シートは幅 540 pt × 高さ 400 pt に固定する。原文は固定幅で改行してあるので、表示するときは段落の中の改行を空白に変え、シートの幅で折り返す。50 字に満たない行（著作権者の列挙や見出し）の後と、番号付きの項目の前の改行、空行は残す。上から、ライセンスのタイトル、区切り線、本文、区切り線、右に既定の完了ボタンを置き、外側の余白は 24 pt とする。完了ボタン、Return、Esc のどれでも閉じる。

開いて閉じても、サイドバーの選択と「このアプリについて」のスクロール位置を保つ。

本文は `Form`（`.grouped`）にし、次の順に、部品名を見出しとするグループ（カード）を置く。シートの中でスクロールして全文を読めるようにし、タイトルと完了ボタンはスクロールさせない。

| 順 | 部品 | 表示する全文 |
| --- | --- | --- |
| 1 | Capsaicin | リポジトリの `LICENSE` |
| 2 | KeyboardShortcuts | 同梱した版のライセンス。版と入手元の URL を含む |
| 3 | Sparkle | 同梱した版の `LICENSE` 全体。含まれる外部のコードの条項を省かず、版と入手元の URL を添える |

全文は、バンドルに入れたテキストファイルから読み、コードに文字列として埋め込まない。部品名と全文は翻訳しない。本文の文字は `SPEC-UI-002` に従い、左寄せで、選択してコピーできるようにする。

### 受け入れ例: 全文を読んでコピーする

1. 設定画面で「このアプリについて」を開く。
2. 「ライセンス」を選び、下端までスクロールして各本文を選択し、コピーする。
3. 設定ウインドウにライセンスのシートが開く。部品が表の順に並び、コピーした本文は、改行と空白の違いを除いてバンドル内の全文と一致する。Sparkle の版と入手元の URL、含まれる外部のコードの条項も読める。スクロールしてもタイトルと完了ボタンは同じ位置にある。

### 受け入れ例: 完了・Return・Esc で閉じる

1. 「このアプリについて」を「リンク」までスクロールし、VoiceOver で「ライセンス」の行に移る。
2. ボタンとして読み上げられる行を操作してシートを開き、完了ボタンで閉じる。再び開いて Return で閉じ、もう一度開いて Esc で閉じる。
3. どの操作でもシートだけが閉じ、「このアプリについて」は開く前と同じスクロール位置にある。サイドバーの選択、設定ウインドウのタイトル、タイトルバーの高さ、閉じるボタンの位置は変わらない。
