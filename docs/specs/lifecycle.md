# 起動と復旧の仕様

## 対象範囲

ログイン時の起動、終了時の後片付け、後片付けをできずに終わったときの扱い、起動時の処理、単一インスタンス、更新のインストールと抑止の関係を定める。後片付けと保存する記録の判断は `DEC-LCY-010`、単一インスタンスの判断は `DEC-LCY-011`、更新で抑止を中断させない判断は `DEC-LCY-005` にある。Mac の起動時にスリープの禁止を解く処理は `SPEC-HLP-003` が定める。

受け入れ例の共通の前提は、`specs/blocking.md` の「受け入れ例の共通の前提」にある。

## 状態

- 終了は、利用者の終了（メニューや設定画面の「Capsaicinを終了」など）と、それ以外（セッションの終了、判定不能、更新のための終了）に分ける。
- アプリは、どう起動しても「停止中」で始まる。抑止の状態とセッションは `SPEC-BLK-011` に従い、メモリーだけに持つ。
- 輝度の記録とその保存の失敗は `SPEC-BLK-013`、`disablesleep` の所有は `SPEC-HLP-005` にある。

## SPEC-LCY-001 ログイン時の起動

関連要件: `REQ-LCY-001`

「ログイン時に起動」がオンのとき、利用者がログインするとアプリが起動する。オフのときは、ログインしても起動しない。

「ログイン時に起動」は、アプリ自身を `SMAppService.mainApp` に登録するか、登録を外すかで切り替える。登録を外しても、動いているアプリは終了しない。

### 受け入れ例: オンなら起動する

1. 「ログイン時に起動」をオンにする。
2. ログアウトして、ログインし直す。
3. メニューバーに Capsaicin のアイコンが表示される。

### 受け入れ例: オフなら起動しない

1. アプリが動いている状態で、「ログイン時に起動」をオフにする。
2. アプリが終了しないことを確かめ、ログアウト時にウインドウを再度開く設定をオフにしてから、ログアウトしてログインし直す。
3. アプリは起動しない。

## SPEC-LCY-002 終了時の後片付け

関連要件: `REQ-LCY-002`

アプリが終了するときは、どの種類でも停止中のあるべき状態に合わせる（`SPEC-BLK-007`）。輝度の復元は `SPEC-BLK-013` の終了時の手順と順序に従う。HUD は表示しない。

| 終了の種類 | 合わせられていない制御が残るとき |
| --- | --- |
| 利用者の終了 | エラーのダイアログ（`SPEC-HLP-006`）を出してから終了する |
| それ以外（セッションの終了、判定不能、更新のための終了） | ログに残し、ダイアログを出さずに終了する |

### 受け入れ例: 手動スリープを止めていたとき

1. 「ディスプレイを閉じたとき」を「オンのまま」にして、抑止を開始する。
2. メニューからアプリを終了する。
3. `pmset -g assertions` に Capsaicin のアサーションがなく、`pmset -g` が `SleepDisabled 0` を示し、Caps Lock の LED は Caps Lock の状態に連動する。

### 受け入れ例: 利用者の終了だけで失敗をダイアログに出す

1. ポートの偽物で、抑止中かつ後片付けに失敗する状態を用意する。
2. 利用者の終了、セッションの終了、判定不能、更新のための終了を、それぞれ別の試行で要求する。
3. どの試行もすべての仕組みを停止中のあるべき状態に合わせようとし、輝度を戻す処理は `disablesleep` を下ろす前に行う。HUD は出ず、失敗のダイアログは利用者の終了だけで出る。

## SPEC-LCY-003 後片付けをできずに終わったとき

関連要件: `REQ-LCY-003`

アプリがクラッシュや強制終了で後片付けをできずに終わったら、デーモンが接続の切断を受け、`SPEC-HLP-002` の役目に従って `off` を実行する。アプリは自動で起動し直されない。電源管理アサーションはプロセスの終了で解放される。

LED の点灯と輝度の変更は残る。利用者がアプリを開き直したときに、`SPEC-LCY-006` の起動時の処理で戻す。

### 受け入れ例: kill -9 で終了する

1. 「ディスプレイを閉じたとき」を「オンのまま」にして抑止を開始し、デーモンが後片付けの役目を持ち、`SleepDisabled` が 1 になっている。
2. 対象のアプリの PID を確かめて `kill -9 <PID>` を実行する。
3. デーモンが切断を受けて `off` を実行し、`pmset -g` は `SleepDisabled 0` を示す。Capsaicin のプロセスとアサーションはなく、アプリは起動し直されない。LED は点いたままである。

### 受け入れ例: kill -SEGV でクラッシュする

1. 「ディスプレイを閉じたとき」を「オンのまま」にして抑止を開始し、デーモンが後片付けの役目を持ち、`SleepDisabled` が 1 になっている。
2. 対象のアプリの PID を確かめて `kill -SEGV <PID>` を実行する。
3. デーモンが切断を受けて `off` を実行し、`pmset -g` は `SleepDisabled 0` を示す。Capsaicin のプロセスとアサーションはなく、アプリは起動し直されない。手で開き直すと、LED が通常の連動に戻り、停止中で始まる。

## SPEC-LCY-006 起動時の処理

関連要件: `REQ-LCY-003`

アプリは起動するたびに、次の順に処理する。

1. 単一インスタンスの判定（`SPEC-LCY-009`）を行う。別のプロセスが動いていれば、後続の処理を行わずに終了する。
2. 輝度の記録があれば、いまの輝度が 0 のときだけ記録した値を書き、それ以外は記録を消すだけにする。失敗時の扱いを含む詳細は `SPEC-BLK-013` に従う。
3. ヘルパーの登録を今の版に合わせる（`SPEC-HLP-007`）。
4. すべての仕組みを停止中のあるべき状態に合わせ、合わせられていない制御の一覧を評価し直す（`SPEC-BLK-007`）。LED は設定にかかわらず通常の Caps Lock 連動に戻す。`disablesleep` の所有は「立てていない」から始まるので、`SleepDisabled` が 1 でも触れない（`SPEC-HLP-005`）。

### 受け入れ例: 開き直すと停止中で始まる

1. 抑止中のアプリが後片付けをできずに終わり、LED の点灯が残っている。
2. 利用者がアプリを開き直す。
3. LED は通常の連動に戻り、状態は停止中である。

### 受け入れ例: 起動時に外部の disablesleep に触れない

1. ポートの偽物で、`SleepDisabled` が 1 の状態を用意する。
2. アプリの起動時の処理を行う。
3. 所有は「立てていない」で、ヘルパーの `on` と `off` は実行されず、`SleepDisabled` は 1 のままである。

## SPEC-LCY-008 更新のインストールと抑止

関連要件: `REQ-SYS-008`

更新の確認とダウンロードだけでは、抑止を解除しない。自動のインストールは、`SPEC-SET-007` で「ダウンロードしてインストール」を選んでいる場合に限る。インストールのためにアプリを終了させる時期は、自動か利用者の操作かで次のように決める。

| 契機 | 条件 | 動作 |
| --- | --- | --- |
| 自動のインストール | 抑止を止めていて、設定ウインドウを開いていない | ダウンロード済みの版をインストールしてアプリを起動し直す |
| 自動のインストール | 抑止中、または設定ウインドウを開いている | インストールを待ち、両方の待つ条件がなくなったときに実行する |
| 利用者がインストールを選ぶ | 抑止中 | 抑止を解除することを確認してから進める |
| 利用者がインストールを選ぶ | 抑止を止めている | 抑止の解除の確認を出さずに進める |

自動のインストールを待っている間は、抑止の状態と設定ウインドウの表示の変化に合わせて、実行できるかを確かめ直す。両方の待つ条件がなくなったら、利用者の終了操作を待たずにインストールする。待っている版は `SPEC-SET-007` の行で示す。

利用者がインストールを選んだときの確認は、Sparkle がインストールを始める前に出す（`DEC-LCY-007`）。確認では、インストールによって抑止を解除することと、更新後は停止中で始まることを伝える。利用者が続けたら、`SPEC-LCY-002` の後片付けをしてインストールする。取り消したら、今はインストールせず、抑止とその解除条件を変えない。Sparkle の画面は閉じる。取り消した版は、抑止の解除や設定ウインドウを閉じたことを契機にはインストールしない。利用者が更新の確認（`SPEC-SET-007`）かメニューのアップデートの項目（`SPEC-MENU-009`）を選ぶと、同じ版をもう一度インストールできる状態で示す。抑止中なら、そこでインストールを選んだときにも確認を出す。利用者がそのまま Capsaicin を終了すると、終了時にその版をインストールし、起動し直さない。

更新のための終了は、`SPEC-LCY-002` の利用者の終了以外の扱いで後片付けする。更新後は `SPEC-LCY-006` の起動時の処理を行い、停止中で始まる。

設定と輝度の記録は、版をまたいで読めるようにする。保存形式を変える版では、前の形式を読み、保存された値の意味を引き継ぐ。

### 受け入れ例: 抑止中は自動でインストールしない

1. 自動アップデートを「ダウンロードしてインストール」にし、抑止を開始して設定ウインドウを閉じる。
2. 試験用の環境で新しい版のダウンロードを完了し、続けて抑止を解除する。
3. 抑止中は終了もインストールもせず、抑止が続く。解除するとインストールして起動し直し、新しい版は停止中になる。

### 受け入れ例: 設定ウインドウを閉じるまで待つ

1. 自動アップデートを「ダウンロードしてインストール」にし、抑止を止めた状態で設定ウインドウを開く。
2. 試験用の環境で新しい版のダウンロードを完了し、続けて設定ウインドウを閉じる。
3. ウインドウを開いている間は待っている版が行に表示され、アプリは終了しない。閉じると、利用者がアプリを終了しなくてもインストールして起動し直す。

### 受け入れ例: 2つの待つ条件が両方なくなるまで待つ

1. 抑止中かつ設定ウインドウを開いている状態で、自動のインストールを待つ版を用意する。
2. 抑止を解除し、その後で設定ウインドウを閉じる。別の試行では、閉じてから抑止を解除する。
3. どちらの順序でも、片方の条件だけがなくなった時点ではインストールせず、両方がなくなった時点でインストールして起動し直す。

### 受け入れ例: 抑止中に手動でインストールを続ける

1. 抑止を開始する。
2. Sparkle の画面でインストールを選び、抑止を解除することの確認で続ける。
3. 確認では解除と更新後に停止中で始まることが伝わる。続けると、更新のための終了として後片付けしてインストールする。起動し直した新しい版は停止中になる。

### 受け入れ例: 抑止中に手動のインストールを取り消す

1. 自動アップデートを「確認のみ」にし、タイマーを 1 時間にして抑止を開始し、新しい版をダウンロードしておく。
2. インストールを選び、抑止を解除することの確認で取り消す。
3. アプリは終了せず、インストールもしない。Sparkle の画面は閉じる。抑止は続き、解除の時刻も変わらない。「このアプリについて」の行とメニューには、新しい版があることが出る。
4. 抑止を解除し、設定ウインドウを閉じる。
5. インストールされない。
6. 「このアプリについて」の行のボタンを押す。
7. ダウンロードし直さずに、同じ版がインストールできる状態で示される。インストールを選ぶと、確認を出さずにインストールして起動し直す。

### 受け入れ例: 取り消した版を終了時にインストールする

1. 抑止中に手動のインストールを確認で取り消す。
2. 抑止を続けたまま、Capsaicin を終了する。
3. `SPEC-LCY-002` の後片付けをして終了し、その版がインストールされる。アプリは起動し直さない。

### 受け入れ例: 停止中は確認せずにインストールする

1. 抑止を止めた状態で、設定ウインドウから Sparkle の画面を開く。
2. ダウンロード済みの版のインストールを選ぶ。
3. 抑止の解除の確認は出ず、設定ウインドウが開いていてもインストールして起動し直す。

### 受け入れ例: 保存形式を変える版でも前の値を読める

1. 前の版が保存した設定と輝度の記録を、試験用の環境に用意する。
2. 保存形式を変えた版で読み込む。
3. 前の値の意味が引き継がれ、形式が違うことだけを理由に設定や輝度の記録を捨てない。輝度は `SPEC-BLK-013` に従って扱い、状態は停止中になる。

## SPEC-LCY-009 単一インスタンス

関連要件: `REQ-LCY-006`

アプリは起動の最初に、`NSRunningApplication` で同じ bundle ID の別のプロセスを探す。動いていれば、後から起動した方は、ヘルパーへの接続、LED や輝度の操作、IPC の受け付けなどを始めず、動いている方を開き直してから終了する。開き直されたアプリは `SPEC-SET-001` に従って設定画面を開く。動いている方の抑止や解除の条件は変えない。

Debug（`io.github.koutyuke.capsaicin.debug`）と正式版（`io.github.koutyuke.capsaicin`）は別のアプリとして同時に動ける。そのときの `disablesleep` の制約は `SPEC-HLP-005` にある。

### 受け入れ例: 同じ bundle ID の別のコピーを起動する

1. アプリが抑止中で、設定画面は閉じている。同じ bundle ID の別のコピーを用意する。
2. 別のコピーを起動する。
3. 動いていた方の設定画面が前面に開き、抑止と解除の条件は変わらない。後から起動した方は制御や IPC を始めずに終了し、動き続けるプロセスは1つだけである。

### 受け入れ例: Debug と正式版は別々に動く

1. ポートの偽物で、Debug のアプリだけが動いている状態を用意する。
2. 正式版の起動時の判定を行う。
3. Debug を同じアプリとみなさず、正式版は起動時の処理を続ける。
