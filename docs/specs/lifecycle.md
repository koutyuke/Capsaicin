# 起動と復旧の仕様

## 対象範囲

ログイン時の起動、launchd の管理下で動くこと、終了時の後片付け、クラッシュからの復旧、起動時の処理、再起動後の抑止の再開を定める。LaunchAgent を使う判断は `DEC-LCY-001` と `DEC-LCY-002`、再開の範囲と起動の理由の判定を選んだ理由は `DEC-LCY-003` にある。Mac の起動時にスリープの禁止を解く処理は `SPEC-HLP-003` が定める。

受け入れ例の共通の前提は、`specs/blocking.md` の「受け入れ例の共通の前提」にある。

## 状態

- アプリの終了は2種類ある。利用者の終了（メニューの「終了」など）と、セッションの終了による終了（ログアウト、再起動、システム終了）である。2つを区別できることは `HYP-LCY-005` で確かめる。
- 起動の理由は、「クラッシュ後」「Mac の再起動・ログアウトの後」「通常の起動」の3つである。判定は `SPEC-LCY-007` にある。
- 再開用の記録の値と、その更新は `SPEC-LCY-007` にある。

## SPEC-LCY-001 ログイン時の起動

関連要件: `REQ-LCY-001`

「ログイン時に起動する」がオンのとき、利用者がログインするとアプリが起動する。オフのときは、ログインしても起動しない。どちらの場合も、クラッシュ時の再起動（`SPEC-LCY-003`）は効く。

### 受け入れ例: オンなら起動する

1. 「ログイン時に起動する」をオンにする。
2. ログアウトして、ログインし直す。
3. メニューバーに Capsaicin のアイコンが表示される。

### 受け入れ例: オフでもクラッシュ時に再起動する

1. 「ログイン時に起動する」をオフにして、ログアウトしてログインし直し、アプリが起動しないことを確かめる。
2. アプリを手で起動し、`SIGSEGV` を送ってクラッシュさせる。
3. アプリが自動で再起動する。

## SPEC-LCY-002 終了時の後片付け

関連要件: `REQ-LCY-002`

アプリが終了するときは、終了の種類によって次のようにする。記録の更新の順序は `SPEC-LCY-007` にある。

| 終了の種類 | 抑止の仕組み | 抑止のセッション | HUD | 合わせられていない制御が残るとき |
| --- | --- | --- | --- | --- |
| 利用者の終了 | 解除（`SPEC-BLK-007`）として、停止中のあるべき状態に合わせる | 消す | 表示しない | エラーのダイアログ（`SPEC-HLP-006`）を出してから終了する。合わせ直しは次の起動に任せる |
| セッションの終了による終了 | 停止中のあるべき状態に合わせる（`SPEC-BLK-007`） | 記録に残す（次の起動で再開に使う。`SPEC-LCY-004`） | 表示しない | 合わせられていない制御として記録し、アラートは出さない |

### 受け入れ例: 手動スリープを止めていたとき

1. 「自動スリープ」と「手動スリープ」を止める設定にして、抑止を開始する。
2. メニューからアプリを終了する。
3. `pmset -g assertions` に Capsaicin のアサーションがなく、`pmset -g` が `SleepDisabled 0` を示し、Caps Lock の LED は Caps Lock の状態に連動する。

### 受け入れ例: 蓋閉じスリープだけを止めていたとき

1. 「蓋閉じスリープ」だけを止める設定にし、電源アダプターにつなぎ外部ディスプレイを外して、抑止を開始する。
2. メニューからアプリを終了し、蓋を閉じる。
3. Mac はスリープする。

## SPEC-LCY-003 クラッシュからの復旧

関連要件: `REQ-LCY-003`

アプリがクラッシュしたら、自動で再起動する。再起動したアプリは、`SPEC-LCY-006` の起動時の処理を行う。

### 受け入れ例: 手動スリープを止めていたとき

1. 「再起動後に抑止を再開する」を「再開しない」にし、「手動スリープ」を止める設定にして抑止を開始する。
2. アプリのプロセスに `SIGSEGV` を送ってクラッシュさせる。
3. アプリが自動で起動し、`pmset -g` が `SleepDisabled 0` を示し、LED が Caps Lock の状態に連動し、状態は「停止中」である。

### 受け入れ例: 蓋閉じスリープだけを止めていたとき

1. 「再開しない」を選び、「蓋閉じスリープ」だけを止める設定にし、電源アダプターにつなぎ外部ディスプレイを外して、抑止を開始する。
2. アプリをクラッシュさせ、自動で起動するのを待ってから、蓋を閉じる。
3. Mac はスリープする。

## SPEC-LCY-004 再起動後の抑止の再開

関連要件: `REQ-LCY-004`

起動時の処理（`SPEC-LCY-006`）で、起動の理由（`SPEC-LCY-007`）と「再起動後に抑止を再開する」の選択から、再開を試みるかを決める。

| 起動の理由 | 再開しない | アプリの再起動時だけ | アプリと Mac の再起動時 |
| --- | --- | --- | --- |
| クラッシュ後 | 試みない | 試みる | 試みる |
| Mac の再起動・ログアウトの後 | 試みない | 試みない | 試みる |
| 通常の起動 | 試みない | 試みない | 試みない |

再開を試みるのは、再開用の記録に抑止のセッションがあるときだけである。次のどれかに当たるときは再開せず、停止中で起動する。

- 解除の時刻を持ち、現在時刻が解除の時刻以上である（`SPEC-BLK-003` と同じ比較）。
- 連続クラッシュの上限に達した（`SPEC-LCY-007`）。

再開は、記録の解除の時刻と由来を引き継いだ開始として行い、`SPEC-BLK-010` の開始の適用に従う。再開が拒否されたら、開始の拒否として記録を更新し（`SPEC-LCY-007`）、停止中で起動する。

### 受け入れ例: クラッシュ後に再開する

1. 「アプリの再起動時だけ」を選び、タイマーを 1 時間にして抑止を開始する。
2. 10 分後にアプリをクラッシュさせ、自動で再起動するのを待つ。
3. 再起動後に状態が「抑止中」になり、開始から 1 時間後に解除される。

### 受け入れ例: 手動スリープを止めたまま再開し、解除する

1. 「アプリの再起動時だけ」を選び、「手動スリープ」を止める設定にして抑止を開始する。
2. アプリをクラッシュさせ、自動で再起動して再開するのを待ってから、メニューで解除する。
3. 再開後も `SleepDisabled` は 1 のままで、解除の後は `pmset -g` が `SleepDisabled 0` を示す。

### 受け入れ例: 再起動の後に再開する

1. 「アプリと Mac の再起動時」を選び、「ログイン時に起動する」をオンにして、抑止を開始する。
2. Apple メニューから再起動し、ログインする。
3. ログイン後に状態が「抑止中」になる。

### 受け入れ例: ログアウトの後に再開する

1. 「アプリと Mac の再起動時」を選び、「ログイン時に起動する」をオンにして、抑止を開始する。
2. ログアウトして、ログインし直す。
3. ログイン後に状態が「抑止中」になる。

### 受け入れ例: アプリの再起動時だけでは、再起動とログアウトの後に再開しない

1. 「アプリの再起動時だけ」を選び、「ログイン時に起動する」をオンにして、抑止を開始する。
2. Apple メニューから再起動してログインする。続けて抑止を開始し直し、ログアウトしてログインし直す。
3. どちらの後も、状態は「停止中」のままである。

### 受け入れ例: 利用者が終了したら再開しない

1. 「アプリと Mac の再起動時」を選び、抑止を開始する。
2. メニューからアプリを終了し、もう一度起動する。
3. 状態は「停止中」のままである。

### 受け入れ例: 解除の時刻を過ぎていたら再開しない

1. 「アプリと Mac の再起動時」を選び、「ログイン時に起動する」をオンにし、タイマーを 5 分にして抑止を開始する。
2. Mac をシステム終了し、10 分後に起動してログインする。
3. 状態は「停止中」のままである。

## SPEC-LCY-005 launchd の管理下で動く

関連要件: `REQ-LCY-005`

アプリは、launchd が起動したものだけが動く。Finder や CLI などから直接起動しても、動き続けるアプリは LaunchAgent から起動されたものになる（方式は `DEC-LCY-002`）。LaunchAgent の登録か起動に失敗したとき（利用者がシステム設定でバックグラウンド項目を無効にした場合など）は、アプリをそのまま動かし、クラッシュ時に再起動されないことを設定画面の「一般」に示す。

### 受け入れ例: Finder から起動しても launchd の管理下になる

1. アプリを終了しておく。
2. Finder からアプリを起動し、`launchctl print gui/$(id -u)/<LaunchAgent のラベル>` を見る。
3. LaunchAgent が実行中で、動いているアプリのプロセスはその LaunchAgent が起動したものだけである。

### 受け入れ例: バックグラウンド項目を無効にしている

1. システム設定で Capsaicin のバックグラウンド項目を無効にする。
2. Finder からアプリを起動し、設定画面の「一般」を開く。
3. アプリは動き、クラッシュ時に再起動されないことが示される。

## SPEC-LCY-006 起動時の処理

関連要件: `REQ-LCY-003`、`REQ-LCY-004`

アプリは起動するたびに、次の順に処理する。記録をどう更新するかは `SPEC-LCY-007` にある。

1. 起動の理由を判定し、連続クラッシュの上限に達したかを確かめる（`SPEC-LCY-007`）。
2. 再開するかを `SPEC-LCY-004` で決める。
3. 再開するなら、`SPEC-LCY-004` のとおり開始する。再開が拒否されたら、開始の拒否として記録を更新し（`SPEC-LCY-007`）、再開しない場合と同じく停止中で起動する。
4. 各仕組みを、その結果の状態のあるべき状態に合わせ、合わせられていない制御の一覧を評価し直す（`SPEC-BLK-007`）。停止中なら、記録に抑止のセッションがあったかどうかにかかわらず、前のプロセスから残ったものを含むすべての仕組みを合わせる。蓋閉じスリープの制御は、プロセスが終わっても戻らないものとして扱う（`HYP-BLK-002`）。`disablesleep` は所有の規則（`SPEC-HLP-005`）に従う。

### 受け入れ例: 連続クラッシュでは再開しない

1. 「アプリの再起動時だけ」を選び、抑止を開始する。
2. 10 分以内に、起動するたびにアプリをクラッシュさせ、3回目のクラッシュ後の起動を待つ。
3. 1回目と2回目のクラッシュ後の起動では抑止が再開し、3回目の起動では停止中で起動し、各仕組みは停止中のあるべき状態に合っている。

### 受け入れ例: 上限の判定の途中で中断しても再開しない

1. 「アプリの再起動時だけ」を選び、抑止を開始する。試験用のビルドで、3回目のクラッシュ後の起動の処理の途中（クラッシュ後の起動の時刻を記録した後）でクラッシュさせる。
2. 10 分以内に、4回目のクラッシュ後の起動を待つ。
3. 4回目の起動でも再開せず、停止中で起動する。

### 受け入れ例: 再開が拒否されたらセッションを消して戻す

1. 「アプリの再起動時だけ」を選び、「手動スリープ」を止める設定にして抑止を開始する。
2. 試験用のビルドで、次の起動の再開ではバッテリー残量の条件（`SPEC-BLK-006`）が成り立つ状態を模して、アプリをクラッシュさせ、自動で再起動するのを待つ。続けて、もう一度アプリをクラッシュさせ、自動で再起動するのを待つ。
3. 1回目の再起動で再開はバッテリー残量の条件で拒否され、停止中で起動し、`pmset -g` は `SleepDisabled 0` を示す。2回目の再起動では、記録にセッションがないので再開しない。

### 受け入れ例: 通常の起動でも残った制御を戻す

1. 試験用のビルドで、蓋閉じスリープの制御を有効にしたまま、記録を「利用者の終了」で終えた状態を作る。
2. アプリを起動し、蓋を閉じる。
3. 起動の理由は「通常の起動」になり、再開せず、蓋を閉じると Mac はスリープする。

## SPEC-LCY-007 再開用の記録の更新

関連要件: `REQ-LCY-003`、`REQ-LCY-004`

再開用の記録は、通常の設定とは別に保存し（`DEC-SET-002`）、次の値を持つ。

| 値 | 内容 |
| --- | --- |
| 抑止のセッション | 抑止中なら、解除の時刻とその由来（`SPEC-BLK-003`）。抑止中でなければない |
| `disablesleep` を立てたか | 所有の規則（`SPEC-HLP-005`）で使う |
| 実行中の印 | アプリが動いている間だけ立つ |
| 終了の理由 | 前回の正常な終了の理由。利用者の終了か、セッションの終了による終了か |
| 合わせられていない制御 | 合わせられていない仕組みと、その向きの一覧（`SPEC-BLK-007`） |
| 最終更新の時刻 | 記録を最後に書いた壁時計の時刻 |
| クラッシュ後の起動の時刻 | 直近 10 分以内のクラッシュ後の起動の時刻の一覧 |

起動の理由は、記録を書き換える前に、次の順に判定する。

1. 記録がない（初めての起動）なら、「通常の起動」。
2. 実行中の印が立っている（前回は正常に終了していない）なら、`kern.boottime` が最終更新の時刻より後なら「Mac の再起動・ログアウトの後」、そうでなければ「クラッシュ後」（`HYP-LCY-004`）。
3. 実行中の印が立っていないなら、終了の理由がセッションの終了なら「Mac の再起動・ログアウトの後」、利用者の終了なら「通常の起動」。

起動の時点で、クラッシュ後の起動の時刻の一覧（今回の起動を加えた後）が3件以上なら、連続クラッシュの上限に達したものとする。

出来事ごとに、記録を次の順（左から）に更新する。

| 出来事 | 記録の更新 |
| --- | --- |
| 起動 | 起動の理由を判定する → クラッシュ後なら、その時刻を一覧に加え、10 分より古いものを除く → 実行中の印を立て、終了の理由を消す → 再開するかを決める（`SPEC-LCY-004`）→ 再開しないなら、抑止のセッションを消して、停止中のあるべき状態に合わせる（`SPEC-LCY-006`） |
| 開始（利用者の操作、再開） | 所有を先に書く（`SPEC-HLP-005`）→ 仕組みを適用する → 抑止のセッションを書く → 合わせられていない制御の一覧を全項目評価し直して置き換える（`SPEC-BLK-007`）。利用者の操作による開始なら、クラッシュ後の起動の一覧を空にする |
| 開始の拒否（再開を含む） | 記録に抑止のセッションがあれば消す → 停止中のあるべき状態に合わせる（試した開始で適用したものと、前のプロセスから残ったものの両方）→ 所有を `SPEC-HLP-005` の規則で更新する → 合わせられていない制御の一覧を全項目評価し直して置き換える（`SPEC-BLK-007`） |
| 解除 | 抑止のセッションを先に消す → 停止中のあるべき状態に合わせる → 所有を `SPEC-HLP-005` の規則で更新する → 合わせられていない制御の一覧を全項目評価し直して置き換える（`SPEC-BLK-007`） → クラッシュ後の起動の一覧を空にする |
| 抑止中の設定の変更 | 所有を `SPEC-HLP-005` の規則で更新する → 反映したか巻き戻した後の状態で、合わせられていない制御の一覧を全項目評価し直して置き換える（`SPEC-BLK-007`）（`SPEC-BLK-009`） |
| 利用者の終了 | 解除と同じ → 終了の理由を「利用者の終了」にする → 実行中の印を下ろす |
| セッションの終了による終了 | 停止中のあるべき状態に合わせる（抑止のセッションは残す）→ 所有を `SPEC-HLP-005` の規則で更新する → 合わせられていない制御の一覧を全項目評価し直して置き換える（`SPEC-BLK-007`） → 終了の理由を「セッションの終了」にする → 実行中の印を下ろす |
| 合わせ直し | 一覧にある仕組みだけを操作し、その項目を合わせた結果で置き換える（`SPEC-BLK-007`）。所有は `SPEC-HLP-005` の規則で更新する |

順序の理由: 抑止のセッションは、仕組みを適用した後に書き、戻す前に消す。所有は、`on` の前に書き、`off` の後に消す。こうすると、どこで中断しても、記録が抑止のセッションを示すなら仕組みは適用済みか、適用し直せる。記録が所有を示すなら、後片付けで `off` すればよい（余分な `off` は害がない）。

記録は書くたびに最終更新の時刻を更新し、ファイルを置き換えて書いて、書きかけの状態を残さない。

記録を保存できないときは、次のようにする。

- 開始（再開を含む）では、記録も開始の一部とし、全部か無しかを保つ。所有の「立てた」を保存できなければ、`on` を実行せずに開始を拒否する（`SPEC-HLP-005`）。仕組みを適用した後に抑止のセッションを保存できなければ、開始を拒否し、開始の拒否として停止中のあるべき状態に合わせる。どちらも、拒否の理由は状態を保存できないことである。
- 開始以外（解除、終了、合わせ直し、設定の変更など）では、処理を続け、動いている間はメモリー上の状態を正とする。ただし、`disablesleep` を立てる必要が生じた場面では、所有の「立てた」を保存できなければ `on` を実行しない（`SPEC-HLP-005`）。保存は合わせ直しと同じ契機（`SPEC-BLK-007`。一覧が空でも、保存できていない間は 1 分ごと）で試み直す。保存できるまで、メニューの警告の行で、状態を保存できていないことを伝える（`SPEC-MENU-004`）。その間の CLI の `off` は終了コード 69 にする（`SPEC-CLI-007`）。

既知の制約: 記録を保存できないまま終了またはクラッシュした場合、次の起動は残っている古い記録のとおりに判定する。そのため、解除したはずの抑止を再開することがある。記録を保存できない環境ではほかの動作も保証できないので、この制約は受け入れる。

### 受け入れ例: 初めての起動

1. 再開用の記録がない状態にする。
2. アプリを起動する。
3. 起動の理由は「通常の起動」になり、停止中で起動し、記録が作られて実行中の印が立つ。

### 受け入れ例: on の後、セッションを書く前に中断した場合

1. 試験用のビルドで、手動スリープを止める開始の途中、ヘルパーの `on` が成功した直後にクラッシュさせる。「再開しない」を選んでおく。
2. 自動で再起動するのを待つ。
3. 起動の理由は「クラッシュ後」になり、記録の所有が「立てた」を示すので、停止中のあるべき状態に合わせるときに `off` が実行され、`pmset -g` は `SleepDisabled 0` を示す。

### 受け入れ例: 所有を保存できなければ on しない

1. 「手動スリープ」を止める設定にし、試験用のビルドで再開用の記録を保存できない状態にする。
2. `capsaicin on` を実行する。
3. 終了コード 69 で失敗し、状態を保存できないことが理由として出る。`pmset -g` は `SleepDisabled 0` のままである。
