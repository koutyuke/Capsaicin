# 起動と復旧の仕様

## 対象範囲

ログイン時の起動、launchd の管理下で動くこと、終了時の後片付け、クラッシュからの復旧、起動時の処理、再起動後の抑止の再開、更新のインストールと抑止の関係を定める。SMAppService の agent と mainApp を使う判断は `DEC-LCY-008`、再開の範囲と起動の理由の判定を選んだ理由は `DEC-LCY-003`、更新で抑止を中断させない判断は `DEC-LCY-005` にある。Mac の起動時にスリープの禁止を解く処理は `SPEC-HLP-003` が定める。

受け入れ例の共通の前提は、`specs/blocking.md` の「受け入れ例の共通の前提」にある。

## 状態

- 終了の判定は、利用者の終了（メニューの「Capsaicinを終了」など）、セッションの終了（ログアウト、再起動、システム終了）、判定不能に分ける。理由を区別できることは `HYP-LCY-005` で確かめ、判定不能の扱いは `DEC-LCY-004` に従う。
- 起動の理由は、「クラッシュ後」「Mac の再起動・ログアウトの後」「通常の起動」の3つである。判定は `SPEC-LCY-007` にある。
- 再開用の記録の値と、その更新は `SPEC-LCY-007` にある。

## SPEC-LCY-001 ログイン時の起動

関連要件: `REQ-LCY-001`

「ログイン時に起動」がオンのとき、利用者がログインするとアプリが起動する。オフのときは、ログインしても起動しない。どちらの場合も、クラッシュ時の再起動（`SPEC-LCY-003`）は効く。

「ログイン時に起動する」は、アプリ自身を `SMAppService.mainApp` に登録するか、登録を外すかで切り替える。登録を外しても、動いているアプリは終了しない。ログイン時に起動したアプリも、直接起動したものとして agent に引き渡す（`SPEC-LCY-005`）。

### 受け入れ例: オンなら起動する

1. 「ログイン時に起動」をオンにする。
2. ログアウトして、ログインし直す。
3. メニューバーに Capsaicin のアイコンが表示される。

### 受け入れ例: オフでもクラッシュ時に再起動する

1. 「ログイン時に起動」をオフにして、ログアウトしてログインし直し、アプリが起動しないことを確かめる。
2. アプリを手で起動し、`SIGSEGV` を送ってクラッシュさせる。
3. アプリが自動で再起動する。

## SPEC-LCY-002 終了時の後片付け

関連要件: `REQ-LCY-002`

アプリが終了するときは、終了の種類によって次のようにする。どの種類でも、輝度の復元は `SPEC-BLK-013` の終了時の手順と順序に従う。再開用の記録の更新の順序は `SPEC-LCY-007` にある。

| 終了の種類 | 抑止の仕組み | 抑止のセッション | HUD | 合わせられていない制御が残るとき |
| --- | --- | --- | --- | --- |
| 利用者の終了 | 解除（`SPEC-BLK-007`）として、停止中のあるべき状態に合わせる | 消す | 表示しない | エラーのダイアログ（`SPEC-HLP-006`）を出してから終了する。合わせ直しは次の起動に任せる |
| セッションの終了による終了 | 停止中のあるべき状態に合わせる（`SPEC-BLK-007`） | 記録に残す（次の起動で再開に使う。`SPEC-LCY-004`） | 表示しない | 合わせられていない制御として記録し、アラートは出さない |
| 終了理由を判定できない | 停止中のあるべき状態に合わせる（`SPEC-BLK-007`） | 消す | 表示しない | 合わせられていない制御として記録し、終了を妨げるダイアログは出さない |

### 受け入れ例: 手動スリープを止めていたとき

1. 「ディスプレイを閉じたとき」を「オンのまま」にして、抑止を開始する。
2. メニューからアプリを終了する。
3. `pmset -g assertions` に Capsaicin のアサーションがなく、`pmset -g` が `SleepDisabled 0` を示し、Caps Lock の LED は Caps Lock の状態に連動する。

## SPEC-LCY-003 クラッシュからの復旧

関連要件: `REQ-LCY-003`

アプリがクラッシュしたら、自動で再起動する。再起動したアプリは、輝度の復元を含む `SPEC-LCY-006` の起動時の処理を行う。

### 受け入れ例: 手動スリープを止めていたとき

1. 「スリープ防止の再開」を「再開しない」にし、「ディスプレイを閉じたとき」を「オンのまま」にして抑止を開始する。
2. アプリのプロセスに `SIGSEGV` を送ってクラッシュさせる。
3. アプリが自動で起動し、`pmset -g` が `SleepDisabled 0` を示し、LED が Caps Lock の状態に連動し、状態は「停止中」である。

## SPEC-LCY-004 再起動後の抑止の再開

関連要件: `REQ-LCY-004`

起動時の処理（`SPEC-LCY-006`）で、起動の理由（`SPEC-LCY-007`）と「スリープ防止の再開」の選択から、再開を試みるかを決める。

| 起動の理由 | 再開しない | クラッシュ後のみ | クラッシュおよびMacの再起動後 |
| --- | --- | --- | --- |
| クラッシュ後 | 試みない | 試みる | 試みる |
| Mac の再起動・ログアウトの後 | 試みない | 試みない | 試みる |
| 通常の起動 | 試みない | 試みない | 試みない |

再開を試みるのは、再開用の記録に抑止のセッションがあるときだけである。次のどれかに当たるときは再開せず、停止中で起動する。

- 解除の時刻を持ち、現在時刻が解除の時刻以上である（`SPEC-BLK-003` と同じ比較）。
- 連続クラッシュの上限に達した（`SPEC-LCY-007`）。

再開は、記録の解除の時刻と由来を引き継いだ開始として行い、`SPEC-BLK-010` の開始の適用に従う。再開が拒否されたら、開始の拒否として記録を更新し（`SPEC-LCY-007`）、停止中で起動する。

### 受け入れ例: クラッシュ後に再開する

1. 「クラッシュ後のみ」を選び、タイマーを 1 時間にして抑止を開始する。
2. 10 分後にアプリをクラッシュさせ、自動で再起動するのを待つ。
3. 再起動後に状態が「抑止中」になり、開始から 1 時間後に解除される。

### 受け入れ例: 手動スリープを止めたまま再開し、解除する

1. 「クラッシュ後のみ」を選び、「ディスプレイを閉じたとき」を「オンのまま」にして抑止を開始する。
2. アプリをクラッシュさせ、自動で再起動して再開するのを待ってから、メニューで解除する。
3. 再開後も `SleepDisabled` は 1 のままで、解除の後は `pmset -g` が `SleepDisabled 0` を示す。

### 受け入れ例: 再起動の後に再開する

1. 「クラッシュおよびMacの再起動後」を選び、「ログイン時に起動」をオンにして、抑止を開始する。
2. Apple メニューから再起動し、ログインする。
3. ログイン後に状態が「抑止中」になる。

### 受け入れ例: ログアウトの後に再開する

1. 「クラッシュおよびMacの再起動後」を選び、「ログイン時に起動」をオンにして、抑止を開始する。
2. ログアウトして、ログインし直す。
3. ログイン後に状態が「抑止中」になる。

### 受け入れ例: 「クラッシュ後のみ」では、再起動とログアウトの後に再開しない

1. 「クラッシュ後のみ」を選び、「ログイン時に起動」をオンにして、抑止を開始する。
2. Apple メニューから再起動してログインする。続けて抑止を開始し直し、ログアウトしてログインし直す。
3. どちらの後も、状態は「停止中」のままである。

### 受け入れ例: 利用者が終了したら再開しない

1. 「クラッシュおよびMacの再起動後」を選び、抑止を開始する。
2. メニューからアプリを終了し、もう一度起動する。
3. 状態は「停止中」のままである。

### 受け入れ例: 解除の時刻を過ぎていたら再開しない

1. 「クラッシュおよびMacの再起動後」を選び、「ログイン時に起動」をオンにし、タイマーを 5 分にして抑止を開始する。
2. Mac をシステム終了し、10 分後に起動してログインする。
3. 状態は「停止中」のままである。

### 受け入れ例: 終了理由が不明なら再開しない

1. 「クラッシュおよびMacの再起動後」を選び、偽物の制御で抑止中の状態を作る。
2. 終了理由を判定できない状態で終了処理を呼ぶ。
3. 抑止のセッションが消え、後片付けが行われる。終了理由は不明のまま記録され、実行中の印が下りる。保存した記録から次回起動しても再開しない。
4. 後片付けを失敗させた場合もダイアログの要求は出ず、所有と合わせられていない制御が既存の規則で記録される。

## SPEC-LCY-005 launchd の管理下で動く

関連要件: `REQ-LCY-005`

アプリは、launchd が起動したものだけが動く。Finder、CLI、ログイン時の起動などから直接起動しても、動き続けるアプリは agent から起動されたものになる（方式は `DEC-LCY-008`）。

agent は、アプリのバンドルの `Contents/Library/LaunchAgents/` の定義（`RunAtLoad` なし、クラッシュしたときだけ起動し直す）を `SMAppService.agent` で常に登録したものである。`~/Library/LaunchAgents` には書かない。直接起動したアプリは、agent を登録してから `launchctl kickstart` で agent からの起動を求める。agent のジョブのプロセスが動いていて、その実行ファイルがこのバンドルのものだと確かめたら、自分は終了する。5 秒の間に確かめられなければ、agent の起動の失敗として扱う。`kickstart` のコマンドの成功だけでは終了しない（`DEC-LCY-009`）。更新の後の登録し直しは、ヘルパーと同じ規則で行う（`SPEC-HLP-007`）。

agent の登録か起動に失敗したとき（利用者がシステム設定で Capsaicin のバックグラウンドの項目をオフにした場合や、launchd が起動の制約で agent を止めた場合など）は、アプリをそのまま動かし、クラッシュ時に再起動されないことを設定画面の「一般」に示す。その項目をオフにすると、ヘルパーも使えなくなる（`SPEC-HLP-004`）。

### 受け入れ例: Finder から起動しても launchd の管理下になる

1. アプリを終了しておく。
2. Finder からアプリを起動し、`launchctl print gui/$(id -u)/<agent のラベル>` を見る。
3. agent が実行中で、動いているアプリのプロセスはその agent が起動したものだけである。

### 受け入れ例: バックグラウンド項目を無効にしている

1. システム設定で Capsaicin のバックグラウンドの項目をオフにする。
2. Finder からアプリを起動し、設定画面の「一般」を開く。
3. アプリは動き、クラッシュ時に再起動されないことが示される。

## SPEC-LCY-006 起動時の処理

関連要件: `REQ-LCY-003`、`REQ-LCY-004`

アプリは起動するたびに、次の順に処理する。記録をどう更新するかは `SPEC-LCY-007` にある。

1. 輝度を戻す処理を行う（`SPEC-BLK-013`）。
2. 起動の理由を判定し、連続クラッシュの上限に達したかを確かめる（`SPEC-LCY-007`）。
3. 再開するかを `SPEC-LCY-004` で決める。
4. 再開するなら、`SPEC-LCY-004` のとおり開始する。再開が拒否されたら、開始の拒否として記録を更新し（`SPEC-LCY-007`）、再開しない場合と同じく停止中で起動する。
5. 各仕組みを、その結果の状態のあるべき状態に合わせ、合わせられていない制御の一覧を評価し直す（`SPEC-BLK-007`）。停止中なら、記録に抑止のセッションがあったかどうかにかかわらず、前のプロセスから残ったものを含むすべての仕組みを合わせる。`disablesleep` は所有の規則（`SPEC-HLP-005`）に従う。

### 受け入れ例: 連続クラッシュでは再開しない

1. 「クラッシュ後のみ」を選び、抑止を開始する。
2. 10 分以内に、起動するたびにアプリをクラッシュさせ、3回目のクラッシュ後の起動を待つ。
3. 1回目と2回目のクラッシュ後の起動では抑止が再開し、3回目の起動では停止中で起動し、各仕組みは停止中のあるべき状態に合っている。

### 受け入れ例: 上限の判定の途中で中断しても再開しない

1. 「クラッシュ後のみ」を選び、抑止を開始する。試験用のビルドで、3回目のクラッシュ後の起動の処理の途中（クラッシュ後の起動の時刻を記録した後）でクラッシュさせる。
2. 10 分以内に、4回目のクラッシュ後の起動を待つ。
3. 4回目の起動でも再開せず、停止中で起動する。

### 受け入れ例: 再開が拒否されたらセッションを消して戻す

1. 「クラッシュ後のみ」を選び、「ディスプレイを閉じたとき」を「オンのまま」にして抑止を開始する。
2. 試験用のビルドで、次の起動の再開ではバッテリー残量の条件（`SPEC-BLK-006`）が成り立つ状態を模して、アプリをクラッシュさせ、自動で再起動するのを待つ。続けて、もう一度アプリをクラッシュさせ、自動で再起動するのを待つ。
3. 1回目の再起動で再開はバッテリー残量の条件で拒否され、停止中で起動し、`pmset -g` は `SleepDisabled 0` を示す。2回目の再起動では、記録にセッションがないので再開しない。

## SPEC-LCY-007 再開用の記録の更新

関連要件: `REQ-LCY-003`、`REQ-LCY-004`、`REQ-BLK-015`

再開用の記録は、通常の設定とは別に保存し（`DEC-SET-002`）、次の値を持つ。

| 値 | 内容 |
| --- | --- |
| 抑止のセッション | 抑止中なら、解除の時刻とその由来（`SPEC-BLK-003`）。抑止中でなければない |
| `disablesleep` を立てたか | 所有の規則（`SPEC-HLP-005`）で使う |
| 実行中の印 | アプリが動いている間だけ立つ |
| 終了の理由 | 前回の正常な終了の理由。利用者の終了か、セッションの終了による終了か。実行中の印が下りていて理由がない場合は判定不能 |
| 合わせられていない制御 | 合わせられていない仕組みと、その向きの一覧（`SPEC-BLK-007`） |
| 最終更新の時刻 | 記録を最後に書いた壁時計の時刻 |
| クラッシュ後の起動の時刻 | 直近 10 分以内のクラッシュ後の起動の時刻の一覧 |

起動の理由は、記録を書き換える前に、次の順に判定する。

1. 記録がない（初めての起動）か、記録または `kern.boottime` を読めないなら、「通常の起動」。
2. 実行中の印が立っている（前回は正常に終了していない）なら、`kern.boottime` が最終更新の時刻より後なら「Mac の再起動・ログアウトの後」、そうでなければ「クラッシュ後」（`HYP-LCY-004`）。
3. 実行中の印が立っていないなら、終了の理由がセッションの終了なら「Mac の再起動・ログアウトの後」、利用者の終了または判定不能なら「通常の起動」。

再開用の記録を読めない（壊れている、形式が違う）ときは、記録がないものとして扱い、そのことをログに残す。

起動時刻は起動ごとに1回読み、起動の理由の判定と所有の更新に同じ結果を使う。起動時刻を取得できないときは、再開の設定にかかわらず自動再開しない。前回の抑止のセッションを消し、所有を `SPEC-HLP-005` に従って外してから、停止中のあるべき状態に合わせる。取得不能を示す `Date.distantPast` は、過去の起動時刻としては扱わない。

起動の時点で、クラッシュ後の起動の時刻の一覧（今回の起動を加えた後）が3件以上なら、連続クラッシュの上限に達したものとする。

出来事ごとに、記録を次の順（左から）に更新する。

| 出来事 | 記録の更新 |
| --- | --- |
| 起動 | 起動の理由を判定する → 起動時刻が取得不能なら、抑止のセッションを消す → 所有を `SPEC-HLP-005` の規則で更新する → クラッシュ後の起動の時刻の一覧から 10 分より古いものを除き、クラッシュ後なら今回の時刻を加える → 実行中の印を立て、終了の理由を消す → 再開するかを決める（`SPEC-LCY-004`）→ 再開しないなら、抑止のセッションを消して、停止中のあるべき状態に合わせる（`SPEC-LCY-006`） |
| 開始（利用者の操作、再開） | 所有を先に書く（`SPEC-HLP-005`）→ 仕組みを適用する → 抑止のセッションを書く → 合わせられていない制御の一覧を全項目評価し直して置き換える（`SPEC-BLK-007`）。利用者の操作による開始なら、クラッシュ後の起動の一覧を空にする |
| 開始の拒否（再開を含む） | 記録に抑止のセッションがあれば消す → 停止中のあるべき状態に合わせる（試した開始で適用したものと、前のプロセスから残ったものの両方）→ 所有を `SPEC-HLP-005` の規則で更新する → 合わせられていない制御の一覧を全項目評価し直して置き換える（`SPEC-BLK-007`） |
| 解除の時刻の置き換え | 置き換え後の解除の時刻と由来で、抑止のセッションを書き直す（`SPEC-BLK-003`、`SPEC-BLK-011`） |
| 解除 | 抑止のセッションを先に消す → 停止中のあるべき状態に合わせる → 所有を `SPEC-HLP-005` の規則で更新する → 合わせられていない制御の一覧を全項目評価し直して置き換える（`SPEC-BLK-007`） → クラッシュ後の起動の一覧を空にする |
| 抑止中の設定の変更 | 所有を `SPEC-HLP-005` の規則で更新する → 反映したか巻き戻した後の状態で、合わせられていない制御の一覧を全項目評価し直して置き換える（`SPEC-BLK-007`）（`SPEC-BLK-009`） |
| 利用者の終了 | 解除と同じ → 終了の理由を「利用者の終了」にする → 実行中の印を下ろす |
| セッションの終了による終了 | 停止中のあるべき状態に合わせる（抑止のセッションは残す）→ 所有を `SPEC-HLP-005` の規則で更新する → 合わせられていない制御の一覧を全項目評価し直して置き換える（`SPEC-BLK-007`） → 終了の理由を「セッションの終了」にする → 実行中の印を下ろす |
| 終了理由を判定できない | 解除と同じ → 終了の理由を消す → 実行中の印を下ろす。ダイアログは要求しない |
| 合わせ直し | 一覧にある仕組みだけを操作し、その項目を合わせた結果で置き換える（`SPEC-BLK-007`）。所有は `SPEC-HLP-005` の規則で更新する |

順序の理由: 抑止のセッションは、仕組みを適用した後に書き、戻す前に消す。所有は、`on` の前に書き、`off` の後に消す。こうすると、どこで中断しても、記録が抑止のセッションを示すなら仕組みは適用済みか、適用し直せる。起動時の所有の更新後も記録が所有を示すなら、後片付けで `off` すればよい。

記録は書くたびに最終更新の時刻を更新し、ファイルを置き換えて書いて、書きかけの状態を残さない。

記録を保存できないときは、次のようにする。

- 開始（再開を含む）では、記録も開始の一部とし、全部か無しかを保つ。所有の「立てた」を保存できなければ、`on` を実行せずに開始を拒否する（`SPEC-HLP-005`）。仕組みを適用した後に抑止のセッションを保存できなければ、開始を拒否し、開始の拒否として停止中のあるべき状態に合わせる。どちらも、拒否の理由は状態を保存できないことである。
- 開始以外（解除の時刻の置き換え、解除、終了、合わせ直し、設定の変更など）では、処理を続け、動いている間はメモリー上の状態を正とする。ただし、`disablesleep` を立てる必要が生じた場面では、所有の「立てた」を保存できなければ `on` を実行しない（`SPEC-HLP-005`）。保存は合わせ直しと同じ契機（`SPEC-BLK-007`。一覧が空でも、保存できていない間は 1 分ごと）で試み直す。保存できるまで、メニューの警告の行で、状態を保存できていないことを伝える（`SPEC-MENU-004`）。その間の CLI の `off` は終了コード 69 にする（`SPEC-CLI-007`）。

既知の制約: 記録を保存できないまま終了またはクラッシュした場合、次の起動は残っている古い記録のとおりに判定する。そのため、解除したはずの抑止を再開することがある。記録を保存できない環境ではほかの動作も保証できないので、この制約は受け入れる。

既知の制約: 記録または起動時刻を読めないときは所有も失うので、Capsaicin が立てた `disablesleep` が残っていても外部のものとして扱い、下ろさない（`SPEC-HLP-005`）。外部のものを誤って下ろすのを避けるため、この残留を受け入れる。ヘルパーが使えれば、Mac の次の起動時に起動時の後片付けが下ろす（`SPEC-HLP-003`）。記録は置き換えて書くので、書きかけで読めなくなることはなく、記録の読み取り失敗はファイルの破損や形式の違いに限られる。

### 受け入れ例: 初めての起動

1. 再開用の記録がない状態にする。
2. アプリを起動する。
3. 起動の理由は「通常の起動」になり、停止中で起動し、記録が作られて実行中の印が立つ。

### 受け入れ例: on の後、セッションを書く前に中断した場合

1. 試験用のビルドで、手動スリープを止める開始の途中、ヘルパーの `on` が成功した直後にクラッシュさせる。「再開しない」を選んでおく。
2. 自動で再起動するのを待つ。
3. 起動の理由は「クラッシュ後」になり、記録の所有が「立てた」を示すので、停止中のあるべき状態に合わせるときに `off` が実行され、`pmset -g` は `SleepDisabled 0` を示す。

### 受け入れ例: 起動時刻を取得できないときは再開せず、前回の所有も引き継がない

1. ポートの偽物で、抑止のセッションと所有の「立てた」が記録され、`SleepDisabled` が 1 の状態を作る。前回の記録は「実行中」と「セッションの終了」の両方、再開の設定は3つすべてを試す。
2. 起動時刻を取得不能にしてアプリの起動処理を行い、解除を要求する。その後、終了またはヘルパーの削除を行う。
3. 起動の理由は「通常の起動」で、停止中になる。記録のセッションは消え、所有は「立てていない」になる。起動時もその後の操作でも、ヘルパーの `on`・`off` と削除時の `disablesleep` の解除は行われず、偽物の `SleepDisabled` は 1 のままである。

### 受け入れ例: 所有を保存できなければ on しない

1. 「ディスプレイを閉じたとき」を「オンのまま」にし、試験用のビルドで再開用の記録を保存できない状態にする。
2. `capsaicin on` を実行する。
3. 終了コード 69 で失敗し、状態を保存できないことが理由として出る。`pmset -g` は `SleepDisabled 0` のままである。

## SPEC-LCY-008 更新のインストールと抑止

関連要件: `REQ-SYS-008`

更新の確認とダウンロードだけでは、抑止を解除しない。自動のインストールは、`SPEC-SET-007` で「ダウンロードしてインストール」を選んでいる場合に限る。インストールのためにアプリを終了させる時期は、自動か利用者の操作かで次のように決める。

| 契機 | 条件 | 動作 |
| --- | --- | --- |
| 自動のインストール | 抑止を止めていて、設定ウインドウを開いていない | ダウンロード済みの版をインストールしてアプリを起動し直す |
| 自動のインストール | 抑止中、または設定ウインドウを開いている | インストールを待ち、両方の待つ条件がなくなったときに実行する |
| 利用者がインストールを選ぶ | 抑止中 | 抑止を解除することを確認してから進める |
| 利用者がインストールを選ぶ | 抑止を止めている | 抑止の解除の確認を出さずに進める |

自動のインストールを待っている間は、抑止の状態と設定ウインドウの表示の変化に合わせて、実行できるかを確かめ直す。両方の待つ条件がなくなったら、利用者の終了操作を待たずにインストールする。待っている版は `SPEC-SET-007` の行で示す。

利用者がインストールを選んだときの確認は、Sparkle がインストールを始める前に出す（`DEC-LCY-007`）。確認では、インストールによって抑止を解除することと、更新後に再開しないことを伝える。利用者が続けたら、`SPEC-LCY-002` の後片付けをしてインストールする。取り消したら、今はインストールせず、抑止とその解除条件を変えない。Sparkle の画面は閉じる。取り消した版は、抑止の解除や設定ウインドウを閉じたことを契機にはインストールしない。利用者が更新の確認（`SPEC-SET-007`）かメニューのアップデートの項目（`SPEC-MENU-009`）を選ぶと、同じ版をもう一度インストールできる状態で示す。抑止中なら、そこでインストールを選んだときにも確認を出す。利用者がそのまま Capsaicin を終了すると、終了時にその版をインストールし、起動し直さない。

更新のための終了は、終了理由を判定できない終了として扱い、新しい終了の種類は足さない。再開用の記録は `SPEC-LCY-007` に従って更新し、更新後は `SPEC-LCY-006` の起動時の処理を行う。再開の設定にかかわらず、更新前の抑止は再開しない。

設定と再開用の記録は、版をまたいで読めるようにする。保存形式を変える版では、前の形式を読み、保存された値の意味を引き継ぐ。インストールを待つ間のクラッシュからの起動し直しとインストールの重なりには、特別な調停を足さない（`DEC-LCY-005`）。

### 受け入れ例: 抑止中は自動でインストールしない

1. 自動アップデートを「ダウンロードしてインストール」にし、抑止を開始して設定ウインドウを閉じる。
2. 試験用の環境で新しい版のダウンロードを完了し、続けて抑止を解除する。
3. 抑止中は終了もインストールもせず、抑止が続く。解除するとインストールして起動し直し、新しい版は停止中になる。

### 受け入れ例: 設定ウインドウを閉じるまで待つ

1. 自動アップデートを「ダウンロードしてインストール」にし、抑止を止めた状態で設定ウインドウを開く。
2. 試験用の環境で新しい版のダウンロードを完了し、続けて設定ウインドウを閉じる。
3. ウインドウを開いている間は待っている版が行に表示され、アプリは終了しない。閉じると、利用者がアプリを終了しなくてもインストールして起動し直す。

### 受け入れ例: 2つの待つ条件が両方なくなるまで待つ

1. 抑止中かつ設定ウインドウを開いている状態で、自動のインストールを待つ版を用意する。
2. 抑止を解除し、その後で設定ウインドウを閉じる。別の試行では、閉じてから抑止を解除する。
3. どちらの順序でも、片方の条件だけがなくなった時点ではインストールせず、両方がなくなった時点でインストールして起動し直す。

### 受け入れ例: 抑止中に手動でインストールを続ける

1. 再開の設定を「クラッシュおよびMacの再起動後」にし、抑止を開始する。
2. Sparkle の画面でインストールを選び、抑止を解除することの確認で続ける。
3. 確認では解除と更新後に再開しないことが伝わる。続けると、判定不能の終了として後片付けし、抑止のセッションを消してインストールする。起動し直した新しい版は停止中になる。

### 受け入れ例: 抑止中に手動のインストールを取り消す

1. 自動アップデートを「確認のみ」にし、タイマーを 1 時間にして抑止を開始し、新しい版をダウンロードしておく。
2. インストールを選び、抑止を解除することの確認で取り消す。
3. アプリは終了せず、インストールもしない。Sparkle の画面は閉じる。抑止は続き、解除の時刻も変わらない。「このアプリについて」の行とメニューには、新しい版があることが出る。
4. 抑止を解除し、設定ウインドウを閉じる。
5. インストールされない。
6. 「このアプリについて」の行のボタンを押す。
7. ダウンロードし直さずに、同じ版がインストールできる状態で示される。インストールを選ぶと、確認を出さずにインストールして起動し直す。

### 受け入れ例: 取り消した版を終了時にインストールする

1. 抑止中に手動のインストールを確認で取り消す。
2. 抑止を続けたまま、Capsaicin を終了する。
3. `SPEC-LCY-002` の後片付けをして終了し、その版がインストールされる。アプリは起動し直さない。

### 受け入れ例: 停止中は確認せずにインストールする

1. 抑止を止めた状態で、設定ウインドウから Sparkle の画面を開く。
2. ダウンロード済みの版のインストールを選ぶ。
3. 抑止の解除の確認は出ず、設定ウインドウが開いていてもインストールして起動し直す。

### 受け入れ例: 保存形式を変える版でも前の値を読める

1. 前の版が保存した設定と再開用の記録を、試験用の環境に用意する。
2. 保存形式を変えた版で読み込む。
3. 前の値の意味が引き継がれ、形式が違うことだけを理由に設定や記録を捨てない。起動の判定と抑止の再開は、読み取った値に対して既存の規則で決まる。
