# 共通デザインの仕様

## 対象範囲

設定画面、メニュー、HUD、ダイアログをまたぐ見た目、動き、アクセシビリティ、アイコン、文字列の扱いを定める。各画面の構成は `specs/settings.md`、`specs/menu.md`、`specs/hud.md`、`specs/helper.md`、`specs/hotkey.md` にある。「システム既定」と書いたものは、SwiftUI や AppKit の標準コントロールの寸法をそのまま使い、上書きしない。

受け入れ例の共通の前提は、`specs/blocking.md` の「受け入れ例の共通の前提」にある。

## SPEC-UI-001 デザインの原則

関連要件: `REQ-UI-001`、`REQ-UI-002`、`REQ-UI-003`

1. 名前を読めば結果が分かる。設定の各行は、項目名と現在の値だけで、オンにすると何が起きるかが伝わる（`SPEC-SET-003`）。
2. 標準のものを標準のまま使う。コントロール、マテリアル、色、フォント、メニューは OS が提供するものを使い、寸法や色を上書きしない。自前で描くのは HUD のパネルとホットキーの記録欄だけにする。
3. 静かである。抑止中であることは LED で伝え、画面の側からは注意を引かない（`SPEC-UI-006`）。
4. 実際の状態を見せ、誤操作を防ぐ（`SPEC-SET-005`）。
5. キーボードと VoiceOver だけで全操作ができる（`SPEC-UI-007`）。

### 受け入れ例: 名前で結果が分かる

1. 要件を読んでいない人を1人用意する。
2. (i) を開かずに、設定の全項目について、オンにすると何が止まるか、何が光るかを答えてもらう。
3. すべての項目について答えられる。

### 受け入れ例: OS の外観に追従する

1. 外観をライトとダークに、アクセントカラーを数色に切り替え、「透明度を下げる」と「コントラストを上げる」をそれぞれオンにする。
2. 設定画面、メニュー、HUD、ダイアログを開く。
3. どの画面も、OS のほかの部分と同じように変わる。

### 受け入れ例: 行の位置が動かない

1. 設定画面の「防止するスリープ」と「解除の条件」を開く。
2. 各スイッチを1つずつ切り替える。
3. ほかの行の位置が動かない。無効になった行には理由を読める (i) がある。無効の原因になった設定を戻すと、無効になった行は操作前の値のまま操作できる。

## SPEC-UI-002 寸法と文字

関連要件: `REQ-UI-001`

- 自前で配置する場所（HUD、「このアプリについて」、入力パネル）の余白は、4、8、12、16、20、24 pt の段階だけを使う。
- 文字はシステムのテキストスタイルだけを使い、ポイント数やフォント名を指定しない。日本語は OS の既定にフォールバックさせる。
- 数字が並ぶ場所（残り時間、時刻、%）は等幅数字（`monospacedDigit()`）にする。

| 用途 | テキストスタイル |
| --- | --- |
| 設定の項目名、メニューの項目 | `.body` |
| 設定の値（ポップアップの選択値、スライダーの数値） | `.body`、`secondaryLabelColor` |
| 設定のグループ見出し | `Form` の `Section` 見出しの既定 |
| (i) のポップオーバーの本文 | `.callout` |
| 「このアプリについて」のアプリ名、バージョン | `.title`。バージョンは `.callout` と `secondaryLabelColor` |

HUD の文字は `SPEC-HUD-004` にある。

### 受け入れ例

1. システム設定で文字の大きさを変える。
2. 設定画面とメニューを開く。
3. 文字が OS のほかの部分と同じように変わる。抑止中のメニューで残り時間が変わっても、行の幅が揺れない。

## SPEC-UI-003 色とマテリアル

関連要件: `REQ-UI-001`

色はセマンティックなシステムカラーを使い、ライトとダークの切り替えは OS に任せる。

| 役割 | 色 |
| --- | --- |
| 本文 | `labelColor` |
| 値、補足 | `secondaryLabelColor` |
| 無効な行 | コントロールの無効状態（OS が描く） |
| 区切り線 | `separatorColor` |
| スイッチ、選択中のサイドバー、既定のボタン | `controlAccentColor` |
| 注意（Karabiner-Elements の案内、ヘルパーの不整合） | `systemOrange` のシンボルと `labelColor` の文字 |
| 正常（ヘルパーがインストール済み） | `systemGreen` のシンボルと `labelColor` の文字 |
| エラー（ホットキーを登録できない） | `systemRed` のシンボルと `labelColor` の文字 |

色だけで状態を伝えない。注意・正常・エラーには、形の異なるシンボルと文字を添える。

アプリのアクセントカラー（asset catalog の `AccentColor`、sRGB）は次の値にする（`DEC-UI-003`）。

| 外観 | 値 |
| --- | --- |
| ライト | `#456F8A` |
| ライト、コントラストを上げる | `#355C75` |
| ダーク | `#6A9CC0` |
| ダーク、コントラストを上げる | `#86B3D3` |

| 面 | マテリアル |
| --- | --- |
| 設定ウインドウのサイドバー | `NavigationSplitView` のサイドバーの既定 |
| 設定ウインドウの右側 | `windowBackgroundColor`。グループは `Form(.grouped)` の既定 |
| メニュー | `NSMenu` の既定 |
| HUD | `SPEC-HUD-004` |
| ダイアログ | `NSAlert` の既定 |

### 受け入れ例

1. システム設定のアクセントカラーを「マルチカラー」にする。
2. 設定画面を開き、オンのスイッチを見る。続けてアクセントカラーを別の色にする。
3. マルチカラーのときはアプリのアクセントカラーで、別の色にするとその色でスイッチが描かれる。

## SPEC-UI-004 アイコン

関連要件: `REQ-UI-001`

アイコンは SF Symbols を Monochrome で描き、色は文字と同じにする（例外は `SPEC-UI-003` の注意・正常・エラー）。LED が消えている・点いていることを、`capslock` の輪郭と `capslock.fill` の塗りつぶしの対比で表し、メニューバー、HUD、サイドバーで同じ意味に使う。

| 場所 | シンボル |
| --- | --- |
| サイドバー | `SPEC-SET-001` の表 |
| 項目名の横の (i) | `info.circle` |
| 注意 | `exclamationmark.triangle.fill` |
| 正常 | `checkmark.circle.fill` |
| コピーのボタン | `doc.on.doc`、コピーの後は `checkmark` |
| ホットキーの割り当てを消すボタン | `xmark.circle.fill` |
| メニューバー | `SPEC-MENU-005` |
| HUD | `SPEC-HUD-002` |

### 受け入れ例

1. 対応環境の Mac でアプリを起動する。
2. 表のシンボルを使う画面をすべて開く。
3. どのシンボルも欠けずに表示される。

## SPEC-UI-005 コントロールの種類

関連要件: `REQ-UI-001`

| 値の種類 | コントロール |
| --- | --- |
| オン・オフ | `Toggle`（`.switch` スタイル。`.controlSize(.small)` は使わない） |
| 3つ以下の排他的な選択肢 | `Picker`（`.menu` スタイルのポップアップ） |
| 時間の長さ | 時間と分の2つの数値欄と `Stepper` |
| 時刻 | `DatePicker`（`.hourAndMinute`、`.stepperField` スタイル） |
| しきい値（範囲は `SPEC-SET-002`） | `Slider` と、その左の数値 |
| ホットキー | 記録欄（`SPEC-KEY-002`） |
| 実行する操作 | `Button`（`.bordered`）。行の右端に置く。アイコンだけのボタンは `.borderless` |
| 読み取り専用の値 | 右寄せの `Text`、`secondaryLabelColor`。選択してコピーできる。パスは中央を省略する |

ウインドウの枠（閉じる・最小化などのボタンを含むタイトルバー）、スイッチ、ラジオボタン、スライダー、一覧などは、SwiftUI と AppKit の標準のものをそのまま使う。見た目を自前で描き直したり、標準の部品に似せた独自の部品を作ったりしない。調整は、標準の修飾子（スタイル、サイズ、色など）の範囲にとどめる。

### 受け入れ例

1. 設定画面の全セクションを開く。
2. 各行のコントロールを見る。
3. 値の種類ごとに、表のコントロールが使われている。

## SPEC-UI-006 動きの指針

関連要件: `REQ-UI-002`

動かすのは、HUD の出入りと内容の置き換え（`SPEC-HUD-005`、`SPEC-HUD-006`）と、OS 標準のコントロールが自分で行う変化（スイッチ、ポップアップ、シート、サイドバーの選択）だけにする。次のものは動かさない。

- メニューバーのアイコン（点滅、脈動、回転、色の変化をしない）。
- 設定の行（子の行の有効・無効の切り替え、Karabiner-Elements の案内の出入り）。
- 残り時間の表示（数字を回転させない。表示の単位は `SPEC-MENU-004`）。
- 抑止の開始・解除を、画面全体の効果や音で伝えること。通知センターへの通知も使わない。

### 受け入れ例

1. 抑止を開始する。
2. 10 分間、画面を見続ける。
3. メニューを開いたときの残り時間の更新を除き、Capsaicin が描く要素は一度も動かない。

## SPEC-UI-007 キーボードと VoiceOver

関連要件: `REQ-UI-003`

設定、メニュー、ダイアログのすべての操作を、フルキーボードアクセスと VoiceOver で行えるようにする。

- 設定画面: サイドバーは ↑↓、右側へは Tab で移る。(i) はキーボードで開ける（`SPEC-SET-003`）。
- メニュー: `NSMenu` の標準のキーボード操作を使う（`SPEC-MENU-001`）。
- ダイアログ: 既定のボタンは Return、キャンセルは Esc。
- 状態を示すシンボルやアイコンだけのボタンには、VoiceOver のラベルを付ける。HUD の内容は読み上げる（`SPEC-HUD-008`）。

### 受け入れ例

1. フルキーボードアクセスと VoiceOver をオンにする。
2. マウスに触れずに、抑止の開始、設定の全項目の変更、ヘルパーの削除までを行う。
3. すべて行える。

## SPEC-UI-008 快適さの確認

関連要件: `REQ-UI-002`

実装後に、次をすべて満たすことを確かめる。

### 受け入れ例: コマ落ちがない

1. 60 Hz と 120 Hz のディスプレイを用意する。
2. HUD の出入りを録画する。
3. コマ落ちがない。

### 受け入れ例: 透明度とコントラストの設定で読める

1. 「透明度を下げる」と「コントラストを上げる」をそれぞれオンにし、明るい壁紙と暗い壁紙を用意する。
2. HUD を表示し、Accessibility Inspector で文字と背景のコントラストを測る。
3. どの組み合わせでも文字が読め、コントラストは 4.5:1 以上である。

### 受け入れ例: 抑止中に気にならない

1. 抑止を開始する。
2. オーナーが 10 分間作業する。
3. Capsaicin の表示で気になったものがない。気になった表示があれば、動かさない側に寄せる。

## SPEC-UI-009 アプリアイコンの技術要件

関連要件: `REQ-UI-004`

正式なアプリアイコンは、次の条件を満たして作る。

| 項目 | 条件 |
| --- | --- |
| 形式 | Icon Composer で作る多層のファイル（推奨）か、層のないビットマップ（PNG など）。ビットマップの場合、OS が前景と背景の2層に自動で分けようとする |
| キャンバス | 1024 × 1024 px の正方形 |
| 形と角丸 | 正方形の層を渡し、角丸のマスクは OS に任せる。キャンバスのマスクを書き出さない |
| 層（Icon Composer の場合） | 背景の層と1つ以上の前景の層。最大4つのグループにまとめる |
| 層の書き出し（Icon Composer の場合） | SVG を優先し、SVG で表せない効果を含む層は PNG にする。文字はアウトライン化する |
| 外観 | 既定、ダーク、クリア、ティント。用意しない外観は OS が作る。どの外観でも主要な形を変えない |
| 主要な要素 | 中央に寄せ、マスクで欠けないようにする |
| 色空間 | sRGB、Gray Gamma 2.2、Display P3 のどれか |
| Xcode への組み込み | Icon Composer のファイルの場合は、プロジェクトに入れ、ターゲットの App Icon 欄の名前を、拡張子を除いたファイル名と一致させる |

### 受け入れ例

1. 正式なアイコン（Icon Composer のファイルかビットマップ）を組み込んでビルドする。
2. 外観を既定、ダーク、クリア、ティントに切り替えて、Finder と Dock でアイコンを見る。
3. どの外観でも角が OS のマスクどおりに丸まり、主要な形が欠けない。

## SPEC-UI-010 メニューバーのアイコンの技術要件

関連要件: `REQ-UI-004`

正式なメニューバーのアイコンは、次の条件を満たして作る。

| 項目 | 条件 |
| --- | --- |
| 素材 | SF Symbols をそのまま使うか、手を加えるか、独自に作る |
| 色 | 黒と透明だけで形を作り、色は OS に任せる。独自の画像は `NSImage.isTemplate = true` にする |
| 高さ | メニューバーの高さ 24 pt の中で、OS 標準のメニューバー項目と並べて太さと高さを揃える |
| 形式 | 独自のアイコンは PDF か SVG |
| 独自のシンボル | SF Symbols のテンプレートから作り、太さと位置を SF Symbols に揃える |
| 状態の対比 | 停止中と抑止中で表示を分ける場合は、同じ外形で輪郭と塗りつぶしにし、色で区別しない |
| アクセシビリティ | VoiceOver のラベルを付ける（`SPEC-MENU-005`） |

### 受け入れ例

1. 正式なアイコンを組み込む。
2. 明るいメニューバーと暗いメニューバーで表示し、アイコンを選択する。
3. どの状態でも OS が色を付けて読め、Wi-Fi やコントロールセンターの項目と太さと高さが揃っている。

## SPEC-UI-011 表示する文字列

関連要件: `REQ-SYS-004`

表示する文字列の正本は String Catalog にする。仕様には、各場所で何を伝えるかだけを書き、文言は書かない。文字列はセクション・機能ごとの String Catalog に分ける（`DEC-SYS-007`）。アプリ名「Capsaicin」とコマンドの書式は翻訳しない。

### 受け入れ例

1. String Catalog に英語の言語を追加し、すべての文字列に仮の訳を入れてビルドする。
2. 表示言語を英語にしてアプリを起動する。
3. すべての画面で仮の訳が表示される。

## 未決のこと

- ダークのアクセントカラーで既定のボタンの文字が読めるか: `HYP-UI-001`
- Icon Composer のファイルだけでアイコンがそろうか: `HYP-UI-002`
- 時刻の表記を地域の設定に合わせるか: `Q-UI-001`
