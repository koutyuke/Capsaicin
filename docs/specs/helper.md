# ヘルパーの仕様

## 対象範囲

root 権限で動く処理（ヘルパー）の、受け付ける処理、設置、起動時の後片付け、状態の表示と修復・削除、ダイアログを定める。この構成を選んだ理由と却下した方式は `DEC-HLP-001`、実装と設置の手順の判断は `DEC-HLP-003` にある。実機での確認は、手順を示してオーナーの承認を得てから行う（`DEC-SYS-008`）。

受け入れ例の共通の前提は、`specs/blocking.md` の「受け入れ例の共通の前提」にある。

## 状態

ヘルパーは次の3つで構成する。

| 構成要素 | 置き場所 | 観測できる振る舞い |
| --- | --- | --- |
| ヘルパー | `/Library/PrivilegedHelperTools/` | root が所有する実行ファイル。`SPEC-HLP-002` の処理だけを受け付ける |
| sudoers のルール | `/etc/sudoers.d/` | インストールしたユーザーに、ヘルパーの `on` と `off` だけをパスワードなしで許可する |
| 起動時の LaunchDaemon | `/Library/LaunchDaemons/` | Mac の起動時にヘルパーの `off` を実行する（`SPEC-HLP-003`） |

インストールの状態は、3つともない「未インストール」、一部だけある「一部だけ残っている」、3つともある「インストール済み」のどれかである。

## SPEC-HLP-001 設置

関連要件: `REQ-HLP-001`、`REQ-HLP-003`

次の操作で設置を始める。

- ヘルパーが未インストールのときに、「ディスプレイを閉じたとき」で「システムスリープ（標準）」以外を選んだ。MacBook 以外の Mac では「メニューからのスリープも防ぐ」をオンにした（`SPEC-SET-002`）。一部だけ残っている場合は、同じ操作から修復を始める（`SPEC-HLP-004`）。
- 「ヘルパー」セクションで「インストール…」を選んだ。

設置の確認（`SPEC-HLP-006`）で承認されたら、管理者認証を1回求め、3つを設置する。書式に誤りのある sudoers のルールは置かない（手順は `DEC-HLP-003`）。

設定から始めた場合、ポップアップは選んだ値を表示し、MacBook 以外の Mac ではスイッチがオンの位置に動く。ただし、設置・修復が終わるまで保存値を変えない。変更前の値が「システムスリープ（標準）」（MacBook 以外の Mac ではオフ）の場合、結果ごとの扱いは次のとおりである。

| 結果 | 表示 | 設定から始めた場合の値と表示 |
| --- | --- | --- |
| 成功 | 何も表示しない。状態がインストール済みになる | 選んだ値を保存する。MacBook 以外の Mac では保存値をオンにする |
| 確認で取り消した、または管理者認証を取り消した | 何も表示しない | 保存値は変えず、「システムスリープ（標準）」に戻す。MacBook 以外の Mac ではオフに戻す |
| 失敗 | 何ができなかったかを伝えるアラート（`SPEC-HLP-006`） | 保存値は変えず、「システムスリープ（標準）」に戻す。MacBook 以外の Mac ではオフに戻す |

「ヘルパー」セクションから設置したときは、ほかの設定を変えない。どちらから設置した場合も、設置の後に合わせ直しを試みる（`SPEC-BLK-007`）。

### 受け入れ例: 設定から設置する

1. ヘルパーが未インストールの状態で、「ディスプレイを閉じたとき」で「ディスプレイスリープ」を選ぶ。
2. 確認で「インストール」を選び、管理者のパスワードを1回入力する。
3. 3つが設置され、「ヘルパー」の状態がインストール済みになり、「ディスプレイスリープ」に対応する値が保存される（`SPEC-SET-005`）。`sudo -n` でヘルパーの `on` と `off` をパスワードなしで実行できる。

### 受け入れ例: 管理者認証を取り消す

1. ヘルパーが未インストールの状態で、「ディスプレイを閉じたとき」で「オンのまま」を選ぶ。
2. 確認で「インストール」を選び、管理者認証で取り消す。
3. 何も表示されず、「ディスプレイを閉じたとき」は「システムスリープ（標準）」に戻り、保存値は変わらず、何も設置されない。

### 受け入れ例: 設定から修復して選択を保存する

1. ヘルパーが一部だけ残っている状態で、「ディスプレイを閉じたとき」は「システムスリープ（標準）」にしておく。
2. 「オンのまま」を選び、修復を承認して管理者のパスワードを入力する。
3. 3つが置き直され、ヘルパーがインストール済みになり、「オンのまま」に対応する値が保存される。

### 受け入れ例: 設定からの設置に失敗する

1. ヘルパーが未インストールの状態で、設置が失敗する試験用の環境にする。
2. 「ディスプレイを閉じたとき」で「オンのまま」を選び、設置を承認する。
3. 失敗のアラートが表示され、保存値は変わらず、ポップアップは「システムスリープ（標準）」に戻る。

### 受け入れ例: 書式の検証に失敗する

1. 書式を誤った sudoers のルールを生成する試験用のビルドを用意する。
2. 設置を実行する。
3. sudoers のルールは置かれず、失敗のアラートが出る。`sudo -v` は従来どおり使える。

## SPEC-HLP-002 ヘルパーが受け付ける処理

関連要件: `REQ-HLP-002`

ヘルパーは、引数がちょうど次のどちらかのときだけ処理し、それ以外（別のサブコマンド、追加の引数、引数なし）は何もせずに終了コード 64 で失敗する。

| 引数 | 処理 |
| --- | --- |
| `on` | システムのスリープを禁止する（`pmset -a disablesleep 1` と同じ） |
| `off` | スリープの禁止を解く（`pmset -a disablesleep 0` と同じ） |

### 受け入れ例

1. ヘルパーをインストール済みにする。
2. `sudo -n` でヘルパーを、`on`、`off`、存在しないサブコマンド、`on` に追加の引数を付けたもの、の順に実行する。
3. `on` の後は `pmset -g` に `SleepDisabled 1` が表示され、`off` の後は `SleepDisabled 0` になる。残りの2つは終了コード 64 で失敗し、スリープの設定は変わらない。

## SPEC-HLP-003 起動時の後片付け

関連要件: `REQ-HLP-004`

Mac の起動時に、LaunchDaemon がヘルパーの `off` を実行する。アプリが起動しているか、抑止中に終了したか、`disablesleep` を誰が立てたかにかかわらず実行する。

### 受け入れ例

1. ヘルパーをインストール済みにし、「ログイン時に起動」をオフにして、アプリを終了する。アプリの終了後に `sudo -n` でヘルパーの `on` を実行し、再起動の直前に `pmset -g` が `SleepDisabled 1` を示すことを確かめる。
2. Mac を再起動してログインし、アプリを起動せずに `pmset -g` を見る。`sudo launchctl print system/<LaunchDaemon のラベル>` で、起動後に実行されたことと終了の状態を見る。
3. `SleepDisabled` は `0` になっていて、LaunchDaemon が起動後に1回実行され、正常に終了している。

この確認は永続的なシステム変更を伴うので、承認を得た実機でだけ行う。

## SPEC-HLP-004 状態の表示、修復、削除

関連要件: `REQ-HLP-005`

設定の「ヘルパー」セクションは、状態と管理の2行で構成し、行の数は状態によらず変えない。カードと項目名の左のアイコンは `SPEC-SET-002` に従う。

| 状態 | 状態の行の値 | 管理の行に置くボタン |
| --- | --- | --- |
| 未インストール | 未インストールであること。シンボルなし、`secondaryLabelColor` | 「インストール…」 |
| 一部だけ残っている | 一部だけ残っていて正しく動かないこと。`exclamationmark.triangle.fill`（`systemOrange`） | 「修復…」と「削除…」 |
| インストール済み | 使えること。`checkmark.circle.fill`（`systemGreen`） | 「削除…」 |

状態の行の (i) では、ヘルパーが何のためにあり、何を置くか（実行ファイル、実行の許可、起動時に元へ戻す設定）を伝える。

- 修復: 3つすべてを置き直す。流れは設置（`SPEC-HLP-001`）と同じで、確認とエラーの内容だけが違う（`SPEC-HLP-006`）。修復の後に合わせ直しを試みる（`SPEC-BLK-007`）。
- 削除: 確認の後、管理者認証を1回求める処理の中で、3つを削除する。その処理の最初に `disablesleep` を戻すかどうかは、所有の規則（`SPEC-HLP-005`）で決める。削除に成功したら、先に所有を「立てていない」にし（`SPEC-HLP-005`）、そのあとでヘルパーが要る設定の保存値をオフにしていまの抑止に反映する（`SPEC-BLK-009`）。この順序にするのは、削除したヘルパーで `off` を試みて失敗し、設定が戻るのを避けるためである。削除に失敗したときは、処理の途中で `disablesleep` が変わっていることがあるので、`SleepDisabled` を読み直して所有を `SPEC-HLP-005` の規則で更新し、合わせられていない制御を評価し直す（`SPEC-BLK-007`）。管理者認証を取り消したら、何も変えない。

削除に失敗した後、自分が所有する `SleepDisabled` を読み直せなければ、適用状態の見込みを「分からない」にし、所有は保つ。抑止中なら「止めるべきなのに適用できていない制御」、停止中なら「戻すべきなのに残っている制御」として記録し、`SPEC-BLK-007` の契機で合わせ直す。

### 受け入れ例: 削除する

1. 「ディスプレイを閉じたとき」を「オンのまま」にして抑止中にする。
2. 「削除…」を選び、確認で「削除」を選んで、管理者のパスワードを入力する。
3. 3つが削除され、状態が未インストールになり、「ディスプレイを閉じたとき」が「システムスリープ（標準）」になり、`pmset -g` は `SleepDisabled 0` を示す。

### 受け入れ例: 外部の disablesleep は削除で戻さない

1. Capsaicin を使わずに `sudo pmset -a disablesleep 1` を実行しておく。「ディスプレイを閉じたとき」を「オンのまま」にして抑止を開始する。
2. 「削除…」を選び、確認で「削除」を選んで、管理者のパスワードを入力する。
3. 3つが削除され、`pmset -g` は `SleepDisabled 1` のままである。最後に `sudo pmset -a disablesleep 0` で元に戻す。

### 受け入れ例: 修復する

1. sudoers のルールだけを手で削除する。
2. 「ヘルパー」セクションを開き、「修復…」を選んで、管理者のパスワードを入力する。
3. 修復の前は一部だけ残っている状態と「修復…」「削除…」が表示され、修復の後はインストール済みになる。

### 受け入れ例: 削除失敗後に読み直せなければ、合わせ直しを続ける

1. ポートの偽物で、「ディスプレイを閉じたとき」を「オンのまま」にして抑止を開始する。
2. 削除の途中で `SleepDisabled` が 0 になった後に処理が失敗し、読み直しも失敗した状態を作る。その後、読み取りを成功させて1分経過を通知する。
3. 読み直しに失敗した時点では所有を保ち、適用できていない制御として記録される。1分後には `on` が実行され、`SleepDisabled` が 1 に戻り、合わせられていない制御から外れる。抑止のセッションと設定は変わらない。

## SPEC-HLP-005 disablesleep の所有の規則

関連要件: `REQ-HLP-006`

Capsaicin は、自分が立てた `disablesleep` だけを戻す。立てたかどうかは、再開用の記録の「`disablesleep` を立てたか」（`SPEC-LCY-007`。以下、所有）で持つ。外部のもの（所有が「立てていない」のに `SleepDisabled` が 1 のもの）は、あるべき状態と常に合っているとみなし、触れない（`SPEC-BLK-007`）。持ち主を問わず `disablesleep` を 0 に戻すのは、Mac の起動時の LaunchDaemon（`SPEC-HLP-003`）だけである。

そのため、記録を最後に書いた後に Mac が起動していたら（`kern.boottime` が記録の最終更新の時刻より後。`SPEC-LCY-007`）、アプリの起動時の処理の最初に所有を「立てていない」にする。前の起動で立てたものは LaunchDaemon が下ろしていて、その後に立っているものは外部のものだからである。起動時刻を読めて、記録の後に Mac が起動していないと判定したときは、ログアウトの後も所有を保つ。

起動時刻を取得できない場合も、ヘルパーを操作する前に前回の所有を「立てていない」にする。前回の所有で外部のものを下ろすのを避けるためである。起動時の `SleepDisabled` が 1 なら外部のものとして扱い、解除・終了・ヘルパーの削除でも下ろさない。前回の抑止のセッションの扱いと、このために残る制御の制約は `SPEC-LCY-007` にある。その後、利用者が 0 から抑止を開始する場合は、次の規則で新たに所有を得る。

規則は「立てるとき」と「下ろすとき」の2つで、場面によらない。

立てるときの規則は、`disablesleep` を立てる必要が生じたときに使う。場面は、開始、再開、抑止中の設定の変更、合わせ直しで適用するときである。

| `SleepDisabled` | 所有 | 扱い | 所有の更新 |
| --- | --- | --- | --- |
| 0 | どちらでも | 所有の「立てた」を保存できてから、ヘルパーの `on` を実行する | `on` の前に「立てた」にして保存する |
| 1 | 立てた | Capsaicin が前に立てたまま残ったもの（クラッシュや、下ろせなかった解除など）とみなし、`on` を実行せずに引き継ぐ | 「立てた」を保つ |
| 1 | 立てていない | 外部のものとみなし、`on` を実行しない。失敗とはしない | 「立てていない」にする |

所有を保存できなかったとき、または `on` が失敗したときは、場面によって次のように扱う。

- 開始、再開: 開始を拒否する（`SPEC-BLK-010`）。
- 抑止中の設定の変更: 反映できなかった変更として、設定を変更前に戻す（`SPEC-BLK-009`）。
- 合わせ直し: `on` を実行せず、止めるべきなのに適用できていない制御として残す（`SPEC-BLK-007`）。

下ろすときの規則は、`disablesleep` を下ろす必要が生じたときに使う。場面は、解除、終了、起動時の処理、抑止中に不要になったとき（設定の変更）、合わせ直しである。

解除と終了での輝度の復元の順序は `SPEC-BLK-013` に従う。

1. 所有が「立てた」でなければ、何もしない。
2. 所有が「立てた」なら、`SleepDisabled` を読む。0 なら `off` を実行せずに「立てていない」にする。
3. 1 なら、ヘルパーの `off` を実行する。成功したら「立てていない」にする。失敗したら「立てた」を保ち、戻すべきなのに残っている制御として残す（`SPEC-BLK-007`）。

`SleepDisabled` を読めなかったときは、立てるときは `on` の失敗と同じに扱い（上の場面ごとの扱い）、下ろすときは `off` の失敗と同じに扱う（「立てた」を保ち、戻すべきなのに残っている制御として残す）。読めなかった値を 0 や 1 とみなさない。

ヘルパーの呼び出し（`on` と `off`）と `SleepDisabled` の読み取りは、5 秒の期限を過ぎたら呼び出し元に失敗を返す。期限を過ぎても、起動した子プロセスは止めずに終わるまで見届け、その間に来た呼び出しと読み取りは、子プロセスを起動せずに失敗として扱う。期限を過ぎた `on` や `off` は後から完了することがあるが、所有は `on` の前に書き、`off` の成功まで保つので、子プロセスが終わった後の合わせ直し（`SPEC-BLK-007`）で、読み直した値から上の規則どおりに合わせられる。

既知の制約は次の2つで、どちらも Mac の起動時の LaunchDaemon（`SPEC-HLP-003`）で戻り、通常の使い方では起きにくいので受け入れる。

- 期限を過ぎた子プロセスが終わる前にアプリが終了すると、次の起動はその完了を待たない。次の起動が 0 を読んで所有を外した後に `on` が完了すると、その `disablesleep` は外部のものとして扱われ、下ろされない。
- Debug と Release を同時に動かし、両方で `disablesleep` を使うと、互いの `disablesleep` を外部のものとみなす。一方が下ろすと、もう一方の抑止も外れる。

ヘルパーの削除（`SPEC-HLP-004`）では、ヘルパーの `off` ではなく、管理者認証を求める削除の処理の中で下ろす。所有が「立てた」で、`SleepDisabled` が 1 か読めなかったときだけ、その処理の最初に `/usr/bin/pmset -a disablesleep 0` を実行し、それ以外は `pmset` を実行しない。読めなかったときも実行するのは、削除で起動時の LaunchDaemon も消え、残すと誰も下ろさなくなるためである。所有しているものだけが対象なので、外部のものには触れない。アプリが選ぶのはこの実行の有無だけで、処理の内容は固定にし、任意の入力を渡さない。削除に成功したら、所有を「立てていない」にしてから、ヘルパーが要る設定を反映する（`SPEC-HLP-004`）。

### 受け入れ例: 外部の disablesleep には触れない

1. Capsaicin を使わずに `sudo pmset -a disablesleep 1` を実行しておく。「ディスプレイを閉じたとき」で「オンのまま」を選ぶ。
2. 抑止を開始し、続けて抑止を解除し、Capsaicin を終了する。
3. 抑止は開始し、解除と終了の後も `pmset -g` は `SleepDisabled 1` のままである。最後に `sudo pmset -a disablesleep 0` で元に戻す。

### 受け入れ例: クラッシュの後も自分の所有を保つ

1. 「クラッシュ後のみ」を選び、「ディスプレイを閉じたとき」を「オンのまま」にして抑止を開始する。
2. アプリをクラッシュさせ、自動で再起動して再開した後に、メニューで抑止を解除する。
3. 再開の時点では `SleepDisabled` は 1 のままで、解除の後は `pmset -g` が `SleepDisabled 0` を示す。

### 受け入れ例: 起動時刻を取得できなくても、利用者の開始で新たに所有できる

1. ポートの偽物で、前回の抑止のセッションと所有が記録された状態を作り、起動時刻を取得不能にして起動処理を行う。「ディスプレイを閉じたとき」は「オンのまま」にする。
2. 偽物の `SleepDisabled` を 0 にして、利用者の操作で抑止を開始し、続けて解除する。
3. 開始では所有の「立てた」を保存してから `on` を実行する。解除では `off` を実行して所有を外し、偽物の `SleepDisabled` は 0 になる。

## SPEC-HLP-006 ヘルパーとエラーのダイアログ

関連要件: `REQ-HLP-001`、`REQ-HLP-005`

ダイアログはすべて `NSAlert` を使い、設定ウインドウから開くものはシートにする。アイコンは OS の既定（アプリアイコン）のままにし、注意の記号は使わない。

| ダイアログ | タイトルで伝えること | 本文で伝えること | ボタン |
| --- | --- | --- | --- |
| 設置（設定から） | 選んだ動作にはヘルパーの設置が要ること | 何を置くか（スリープを切り替えるだけの小さなプログラム、その実行の許可、起動時に元へ戻す設定）、管理者のパスワードを1回求めること、設定の「ヘルパー」から削除できること。3文以内 | 既定: インストール、ほか: キャンセル |
| 設置（「インストール…」から） | ヘルパーを設置するかの確認 | 設置（設定から）と同じ | 既定: インストール、ほか: キャンセル |
| 修復 | ヘルパーを置き直すかの確認 | 一部が見つからないので3つすべてを置き直すこと、管理者のパスワードを求めること | 既定: 修復、ほか: キャンセル |
| 削除 | ヘルパーを削除するかの確認 | 「ディスプレイを閉じたとき」が「システムスリープ（標準）」になること（MacBook 以外の Mac では「メニューからのスリープも防ぐ」がオフになること）、抑止中ならそのスリープが止まらなくなること、管理者のパスワードを求めること | 既定: 削除（破壊的な表示にしない）、ほか: キャンセル |
| エラー | 何ができなかったか（「エラー」だけのタイトルにしない） | 分かっている範囲の理由と、設定や状態がどうなったか。1〜2文 | OK |

エラーのダイアログを出すのは、次の場面だけである。

- ヘルパーの設置、修復、削除に失敗した（`SPEC-HLP-001`、`SPEC-HLP-004`）。
- 抑止中の設定の変更を反映できず、設定を元に戻した（`SPEC-BLK-009`）。
- 利用者の終了で、合わせられていない制御が残った（`SPEC-LCY-002`）。

- 設置、修復、削除の確認で既定のボタンを押すと、OS の管理者認証が開き、その間シートは閉じる。エラーのダイアログの OK は、ダイアログを閉じるだけである。
- エラーの詳細（終了コード、標準エラー出力）はアラートに出さず、ログ（`os_log`）に残す。
- 同じエラーが続いても、アラートは1枚ずつ表示する。
- 利用者が操作していない場面（抑止の自動解除、セッションの終了による終了など）ではアラートを出さない。

### 受け入れ例

1. ヘルパーが未インストールの状態で、設定ウインドウから「インストール…」を選ぶ。
2. 表示されたダイアログを見る。
3. 設定ウインドウのシートとして開き、注意の記号がなく、既定のボタンがインストール、もう一方がキャンセルである。
