# ヘルパーの仕様

## 対象範囲

root 権限で動く処理（ヘルパー）の、受け付ける処理、設置、起動時の後片付け、更新の後の登録し直し、状態の表示と削除、ダイアログを定める。構成を選んだ理由は `DEC-HLP-005` にある。実機での確認は、手順を示してオーナーの承認を得てから行う（`DEC-SYS-008`）。

受け入れ例の共通の前提は、`specs/blocking.md` の「受け入れ例の共通の前提」にある。

## 状態

ヘルパーは、アプリのバンドルに入れたデーモンである。実行ファイルは `Contents/Helpers/`、launchd の定義は `Contents/Library/LaunchDaemons/` に置き、`SMAppService.daemon` で登録する。sudoers や `/Library/LaunchDaemons` などのシステムの設定は書き換えない。デーモンが書くのは、起動時の後片付けの記録（`SPEC-HLP-003`）だけである。

| 構成要素 | 観測できる振る舞い |
| --- | --- |
| デーモン | root で動き、XPC で `SPEC-HLP-002` の要求だけを受け付ける。後片付けの役目がなく、使われていなければ終了し、次の要求で launchd が起動する |
| launchd の定義 | Mach サービスを1つ持つ。Mac の起動時にデーモンを起動し、起動時の後片付けを行わせる（`SPEC-HLP-003`） |
| システム設定の項目 | 「一般 > ログイン項目と機能拡張」のバックグラウンドの一覧に、アプリ名の項目として出る |

ヘルパーの状態は、`SMAppService` の状態とアプリの署名から決まる、次の4つのどれかである。

| 状態 | 条件 |
| --- | --- |
| 未インストール | 登録されていない（`notRegistered`、`notFound`） |
| 承認待ち | 登録したが、システム設定で許可されていないか、許可が外れた（`requiresApproval`） |
| 使える | 登録され、許可されている（`enabled`） |
| このビルドでは使えない | アプリの署名に Team ID がない（ad-hoc 署名）。デーモンとの接続が署名の条件で拒まれるので、登録の状態によらずこの状態にする |

ヘルパーが要る設定（`SPEC-SET-005`）を適用できるのは「使える」のときだけである。アプリは状態を、起動時、設定ウインドウが前面に来たとき、設置と削除の後に読み直す。承認待ちで設定ウインドウが開いている間は、2 秒ごとにも読み直す。

## SPEC-HLP-001 設置

関連要件: `REQ-HLP-001`

次の操作で設置を始める。

- ヘルパーが使えないときに、「ディスプレイを閉じたとき」で「Macをスリープ（標準）」以外を選んだ。MacBook 以外の Mac では「メニューからのスリープも防ぐ」をオンにした（`SPEC-SET-002`）。
- 「ヘルパー」セクションで「インストール…」を選んだ。

状態ごとの扱いは次のとおりである。

| 状態 | 扱い |
| --- | --- |
| 未インストール | 設置の確認（`SPEC-HLP-006`）を出し、承認されたら登録する |
| 承認待ち | 設定から始めたときは、許可を案内するアラート（`SPEC-HLP-006`）を出し、利用者が開くと選んだらシステム設定の「ログイン項目と機能拡張」を開く。取り消したら選んだ値を捨てる。「ヘルパー」セクションの「システム設定を開く」からは、確認を出さずに開く（`DEC-SET-007`） |
| このビルドでは使えない | 登録せず、このビルドではヘルパーを使えないことをエラーのダイアログで伝える |

App Translocation された場所（`/AppTranslocation/` を含むパス）で動いているときは登録せず、アプリを「アプリケーション」フォルダーに移すよう、エラーのダイアログで伝える。

登録の結果ごとの扱いは次のとおりである。

| 結果 | 扱い |
| --- | --- |
| 使える | 設置の完了とする |
| 承認待ち | システム設定の「ログイン項目と機能拡張」を開く。許可されて「使える」になったときに、設置の完了とする |
| 失敗 | 何ができなかったかを伝えるエラーのダイアログ（`SPEC-HLP-006`）を出す |

設定から始めた場合、ポップアップは選んだ値を表示し、MacBook 以外の Mac ではスイッチがオンの位置に動く。ただし、設置が完了するまで保存値を変えない。承認待ちの間、その行は選んだ値のまま、注意の記号と状態の文を出し、システム設定で許可すると有効になることを説明文で示す（`SPEC-SET-005`）。設置が完了したら選んだ値を保存する。次のときは、選んだ値を捨て、保存値に対応する表示に戻す。

- 確認か、許可を案内するアラートで取り消した。または登録に失敗した。
- 承認を待つ間に、設定ウインドウを閉じた、その設定を別の値に変えた、またはアプリが終了した。

「ヘルパー」セクションから設置したときは、ほかの設定を変えない。どちらから設置した場合も、設置の完了の後に合わせ直しを試みる（`SPEC-BLK-007`）。

### 受け入れ例: 設定から設置する

1. ヘルパーが未インストールの状態で、「ディスプレイを閉じたとき」で「ディスプレイをオフ」を選ぶ。
2. 確認で「インストール」を選ぶ。システム設定が開くので、Capsaicin のバックグラウンドの項目を許可し、設定ウインドウに戻る。
3. 許可するまでは、ポップアップは「ディスプレイをオフ」のまま注意の記号が付き、保存値は変わらない。許可した後は「ヘルパー」の状態が「有効」になり、「ディスプレイをオフ」に対応する値が保存される（`SPEC-SET-005`）。

### 受け入れ例: 承認を待つ間に設定ウインドウを閉じる

1. ヘルパーが未インストールの状態で、「ディスプレイを閉じたとき」で「オンのまま」を選び、確認で「インストール」を選ぶ。
2. システム設定で許可せずに、設定ウインドウを閉じて開き直す。
3. 「ディスプレイを閉じたとき」は「Macをスリープ（標準）」で、保存値は変わらず、「ヘルパー」の状態は「システム設定での許可待ち」である。

### 受け入れ例: 承認待ちのときに設定で選び直す

1. ヘルパーが承認待ちの状態で、「ディスプレイを閉じたとき」は「Macをスリープ（標準）」にしておく。
2. 「オンのまま」を選び、表示されたアラートで「キャンセル」を選ぶ。もう一度「オンのまま」を選び、今度は「システム設定を開く」を選ぶ。
3. 1回目はシステム設定が開かず、ポップアップは「Macをスリープ（標準）」に戻る。2回目はシステム設定の「ログイン項目と機能拡張」が開き、ポップアップは「オンのまま」のまま注意の記号と状態の文が出て、保存値は変わらない。

### 受け入れ例: 設定からの設置に失敗する

1. ポートの偽物で、登録が失敗する状態にする。ヘルパーは未インストールにする。
2. 「ディスプレイを閉じたとき」で「オンのまま」を選び、設置を承認する。
3. 失敗のアラートが表示され、保存値は変わらず、ポップアップは「Macをスリープ（標準）」に戻る。

### 受け入れ例: ad-hoc 署名のビルドでは設置しない

1. ad-hoc 署名の Debug ビルドで、「ディスプレイを閉じたとき」で「オンのまま」を選ぶ。
2. 表示されたダイアログを見る。
3. このビルドではヘルパーを使えないことを伝えるエラーのダイアログが出て、ポップアップは「スリープ」に戻り、何も登録されない。

## SPEC-HLP-002 ヘルパーが受け付ける処理

関連要件: `REQ-HLP-002`、`REQ-LCY-003`

デーモンは、アプリと同じ Team ID を持ち、署名識別子がアプリの bundle ID である相手の接続だけを受け付ける。それ以外の相手の接続は、要求を読む前に落とす。アプリの側も、デーモンが同じ Team ID と、決めたデーモンの署名識別子を持つことを確かめる。条件の値は、ビルドで決めた識別子と、自分の署名の Team ID から取り、引数、環境変数、ファイルからは受け取らない。

要求は、`command` の値がちょうど次のどちらかの辞書だけを受け付け、それ以外（別の値、ほかのキー、型の違い）は何もせずに失敗を返す。

| `command` | 処理 |
| --- | --- |
| `on` | システムのスリープを禁止する。空の環境で `/usr/bin/pmset -a disablesleep 1` を実行する |
| `off` | スリープの禁止を解く。空の環境で `/usr/bin/pmset -a disablesleep 0` を実行する |

応答は、`pmset` が終了コード 0 で終わったかどうかだけを返す。

デーモンは、`on` を受けた接続に後片付けの役目を持たせる。その接続から `off` を受けたら役目を外し、`off` を受けずに接続が切れたら `off` を実行する。launchd から `SIGTERM` を受けたときも、役目を持つ接続があれば `off` を実行してから終了する。役目を持つ接続がある間は、アイドルでも終了しない。アプリは、抑止中に `disablesleep` が要る間、`on` を送った接続を保つ。要求の種類は増やさない（`DEC-LCY-010`）。

### 受け入れ例: off なしの切断で後片付けする

1. アプリが `on` を送り、その接続を保っている。
2. 要求を送らずに待ち、続けて `off` を送らずに接続を切る。
3. 待っている間はデーモンがアイドルで終了しない。切断すると `off` が実行され、`SleepDisabled` は 0 になる。

### 受け入れ例: off で役目を外す

1. ポートの偽物で、接続が `on` を送り、デーモンが役目を持つ状態を用意する。
2. 同じ接続から `off` を送り、その後に切断する。
3. `off` で役目が外れ、切断による `off` の追加実行はない。

### 受け入れ例: SIGTERM で後片付けして終了する

1. デーモンが `on` を受けた接続の役目を持ち、`SleepDisabled` が 1 である。
2. 承認済みの検証環境で、対象のデーモンに `SIGTERM` を送る。
3. デーモンは `off` を実行してから終了し、`SleepDisabled` は 0 になる。

### 受け入れ例: 受け付ける要求

1. ヘルパーを「使える」にする。
2. アプリからデーモンに、`on`、`off`、存在しない値、`on` にほかのキーを加えたもの、の順に要求を送る。
3. `on` の後は `pmset -g` に `SleepDisabled 1` が表示され、`off` の後は `SleepDisabled 0` になる。残りの2つは失敗を返し、スリープの設定は変わらない。

### 受け入れ例: 正規でない相手を拒む

1. ヘルパーを「使える」にする。
2. ad-hoc 署名の小さなプログラムから、デーモンの Mach サービスに `on` を送る。
3. 応答は返らず接続が切れ、`SleepDisabled` は変わらない。

## SPEC-HLP-003 起動時の後片付け

関連要件: `REQ-HLP-004`

Mac の起動時に、launchd がデーモンを起動し、デーモンが `off` を実行する。アプリが起動しているか、抑止中に終了したか、`disablesleep` を誰が立てたかにかかわらず実行する。ヘルパーが承認待ちで、デーモンが起動できないときは行われない。

デーモンは、起動したときに `kern.bootsessionuuid` を読み、root だけが書き込める `/Library/Application Support/` の下の記録と比べる。

| 記録 | 扱い |
| --- | --- |
| ない | `off` を実行せずに、今の値を書く。初めての設置で、外部の `disablesleep` を戻さないためである |
| 今の値と違う | `off` を実行し、今の値を書く |
| 今の値と同じ | 何もしない |

launchd は、設置や登録し直しのとき、要求を受けたときにもデーモンを起動するが、同じ Mac の起動の中では記録が同じなので、`off` を繰り返さない。

既知の制約として、削除しても記録は残る。後の Mac の起動の中で設置し直すと、その時点で `off` を実行し、外部の `disablesleep` も戻す。削除と設置し直しは通常の使い方では少ないので受け入れる。

### 受け入れ例

1. ヘルパーを「有効」にし、「ログイン時に起動」をオフにして、アプリを終了する。`sudo pmset -a disablesleep 1` を実行し、再起動の直前に `pmset -g` が `SleepDisabled 1` を示すことを確かめる。
2. Mac を再起動してログインし、アプリを起動せずに `pmset -g` を見る。`log show --last boot` で、デーモンの起動の記録を見る。
3. `SleepDisabled` は `0` になっていて、デーモンが起動後に1回だけ `off` を実行している。

この確認は永続的なシステム変更を伴うので、承認を得た実機でだけ行う。

## SPEC-HLP-004 状態の表示と削除

関連要件: `REQ-HLP-005`

設定の「ヘルパー」セクションは、状態と管理の2行で構成し、行の数は状態によらず変えない。カードと項目名の左のアイコンは `SPEC-SET-002` に従う。

| 状態 | 状態の行の値 | 管理の行に置くボタン |
| --- | --- | --- |
| 未インストール | 未インストールであること。シンボルなし、`secondaryLabelColor` | 「インストール…」 |
| 承認待ち | システム設定での許可を待っていること。`exclamationmark.triangle.fill`（`systemOrange`） | 「システム設定を開く」と「削除…」 |
| 使える | 使えること。`checkmark.circle.fill`（`systemGreen`） | 「削除…」 |
| このビルドでは使えない | このビルドでは使えないこと。シンボルなし、`secondaryLabelColor` | なし |

状態の行の説明文では、ヘルパーが何のためにあり、何をするか（スリープを切り替えるだけの小さなプログラムを root で動かすこと、Mac の起動時やアプリが後片付けをできずに終わったときに元へ戻すこと）と、システム設定の「ログイン項目と機能拡張」で Capsaicin の項目を許可する必要があることを伝える。その項目をオフにするとヘルパーを使えなくなることも伝える。

抑止中に項目がオフになり、アプリが接続の切断とデーモンの承認待ち（`requiresApproval`）を検知したら、ヘルパーが要る抑止を解除する（`SPEC-BLK-007`）。アプリ自身は終了せず、解除したことと理由を HUD で知らせる（`SPEC-HUD-001`、`SPEC-HUD-002`）。設定の保存値は変えない。

- システム設定を開く: システム設定の「ログイン項目と機能拡張」を開く。
- 削除: 確認の後、次の順に行う。
  1. 所有の規則（`SPEC-HLP-005`）で、`disablesleep` を下ろす。下ろす必要があるのに失敗したら、登録を外さず、`disablesleep` を戻せなかったことをエラーのダイアログで伝えて終える。登録を外すと、起動時の後片付けもなくなり、誰も下ろさなくなるためである。
  2. 登録を外す（unregister）。
  3. 成功したら、ヘルパーが要る設定の保存値をオフにして、いまの抑止に反映する（`SPEC-BLK-009`）。手順 1 で所有は「立てていない」になっているので、ヘルパーの `off` を試みて設定が戻ることはない。
  4. 登録を外すのに失敗したら、状態を読み直して示し、エラーのダイアログを出す。所有と設定は変えない。

削除の後も、システム設定のバックグラウンドの一覧には、Capsaicin の項目が「許可済み」のまま残ることがある。これは OS の記録で、アプリを削除すると消える。

### 受け入れ例: 削除する

1. 「ディスプレイを閉じたとき」を「オンのまま」にして抑止中にする。
2. 「削除…」を選び、確認で「削除」を選ぶ。
3. 状態が未インストールになり、「ディスプレイを閉じたとき」が「Macをスリープ（標準）」になり、`pmset -g` は `SleepDisabled 0` を示す。管理者のパスワードは求められない。

### 受け入れ例: 外部の disablesleep は削除で戻さない

1. Capsaicin を使わずに `sudo pmset -a disablesleep 1` を実行しておく。「ディスプレイを閉じたとき」を「オンのまま」にして抑止を開始する。
2. 「削除…」を選び、確認で「削除」を選ぶ。
3. 状態が未インストールになり、`pmset -g` は `SleepDisabled 1` のままである。最後に `sudo pmset -a disablesleep 0` で元に戻す。

### 受け入れ例: 戻せないときは削除しない

1. ポートの偽物で、所有が「立てた」で `SleepDisabled` が 1、ヘルパーの `off` が失敗する状態を作る。
2. 「削除…」を選び、確認で「削除」を選ぶ。
3. エラーのダイアログが出て、登録は外れず、所有と設定は変わらない。

### 受け入れ例: システム設定で項目をオフにする

1. ヘルパーを「有効」にし、「ディスプレイを閉じたとき」を「オンのまま」にして抑止中にする。「切り替え時にHUDを表示」をオンにしておく。
2. システム設定の「ログイン項目と機能拡張」で、Capsaicin の項目をオフにし、設定ウインドウに戻る。
3. デーモンは `SPEC-HLP-002` に従って後片付けして終了する。アプリは切断と承認待ちを検知して抑止を解除し、HUD で理由を伝える。アプリの PID と設定の保存値は変わらない。「ヘルパー」の状態は「システム設定での許可待ち」になり、「システム設定を開く」と「削除…」が表示される。ヘルパーが要る設定の行には注意の記号が付く（`SPEC-SET-005`）。

## SPEC-HLP-007 更新の後の登録し直し

関連要件: `REQ-HLP-005`

アプリは、起動時の処理（`SPEC-LCY-006`）で、ヘルパーの登録を今の版に合わせる。アプリを入れ替えただけでも、次に起動したデーモンは新しい版になるが、launchd の定義の変更を確実に反映するために登録し直す。

1. 状態が「承認待ち」か「使える」で、前回登録したときに記録した版（`CFBundleVersion`）が今の版と違うときだけ行う。未インストールと「このビルドでは使えない」のときは何もしない。
2. 登録を外し、その完了を待ってから登録する。登録が `EPERM` で失敗したら、3 秒待って、最大 3 回まで試し直す。
3. 登録に成功したら、今の版を記録する。設置（`SPEC-HLP-001`）で登録に成功したときも記録する。
4. 失敗したら、ログに残し、状態を読み直して示す。ダイアログは出さない。

登録し直しで承認を求められることはない（`EVID-HLP-005`）。登録し直しの間にデーモンが起動しても、起動時の後片付けは同じ Mac の起動の中では繰り返さない（`SPEC-HLP-003`）。

### 受け入れ例

1. ヘルパーを「使える」にした版を、`CFBundleVersion` だけを上げた版に入れ替えて起動する。
2. 「ヘルパー」セクションを開き、ヘルパーが要る設定で抑止を開始する。
3. 承認を求められず、状態は「使える」のままで、抑止が `disablesleep` を立てる。前回登録した版の記録は新しい版になっている。

## SPEC-HLP-005 disablesleep の所有の規則

関連要件: `REQ-HLP-006`

Capsaicin は、自分が立てた `disablesleep` だけを戻す。立てたかどうか（以下、所有）はアプリのメモリーだけに持ち、保存しない。起動時は常に「立てていない」から始める。外部のもの（所有が「立てていない」のに `SleepDisabled` が 1 のもの）は、あるべき状態と常に合っているとみなし、触れない（`SPEC-BLK-007`）。持ち主を問わず `disablesleep` を 0 に戻すのは、Mac の起動時の後片付け（`SPEC-HLP-003`）だけである。

規則は「立てるとき」と「下ろすとき」の2つで、場面によらない。

立てるときの規則は、`disablesleep` を立てる必要が生じたときに使う。場面は、開始、抑止中の設定の変更、合わせ直しで適用するときである。

| `SleepDisabled` | 所有 | 扱い | 所有の更新 |
| --- | --- | --- | --- |
| 0 | どちらでも | ヘルパーの `on` を実行する | `on` の前に「立てた」にする |
| 1 | 立てた | 同じプロセスが立てたまま残ったもの（下ろせなかった解除など）とみなす。値は変わらないが、デーモンに後片付けの役目を持たせるため、ヘルパーの `on` を実行する | 「立てた」を保つ |
| 1 | 立てていない | 外部のものとみなし、`on` を実行しない。失敗とはしない | 「立てていない」にする |

`on` が失敗したときは、場面によって次のように扱う。

- 開始: 開始を拒否する（`SPEC-BLK-010`）。
- 抑止中の設定の変更: 反映できなかった変更として、設定を変更前に戻す（`SPEC-BLK-009`）。
- 合わせ直し: 止めるべきなのに適用できていない制御として残す（`SPEC-BLK-007`）。

抑止中に所有が「立てた」で、`disablesleep` が要る間にデーモンへの接続の中断を受けたら、接続を張り直して `on` を送り直す。`SleepDisabled` が 1 のままでも、新しいデーモンに後片付けの役目を戻すために送る。送り直せなければ、合わせられていない制御として残し、合わせ直しで再び役目を戻そうとする（`SPEC-BLK-007`）。切断と承認待ちを検知した場合は `SPEC-HLP-004` に従う。

下ろすときの規則は、`disablesleep` を下ろす必要が生じたときに使う。場面は、解除、終了、起動時の処理、抑止中に不要になったとき（設定の変更）、合わせ直しである。

解除と終了での輝度の復元の順序は `SPEC-BLK-013` に従う。

1. 所有が「立てた」でなければ、何もしない。
2. 所有が「立てた」なら、`SleepDisabled` を読む。0 なら `off` を実行せずに「立てていない」にする。
3. 1 なら、ヘルパーの `off` を実行する。成功したら「立てていない」にする。失敗したら「立てた」を保ち、戻すべきなのに残っている制御として残す（`SPEC-BLK-007`）。

`SleepDisabled` を読めなかったときは、立てるときは `on` の失敗と同じに扱い（上の場面ごとの扱い）、下ろすときは `off` の失敗と同じに扱う（「立てた」を保ち、戻すべきなのに残っている制御として残す）。読めなかった値を 0 や 1 とみなさない。

ヘルパーへの要求（`on` と `off`）と `SleepDisabled` の読み取りは、5 秒の期限を過ぎたら呼び出し元に失敗を返す。期限を過ぎた要求は、接続を取り消す。デーモンが起動できない間、保留中の接続があると launchd が起動を試し続けるためである。読み取りの子プロセスは止めずに終わるまで見届け、その間に来た読み取りは、子プロセスを起動せずに失敗として扱う。デーモンは要求を届いた順に1つずつ処理するので、期限を過ぎた `on` や `off` が後から完了しても、後の要求より後に実行されることはない。所有は `on` の前にメモリー上で「立てた」にし、下ろすときの規則で外すまで保つ。接続が失われた後は、値だけでなく後片付けの役目も合わせ直す。

既知の制約は次のとおりである。残った `disablesleep` は、Mac の次の起動時にヘルパーが使えれば `SPEC-HLP-003` が戻す。

- デーモンが落ちてから `on` を送り直すまでの間にアプリも終了すると、後片付けの役目を持つデーモンがいないため、`disablesleep` が残りうる。次のアプリの起動では外部のものとして扱い、下ろさない。
- Debug と正式版を同時に動かし、両方で `disablesleep` を使うと、互いの `disablesleep` を外部のものとみなす。一方が下ろすと、もう一方の抑止も外れる。
- 抑止中に電源断などが起き、次の Mac の起動の時点でヘルパーが承認待ちだと、起動時の後片付けは行われない。`disablesleep` が再起動で残る環境では、その値は外部のものとして扱われ、下ろされない。

ヘルパーの削除（`SPEC-HLP-004`）では、登録を外す前に、上の下ろすときの規則でヘルパーの `off` を実行する。下ろせなかったとき（`off` の失敗と、`SleepDisabled` を読めなかったとき）は、削除をやめる。登録を外すと起動時の後片付けもなくなり、残すと誰も下ろさなくなるためである。削除に成功したら、所有が「立てていない」の状態で、ヘルパーが要る設定を反映する（`SPEC-HLP-004`）。

### 受け入れ例: 外部の disablesleep には触れない

1. Capsaicin を使わずに `sudo pmset -a disablesleep 1` を実行しておく。「ディスプレイを閉じたとき」で「オンのまま」を選ぶ。
2. 抑止を開始し、続けて抑止を解除し、Capsaicin を終了する。
3. 抑止は開始し、解除と終了の後も `pmset -g` は `SleepDisabled 1` のままである。最後に `sudo pmset -a disablesleep 0` で元に戻す。

### 受け入れ例: デーモンが落ちたら役目を戻す

1. 「ディスプレイを閉じたとき」を「オンのまま」にして抑止を開始し、ヘルパーの登録と許可は保っておく。
2. 承認済みの検証環境で、対象のデーモンだけを `SIGKILL` で終了させる。接続の中断と `on` の送り直しを観測してから、アプリを後片付けなしで終了させる。
3. 新しいデーモンが `on` を受けて役目を持ち、アプリの切断で `off` を実行する。`SleepDisabled` は 0 に戻る。

### 受け入れ例: 起動後の開始で新たに所有する

1. ポートの偽物で、`SleepDisabled` が 0 の状態で起動処理を行う。「ディスプレイを閉じたとき」は「オンのまま」にする。
2. 利用者の操作で抑止を開始し、続けて解除する。
3. 開始ではメモリー上の所有が「立てた」になり、`on` を実行する。解除では `off` を実行して所有を外し、`SleepDisabled` は 0 になる。所有は保存されない。

### 受け入れ例: 送り直せなければ合わせられていない制御にする

1. ポートの偽物で、抑止中に所有が「立てた」で接続が中断し、承認待ちにはならず、`on` の送り直しが失敗する状態を用意する。
2. 中断の通知を受け、続けて送り直しが成功する状態にして合わせ直す。
3. 失敗した間は `SleepDisabled` が 1 でも合わせられていない制御が残る。合わせ直しでは `on` を送り、役目を戻せたら一覧から外れる。


## SPEC-HLP-006 ヘルパーとエラーのダイアログ

関連要件: `REQ-HLP-001`、`REQ-HLP-005`

ダイアログはすべて `NSAlert` を使い、設定ウインドウから開くものはシートにする。アイコンは OS の既定（アプリアイコン）のままにし、注意の記号は使わない。

| ダイアログ | タイトルで伝えること | 本文で伝えること | ボタン |
| --- | --- | --- | --- |
| 設置（設定から） | 選んだ動作にはヘルパーの設置が要ること | 何をするか（スリープを切り替えるだけの小さなプログラムを root で動かし、Mac の起動時に元へ戻すこと）、続けるとシステム設定が開くので Capsaicin の項目を許可すること、設定の「ヘルパー」から削除できること。3文以内 | 既定: インストール、ほか: キャンセル |
| 設置（「インストール…」から） | ヘルパーを設置するかの確認 | 設置（設定から）と同じ | 既定: インストール、ほか: キャンセル |
| 許可の案内（承認待ちのときに設定から） | 選んだ動作には、システム設定でヘルパーを許可する必要があること | 「ログイン項目と機能拡張」で Capsaicin の項目を許可すると、選んだ設定が有効になること。2文以内 | 既定: システム設定を開く、ほか: キャンセル |
| 削除 | ヘルパーを削除するかの確認 | 「ディスプレイを閉じたとき」が「Macをスリープ（標準）」になること（MacBook 以外の Mac では「メニューからのスリープも防ぐ」がオフになること）、抑止中ならそのスリープが止まらなくなること | 既定: 削除（破壊的な表示にしない）、ほか: キャンセル |
| エラー | 何ができなかったか（「エラー」だけのタイトルにしない） | 分かっている範囲の理由と、設定や状態がどうなったか。1〜2文 | OK |

エラーのダイアログを出すのは、次の場面だけである。

- ヘルパーの設置か削除に失敗した。このビルドでは使えない、App Translocation された場所で動いている、の場合を含む（`SPEC-HLP-001`、`SPEC-HLP-004`）。
- 抑止中の設定の変更を反映できず、設定を元に戻した（`SPEC-BLK-009`）。
- 利用者の終了で、合わせられていない制御が残った（`SPEC-LCY-002`）。

- 設置の確認で既定のボタンを押すと、シートを閉じてから登録する。承認待ちになったら、システム設定を開く。許可の案内で既定のボタンを押すと、シートを閉じてからシステム設定を開く。エラーのダイアログの OK は、ダイアログを閉じるだけである。
- エラーの詳細（`SMAppService` のエラー、XPC のエラー）はアラートに出さず、ログ（`os_log`）に残す。
- 同じエラーが続いても、アラートは1枚ずつ表示する。
- 利用者が操作していない場面（抑止の自動解除、セッションの終了による終了、更新の後の登録し直しなど）ではアラートを出さない。

### 受け入れ例

1. ヘルパーが未インストールの状態で、設定ウインドウから「インストール…」を選ぶ。
2. 表示されたダイアログを見る。
3. 設定ウインドウのシートとして開き、注意の記号がなく、既定のボタンがインストール、もう一方がキャンセルである。
