# コマンドラインの仕様

## 対象範囲

`capsaicin` コマンドの書式、出力、終了コード、アプリの起動、設定との関係を定める。CLI の置き場所、Homebrew で入れたときのリンク、設定の意味の判断は `DEC-CLI-004`、アプリとの通信の判断は `DEC-CLI-002` にある。CLI で切り替えたときの HUD の扱いは `SPEC-HUD-001` にある。

出力は英語だけで、ロケールやアプリの表示言語で変わらない。文言の正本は CLI のコードにあり、String Catalog は使わない（`DEC-CLI-003`）。ここでは何を伝えるか、記号、出力先を定め、出力の文言の例は `DEC-CLI-003` を参照する。

受け入れ例の共通の前提は、`specs/blocking.md` の「受け入れ例の共通の前提」にある。

## SPEC-CLI-001 capsaicin on

関連要件: `REQ-CLI-001`、`REQ-BLK-015`

```text
capsaicin on [--for <時間> | --until <時刻> | --no-time-limit]
```

抑止の開始を要求する。オプションがなければ指定のない開始、あれば時間の指定のある開始になる（`SPEC-BLK-003`）。抑止中にオプションを指定した `on` は、解除の時刻を置き換える。オプションのない `on` を含む、現在の状態ごとの結果は `SPEC-BLK-011`、出力と終了コードは `SPEC-CLI-007` にある。

- `--for <時間>`: `<時間>h`、`<分>m`、`<時間>h<分>m` のどれか。正規表現 `^([0-9]+h)?([0-9]+m)?$` に一致し、`h` と `m` の少なくとも一方を含むものだけを受け付ける。小数、単位の重複（`1h1h`）、順序の逆（`30m1h`）、単位のない数字、空白を含むものは拒む。長さがタイマーの範囲（`SPEC-SET-002`）に収まらなければ拒む。
- `--until <時刻>`: `H:MM` か `HH:MM`。時は 0〜23、分は 00〜59 の2桁。解除の時刻は `SPEC-BLK-005` で決まる。
- `--no-time-limit`: 値を取らず、時間の条件なしを指定する。停止中なら設定のタイマーと指定時刻を使わずに開始し、抑止中なら解除の時刻をなくす。バッテリー残量の条件は `SPEC-BLK-003` に従う。
- `--for`、`--until`、`--no-time-limit` のどの2つを同時に指定しても拒む。同じオプションを2回指定したとき（`--for 1h --for 2h`、`--no-time-limit --no-time-limit`）も拒む。

拒んだときは、使い方の誤りとして失敗する（`SPEC-CLI-007`）。

### 受け入れ例: 時刻を指定する

1. 23:00 に、停止中で、バッテリー残量をオフにした状態にする。
2. `capsaicin on --until 4:00` を実行する。
3. 終了コードは 0 で、状態が「抑止中」になり、翌日の 4:00 に解除される。

### 受け入れ例: 時間を指定する

1. 停止中で、設定の指定時刻を 10 分後にしてオンにし、バッテリー残量をオフにした状態にする。
2. `capsaicin on --for 1h30m` を実行する。
3. 10 分後には解除されず、1 時間 30 分後に解除される。

### 受け入れ例: 書式の誤り

1. 停止中の状態にする。
2. `capsaicin on` に、`--for 30m --until 4:00`、`--for 30m --no-time-limit`、`--no-time-limit --until 4:00`、`--no-time-limit 1h`、`--for 1h --for 2h`、`--until 4:00 --until 5:00`、`--no-time-limit --no-time-limit`、`--for 0m`、`--for 25h`、`--for 1.5h`、`--for 30m1h`、`--for 90`、`--until 4:5`、`--until 24:00` をそれぞれ付けて実行する。
3. どれも終了コード 64 で失敗し、標準エラー出力に理由が出て、抑止は開始されない。

### 受け入れ例: 抑止中の時間と時刻の指定

1. 13:00 にタイマーを 1 時間にして抑止を開始する。
2. 13:10 に `capsaicin on --for 30m`、13:20 に `capsaicin on --until 15:00` を実行する。
3. どちらも終了コードは 0 で、置き換えたことと解除の時刻が標準出力に出る。1回目は 13:40、2回目は 15:00 に置き換わり、抑止は途切れず 15:00 に解除される。HUD は表示されない。

### 受け入れ例: 時間の条件なしで開始する

1. 停止中で、設定のタイマーを 15 分、指定時刻を 30 分後にして両方をオンにする。バッテリー残量の条件はオフにする。
2. `capsaicin on --no-time-limit` を実行する。
3. 終了コードは 0 で、解除の時刻を持たずに抑止を開始し、30 分後も続く。設定のタイマーと指定時刻は変わらない。

### 受け入れ例: 抑止中の時間の条件をなくす

1. 「バッテリー残量が少ないときに自動解除」をオフにし、`capsaicin on --for 15m` で抑止を開始して5分待つ。
2. `capsaicin on --no-time-limit` を実行する。
3. 終了コードは 0 で、解除の時刻がなくなる。抑止は途切れず、開始から 15 分後も続く。HUD は表示されない。

## SPEC-CLI-002 capsaicin off

関連要件: `REQ-CLI-002`

```text
capsaicin off
```

抑止の解除を要求する。現在の状態ごとの結果は `SPEC-BLK-011` にある。

### 受け入れ例

1. 抑止中の状態にする。
2. `capsaicin off` を実行する。
3. 終了コードは 0 で、状態が「停止中」になる。

## SPEC-CLI-003 capsaicin status

関連要件: `REQ-CLI-003`

```text
capsaicin status
```

1行目で抑止中か停止中かを示し、抑止中なら続く行で解除の条件を示す。結果の記号と出力先は `SPEC-CLI-007` に従う。

解除の条件は、字下げしたラベル付きの行で示す。抑止中の `on` の結果にも同じ形を使う（`DEC-CLI-003`）。

- 時間の条件は必ず示す。解除の時刻があれば、ローカルのタイムゾーンの24時間制（`H:mm`）と残り時間を出す。残り時間の丸めは `SPEC-MENU-004` と同じく分の単位に切り捨て、1分未満ならそのことを示す。解除の時刻がなければ、自分でオフにするまで続くことを示す。
- バッテリー残量の条件は、有効なときだけ示す。しきい値と、電源アダプター接続中は残量で解除しない設定を伝える。

警告の対象は `SPEC-CLI-007` に従う。終了コードは、警告の有無によらず、抑止の状態だけで決める。

### 受け入れ例: 抑止中と停止中の状態を確かめる

1. タイマーを 1 時間にして抑止を開始する。
2. `capsaicin status` を実行し、続けて `capsaicin off` の後にもう一度実行する。
3. 1回目は標準出力に抑止中であることと、続く行にローカル時刻と残り時間を含む解除の条件が出て、終了コードは 0 になる。2回目は停止中であることが出て、解除の条件の行はなく、終了コードは 1 になる。

### 受け入れ例: 警告と状態を分ける

1. 試験用の環境で、停止中で合わせられていない制御がある状態を用意する。
2. `capsaicin status` を実行する。
3. 標準出力には停止中であること、標準エラー出力には警告が出る。終了コードは 1 になる。

### 受け入れ例: 輝度の記録の警告があっても抑止の状態を返す

1. 試験用の環境で、抑止中に輝度の記録の保存に失敗した状態と、抑止を解除した後に記録を削除できずにいる状態を用意する。
2. それぞれで `capsaicin status` を実行する。
3. 前者は抑止中と解除の条件を標準出力に、保存の警告を標準エラー出力に出し、終了コードは 0 になる。後者は停止中を標準出力に、削除の警告を標準エラー出力に出し、終了コードは 1 になる。

## SPEC-CLI-004 アプリの起動

関連要件: `REQ-CLI-004`

アプリが起動していないときに、`on`、`off`、`status` の要求を実行したら、CLI は自分を含む `.app` の起動を求め、接続できるまで期限付きで待ってから処理する。期限までに接続できなければ失敗する（`SPEC-CLI-007`）。ヘルプは `SPEC-CLI-008` に従い、アプリを起動しない。

### 受け入れ例

1. アプリを終了しておく。
2. `capsaicin on` を実行する。
3. その CLI を含む `.app` が起動し、状態が「抑止中」になる。

## SPEC-CLI-005 CLI からの操作を受け付けるかの設定

関連要件: `REQ-CLI-005`

設定の「CLIからの操作を許可」がオフのとき、アプリは CLI からの要求を拒み、CLI は理由を表示して失敗する（`SPEC-CLI-007`）。コマンド自体はアプリの中に残る。

### 受け入れ例

1. 「CLIからの操作を許可」をオフにし、抑止中にする。
2. `capsaicin off` を実行する。
3. 終了コード 69 で失敗し、標準エラー出力に理由が出て、状態は「抑止中」のままである。

## SPEC-CLI-006 コマンドの場所

関連要件: `REQ-CLI-006`

設定の「操作」セクションの「コマンドの場所」に、実行中のアプリのバンドルから組み立てた `capsaicin` のパス（例: `/Applications/Capsaicin.app/Contents/Helpers/capsaicin`）を表示する。

- 文字は `.body` と `secondaryLabelColor`。1行に収まらないときは中央を省略し、ツールチップに全体を出す。選択してコピーできる。
- 行の右端に、アイコンだけのコピーのボタン（`doc.on.doc`、`.borderless`）を置く。押すとパスをクリップボードに入れ、シンボルを 1.5 秒だけ `checkmark` に置き換えて戻す。「視差効果を減らす」がオンなら瞬時に切り替える。同時に、コピーしたことを VoiceOver で読み上げる。
- この行は「CLIからの操作を許可」がオフでも有効のままにする。
- アプリはシンボリックリンクを作らず、そのための管理者権限も求めない。

### 受け入れ例

1. アプリを `/Applications` に置いて起動し、設定の「操作」を開く。
2. コピーのボタンを押し、ターミナルに貼り付けて `status` を付けて実行する。
3. ボタンが一時的に `checkmark` になり、貼り付けたパスで `capsaicin status` が動く。

## SPEC-CLI-007 出力と終了コード

関連要件: `REQ-CLI-001`、`REQ-CLI-002`、`REQ-CLI-003`、`REQ-CLI-005`、`REQ-BLK-015`

結果と状態は標準出力、警告とエラーは標準エラー出力に出す。終了コードは `sysexits.h` に従う。

結果と状態の1行目には、次の記号を付ける。抑止中なら、続く行で解除の条件を示す（`SPEC-CLI-003`）。

| 結果・状態 | 記号 |
| --- | --- |
| 開始、解除、解除の時刻の置き換えで状態を変えた | `✓` |
| すでに抑止中、または停止中で状態を変えなかった | `•` |
| `status` で抑止中 | `●` |
| `status` で停止中 | `○` |

抑止中にオプションを指定した `on` は、解除の時刻を置き換えたことを伝え、終了コードを 0 にする（`SPEC-CLI-001`）。抑止中にオプションのない `on` を実行したときは、すでに抑止中であることと、`--for`、`--until`、`--no-time-limit` で解除の時刻を変えられることを伝える。

警告は `warning: `、エラーは `error: ` で始める。使い方の誤りでは、理由に続けて `--help` を案内する行を出す。引数がないときも使い方の誤りになる。

`off` で合わせられていない制御が残ったときは、結果を標準出力、警告を標準エラー出力に出し、終了コードを 69 にする。開始の拒否、CLI からの操作を受け付けない設定、接続の失敗では、標準出力には何も出さず、標準エラー出力にエラーを出す。アプリから応答を受け取った場合は、警告があればエラーに続けて出す。

`on`、`off`、`status` の警告の対象は、合わせられていない制御（`SPEC-BLK-007`）と、輝度の記録の保存・削除の失敗（`SPEC-BLK-013`）である。輝度の記録の警告では、保存に失敗したのか、削除できていないのかを伝える。この警告だけを理由に、`on` や `off` の終了コードを 69 にしない。

色は、出力先が端末で、`NO_COLOR` が空でない値で設定されておらず、`TERM` が `dumb` でないときだけ付ける。標準出力と標準エラー出力で別々に判定する（`DEC-CLI-003`）。

| 状況 | 終了コード |
| --- | --- |
| 成功。状態を変えなかった場合（`SPEC-BLK-011`）を含む。`on` で開始できたときは、合わせられていない制御が残っていても 0。`status` は抑止中（合わせられていない制御の有無によらない） | 0 |
| `status` で停止中（合わせられていない制御の有無によらない） | 1 |
| 使い方の誤り（不明なサブコマンド、`SPEC-CLI-001` で拒んだ書式） | 64（`EX_USAGE`） |
| 要求を完了できなかった。アプリに接続できない、CLI からの操作を受け付けない設定で拒まれた、開始を拒否した（`SPEC-BLK-010`）、`off` の要求で合わせられていない制御が残った（`SPEC-BLK-007`、`SPEC-BLK-011`） | 69（`EX_UNAVAILABLE`） |

### 受け入れ例: バッテリー残量で開始を拒否する

1. 「バッテリー残量が少ないときに自動解除」をオン、しきい値を 20%、「電源アダプタ接続中は自動解除しない」をオフにし、残量が 20% を下回った状態で電源アダプターを外す。
2. `capsaicin on` を実行する。
3. 終了コード 69 で失敗し、標準エラー出力に、開始できないことと、バッテリー残量が理由であることが出る。

### 受け入れ例: 輝度の記録の保存の失敗だけなら成功を返す

1. 試験用の環境で「ディスプレイを閉じたとき」を「明るさを0」にし、輝度の記録の保存だけを失敗させる。
2. 停止中から `capsaicin on` を実行し、閉じた通知を送る。その後、`capsaicin on`、`capsaicin off` の順に実行する。
3. 最初の `on` で抑止が開始する。2回目の `on` はすでに抑止中であること、`off` は解除したことを標準出力に出す。保存の警告は 2回目の `on` だけで標準エラー出力に出る。終了コードはいずれも 0 になる。

### 受け入れ例: 輝度の記録の削除に失敗しても解除は成功を返す

1. 試験用の環境でディスプレイを閉じて輝度を 0 にした状態を作り、記録の削除だけを失敗させる。
2. `capsaicin off` を実行する。
3. 解除したことを標準出力に、削除の警告を標準エラー出力に出す。終了コードは 0 になる。

## SPEC-CLI-008 ヘルプ

関連要件: `REQ-CLI-007`

`-h` か `--help` が引数のどこかにあれば、ほかの引数によらず、説明、書式、サブコマンド、`on` のオプション、終了コードを標準出力に出し、終了コード 0 で終わる。アプリには接続せず、アプリを起動しない。`.app` の外に置いたコマンドのコピーでも出す。引数がないときは、`SPEC-CLI-007` の使い方の誤りになる。

### 受け入れ例: アプリを起動せずに使い方を確かめる

1. アプリを終了しておく。
2. `capsaicin --help` と `capsaicin -h` を実行する。
3. どちらも標準出力に使い方が出て、終了コードは 0 になる。アプリは起動しない。

### 受け入れ例: ほかの引数やアプリの場所によらず表示する

1. アプリを終了し、コマンドのコピーを `.app` の外に置く。
2. そのコピーで `on --for x --help` を実行する。
3. 不正な時間の指定によらず標準出力にヘルプが出て、終了コードは 0 になる。アプリは起動しない。
