# EVID-LED-013 接続の通知の後に1秒ごとに書き直すと、抑止中に接続したキーボードが点灯した

## 確かめた事実

`fa6cae8:docs/manual/led-fix-verification.md` の手順0と、手順2の操作1〜3を行った。Capsaicin は、接続・切断の通知でその場で書き、その後1秒ごとに5回書き直す版である。LED はオーナーの目視による。

抑止中に Lofree を接続すると、2.4 GHz と Bluetooth のどちらでも、Lofree の LED が10秒以内に点灯した。書き込みの失敗はなかった。

| 接続 | 通知による書き込み | Lofree のサービスが対象に入った書き込み | 追いかけの書き込み |
| --- | --- | --- | --- |
| 2.4 GHz | 14:15:24.695 と 14:15:24.716 | `0x1000474bc` は 14:15:24.716、`0x1000474c3` は 14:15:25.714 | 14:15:25.714 から 14:15:29.712 までの5回 |
| Bluetooth | 14:17:00.073 | `0x1000475ac` は 14:17:01.087 | 14:17:01.087 から 14:17:05.091 までの5回 |

- 2.4 GHz のレシーバーの2つのサービスのうち、`0x1000474c3` は、通知による書き込みの対象に入らず、1回目の追いかけで初めて入った。Bluetooth の `0x1000475ac` も同じである。通知による書き込みだけでは、どちらも対象に入らなかった（`EVID-LED-011` と同じ）。
- 接続の後の `ioreg` では、レシーバーの2つのサービスと、Bluetooth のサービスの `HIDCapsLockLED` が `"On"` だった。
- レシーバーを外したとき（14:16:39）も、通知による書き込みが2回と、追いかけが5回あった。
- 抑止を始めたとき（14:13:29、14:13:50）は、続けて3回書き、その後に追いかけが5回あった。
- 通知がない間は書かなかった。14:13:55 の追いかけの終わりから、14:15:24 の接続まで、書き込みはなかった。
- 解除（14:17:22）では、Bluetooth のサービスを含む対象に `"Auto"` を書き、失敗はなかった。HUD は通常のオフの表示だった。
- 14:12〜14:17 の1分ごとの記録で、Capsaicin の RSS は抑止の開始後 136 MB 前後で変わらず、CPU は抑止を始めた直後の1回（3.4%）を除いて 0.0% だった。

## 確かめ方

手順は `fa6cae8:docs/manual/led-fix-verification.md` の手順0と手順2。書き込みの時刻と対象はアプリのログの `LED 書き込み` の行を読み、登録 ID は手順2で保存した、2台のキーボードのサービスごとの LED の状態の一覧と照らした。

## 適用範囲

- 接続の通知の後に1秒ごとに書き直せば、抑止中に接続したキーボードが点灯することの根拠に使ってよい。
- 通知がない間は書き直さないことの根拠に使ってよい。
- この1台の Lofree での、接続方式ごとに1回ずつの結果である。サービスが一覧に入るまで5秒を超える機器があるかの根拠には使えない。

## 未確認のこと

- 2.4 GHz のレシーバーで、点灯に `0x1000474c3` への書き込みだけが要るのか、両方が要るのか。
- USB で接続した場合。今回は試していない。
- 追いかけの途中で抑止を解除したとき、実機で書き込みが止まること。今回は、追いかけが終わってから解除した。テストでは確かめている。
