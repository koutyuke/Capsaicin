# EVID-SYS-004 抑止中にインストールを確認で取り消すと Sparkle の画面が閉じ、同じ版をダウンロードし直さずに再び選べ、終了時にインストールされた

## 確かめた事実

ブランチ `feature/sparkle-install-dismiss` の `75baafa` のコードでビルドした2つの版で確かめた。

- 取り消し: 抑止中に「インストールして再起動」を押し、抑止の解除の確認で取り消すと、Sparkle の画面が閉じた。アプリは終了せず（PID は変わらなかった）、抑止は続いた。「このアプリについて」の行とメニューに 0.9.1 が出た（オーナーの目視）。
- 再び選ぶ: 行のボタンをもう一度押すと、同じ版がインストールできる状態で示された。配信のサーバーの記録では、この間の zip の取得は最初の1回だけだった。
- 抑止の解除の後: 抑止を解除し、設定ウインドウを閉じて1分待っても、インストールされなかった（オーナーの目視）。
- 続けた場合: 確認で続けると、0.9.1 がインストールされ、launchd の管理下で1つだけ起動し直した。ジョブの実行ファイルのパスは入れ替え前と同じだった。
- 終了時: 0.9.0 に戻してやり直し、抑止中に確認で取り消した後、メニューの「終了」で終了した。アプリは起動し直さず、ジョブは `state = not running`、`last exit code = 0` だった。バンドルは 0.9.1 に入れ替わり、`codesign --verify --deep --strict` が通った。`SleepDisabled` は 0 だった。

## 確かめ方

`ac1897d` の `scripts/manual/update-test.sh` を作業用に写し、リポジトリのルートだけを書き換えて使った。使い捨ての鍵で 0.9.0 と 0.9.1 の Debug ビルドと署名した appcast を作り、`127.0.0.1:8123` から配った。アプリの起動と終了、ジョブの読み取りは、オーナーの承認を得てエージェントが行い（`DEC-SYS-024`）、Sparkle の画面と確認の操作はオーナーが行った。終わった後、作業先と鍵を片付けた。

## 適用範囲

- 使ってよい: Sparkle 2.10.1 で、準備済みの版に Dismiss を返した後の振る舞いと、`DEC-LCY-007` の取り消しの流れを判断するとき。
- 使ってはいけない: 自動アップデートを「ダウンロードしてインストール」にした場合、別の版の Sparkle、Developer ID で署名した Release 構成のビルド。

## 未確認のこと

- 「ダウンロードしてインストール」を選んでいるときに、取り消した版が次の定期の確認で自動のインストールとして扱われるか（`DEC-LCY-007` の影響に書いた推論）。
- 取り消した後の画面の状態は、オーナーの目視だけで、画面写真は残していない。
