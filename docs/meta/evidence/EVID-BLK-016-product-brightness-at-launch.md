# EVID-BLK-016 製品のビルドで暗くした後にアプリを SIGKILL で終了させ、手で起動すると、輝度が 0 のときだけ記録した値に戻し、どちらの場合も記録を消した

## 確かめた事実

「ディスプレイを閉じたとき」を「明るさを0」、「ディスプレイを自動でオフにしない」をオンにして抑止し、ディスプレイを閉じて内蔵ディスプレイの輝度が 0 になったことを読んでから、アプリに `kill -9` を送った。起動直前の輝度を変えて2回試した。輝度はアプリと同じ `DisplayServicesGetBrightness` で読んだ。

| 試行 | 閉じる前 | 記録（`savedBrightness`） | 閉じている間 | 開けた直後 | 起動の直前 | 起動の後 |
| --- | --- | --- | --- | --- | --- | --- |
| 起動の直前が 0 より大きい | 1.0 | 0.7801 | 0 | 1.0 | 1.0 | 1.0 |
| 起動の直前が 0 | 1.0 | 0.6322 | 0 | 0.9727 | 0 | 0.6322 |

- 起動の直前が 0 より大きいときは、輝度を書かなかった。起動の直前が 0 のときは、記録した値を書いた。
- どちらも、起動の後に `resume-record.json` はなくなり、抑止は再開しなかった。終了の後は `SleepDisabled 0` だった。

## 確かめ方

`docs/manual/verification/brightness-at-launch.md`（`fa4bc85`）の手順で、閉じた状態と輝度 0 を読んでから強制終了し、各時点の輝度と記録を読んだ。起動の直前の輝度 0 は、オーナーが輝度のキーで下げて作った。

## 適用範囲

製品の実装で、暗くした後にアプリが後片付けなしで終了し、利用者が手で起動した場合に当てはまる。

## 未確認のこと

- 記録した値が、閉じる前に読んだ輝度（1.0）と違った（0.7801、0.6322）。記録した時点の輝度は読んでいない。「輝度を自動調節」が働き、閉じていく間に光センサーが覆われて輝度を下げた後に記録した、と考えるのが自然である。開けた直後にアプリが輝度を書いていないのに 1.0 と 0.9727 に上がったことと、閉じていく間に自動調節が輝度を下げた記録（`EVID-BLK-012`）がこれに合う。ただし、試行の間に「輝度を自動調節」がオンだったかは記録していない。
- 記録を保存できなかったときに暗くせず警告を出すこと。既存のデータを壊さずに実機で起こせないので、単体テストだけで確かめている。
