# EVID-BLK-010 蓋が閉じた通知で輝度を 0 にすると、閉じている間は 0 のままで、開いた通知で元の輝度に戻せた

## 確かめた事実

`e9e7e3d:docs/manual/lid-close-dimming-verification.md` の C3 のうち、自動輝度調節がオフの回を行った。C4 も同じ補助（`watch --dim`）で行ったので、その記録も合わせて読んだ。補助は一般ユーザーの権限で動き、蓋が閉じた通知で輝度を覚えてから 0 にし、開いた通知で覚えた輝度に戻す。

| 回 | 閉じていた区間 | 閉じている間の読み取り | 開けた後 |
| --- | --- | --- | --- |
| C3 | 14:52:59〜14:56:49（3分50秒） | 22回すべて `brightness=0.0`、`CGDisplayIsAsleep=0` | 復元先 `0.4492228` に対し `0.44922277`。1分後まで変わらなかった |
| C4 | 15:00:32〜15:11:46（11分14秒） | 67回すべて `brightness=0.0`、`CGDisplayIsAsleep=0` | 復元先 `0.44922277` に対し `0.44922274` |

- 閉じている間に、輝度が 0 から変わったことはなかった。
- 開けた直後に、画面が閉じる前と同じくらいの明るさに戻ったことを、オーナーが目で確かめた（C3）。
- 開閉の通知は、C2〜C4 の8回の開閉のすべてで、閉じた通知と開いた通知の両方が届いた。10秒ごとの読み取りで、通知より先に蓋の新しい状態が読めたことはなかった。C3 で閉じたときは、同じ秒の読み取りが開いた状態を示し、その直後に閉じた通知が届いた。
- 書いた値と読み戻した値は、小数点以下8桁目で食い違った（`0.4492228` と `0.44922277`）。

時刻は日本時間である。

## 確かめ方

手順は `e9e7e3d:docs/manual/lid-close-dimming-verification.md` の準備、C3 の操作1〜3、C4 の操作1〜3。記録は `~/Capsaicin-dimming.B7nQAG/` にある。各ログの `event=close` と `event=open` の行と、その間の `timer` の行を読んだ。開閉の操作を別の時計で秒まで控えていないので、蓋を動かしてから通知が届くまでの遅れは測っていない。

## 適用範囲

- 自動輝度調節がオフのとき、閉じている間に DisplayServices で設定した輝度 0 が macOS に上書きされず、開いたときに元の輝度に戻せることの根拠に使ってよい。
- 一般ユーザーの権限で動くプロセスが、蓋閉じスリープを止めた状態で、閉じた通知と開いた通知の両方を受け取れることの根拠に使ってよい。
- 読み戻しの値は書いた値と完全には一致しない。比べるときは許容幅を置く。
