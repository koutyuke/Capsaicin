# DEC-SYS-008 テストは偽物に差し替えて行い、永続的なシステム変更はビルドとテストで行わない

## 結論

- 単体テストは Swift Testing で書く。副作用のある処理はプロトコルの後ろに置き、テストでは偽物（fake）に差し替える。時刻、暦、タイムゾーンは注入する。
- 画面は、アプリを起動せず、ビューを画像に描画して確かめる（ライトとダーク）。
- 永続的なシステム変更（ヘルパー、sudoers、LaunchAgent・LaunchDaemon の登録、`pmset` の設定）は、ビルドとテストで行わない。実機での確認は、手順を書いてオーナーの承認を得て行う。
- Debug ビルドは、bundle ID、ソケット、launchd のラベルに `.debug` を付け、本番の設定と衝突させない。

## 背景

Capsaicin の主な機能は、スリープの設定や root の処理など、システムを永続的に変える。テストのたびにそれを行うと、開発者の Mac にスリープできない状態や不要な設定を残す。

## 選択肢

- 実機のシステムを変えて自動テストする。開発者の Mac の状態を壊しうる（不採用）。
- 偽物に差し替えて自動テストし、実機での確認は承認を得て手で行う（採用）。

## 理由

自動テストを安全に何度でも実行でき、システムを変える確認だけを、承認と元に戻す手順を伴って行えるため。

## 影響

- 仕様の受け入れ例のうち、システムを変えるものは、承認を得た実機で手で確かめる。
- 偽物と実物の挙動の差は、実機での確認で見つける。

## 覆す条件

- システムを変える確認を安全に自動化できる環境（使い捨ての仮想マシンなど）が用意できたら見直す。
