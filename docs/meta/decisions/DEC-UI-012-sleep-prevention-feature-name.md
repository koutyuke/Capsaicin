# DEC-UI-012 機能名を「スリープ防止」とし、止めるものを「システムスリープ」「ディスプレイスリープ」と書く

## 結論

画面に出す日本語の文言を、次の規則で書く。

### 機能名と切り替え

- スリープを止める機能の名前を「スリープ防止」とする。メニュー、HUD、CLI、設定の項目名で同じ名前を使う。
- 切り替えは「スリープ防止をオンにする」「スリープ防止をオフにする」、状態は「スリープ防止中」と書く。文脈から対象が分かる場所では「オン」「オフ」だけでよい（「時間を指定してオン」「4:00にオフ」）。
- メニューの開始と解除の項目は、状態に応じて項目名を入れ替える。チェックマークでは表さない。
- 利用者の操作で切ることを「停止する」「解除する」とは書かない。自動でオフにする条件をまとめて呼ぶときは「スリープ防止の自動解除」と書く（設定のグループ見出しなど）。
- 設定画面の (i) で、スリープ防止がオンの間のことを書くときは「スリープ防止中は」で始める。

### 止めるもの

| 指すもの | 書き方 |
| --- | --- |
| Mac 全体のスリープ | システムスリープ |
| Mac を動かしたまま、ディスプレイだけがスリープすること | ディスプレイスリープ |
| ディスプレイをスリープさせず、輝度を 0 にすること | 明るさを0（追加の判断は `DEC-BLK-007`） |

- 設定の項目名は、項目が何をするかを「〜させない」「〜しない」の形で書く。「防ぐ」「制限」「抑止」は項目名に使わない。
- 「手動スリープ」は画面に出さない。アップルメニューの「スリープ」などの操作で書く。

### そのほかの言い方

- 装置としての画面と、その状態（スリープ、閉じる、明るさ）は「ディスプレイ」と書く。「画面」は、設定画面、ロック画面のような表示の内容や機能を指すときだけに使う。
- ノートブックの蓋と、それを閉じる操作は「ディスプレイ」「ディスプレイを閉じる」と書く。「蓋」は画面に出さない。
- 「消灯」「点灯」は Caps Lock の LED だけに使う。ディスプレイが暗くなることは「ディスプレイスリープ」と書く。
- macOS の日本語 UI に同じ語があれば、その表記に合わせる。「スクリーンセーバ」「電源アダプタ」は語尾を伸ばさない。

文書の中の呼び名（`specs/blocking.md` の「抑止」「手動スリープ」など）は、この判断の対象にしない。

## 背景

`DEC-UI-011` は、スリープとディスプレイを macOS のシステム設定と同じ言葉（「スリープ」「ディスプレイをオフにする」）で書き、アプリ自身の動作を「防止」と書かないことにしていた。機能名「スリープ防止」をどうするかは論点として残っていた。

オーナーは、開始の文言の候補として「Capsaicinをオンにする」「スリープを防止する」「セッションを開始する」を挙げ、それまでの制約を外して、日本語としての自然さと、機能が分かるかどうかで比べ直した。そのうえで用語の規則を見直し、止めるものを「システムスリープ」「ディスプレイスリープ」と書くこと、項目名は「〜させない」の形を保つこと、自動でオフにする条件の見出しを「スリープ防止の自動解除」とすることを選んだ。

macOS 26 のシステム設定の日本語 UI は、ディスプレイスリープを「ディスプレイをオフにする」、スクリーンセーバを「スクリーンセーバ」、電源アダプタを「電源アダプタ」と書く（開発機の `/System/Library/ExtensionKit/Extensions/LockScreen.appex` と `BatterySettingsIntentsExtension.appex` の `Localizable.loctable`、2026-11-13 に確認）。

## 選択肢

機能の呼び方:

- 「スリープ防止」をオン／オフで切り替える（採用）。
- 「Capsaicinをオンにする」。オン／オフの対はそろうが、文言だけでは何がオンになるのかが分からない。常駐しているアプリを起動する意味にも読める。
- 「セッションを開始する」。何のセッションかが分からない。複数の条件を束ねる単位を持たない Capsaicin では、覚える概念が増えるだけになる。

解除の書き方:

- 「スリープ防止をオフにする」（採用）。
- 「スリープ防止を停止する」。「防止」と「停止」が形の似た打ち消しの語で重なり、スリープするのかしないのかを読み解く手間が増える。
- 「通常のスリープに戻す」。結果は分かるが、開始と文型がそろわず、HUD や自動解除の設定と言葉がつながらない。

メニューの形:

- 項目名を入れ替える（採用）。
- 「スリープ防止」の1項目にチェックマークを付ける。解除の文言は要らなくなるが、開始の項目の副題（開始したら使う解除条件）が、チェックのない項目の下では今の状態の説明に見える。

止めるものの呼び方:

- 「システムスリープ」「ディスプレイスリープ」（採用）。
- macOS のシステム設定に合わせて「スリープ」「ディスプレイをオフにする」と書く（`DEC-UI-011`）。システム設定と見比べやすいが、「オフにする」がスリープ防止のオン・オフと同じ言葉になる。

自動でオフにする条件の見出し:

- 「スリープ防止の自動解除」（採用）。
- 「スリープ防止を自動でオフにする」。メニューや HUD のオン・オフとそろうが、オーナーは見出しとして「スリープ防止の自動解除」を選んだ。

## 理由

- 3つの機能名の候補のうち、文言だけで何が起きるかが分かるのは「スリープ防止」だけである。この種のアプリを指す言葉としても通じる。
- 「スリープ防止」を機能名として扱えば、解除は機能のスイッチを切る表現になり、開始と対になる。抑止中は見出しに「スリープ防止中」と出るので、「オフにする」を読み違えにくい。
- 「システムスリープ」と「ディスプレイスリープ」は、名前だけで止まるもの（Mac 全体か、ディスプレイだけか）が分かる。「オフにする」をスリープ防止の切り替えだけに使えるので、同じ言葉が2つの意味を持たない。

## 影響

- メニュー、HUD、CLI、設定の項目名にある「スリープ防止」は、そのまま使う。
- 設定画面のセクション名「スリープ」（`DEC-SET-005`）は変えない。
- String Catalog のうち、この判断と合わない文言（「ディスプレイをオフ」、ディスプレイについての「消灯」、「スクリーンセーバー」、装置を指す「画面」、「Capsaicinがオンの間は」で始まる (i) など）を直す。
- macOS のシステム設定とは、ディスプレイスリープの言い方が違う。

## 覆す条件

- 「スリープ防止をオフにする」を、スリープしなくなる意味に読み違えたという報告が続く。
- 「システムスリープ」「ディスプレイスリープ」の意味が分からないという報告が続く。
- macOS の日本語 UI が、スリープとディスプレイについて別の言い方に変わる。
