# DEC-SYS-009 ソースを MIT ライセンスで GitHub に公開する

## 結論

リポジトリを GitHub の公開リポジトリにし、ソースを MIT ライセンスで公開する。著作権者の表記は GitHub のアカウント名 `koutyuke` とする。公開するのは `main` ブランチだけで、作業用のブランチやツールのチェックポイントの参照は公開しない。配布物の置き場所は `DEC-SYS-004` のとおり GitHub Releases か自前の Homebrew tap とし、この判断では変えない。

## 背景

将来ほかの人に無料で配る可能性がある（`docs/product/overview.md`）。配るアプリは公証せず（`DEC-SYS-004`）、root で動くヘルパーと sudoers のルールを利用者の Mac に設置する（`DEC-HLP-001`）。利用者には、公証されていないアプリを「このまま開く」で開き、管理者のパスワードを入力してもらうことになる。有料販売は非目標である。

## 選択肢

- 非公開のまま、配布物だけを配る。利用者はヘルパーが何をするかを確かめられない。非公開リポジトリの Releases は外部からダウンロードできないので、配布用の置き場所が別に要る。非公開リポジトリの GitHub Actions は無料枠を超えると課金される（不採用）。
- ソースを公開するが、OSS のライセンスを付けない。読めるが、利用者は改変したものを配れず、手を入れてもらう余地もない（不採用）。
- ソースを MIT ライセンスで公開する（採用）。
- ソースを GPL などのコピーレフトのライセンスで公開する。派生物にソースの公開を求められるが、守りたい独自の技術や収益がないので、条件を増やす利点がない（不採用）。

## 理由

- 利用者がヘルパーの受け付ける処理（`SPEC-HLP-002`）を読み、自分でビルドして使えるようになる。公証しないことによる信用の不足を、ソースを読めることで補える。
- `DEC-SYS-004` の配布手段（GitHub Releases、自前の Homebrew tap）を、公開リポジトリのままで使える。
- 依存する KeyboardShortcuts（`DEC-KEY-002`）と、リポジトリに含めるエージェントのスキルの取得元（emilkowalski/skills）がどちらも MIT で、条件が揃う。

## 影響

- リポジトリの直下に `LICENSE` を置く。
- リポジトリに第三者の著作物を含めるときは、取得元のライセンスが再配布を許すことを確かめ、著作権表示とライセンス文を `THIRD_PARTY_NOTICES.md` にまとめる。外部のスキルは追跡しないので（`AGENTS.md`）、いまは含めるものがない。
- 公開後の履歴は消せない前提で扱う。秘密情報や個人の情報をコミットしないこと（`AGENTS.md`）が、公開の前提になる。
- 配布物にアプリを入れる場合は、KeyboardShortcuts のライセンス表示をアプリに含める（`DEC-KEY-002`）。
- 第三者からの Issue や Pull Request を受け付けるかは、この判断では決めない。

## 覆す条件

- 収益化や、他人に改変させたくない理由が生じたら、ライセンスを見直す。公開済みの版の MIT ライセンスは取り消せない。
- 依存やリポジトリに含める著作物に、MIT と両立しないライセンスのものを入れる必要が生じたら見直す。
