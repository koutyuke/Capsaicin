# DEC-SET-005 セクション名を「スリープ」にし、ディスプレイを閉じたときの動作を1つのポップアップにまとめ、(i) は項目名から分からない制約にだけ置く

## 結論

`DEC-SET-004` のうち、次を改める。ほかの決定（2つのグループ、カードとアイコン、子の行の字下げ、スクロールを許すこと）はそのまま引き継ぐ。

- セクション名を「スリープ」にする。グループの見出しは「スリープとディスプレイ」と「自動でオフにする」にする。
- MacBook では、「ディスプレイを閉じてもスリープさせない」のスイッチと子の「閉じたときのディスプレイ」を、1つのポップアップ「ディスプレイを閉じたとき」にまとめる。選択肢は「スリープ（標準）」「ディスプレイをオフ」「オンのまま」の3つにする。「明るさを0」は、のちに `DEC-BLK-007` で加えた。
  - 「スリープ」は手動スリープの保存値（`blocksManualSleep`）をオフにする。「ディスプレイをオフ」と「オンのまま」は手動スリープの保存値をオンにし、閉じたときのディスプレイの保存値（`lidCloseDisplay`）をそれぞれ `turnOff`、`keepOn` にする。保存の形は変えない。
  - MacBook 以外の Mac は、今のスイッチ「メニューから選んでもスリープさせない」のままにする。
- (i) は、項目名から分からない連動や制約（一緒に止まるもの、OS の仕組みで個別に設定できないこと、ヘルパーと管理者パスワードが要ること、過ぎた時刻が翌日になること）がある行にだけ置く。親のスイッチがオフで子の行が無効になっていることや、項目名の言い換えだけの説明には置かない。

## 背景

オーナーから2つの指摘があった。1つは、スイッチとポップアップの組み合わせで選べる状態は実際には3通りしかなく、1つのポップアップで選ぶほうが分かりやすいということ。もう1つは、スリープのページの (i) が多く、そもそも説明が必要かを考え直したいということである。

`DEC-SET-004` は、ポップアップ1つにまとめる案を、閉じたときの状態の選択肢が増えるたびに組み合わせが増えるとして退けていた。実際には「スリープ」の1つと、スリープしないときのディスプレイの状態の数だけなので、選択肢は状態が1つ増えるごとに1つ増えるだけである。

(i) の要否は、独立した2人のアドバイザー（Gemini と Codex）に別々に検討を頼み、2人とも、親がオフのために子が無効になる理由の説明と、項目名の言い換えは要らないという結論を出した。

## 選択肢

ディスプレイを閉じたときの行の形:

- スイッチと子のポップアップに分けたままにする。親がオフのときに子を無効にする表示と、その理由の (i) が要る。
- 3択のポップアップ1つにまとめる（採用）。無効の子の行がなくなる。アップルメニューの「スリープ」も止まることは項目名から分からないので、(i) で伝える。

(i) を置く範囲:

- 無効になる行すべてに置く（`DEC-SET-004` の時点の仕様）。字下げとグレーの表示で分かることを繰り返し、(i) が多くなる。
- 項目名から分からない制約がある行だけに置く（採用）。

セクション名:

- 「スリープ防止」。メニューや HUD の機能名と同じだが、`DEC-UI-011` でアプリ自身の動作を「防止」と書かないことにした。
- 「スリープ」（採用）。システム設定のスリープの設定と同じ言葉になる。

## 理由

- 選べる組み合わせをそのまま選択肢に並べれば、無効の行と、その理由を説明する文が要らない。
- (i) を制約のある行に絞ると、(i) があること自体が「知っておくべきことがある」という合図になる。
- 保存の形を変えないので、CLI、抑止の判定、設定の読み込みに影響しない。

## 影響

- `SleepSettingsPresentation` は、閉じたときのディスプレイを独立した行として扱わなくなる。前提による無効（`prerequisiteUnmet`）を使う行がなくなる。
- 「スリープ」以外を選んだときにヘルパーがなければ、インストール（一部だけ残っていれば修復）を確かめてから保存する。断ったり失敗したりしたら保存値を変えない。ヘルパーの確認ダイアログとエラーの文言を、スイッチではなくポップアップの操作に合わせる。
- `timer.duration`、`time.value`、`battery`、`battery.threshold`、`battery.ignoreOnAdapter` の (i) をなくす。`battery.ignoreOnAdapter` は項目名を「電源アダプタ接続中は残量でオフにしない」にして、説明なしで分かるようにする。
- アップルメニューの「スリープ」も止まることは、(i) を開かないと分からない。

## 覆す条件

- 利用者が「ディスプレイを閉じたとき」の選択から、アップルメニューの「スリープ」も止まることを予想できず、困ったという報告が続く。
- 手動スリープとディスプレイを閉じたときのスリープを、個別に止められる仕組みが見つかる。
- (i) をなくした項目について、意味が分からないという報告が続く。
