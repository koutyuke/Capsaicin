# DEC-CLI-003 CLI の出力を英語に固定して記号付きの複数行の形にし、--help と --no-time-limit を加える

## 結論

言語:

- CLI の出力（結果、状態、警告、エラー、ヘルプ）は英語だけにし、アプリの表示言語やロケールで変えない。
- 文言は CLI のコードに置き、String Catalog を使わない。CLI 用の String Catalog はなくす。`DEC-SYS-002` の「文字列をコードに直接書かず、String Catalog を経由させる」の例外にする。
- 時刻はローカルのタイムゾーンの24時間制（`H:mm`）で示し、残り時間を添える。メニューの状態の表示（`SPEC-MENU-004`）と同じく、残り時間は分の単位に切り捨て、1分未満はそのことを示す。

出力の形:

```text
$ capsaicin on --for 1h30m
✓ Sleep prevention on
  Turns off  15:53 (in 1h 30m)
  Battery    turns off below 20%

$ capsaicin status
● Sleep prevention on
  Turns off  15:53 (in 1h 29m)
  Battery    turns off below 20%, except on AC power

$ capsaicin status
○ Sleep prevention off

$ capsaicin on
• Sleep prevention is already on
  Turns off  15:53 (in 1h 29m)
  Use --for, --until or --no-time-limit to change when it turns off.

$ capsaicin on --until 25:00
error: invalid time "25:00" for --until; use H:MM, e.g. 4:00
Run 'capsaicin --help' for usage.
```

- 結果と状態は標準出力、警告とエラーは標準エラー出力に出す。終了コードの意味は変えない。
- 1行目に記号と結果を出す。状態を変えたら `✓`、変えなかったら `•`、`status` は抑止中なら `●`、停止中なら `○` を付ける。
- 抑止中なら、2行目から字下げしてラベル付きで解除の条件を並べる。時間の条件（解除の時刻と残り時間。なければ自分でオフにするまで続くこと）と、バッテリー残量の条件（有効なときだけ。しきい値と、電源アダプタ接続中は残量で解除しない設定）である。
- 警告は `warning: `、エラーは `error: ` で始める。使い方の誤りでは、続けて `--help` を案内する行を出す。
- 色は、出力先が端末で、`NO_COLOR` が空でない値で設定されておらず、`TERM` が `dumb` でないときだけ付ける。判定は標準出力と標準エラー出力で別々に行う。

`--help`:

- `-h` か `--help` が引数のどこかにあれば、ほかの引数によらず、説明、書式、サブコマンド、`on` のオプション、終了コードを標準出力に出し、終了コード 0 で終わる。アプリに接続せず、アプリを起動しない。`.app` の外に置いたコピーでも出す。
- 引数がないときは、今までどおり使い方の誤りにする。

`--no-time-limit`:

- `on` に、時間の条件なしの開始の要求（`DEC-BLK-009`）を指定する `--no-time-limit` を加える。停止中なら設定のタイマーと指定時刻を使わずに開始し、抑止中なら解除の時刻をなくす。値は取らない。
- `--for`、`--until`、`--no-time-limit` は、どの2つも同時に指定できない。
- `DEC-BLK-009` の結論のうち「CLI に時間の条件なしの指定は加えない」を、この判断で改める。ほかの結論は変えない。
- `on` のオプションは、メニューの開始の方法（設定の既定値、時間の条件なし、時間、時刻）と1対1にする。バッテリー残量の条件と「スリープとディスプレイ」の設定は、開始ごとの指定ではなく保存される設定なので、`on` のオプションにしない。

## 背景

オーナーから次の依頼があった。アプリは今後 i18n に対応する予定なので CLI は英語で出力すること、`--help` でオプションの一覧を出すこと、出力を一般的で見栄えのよい形にすること、設定項目と `on` のオプションが一致していなければ整えること。

それまでの CLI は、アプリのバンドルの String Catalog から日本語の文言を読み、結果と状態を ` / ` でつないだ1行に出していた。解除の時刻は UTC の ISO 8601（`2026-11-13T05:00:00Z`）で、`--help` はなかった。メニューにある「時間の条件なしで開始する」方法が、CLI にはなかった。

## 選択肢

英語の持ち方:

- 英語に固定し、文言をコードに書く（採用）。
- String Catalog に英語の文言を置き、アプリの表示言語に合わせて翻訳する。CLI の出力がロケールで変わり、スクリプトで扱いにくい。文言を出すたびにアプリのバンドルを読む必要がある。

出力の形（オーナーが選んだ）:

- 記号の付いた結果の行と、字下げした詳細の行に分ける（採用）。`gh` や `systemctl status` に近い。
- 今と同じく1行に詰める。`grep` や通知に流しやすいが、条件が増えると読みにくい。
- 記号を使わず、英語の文で伝える。一覧性が低い。

時刻の表し方:

- ローカルの `H:mm` と残り時間（採用）。メニューと同じ表し方で、人が読みやすい。
- UTC の ISO 8601 のまま。曖昧さはないが、人が読む出力として分かりにくい。

時間の条件なしのオプション名（オーナーが選んだ）:

- `--no-time-limit`（採用）。時間の条件だけを外すことが名前で分かり、バッテリー残量で解除されうることとも矛盾しない。
- `--until-off`。メニューの「オフにするまでオン」に対応して短いが、`--until <時刻>` と見間違えやすい。
- `--indefinitely`。見慣れた語だが、バッテリー残量でオフになりうるので、文字どおりには誤りになる。

## 理由

- CLI はスクリプトから使われる。出力がロケールやアプリの表示言語で変わらないほうが扱いやすく、英語だけの出力は多くの CLI の慣習でもある。
- 結果と条件を行に分ければ、条件が増えても読みやすい。スクリプトは終了コードで状態を判断できるので（`SPEC-CLI-007`）、出力を1行に保つ必要はない。
- 警告とエラーを標準エラー出力に分けると、標準出力をパイプに流しても結果だけが渡る。
- 色を端末のときだけに限り、`NO_COLOR` に従えば、ログやパイプにエスケープシーケンスが混ざらない。
- `--help` はアプリに頼らずに出せる情報なので、アプリを起動しない。起動すると、使い方を見ただけでアプリが立ち上がる。
- メニューで選べる開始の方法を CLI で選べないと、スクリプトで時間の条件なしの抑止を始めたり、抑止中に時間の条件をなくしたりできない。`DEC-BLK-009` で CLI に加えなかったのは、加える理由がまだなかったためで、加えない理由は記録されていない。

## 影響

- `REQ-CLI-001`、`REQ-SYS-003`、`REQ-SYS-004` と、`SPEC-CLI-001`、`SPEC-CLI-003`、`SPEC-CLI-007`、`SPEC-UI-011`、手順書の CLI の確認を直す。`--help` の要件と仕様を足す。
- CLI の出力の文言は、翻訳の対象にならない。アプリに英語以外の言語を足しても、CLI は英語のままになる。
- `status` の出力が複数行になる。1行を前提に出力を読んでいたスクリプトは、終了コードを使うように直す必要がある。
- CLI はアプリのバンドルから文言を読まなくなる。バンドルを確かめるのは、接続先を決めるためだけになる。

## 覆す条件

- CLI を英語以外で使いたいという要望が続く。
- スクリプトから状態の詳細（解除の時刻など）を読みたいという要望が出る。そのときは、機械が読む出力形式（JSON など）を別に検討する。
- `--no-time-limit` で始めた抑止がバッテリー残量で解除され、意図と違ったという報告が続く。
