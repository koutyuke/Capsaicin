# DEC-BLK-005 開始時に時間の条件を指定したら、時間の既定値は使わない

## 結論

選択肢のうち「指定したら、時間の既定値を使わない」を採り、バッテリー残量の条件は開始の要求で外さない。規則は `SPEC-BLK-003` にある。

## 背景

移行元の要件定義書は、メニューと CLI で既定値を別の値で上書きできるとしていたが、タイマーと指定時刻の片方だけを指定したときに、もう片方の既定値を使うかを決めていなかった。

## 選択肢

- 指定しなかった方の既定値を使う。たとえば「2時間」を選んだのに、既定の指定時刻で先に解除されることがある（不採用）。
- 指定したら、時間の既定値をどちらも使わない（採用）。
- バッテリー残量の条件も、開始時に指定したら使わない。電池切れを防ぐ役割が、開始の方法によって外れる（不採用）。

## 理由

- 選んだ時間と実際に解除される時刻が食い違わないようにするため。
- バッテリー残量の条件は電池切れを防ぐ安全のためのものなので、開始の方法で外さないため。

## 影響

- 設定の指定時刻を使いながら、その場で別のタイマーも加えることはできない。

## 覆す条件

- 指定した条件と既定値を組み合わせて使いたいという要望が多いと分かったら見直す。
