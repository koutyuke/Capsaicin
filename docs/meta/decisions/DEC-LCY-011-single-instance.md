# DEC-LCY-011 同じ bundle ID のアプリがすでに動いていたら、後から起動した方は動いている方を開き直して終了する

## 結論

アプリは起動の最初に、同じ bundle ID の別のプロセスが動いているかを `NSRunningApplication` で調べる。動いていたら、後から起動した方は、ヘルパーへの接続、LED や輝度の操作、IPC の受け付けなど、何も始めずに、動いている方のアプリを開き直して（`SPEC-SET-001` の開き直しと同じく設定画面が開く）終了する。

対象は同じ bundle ID だけである。Debug（`io.github.koutyuke.capsaicin.debug`）と正式版（`io.github.koutyuke.capsaicin`）は別のアプリとして同時に動けるので、互いの `disablesleep` を外部のものとみなす既知の制約（`SPEC-HLP-005`）は残る。

## 背景

`DEC-LCY-010` まで、動くアプリは agent から起動したものだけで、launchd が1つに保っていた。agent をやめると、Finder、CLI、ログイン時の起動、別の場所に置いたコピーから、同じアプリがいくつも動きうる。同時に動くと、メニューバーのアイコンが並び、LED、輝度、ヘルパーの接続、CLI の IPC を取り合う。

## 選択肢

1. 後から起動した方が、動いている方を開き直して終了する（採用）。
2. 後から起動した方が、動いている方を終了させて代わる: 抑止中のアプリが、利用者の意図しない操作で止まる。
3. 何もしない: 取り合いが起き、後片付けの役目もどちらにあるか分からなくなる。

## 理由

利用者が2つ目を開くのは、たいてい動いていることに気づかずに設定を開きたいときである。macOS の通常のアプリも、すでに動いているアプリを開くと、そのアプリを前面に出す。同じ振る舞いにすると、抑止を止めずに済む。

Sparkle は、古いアプリが終了してから新しい版を起動する（`EVID-LCY-006`）ので、更新の起動し直しはこの判定とぶつからない。

## 影響

- 要件に、同じアプリを1つだけ動かすことを足す（`REQ-LCY-006`）。
- 仕様: lifecycle に起動時の判定を足す。
- 実装: アプリの起動の最初に判定を足す。

## 覆す条件

- `NSRunningApplication` で、終了しかけのプロセスや起動途中のプロセスを取り違え、どちらも動かない、または両方が動く状態が実際に起きたとき。
- 実機の更新で、Sparkle の起動し直しがこの判定に止められたとき。
