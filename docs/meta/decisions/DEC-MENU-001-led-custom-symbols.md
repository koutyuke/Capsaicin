# DEC-MENU-001 LED のアイコンを Caps Lock キーと LED の独自シンボルにする

## 結論

ステータスアイコンの意匠は、Caps Lock キーと LED にする。オーナーが SF Symbols のテンプレートから作った独自シンボル `custom.capsaicin.led`（輪郭）と `custom.capsaicin.led.fill`（塗りつぶし）を、これまで SF Symbols の `capslock` と `capslock.fill` を使っていたすべての場所（メニューバー、HUD、設定のサイドバーと LED の項目）で置き換える。

## 背景

これまで、ステータスアイコンを LED（Caps Lock）の意匠にするか、唐辛子の意匠にするかが未決だった。オーナーは Caps Lock キーの左上に LED がある形で、輪郭と塗りつぶしの2つのシンボルを作った。アプリアイコンも左上の LED を描いている。

## 選択肢

- LED の独自シンボルにし、`capslock` と `capslock.fill` を使う場所をすべて置き換える（採用）。
- メニューバーだけを独自シンボルにする。HUD とサイドバーは `capslock` のままになり、同じ意味を2つの形で表すことになる。
- 唐辛子の意匠にする。アプリ名と結びつくが、LED の点灯・消灯の対比と別の比喩が併存する。

## 理由

- LED が消えている・点いていることを輪郭と塗りつぶしの対比で表す規則（`SPEC-UI-004`）を、形を変えずに保てる。
- メニューバーだけを替えると、メニューバー、HUD、サイドバーで同じ意味のアイコンの形が揃わない。
- SF Symbols のテンプレートから作ったので、文字との高さと太さの揃え方、HUD の置き換えアニメーションを SF Symbols と同じ仕組みで使える（`SPEC-UI-010`）。

## 影響

- 独自シンボルの名前は `custom.capsaicin.` で始める。`custom.` でアプリの Asset Catalog から読むことを示し、アプリ名を入れて、置き換え前の `capslock` と読み違えないようにする。
- 2つのシンボルをアプリの Asset Catalog に入れる。2つとも Regular の S、M、L を描き、輪郭と塗りつぶしの外形を揃える。外形は `capslock` と同じ大きさにし、メニューバーでは表示の大きさだけを上げる（`SPEC-MENU-005`）。設定のサイドバーは L を求めるので、L がないと描かれない。ほかの太さで表示する場所を足すときは、その形を描き足す。
- 消灯の版は内側を透明にし、半透明の層を使わない。半透明にすると、階層表示の指定が抜けた場所で点灯の版と見分けにくくなる。
- HUD の左の余白は、独自シンボルの外側の空白に合わせて直す（`SPEC-HUD-002`）。
- メニューバーで抑止中かどうかを示すときも、この2つの対比を使う（`DEC-MENU-002`）。

## 覆す条件

- メニューバーの明暗のどちらかで、塗りつぶしの版の LED の穴が「消えている」と読まれ、意味が逆に伝わる。
- 文字や OS 標準のメニューバー項目と並べたとき、太さや高さが揃わず、テンプレートの描き直しで直せない。
