# DEC-UI-007 HUD のガラスは SwiftUI で描き、置き換えでは中央を保って伸び縮みし、文字をぼかして切り替える

## 結論

HUD の素材は Liquid Glass の Regular とし、SwiftUI の `glassEffect(.regular, in: Capsule())` で描く。動きは、揺れ（バネ）を使わない短い出入りにし、続けて切り替えたときは1枚のパネルの内容を置き換える。

置き換えで幅が変わるときは、カプセルが中央を保って左右に伸び縮みし、アイコンと文字の行は左端を揃えたままカプセルの左端に合わせて横に移る。文字はぼかしと不透明度で切り替え、新旧の文字が両方読める瞬間を作らない。寸法と動きの値は `SPEC-HUD-004`〜`SPEC-HUD-006` にある。

## 背景

`DEC-UI-004` は、素材を Liquid Glass の Regular（`NSGlassEffectView`）とし、置き換えの文字はクロスフェードとしていた。オーナーが実機で、幅の違う内容へ置き換える様子を見たところ、次のことが起きた。

- ガラスが元の幅のまま新しい左端へ一気に移り、その後右へだけ伸びた。中央が保たれなかった。
- 新しい文字が最初から最終の位置に出て、伸びきる前のガラスからはみ出した。
- 古い文字と新しい文字が重なって両方読めた。

原因は、幅のアニメーションがカプセルの内側にしか効いていなかったことである。カプセルを中央に置く外側の枠はアニメーションの外にあり、置き場所だけが一度で最終の位置に移った。画面外で描いた途中のコマで、置き換えた直後に左端が最終の位置に移ることを確かめた（`TASK-021`）。

## 選択肢

- `NSGlassEffectView` を `NSViewRepresentable` で置く。ガラスの枠を SwiftUI と AppKit の両方が扱うことになる（不採用）。
- SwiftUI の `glassEffect` で描く。ガラスの形がビューの枠に結びつき、幅のアニメーションと一緒に補間される（採用）。
- 文字はクロスフェードのままにする。途中で新旧の文字が重なって読める（不採用）。
- 文字を拡大・縮小を伴うぼかし（`.blurReplace`）で切り替える。左揃えの行が中央を基準に縮み、揺れて見える（不採用）。
- 文字をぼかしと不透明度だけで切り替える（採用）。
  - 新旧の文字を同時に入れ替えると、オンとオフのように共通の部分（「スリープ防止」）がある場合、その部分が一瞬薄くなってチラついて見えた。このため、古い文字を消してから新しい文字を現す。
- アイコンの系統が変わるときだけぼかしで切り替える。HUD が使うアイコンは `capslock` と `capslock.fill` だけで、系統が変わる場面がない（不採用。下の「覆す条件」を参照）。

## 理由

- HIG は、Liquid Glass をコントロールとナビゲーションの層に使い、文字の多い部品には Regular を使うとしている（`EVID-UI-004`）。`glassEffect(_:in:)` は macOS 26.0 から使え、ガラスをビューの枠に合わせて描く。
- 画面の側から注意を引かない原則（`REQ-UI-002`）に合わせ、揺れのない短い動きにする。中央を保って伸び縮みすれば、HUD の位置そのものは動かない。
- 行を左揃えにしてカプセルの左端と一緒に動かすと、伸び縮みの途中でも内容がカプセルの内側に収まる。
- HIG は、視差効果を減らす設定がオンのとき、拡大や移動をフェードに置き換えるよう求めている（`EVID-UI-004`）。そのときの動きは `SPEC-HUD-008` にある。

## 影響

- `SPEC-HUD-004` の素材、`SPEC-HUD-006` の置き換えの動き、`SPEC-HUD-008` のアイコンの置き換えの記述が変わる。
- 「透明度を下げる」がオンのとき、ガラスが自動で不透明になるかを実装時に確かめ、ならなければアプリが置き換える（`SPEC-HUD-008`）。

## 覆す条件

- 実機で、Regular のガラスの上の文字が読みにくいと分かったら（`SPEC-UI-008`）、素材を見直す。
- `glassEffect` が、フォーカスを受けないパネルの上で正しく描けないと分かったら、描き方を見直す。
- HUD が `capslock` と別の系統のアイコンを使うようになったら、アイコンの切り替え方を見直す。
