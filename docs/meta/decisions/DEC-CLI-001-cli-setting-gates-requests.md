# DEC-CLI-001 CLI の設定はアプリが要求を受け付けるかを切り替え、コマンドはアプリの中に置く

## 結論

- 「CLI」の設定は、コマンドの有無ではなく、アプリが CLI からの要求を受け付けるかどうかを切り替えるものにする。
- CLI はアプリの中の `Contents/Helpers` に置き、シェルから使うためのリンクやエイリアスは利用者が作る。アプリはリンクを作らない。

振る舞いは `SPEC-CLI-005`、`SPEC-CLI-006`、`SPEC-CLI-007` にある。

## 背景

移行元の要件定義書は、CLI の設定（既定値は「使える」）を定めていたが、「使えない」にしたときの意味と、コマンドの置き場所を決めていなかった。

## 選択肢

- 設定をオフにしたらコマンドをシステムから外す（パスに置いたリンクを消す）。リンクを `/usr/local/bin` などに作るには管理者権限が要り、設定を切り替えるたびに権限を求めることになる（不採用）。
- アプリが要求を受け付けるかを切り替え、コマンドはアプリの中に置く（採用）。
- コマンドを `Contents/MacOS` に置く。アプリ本体の `Capsaicin` と大文字小文字だけが違う名前になり、大文字小文字を区別しない APFS で衝突する（不採用）。

## 理由

- 設定の切り替えに管理者権限を求めずに済み、コマンドの有無がアプリの置き場所だけで決まるため。
- `Contents/Helpers` なら、アプリ本体の名前と衝突しないため。

## 影響

- 利用者は、シェルから使うためのリンクやエイリアスを自分で作る必要がある。その方法を設定画面の (i) で伝える（`SPEC-SET-002`）。
- アプリを移動すると、利用者が作ったリンクは切れる。

## 覆す条件

- Homebrew の tap などで配り、配布の仕組みがリンクを作れるようになったら、リンクの扱いを見直す。
- 大文字小文字を区別しない APFS での衝突が問題にならない置き場所や名前の規則に変えるときは、置き場所を見直す。
