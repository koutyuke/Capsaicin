# DEC-MENU-006 設定の項目を「クイック設定」のサブメニュー1つにまとめ、時間と時刻の指定を1つのサブメニューにする

## 結論

`DEC-MENU-005` のうち、メニューの構成を次のように改める。ここに書かない決定（指定のない開始の副題、スリープ防止中の状態の行、バッテリー残量の条件を安全策として副題に含めないこと、しきい値の範囲）はそのまま引き継ぐ。

停止中のメニュー:

```text
Capsaicin
スリープ防止をオンにする
  1時間後にオフ ／ 12:00にオフ ／ 明日12:00にオフ ／ オフにするまで
───
時間指定なしでオン
時間・時刻を指定してオン   ▸   今から（見出し）、15分〜8時間、時間を入力…、───、時刻を指定…
───
クイック設定               ▸
───
設定…
Capsaicinを終了
```

スリープ防止中のメニュー:

```text
スリープ防止中
（状態の行）
スリープ防止をオフにする
オフにする時刻を変更       ▸   今から（見出し）、15分〜8時間、時間を入力…、───、時刻を指定…、───、時間指定なし
───
クイック設定               ▸
───
設定…
Capsaicinを終了
```

「クイック設定」のサブメニュー（停止中とスリープ防止中で同じ。MacBook の例）:

```text
スリープとディスプレイ          （見出し）
✓ ディスプレイを自動でオフにしない
ディスプレイを閉じたとき        （見出し）
✓ システムスリープ（標準）
  ディスプレイスリープ
  明るさを0
  オンのまま
バッテリー                      （見出し）
✓ 残量20%未満でオフにする
    電源アダプタ接続中は除く
```

開始と時間:

- 指定のない開始の項目と副題は `DEC-MENU-005` のまま（副題は時間の条件だけを示し、時間の条件がなければ「オフにするまで」）。
- 時間の条件なしで開始する項目（「時間指定なしでオン」）は、設定の時間の条件の有無にかかわらず常にトップレベルに出す。
- 時刻の指定は、時間の指定と同じサブメニューに入れる。停止中のサブメニューと、スリープ防止中の「オフにする時刻を変更」のサブメニューは、先頭に起点が今であることを示す見出しを置き、同じ並びにする。スリープ防止中だけ、最後に時間の条件なしの項目を置く。

クイック設定:

- 設定の項目を「クイック設定」のサブメニュー1つにまとめ、トップレベルにチェックの付く項目を置かない。サブメニューの中には、さらにサブメニューを開く項目を置かない。
- 「ディスプレイを閉じたとき」は見出しにし、その下に選択肢を並べる。チェックは保存値の選択肢に付ける。MacBook 以外の Mac では、この見出しと選択肢の代わりに、設定画面と同じオン・オフの項目を「スリープとディスプレイ」の下に置く。
- 見出しと項目名は設定画面と同じ文言を使う（`DEC-SET-006`）。どの項目も、チェックは「それが有効」を示す。
- バッテリー残量の項目は `DEC-MENU-005` と同じく保存値のオン・オフだけを切り替え、項目名にしきい値を示す。内蔵バッテリーのない Mac では、見出しごと出さない。
- 「クイック設定」の行には、次を示す。
  - 中の項目に注意（`SPEC-SET-005`）があれば、注意の記号。
  - バッテリー残量の条件をオフにしている間は、そのことを副題で示す。
- 中の項目の注意は、オン・オフの項目ならその項目に、「ディスプレイを閉じたとき」なら保存値の選択肢に、記号と副題で示す。
- 保存と反映、ヘルパーの確認・エラー・巻き戻しは `DEC-MENU-005` のまま、設定画面と同じにする。

## 背景

`DEC-MENU-005` のとおり実装したメニューを実機で見たオーナーから、次の違和感が挙がった。

- 設定画面ではタイマー・指定時刻・バッテリー残量が同じグループなのに、メニューでは分かれて見える。
- トップレベルのチェックのせいで、メニュー全体の左に余白ができる。
- 指定のない開始の副題「オフにするまで」のすぐ下に「オフにするまでオン」があり、同じものが2つあるように見える。
- 選択方式がバラバラに見える（オン・オフ、「▸」の奥の選択、オン・オフ）。
- バッテリー残量は時間・時刻と違って開始の条件ではなく、オプションである。

オーナーの要望は、時間の条件なしで開始する項目を常に出すこと、設定の選択はサブメニューを開くのが1回までで済むこと、バッテリー残量の条件をメニューに残すこと（Amphetamine のメニューの「クイック設定」が扱っているため）である。時間の条件なしで開始する項目の文言は、オーナーが Gemini に相談して「時間指定なし」を選んだ。

PM が AppKit で `NSMenu.size` を測ったところ、メニューに `.on` の項目が1つでもあると左に約14pt の列が取られ、すべて `.off` なら取られなかった。サブメニューのチェックは親の幅に影響しなかった。

## 選択肢

設定の項目の置き場所:

- サブメニュー1つにまとめ、「ディスプレイを閉じたとき」の選択肢を見出しの下に並べる（採用）。
- 見出しの下でトップレベルに並べる（`DEC-MENU-005`）。状態がすぐ見えるが、チェックの列で余白ができ、設定によって列が出たり消えたりする。「ディスプレイを閉じたとき」だけ値が見えない。
- 「スリープとディスプレイ」と「バッテリー」の2つのサブメニューにする。バッテリーは1項目のためにサブメニューを開く。
- 「ディスプレイを閉じたとき」をオン・オフの組み合わせで表す。排他の選択が残り、`DEC-SET-005` で減らした組み合わせの説明が戻る。
- 状態の画像をチェックボックス風にする。排他の選択まで複数選べるように見え、余白も解けない。

時刻の指定:

- 時間のサブメニューに入れる（採用）。
- トップレベルに置く（`DEC-MENU-005`）。

時間の条件なしで開始する項目:

- 常に出す（採用）。設定に時間の条件がないときは、指定のない開始と同じ動きになる。
- 同じ動きになるときは出さない。設定によってメニューの形が変わる。
- 時間のサブメニューに入れる。

サブメニューの名前は「クイック設定」と「スリープの設定」が挙がった。

アドバイザーの2人（Codex と Claude）は、どちらもサブメニュー1つ、別のグループのバッテリー、時刻を時間のサブメニューに入れる組み合わせを推した。

## 理由

- 設定の選択がどれもサブメニュー1回で済み、トップレベルにチェックがないので余白が出ない。
- 「ディスプレイを閉じたとき」の今の値が見え、どの項目もチェックで状態を示し選ぶと切り替わる形にそろう。オン・オフと排他の選択の違いは意味のある違いなので残す。
- トップレベルは今回のスリープ防止の操作だけになり、保存される設定と分かれる。
- 時刻の指定は入力パネルで確定が要るので、1段深くなる負担は小さい。停止中とスリープ防止中のサブメニューが同じ並びになる。
- 「時間指定なしでオン」は副題の「オフにするまで」と言葉が重ならず、「時間・時刻を指定してオン」と対になる。
- バッテリー残量の条件を外したことがトップレベルから見えなくなるので、オフの間は「クイック設定」の行で示して戻し忘れを補う。

## 影響

- `SPEC-MENU-001`〜`SPEC-MENU-003`、`SPEC-MENU-008`、手順書のメニューの確認を直す。
- 設定の状態を見るのに、サブメニューを1回開く。
- 「ディスプレイを閉じたとき」の選択肢の読み上げで、何の選択かが伝わるようにする必要がある。

## 覆す条件

- サブメニューを開く手間で、設定の切り替えが面倒になったという報告が続く。
- 時刻の指定を日常的に使い、1段深いことが負担になる。
- `HYP-BLK-005` が否定される。バッテリー残量の条件をメニューで外せるようにするか自体を決め直す。
