# DEC-BLK-009 抑止中に、時間の指定のある開始の要求で解除の時刻を置き換える

## 結論

- 時間の指定のある開始の要求（タイマー、指定時刻、時間の条件なし）は、停止中なら開始し、抑止中ならいまの抑止の解除の時刻と由来を置き換える。抑止は続けたままにし、仕組み（アサーション、`disablesleep`、LED）を外したり掛け直したりしない。
- 置き換えの起点は、要求を受けた時刻にする。タイマーは「今から」の長さ、指定時刻は `SPEC-BLK-005` の規則でその時点より後に来る時刻になる。
- 開始の要求の指定に「時間の条件なし」を加える。停止中に使えば、設定のタイマーと指定時刻を使わずに開始する。抑止中に使えば、解除の時刻をなくす。
- バッテリー残量の条件は、置き換えで変えない（`DEC-BLK-005` の理由のまま）。
- 指定のない開始の要求は、抑止中は今までどおり何も変えない。ホットキーは今までどおり、抑止中なら解除する。
- CLI の `on --for` と `on --until` も、抑止中なら置き換える。CLI に「時間の条件なし」の指定は加えない。
- 置き換えたら、再開用の記録のセッションを書き直す。保存できないときは、開始以外の出来事と同じ扱い（`SPEC-LCY-007`）にする。
- メニューで置き換えたときは、開始したときと同じ形の HUD に、新しい条件を載せて表示する。CLI では表示しない。
- 置き換えを受けた時点で解除の時刻を過ぎていたら、自動の解除を先に行い、置き換えでは抑止を続けない。
- 設定のタイマーと指定時刻は、抑止中に変えても、いまの抑止には効かないまま（`SPEC-BLK-009`）にする。
- 設定でタイマーと指定時刻の両方をオンにでき、早い方で解除する今の形（`SPEC-BLK-003`）は変えない。

## 背景

`SPEC-BLK-011` は「抑止中に解除の時刻を変える操作はない」と定めていた。時間を変えるには、一度オフにしてオンし直すしかない。オーナーから、オンにした後に時間を変えたいという要望があった。

あわせてオーナーは、Amphetamine がタイマーと時刻の指定を同時に使えないことを挙げ、設定のタイマーと指定時刻を排他にすべきかを問うた。

## 選択肢

抑止中の時間の変更:

- 今のまま、オフにしてオンし直す。その間に `disablesleep` とアサーションが一度外れ、LED が消え、HUD が2回出る。
- 時間の指定のある開始の要求で置き換える（採用）。短縮、延長、時刻の指定、時間の条件をなくすことが1操作でできる。開始と同じ項目なので覚えることが増えない。
- 延長だけを用意する（「15分延長」など）。短縮と時間の条件をなくすことができず、開始は「○分間」、変更は「+○分」と考え方が2つになる。
- オン・オフにかかわらず同じメニューで、時間の選択を現在値にチェックの付く状態として扱う。「1時間」が開始からか今からかが曖昧になり、任意の時間と時刻の指定をチェックで表せない。

要求の形:

- 開始の要求のまま、抑止中は置き換える（採用）。CLI の `on --for` も同じ規則になる。
- 開始とは別の「変更」の要求を作り、CLI の `on --for` は抑止中は何も変えないままにする。スクリプトが手で始めた長い抑止を短くする事故を防げるが、要求の種類が増え、メニューと CLI で規則が分かれる。

設定のタイマーと指定時刻:

- 両方オンにでき、早い方で解除する今のまま（採用）。「2時間、ただし遅くとも4:00まで」を既定値として表せる。
- 「なし／タイマー／指定時刻」の排他にする。設定は単純になるが、上の組み合わせが作れなくなり、保存値の移行が要る。
- 既定値を設定に持たず、時間の指定をメニューだけにする。ホットキーと引数なしの `capsaicin on` が常に時間の条件なしになる。

独立した2人のアドバイザー（Codex と Claude）は、置き換え、詳細設定の扱い、既定値の今の形の維持で一致した。要求の形は2人で分かれ、オーナーが置き換えを選んだ。

## 理由

- 抑止を続けたまま時間だけを変えられれば、スリープ防止が途中で外れない。
- 1回の開始で指定できる時間の条件が1つであることは、Amphetamine と同じである。違いは設定に既定値を持つことで、これはホットキーで画面を見ずに始める使い方に要る。
- CLI でも、時間を指定した `on` は「その時間で動いてほしい」という意図なので、黙って古い時刻のままにするより合う。

## 影響

- `SPEC-BLK-003`、`SPEC-BLK-011`、`SPEC-CLI-001`、`SPEC-CLI-007`、`SPEC-HUD-001`、`SPEC-HUD-002`、`SPEC-LCY-007`、`SPEC-MENU-001`〜`SPEC-MENU-004` を直す。
- スクリプトの `on --for` が、手で始めた長い抑止を短くすることがある。
- 置き換えの後に記録を保存できないままクラッシュすると、古い時刻で再開することがある。

## 覆す条件

- CLI の置き換えで、意図せず抑止が短くなったという報告が続く。
- 既定値の組み合わせ（タイマーと指定時刻の両方オン）を使う人がいないと分かり、設定を単純にしたくなる。
