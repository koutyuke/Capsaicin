# DEC-MENU-009 メニューの警告をスリープ防止の2つに絞り、注意は項目名の先頭の「⚠︎」で示す

## 結論

`DEC-MENU-008` と `DEC-LED-007` のうち、メニューに出す警告と、注意の示し方を改める。ほかの決定はそのまま引き継ぐ。引き継ぐのは、クイック設定の項目を字下げせずに1つを選ぶ選択肢を区切りで囲むこと、「クイック設定」の行に副題を付けないこと（`DEC-MENU-008`）、キー配列を変更するアプリの案内を設定の「フィードバック」だけに出すこと（`DEC-LED-007`）である。

```text
Capsaicin                                        （見出し）
⚠︎ スリープ防止の一部が解除されていません
───
スリープ防止をオンにする
…
⚠︎ クイック設定 >
    ✓ ⚠︎ オンのまま
         ヘルパーが有効になっていないため、設定を反映できません。
```

- メニューの先頭の警告は、スリープを止める仕組みのずれ（`SPEC-BLK-007`）の2つだけにする。戻すべきものが残っていれば「スリープ防止の一部が解除されていません」、適用すべきものを適用できていなければ「スリープ防止の一部が有効になっていません」を出す。副題は付けない。警告のまとまりの後には区切りを置く。
- LED のずれと、輝度の記録の保存・削除の失敗は、メニューに出さない。検出と合わせ直しは変えない。CLI の警告（`SPEC-CLI-007`）と、解除したときの HUD（`SPEC-HUD-002`）では、これまでどおり伝える。
- 警告の行と注意のある項目には画像を付けず、項目名の先頭に文字の「⚠︎」（U+26A0 と、絵文字にしない U+FE0E）を付ける。クイック設定の中の項目に注意があれば、「クイック設定」の行も「⚠︎ クイック設定」にする。中の項目のチェックはそのまま表示する。VoiceOver では記号を読ませず、「警告: 」を付けた名前を読ませる。

## 背景

オーナーは、メニューの警告の文言を見直す中で、輝度の記録と LED の警告、副題の「設定の「ヘルパー」で直せます」は、メニューで知らせるよりトラブルシューティングに載せる内容だとした。

警告の画像（`exclamationmark.triangle.fill`）を付けた行は、メニューを開いたまま中身を書き直すと、そのまとまりだけ右に1列ずれることがあった（macOS 27）。メニューは開いている間も1分ごとに書き直す（`SPEC-MENU-004`）。原因は確かめていない。

オーナーは、クイック設定の中の注意を、サブメニューを開く前から気づけるようにしたいとした。

## 選択肢

警告の範囲:

- スリープを止める仕組みのずれの2つだけにする（採用）。
- これまでどおり、LED と輝度の記録を含む5種類と、ヘルパーの副題を出す。

注意の示し方:

- 項目名の先頭に文字の「⚠︎」を付ける（採用）。画像の列を作らないので、字下げがずれない。記号は項目名と同じ色になり、色では目立たない。
- 画像のまま（これまで）。開いたままの書き直しで字下げがずれる。
- 記号を付けない。警告の行は選べない灰色の行なので、ほかの行に紛れる。
- 「▲」を付ける。日本語の画面では、増えたことやマイナスの意味で使われることがある。

クイック設定の中の注意を付ける場所:

- 保存値の選択肢と、オン・オフの項目（採用）。注意の文はその行の副題に出す。
- 「ディスプレイを閉じたとき」の見出し。見出しには副題を置けず、原因が選んだ値にあることも伝わらない。

## 理由

- スリープを止める仕組みのずれは、気づかないと Mac が意図せずスリープするか、スリープしないまま電池を使い続ける。解除の後も残りうるので、開くたびに見えるメニューで伝え続ける（`REQ-BLK-010`）。
- LED を戻せなかったことは、解除したときの HUD で伝わり（`REQ-LED-002`）、CLI にも残る。輝度の記録は、保存できなければ輝度を0にせず、削除できなければ自動でやり直すので、利用者がメニューから対処することはない。
- 文字の記号なら、画像を付けた行と付けない行が同じまとまりに並ばないので、開いたまま書き直しても字下げが変わらない。

## 影響

- `SPEC-MENU-001`、`SPEC-MENU-004`、`SPEC-MENU-008`、`SPEC-BLK-007`、`SPEC-BLK-013`、`SPEC-LED-002` の受け入れ例、手順書のクイック設定の確認を直す。
- LED を合わせられていないことは、メニューを開いても分からない。抑止中に LED を点けられなかったときは、CLI でしか分からない。
- 輝度の記録の保存・削除の失敗は、CLI でしか分からない。

## 覆す条件

- LED が点かない、または消えないのに、理由が分からないという報告が続く。
- 文字の「⚠︎」では注意に気づかないという報告が続く。
- 「⚠︎」がカラーの絵文字で表示される環境がある。
