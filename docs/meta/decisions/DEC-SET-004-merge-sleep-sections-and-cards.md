# DEC-SET-004 「防止するスリープ」と「解除の条件」を「スリープ防止」にまとめ、項目をアイコン付きのカードで分ける

## 結論

- 設定画面の「防止するスリープ」と「解除の条件」を1つのセクション「スリープ防止」にまとめる。中は「防止中の動作」と「自動でオフにする条件」の2つのグループに分ける。
- 「防止中の動作」のスイッチは、どちらもオンで止める向きのまま、オンにしたときの結果を項目名にする。
  - ディスプレイの行: 「自動でディスプレイスリープしない」
  - 手動と蓋の行: 「ディスプレイを閉じてもシステムスリープしない」。蓋のない Mac では「メニューから選んでもシステムスリープしない」。アップルメニューの「スリープ」なども止まることは (i) で伝える。
  - 子の行: 「閉じたときのディスプレイ」。選択肢は「ディスプレイスリープ」「オンのまま」。「ディスプレイの明るさを0にする」の追加の判断は `DEC-BLK-007` にある。
- 用語は `DEC-UI-009` に従う。
- どのセクションでも、親の行とその子の行を1つのカード（`Form` の `Section`）にまとめ、関係のないものは別のカードに分ける。関連するカードがまとまっているときは、最初のカードにグループの見出しを付ける。
- 親の行と子を持たない行には、項目名の左に SF Symbols のアイコンを付ける。子の行にはアイコンを付けず、項目名の始まりを親の項目名にそろえる。
- 「スリープ防止」は行が多いので、ウインドウの高さに収まらないときはスクロールを許す。

各行の文言は String Catalog、アイコンと並びは `SPEC-SET-001`、`SPEC-SET-002` にある。

## 背景

オーナーから、設定画面について次の指摘があった。

- 「画面の自動消灯とスクリーンセーバー」「手動スリープとディスプレイを閉じたときのスリープ」は、スイッチで何が起きるかが項目名から分からない。長い。「自動消灯」「手動スリープ」は分かりにくい。「スクリーンセーバ」は説明に回したい。
- 項目名を変えると、「防止するスリープ」というセクション名が中身と合わなくなる。項目数が少ないので、「解除の条件」とまとめたい。
- 各項目にアイコンを付け、Dropover の設定画面のように項目をまとまりで分けたい。

オーナーは Karabiner-Elements のような「〜を許可」型を候補に挙げた。子の「閉じたときのディスプレイ」は、蓋を閉じてもスリープしないときだけ意味を持つ。

## 選択肢

スイッチの向きと項目名:

- オンで止める向きのまま、結果を「〜しない」で書く（採用）。
- オンで許可する向きにする（「ディスプレイのスリープを許可」など）。子の行が、親がオフのときにだけ使えるようになり、字下げの見た目と食い違う。ディスプレイの行の既定値もオフになり、「スリープ防止中なのにオフ」に見える。
- 止める範囲をすべて書く（「メニュー操作やディスプレイを閉じたときのスリープを防ぐ」）。正確だが長く、行が折り返す。

蓋を閉じたときの行の形:

- スイッチと、子の状態のポップアップに分ける（採用）。「明るさを 0 にする」（追加の判断は `DEC-BLK-007`）が加わっても、ポップアップの選択肢が増えるだけで済む。
- 「スリープする」「スリープせずディスプレイをオフ」「スリープせずオンのまま」の3択のポップアップ1つにまとめる。子の行はなくなるが、状態の選択肢が増えるたびに組み合わせの数だけ選択肢が増える。

セクション名:

- 「スリープ防止」（採用）。メニュー、HUD、CLI が使う機能の名前と同じになる。
- 「スリープ」。短いが、OS のスリープ設定そのものに見える。
- 「防止と自動オフ」。何を防止するかが名前から分からない。

## 理由

- 子の行が親のオンに従う形を保てるのは、オンで止める向きだけである。オンにしたときの結果を項目名に書けば、「何が起きるか分からない」という指摘は向きを変えずに解ける。
- 「ディスプレイスリープ」と「システムスリープ」を項目名に入れると、ディスプレイだけが止まるのか Mac 全体が止まるのかが分かる。「自動で」と「閉じても」で、きっかけの違いも分かる。
- 項目名を短く保ち、手動スリープも止まることは (i) で伝える。2つを個別に止められないことは、OS の仕組みによる（`HYP-BLK-006`）。
- 独立した2人のアドバイザー（Gemini と Codex）は、オンで止める向き、「スリープ防止」というセクション名、子の行の名前について、同じ結論を出した。止める範囲を項目名にすべて書く案は2人が推したが、オーナーは短い形を選んだ。

## 影響

- サイドバーは6項目になる。上の4つ（一般、スリープ防止、LED、操作）と下の2つ（ヘルパー、このアプリについて）に分かれる。
- 前回開いていたセクションが「解除の条件」だった場合は、保存された値が使えなくなり、「一般」を開く。
- 解除の条件の String Catalog は「スリープ防止」の String Catalog にまとめる。
- 「スリープ防止」はスクロールすることがある。`HYP-UI-004` は、ほかのセクションについての仮説になる。
- 保存値と、止める仕組みは変わらない。

## 覆す条件

- 利用者が「ディスプレイを閉じてもシステムスリープしない」から、アップルメニューのスリープも止まることを予想できず、困ったという報告が続く。
- 手動スリープと蓋を閉じたときのスリープを、個別に止められる仕組みが見つかる。
