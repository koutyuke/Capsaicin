# DEC-MENU-008 クイック設定の選択肢を字下げせずに区切りで囲み、クイック設定の行の副題をなくす

## 結論

`DEC-MENU-007` のうち、次を改める。ほかの決定（見出しは選択肢を持つ項目の名前にだけ使うこと、バッテリー残量の項目名、`DEC-MENU-006` と `DEC-MENU-005` から引き継いだもの）はそのまま引き継ぐ。

```text
✓ ディスプレイを自動でオフにしない
───
  ディスプレイを閉じたとき          （見出し）
✓ システムスリープ（標準）
  ディスプレイスリープ
  明るさを0
  オンのまま
───
✓ バッテリー残量20%未満でオフにする
    電源アダプタ接続中は除く
```

- クイック設定の項目を字下げしない。見出しと項目名は同じ位置から描かれ、チェックはその左の列に出る、標準の並びにする。
- 1つを選ぶ選択肢（「ディスプレイを閉じたとき」）は、前後を区切りで囲む。オン・オフの項目は1行で1つの設定として置き、まとまり（スリープとディスプレイ、バッテリー）の間にも区切りを置く。
- 「クイック設定」の行には、バッテリー残量の条件がオフであることを示す副題を付けない。中の項目に注意があるときの注意の記号は残す。

## 背景

`DEC-MENU-007` のとおり選択肢を `NSMenuItem.indentationLevel` で字下げしたところ、字下げで動くのは項目名と画像だけで、チェックの列は動かなかった。チェックが見出しより左に残り、オーナーから、チェックと見出しの位置がそろわないと挙がった。

Apple Human Interface Guidelines の「Menus」は、字下げよりサブメニューを勧め、字下げはシステムと一貫せず項目の関係も伝わらないとしている。状態はチェックマークで示し、まとまりは区切りで分けるとしている。

オーナーは、区切りの有無で、オン・オフの項目と1つを選ぶ選択肢を見分けられるか、設定がひと目で分かれて見えるかを重視した。

「クイック設定」の行の副題は、`DEC-MENU-006` で、バッテリー残量の条件を外したまま忘れることへの補いとして置いた。オーナーから、クイック設定の中の設定のうちバッテリーだけをトップレベルで示す必要があるのかと挙がった。

## 選択肢

選択肢の見せ方:

- 字下げせず、1つを選ぶ選択肢の前後を区切りで囲む（採用）。
- 字下げせず、「スリープとディスプレイ」のまとまりの中では区切りを置かない。HIG の「関係するものは同じまとまりに入れる」に近いが、オン・オフの項目と選択肢の境目が見出しだけになり、ひと目で分かりにくい。
- 字下げする（`DEC-MENU-007`）。チェックの列が動かず、見出しとそろわない。
- チェックを項目の画像として描き、見出しの位置にそろえる。VoiceOver にチェックの状態が伝わらず、同じメニューの中でオン・オフの項目のチェックと位置が分かれる。
- Amphetamine のように、チェックボックスの画像と字下げで並べる。標準の部品ではなく、1つを選ぶ選択肢には別の画像が要る。

「クイック設定」の行の副題:

- 付けない（採用）。
- 付ける（`DEC-MENU-006`）。
- スリープ防止中の状態の行で、条件がオフであることを示す。

## 理由

- 標準の並びでは、チェックが1つの列にそろい、VoiceOver にもチェックの状態が伝わる。
- 1つを選ぶ選択肢を区切りで囲むと、その中から1つを選ぶまとまりだと形で分かり、3つの設定がそのまま3つのまとまりに分かれる。macOS のメニューでも、1つを選ぶ選択肢は区切りで囲んでオン・オフの項目と分けることが多い。
- 中の設定のうちバッテリーだけをトップレベルで示すと、扱いがそろわない。状態はクイック設定を開けばチェックで分かり、オフにするのは利用者自身の操作である。スリープ防止中は、条件が有効なときだけバッテリーの状態の行を出すので、行がないこと自体がバッテリーではオフにならないことを示す。

## 影響

- `SPEC-MENU-008`、`SPEC-SET-006`、手順書のクイック設定の確認を直す。
- バッテリー残量の条件を外したことは、クイック設定を開くか、スリープ防止中に状態の行がないことでしか分からない。

## 覆す条件

- バッテリー残量の条件を外したまま忘れ、電池を使い切ったという報告が出る。
- `HYP-BLK-005` が否定される。バッテリー残量の条件をメニューで外せるようにするか自体を決め直す。
- 区切りで囲んでも、オン・オフの項目と選択肢の違いが分かりにくいという報告が続く。
