# DEC-BLK-007 蓋を閉じたときの動作に「明るさを0」を加え、DisplayServices で内蔵ディスプレイの輝度を 0 にする

## 結論

「ディスプレイを閉じたとき」のポップアップ（`DEC-SET-005`）に「明るさを0」を加え、選択肢を「スリープ（標準）」「ディスプレイをオフ」「明るさを0」「オンのまま」の4つにする。「明るさを0」の保存値は、手動スリープをオン、`lidCloseDisplay` を `zeroBrightness` にする。

抑止中に「明るさを0」なら、次のように動く。

- 蓋が閉じた通知で、オンラインの内蔵ディスプレイの輝度を読み、その値をファイルに残してから輝度を 0 にする。読めないときと残せないときは暗くしない。外部ディスプレイは変えない。
- 蓋が開いた通知、抑止の解除、アプリの終了で、残した値に戻してファイルを消す。解除では、`disablesleep` を下ろす前に戻す。戻す時点の輝度が 0 でなければ、閉じている間に利用者か macOS が変えたものとして書き戻さず、ファイルだけを消す。
- 戻す処理は、暗くしたこと（ファイルがあること）に結びつけ、その時点の設定の値によらない。
- 起動したときにファイルが残っていれば、前回は暗くしたまま終わったものとして、輝度が 0 のときだけ戻し、ファイルを消す。
- 輝度は、非公開の DisplayServices の関数を実行時に引いて読み書きする。ヘルパーと root は使わない。
- DisplayServices で内蔵ディスプレイの輝度を変えられない Mac では、「明るさを0」を選べるままにし、その行に注意の記号を出して、(i) で輝度を変えられないため閉じても画面が点いたままになることを伝える。閉じたときに読み書きが失敗したら、明るいままにしてログに残す。「ディスプレイをオフ」には切り替えない。
- 「ディスプレイを自動でオフにしない」とは連動させない。(i) で、暗い画面はロックされていないことと、「ディスプレイを自動でオフにしない」がオフなら時間が来るとディスプレイスリープし、ロックされうることを伝える。

## 背景

蓋閉じスリープを止めているとき、閉じた蓋の中の画面の扱いは「ディスプレイをオフ」と「オンのまま」の2つだった。「ディスプレイをオフ」はディスプレイスリープさせるので、パスワードの設定によってはロックされ、画面収録や Computer Use が止まる。「オンのまま」では、閉じた蓋の隙間から内蔵ディスプレイのバックライトの光が漏れる（`EVID-BLK-009`、`EVID-BLK-013`）。

オーナーは、蓋を閉じたまま画面をロックさせずに画面収録・Computer Use・画面共有を続けることと、閉じた蓋の中の光漏れ・電力・発熱を抑えることの両方を求めた。

## 選択肢

加えるか:

- 加えない。非公開の API への依存と、輝度を戻す処理が増えない。ロックさせずに続けたいときは「オンのまま」を選び、光漏れと発熱を受け入れる。
- 加える（採用）。

暗くする方式:

- DisplayServices の輝度を 0 にする（採用）。
- ガンマで画素を黒くする。バックライトが消えないので、光漏れと電力を抑えられない。
- 内蔵ディスプレイを無効にする（SkyLight の非公開の関数）。取り込む画面がなくなり、ウインドウの配置が変わる。
- 黒いウインドウで覆う。取り込む画面も黒くなる。
- CoreDisplay の輝度、IOKit の `IODisplaySetFloatParameter`。CoreDisplay は読み取りが実際の輝度と食い違い、IOKit の経路は Apple Silicon の Mac で使えない（`EVID-BLK-007`）。

輝度を変えられなかったとき:

- 明るいままにする（採用）。
- 「ディスプレイをオフ」に切り替える。光らないが、選んだ動作と違い、ロックされうる。

閉じている間に輝度が変えられていたとき:

- 書き戻さない（採用）。
- 書き戻す。利用者が閉じたまま変えた明るさを打ち消す。

「ディスプレイを自動でオフにしない」との関係:

- 連動させない（採用）。
- 「明るさを0」を選んだら一緒にオンにする。`DEC-BLK-006` でなくした、項目が別の項目を含意する関係が戻る。

## 理由

- 実機で、輝度 0 なら閉じた蓋の隙間から光が漏れなかった（`EVID-BLK-012`、`EVID-BLK-013`）。閉じたまま11分置いても、ディスプレイスリープもロックもせず、画面収録が続いた（`EVID-BLK-011`）。自動輝度調節のオンとオフのどちらでも、閉じている間は 0 のままで、開けると元の輝度に戻せ、閉じたままでも戻せた（`EVID-BLK-010`、`EVID-BLK-012`）。ほかの方式は、目的のどちらかを満たさない。
- 輝度は、ディスプレイスリープを止めるアサーションと違い、プロセスが終わっても戻らない。戻す値をファイルに残さないと、落ちたときに画面が暗いまま残る。
- 失敗したときに「ディスプレイをオフ」へ切り替えると、この選択肢を選ぶ一番の理由（ロックさせない）が崩れる。明るいままなら、光漏れは「オンのまま」と同じだけで、作業は止まらない。
- 戻す時点で 0 でなければ、閉じている間に利用者が明るさを変えている。その値を残すほうが利用者の意図に合う。

## 影響

- `REQ-BLK-014` を加え、動作を `SPEC-BLK-013` に書く。`SPEC-SET-002`、`SPEC-SET-005`、`SPEC-BLK-012`、解除の手順、`SPEC-LCY-002`、`SPEC-LCY-003` を直す。
- 非公開の DisplayServices に依存する。macOS の更新で関数がなくなれば注意の表示で分かるが、成功を返しても効かなくなる変化は、アプリから見分けられない。
- 描画は続くので、発熱と電力は「ディスプレイをオフ」より不利である。「オンのまま」よりどれだけ下がるかは測っていない。
- 暗い画面はロックされていない。蓋を開けた人は、すぐに操作できる。
- 閉じていく間に自動輝度調節が輝度を少し下げるので、戻す値は、閉じる直前に見ていた明るさより少し暗い（`EVID-BLK-012`）。開けた後は、自動輝度調節が合わせ直す。
- 輝度 0 のまま Mac が再起動したとき、ログイン画面が暗いまま残るかは確かめていない。明るさのキーで戻せる。

## 覆す条件

- macOS の更新で DisplayServices の輝度が使えなくなる、または輝度 0 でもバックライトが消えなくなる。
- 輝度 0 のまま再起動したとき、ログイン画面が暗いまま残り、明るさのキーでも戻せないことが分かる。
- ディスプレイスリープさせずにバックライトを消せる公開の API が見つかる。
- macOS 26 で同じ結果にならない（`HYP-SYS-001`）。
