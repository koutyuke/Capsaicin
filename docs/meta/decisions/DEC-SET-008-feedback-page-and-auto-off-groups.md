# DEC-SET-008 LED と HUD を「フィードバック」にまとめてイラストを置き、自動解除のグループを何で解除するかで名付ける

## 結論

`DEC-SET-006` のうち、セクションの構成、「スリープ」の2つのグループの見出し、バッテリー残量の条件の項目名を改める。時間の自動解除とバッテリー残量の条件を別のグループにすることと、ここで改めないもの（セクション名「スリープ」、「ディスプレイを閉じたとき」のポップアップ、カード・アイコン・子の行の字下げ・スクロール）は引き継ぐ。

- 「一般」は見出しを置かず、「ログイン時に起動」のカードと、「メニューバーにアイコンを表示」「Dockにアイコンを表示」をまとめたカードの2枚にする。
- セクション「LED」を「フィードバック」（英語は Feedback）に置き換え、「Caps LockのLED」と「HUD」の2つのグループを置く。「切り替え時にHUDを表示」は「一般」からここへ移す。
  - 各グループの先頭に、説明文とイラストのカードを置く。イラストはカードの右端と上下端まで広げ、カードの角で切り取る。macOS のシステム設定の「メニューバー」の「メニューバーコントロール」と同じ形である。
  - LED のイラストは、キーボードの左側を描き、Caps Lock の LED を点灯・消灯させる。点いた直後だけ淡い輪を広げ、その後は点いたまま保つ。
  - HUD のイラストは、画面の縮小図を描き、メニューバーのアイコンの状態が変わるのに合わせて、画面下部に HUD を出して消す。特定の操作（メニュー、ホットキー）は描かない。
  - 2つのイラストは同じ周期で、オンとオフの場面を交互に繰り返す。「視差効果を減らす」がオンなら、オンの場面の止めた絵にする。ウインドウが非アクティブの間は止める。
  - イラストは SwiftUI の図形と、メニューバーと HUD が使う独自シンボルで描き、画像や動画を使わない。
- 「スリープ」の自動解除のグループを、何をきっかけに解除するかで名付け、項目名を「自動解除」にそろえる。
  - 「時間による自動解除」: 「タイマーで自動解除」（子の行は「継続時間」）、「指定時刻に自動解除」（子の行は「時刻」）。
  - 「バッテリーによる自動解除」: 「バッテリー残量が少ないときに自動解除」、子の行の「バッテリー残量」（値は「20%未満」の形）と「電源アダプタ接続中は自動解除しない」。

## 背景

「ログイン時に起動」は、クラッシュからの復旧を外して（`DEC-LCY-010`）、グループ「起動」のただ1つの項目になった。グループ「表示」には、メニューバーと Dock のアイコンと並んで HUD の項目があった。オーナーは、見出しで分ける理由が薄いので「一般」の見出しを外してアイコンの2項目を1枚にまとめ、LED と HUD は知らせ方の設定として1つのセクションにまとめ、システム設定のようなイラストで何が起きるかを見せたいとした。

`DEC-SET-006` で分けた時間の自動解除とバッテリー残量の条件は、見出しが「スリープ防止の自動解除」と「バッテリー」だった。オーナーは、バッテリー残量の条件も自動で解除するのに見出しがそれを含まないこと、「バッテリー」だけではバッテリーそのものの設定に見えることを挙げた。見出しと項目名の案は Gemini にも出させて比べた。

## 選択肢

セクションの名前:

- 「フィードバック」（採用）。トラックパッドの「触覚フィードバック」のように、操作や出来事への反応を指す言葉として macOS でも使われる。開発元に意見を送る場所と取り違えるおそれはあるが、先頭のイラストで中身がすぐ分かる。
- 「通知」「通知・フィードバック」「イベント通知」。macOS の通知（通知センター）と取り違えられる。
- 「アラート」。異常を知らせる意味が強く、スリープ防止の開始と解除に合わない。
- 「インジケーション」「報知」「通知演出」など。設定画面の言葉として硬いか、意味がぼやける。

HUD のイラストのきっかけ:

- メニューバーのアイコンの状態の変化に合わせる（採用）。HUD は、メニューとホットキーの操作のほか、タイマー・指定時刻・バッテリー残量による自動解除でも出る（`SPEC-HUD-001`）。どの場面にも当てはまる。
- ホットキーを描く。初期状態では割り当てがなく、決まったキーを描けない。
- メニューを開く場面を描く。縮小図では文字が読めず、何が起きているかが伝わりにくい。

イラストの作り方:

- SwiftUI の図形で描く（採用）。部品ごとに動かせ、ダークモードと「コントラストを上げる」にシステムの色で従い、「視差効果を減らす」を HUD 本体と同じ方法で判定できる。
- PNG や SVG の画像。部品ごとに動かせず、動かすには連番画像か動画が要る。外観ごとに別の絵も要る。

自動解除のグループと項目名:

- 見出しを何で解除するかで名付け、項目名を「〜で自動解除」にそろえる（採用）。分けている理由が見出しから読め、`DEC-UI-015` の「自動で切ることを解除と書く」規則に合う。時間の既定値と常に働く安全策という性質の違いは見出しからは読めなくなるが、オーナーは説明文で補わないとした。
- 見出しを性質で名付ける（例: 「標準の時間指定」と「常時有効なバッテリー保護」）。性質の違いは伝わるが、2つの見出しの形がそろわず、項目名との重なりも残る。
- 電源アダプタの子の行を「電源アダプタ接続中は除く」にする。メニューの副題とそろうが、VoiceOver が行の名前だけを読み上げたときに何を除くのかが分からない。
- タイマーの子の行を「時間」にする。入力欄の単位の「時間」と同じ文字になり、VoiceOver でも区別できない。

## 理由

- 「一般」の3項目は、1項目と2項目のまとまりしかなく、見出しを付けても読み手の判断を助けない。起動とアイコンの表示はカードで分ければ足りる。
- LED と HUD は、どちらもスリープ防止の状態を利用者に知らせる手段で、同じ独自シンボルで表す。まとめると、知らせ方を1か所で選べる。
- イラストは、スイッチをオンにすると何が起きるかを、文を読まずに伝えられる。LED を点いたまま保つのは、実際の LED が点滅しない（`DEC-LED-002`）ことを絵でも誤解させないためである。
- 自動解除の見出しを何で解除するかにそろえると、2つのグループがなぜ分かれているかが見出しだけで分かる。

## 影響

- `SPEC-SET-001` のセクションの表、`SPEC-SET-002` の表、`SPEC-SET-006`、`SPEC-LED-005` の案内の場所、手順書と要件の項目名を直す。イラストの振る舞いは `SPEC-SET-009` にまとめる。
- 保存値の形とキーは変えない。設定ウインドウが前回のセクションとして「LED」を覚えていた場合は、存在しないセクションとして「一般」を開く。
- 「フィードバック」は、キー配列を変更するアプリの案内が出ていると高さに収まらないので、スクロールを許す。
- イラストが動く間は描画が続く。ウインドウが非アクティブの間と「視差効果を減らす」がオンの間は止める。
- イラストをカードの端まで広げるため、grouped の `Form` が行に持たせる余白を負の余白で打ち消している。OS の更新で行の余白が変わると、イラストの位置がずれる。

## 覆す条件

- バッテリー残量の条件が、タイマーや指定時刻と同じく開始のときに選ぶものになる。
- 「フィードバック」を開発元に意見を送る場所と取り違えたという報告が続く。
- イラストの描画で、設定ウインドウを開いている間の負荷が問題になる。
