# DEC-UI-014 「このアプリについて」をスクロールする Form にし、アップデートとリンクを置く

## 結論

- 「このアプリについて」を、ほかのセクションと同じ `Form`（`.grouped`）にする。縦の中央にはそろえず、内容が収まらなければスクロールする。
- 上から、見出し（アプリアイコン、アプリ名、バージョンとビルド番号）、「アップデート」のグループ、「リンク」のグループ、終わりの部分（終了ボタンと著作権の表示）の順に置く。見出しと終わりの部分はカードにせず、中央にそろえる。
- 「アップデート」には次の2行を置く。
  - 「自動アップデート」: 「オフ」「確認のみ」「ダウンロードしてインストール」のポップアップ。Sparkle の自動の確認と自動のダウンロードの2つの設定に対応させる。
  - 「ソフトウェアアップデート」: 最後に確認した日時と、今すぐ確認するボタン。新しい版があるときと、インストールを待っている版があるときは、その版を示し、ボタンをアップデートの操作にする。
- 「リンク」には、GitHub のリポジトリを開く「Web サイト」と、設定ウインドウのシートで開く「ライセンス」を置く。ライセンスには Capsaicin、KeyboardShortcuts、Sparkle の全文を載せる。
- 各行の左には、ほかのセクションと同じく SF Symbols のアイコンを置く。
- 著作権の表示は「© 2026 koutyuke」とし、Info.plist の `NSHumanReadableCopyright` を正本にする。
- 定期の確認で新しい版が見つかったら、ステータスメニューの見出しと警告の行の直後に「アップデートがあります」の項目を置き、選ぶと Sparkle の画面を開く。メニューバーのアイコンを隠しているときは、「このアプリについて」の行だけで知らせる。

## 背景

`DEC-SYS-019` でアプリから更新できるようにした。`DEC-UI-010` で、アプリそのものについての操作は「このアプリについて」にまとめると決めており、のちの更新の確認もここに入る想定だった。オーナーは、アップデートとリンクを置いたこの画面のモックを示した。

これまでの「このアプリについて」は `Form` を使わず、中央に縦に並べ、著作権の表示と Web サイトへのリンクを置かなかった。設定ウインドウは 720 × 500 pt に固定されている。

## 選択肢

- これまでの中央にそろえた配置のまま項目を足す。500 pt に収めるには、アイコンを小さくし、余白を詰める必要がある（不採用）。
- ほかのセクションと同じスクロールする `Form` にする（採用）。
- 自動の確認と自動のインストールを2つのスイッチにする。スイッチの組み合わせのうち、確認がオフでインストールがオンの組み合わせが意味を持たない（不採用）。
- 3つの選択肢のポップアップにする（採用）。
- 定期の確認で新しい版が見つかったら、Sparkle の画面を出す。常駐するアプリでは、作業中に突然ウインドウが出る（不採用）。
- メニューと「このアプリについて」で控えめに知らせる（採用）。
- ライセンスを、同じ右側の下の階層（`NavigationStack`）に開く。AppKit で用意したウインドウのツールバーと SwiftUI のナビゲーションがぶつかり、開いて戻るとタイトルバーの高さと閉じるボタンの位置が崩れた（不採用）。
- ライセンスをシートで開く（採用）。

## 理由

- スクロールを許すと、ほかのセクションと同じ部品と余白で作れ、文字を大きくしても崩れない。
- 3つの選択肢なら、意味のある組み合わせだけを選べる。値は Sparkle が保存するので、Capsaicin の設定と二重に持たない。
- シートなら、ウインドウのツールバーとサイドバーの選択に触れずに開いて閉じられる。読み終えたら閉じるだけの内容なので、階層を持たせる必要もない。
- メニューバーのアイコンを隠す利用者は、画面から知らされないことを選んでいると考えられる。

## 影響

- `SPEC-SET-004` の配置と、`SPEC-MENU-001` のメニューの並びが変わる。
- ライセンスの全文をアプリに同梱する。
- 文言はモックから一部変える。「自動更新」は「自動アップデート」、「公式サイト」は「Web サイト」、「アプリを終了」はメニューと同じ「Capsaicin を終了」にする。

## 覆す条件

- 控えめな知らせでは、利用者が新しい版に気づかないと分かったとき。
- 設定ウインドウの大きさを変えるとき。
