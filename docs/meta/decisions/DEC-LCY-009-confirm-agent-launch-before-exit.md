# DEC-LCY-009 直接起動したアプリは、agent のジョブがこのバンドルの実行ファイルで動き出したことを確かめてから終了する

## 結論

`DEC-LCY-008` の引き渡しで、直接起動したアプリが終了してよい条件を改める。

- 直接起動したアプリは、agent を登録して `launchctl kickstart` で起動を求めた後、agent のジョブのプロセスが動いていて、その実行ファイルがこのバンドルの実行ファイルであることを確かめてから終了する。
- 5 秒の間に確かめられなければ、agent の起動の失敗として扱う。アプリはそのまま動き続け、クラッシュ時に再起動されないことを設定画面の「一般」に示す（`SPEC-LCY-005` の既存の失敗の扱い）。
- `kickstart` のコマンドの成功は、引き渡しの完了とみなさない。

## 背景

`SPEC-LCY-005` は、agent の起動に失敗したら、アプリをそのまま動かして「一般」に示すと決めている。ところが実装は、`kickstart` のコマンドが成功したら引き渡しの完了とみなして終了していた。launchd が起動の制約の違反で agent を止めたとき、アプリは何も示さずに消えた（`EVID-LCY-004`）。`kickstart` は起動を始めるだけで、exec の成否を待たないので、コマンドの成功は agent が動いたことを意味しない。

## 選択肢

- `kickstart` の成功で終了する（これまで）。起動の失敗に気づけず、アプリが消える。
- agent のプロセスが動いたことを確かめてから終了し、確かめられなければ動き続ける（採用）。
- 確かめられなければ、アラートで失敗を示して終了する（不採用）。利用者はアプリを使えなくなる。動き続けて「一般」に示す既存の扱いで足りる。

## 理由

- 利用者から見て、起動したアプリが黙って消えることがなくなる。失敗の扱いは既存の仕様のままでよい。
- 実行ファイルまで照らすのは、同じラベルのジョブが別のチェックアウトや別の場所のビルドを動かしている場合に、自分の引き渡しと取り違えないためである。

## 影響

- `SPEC-LCY-005` の引き渡しの記述を、この条件に合わせる。
- 確かめる間（多くは1秒未満）、直接起動したアプリと agent のアプリが同時に動く。直接起動したアプリは、確かめ終えるまでサービスを始めない（今の `AppRuntime.start` の順序のまま）。
- 起動の制約で止められる手元の ad-hoc 署名のビルドも、アプリは動き続け、「一般」に再起動されないことを示す。

## 覆す条件

- 5 秒を過ぎてから agent が起動し、アプリが2つ動く事例が見つかったとき。待つ時間か、確かめ方を見直す。
- macOS が、`kickstart` の結果で exec の成否を返すようになったとき。
