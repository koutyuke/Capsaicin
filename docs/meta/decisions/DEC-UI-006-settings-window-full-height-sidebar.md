# DEC-UI-006 設定ウインドウは全幅のタイトルバーを置かず、サイドバーを上端まで伸ばす

## 結論

設定ウインドウの上端に、全幅のタイトルバーの帯を置かない。サイドバーはウインドウの上端から下端まで伸ばし、閉じるボタンなどはサイドバーの上に重ねる。選んだセクション名は、システムのタイトルを隠し、右側の最上段にアプリが見出しとして描く。サイドバーの下の2項目（「ヘルパー」と「このアプリについて」）は、サイドバーの下端に寄せる。寸法と配置は `SPEC-SET-001` にある。

## 背景

オーナーが実機で見たところ、全幅のタイトルバーの帯がサイドバーと右側の上をまたいで横切り、違和感があった。また、下の2項目がサイドバーの下端から浮いていた。下の2項目の位置は、サイドバーの高さから固定の値を引いて決めていたため、行の高さと合っていなかった。

オーナーは、Xcode、Dropover、AltTab の設定ウインドウを参考に挙げた。いずれも、サイドバーがウインドウの上端まで伸び、閉じるボタンなどがサイドバーの上に乗っている。

## 選択肢

- 全幅のタイトルバーを残す（不採用。違和感の元である）。
- システムのタイトルをそのまま右側の最上段に出す（不採用）。実機で見ると、13 pt の灰色の文字で、項目のグループの左端より 7 pt 左にずれる。標準の仕組みでは位置を動かせない。
- 標準のツールバー（`.unified`）を付け、ツールバーのタイトルとして出す（不採用）。タイトルは項目の左端に揃い、15 pt の太字になる。一方で、上端の領域が 32 pt から 66 pt に広がって、両方の列の中身が下がる。さらに、SwiftUI の `List` が上端の余白を下端に回すため、下の2項目が下端から浮く。`contentMargins` では直せなかった。
- Dropover や AltTab のように、右側の内容の先頭に大きな見出しを置く（不採用）。内容の縦の余裕が減る。
- システムのタイトルを隠し、閉じるボタンなどと同じ行に、アプリが見出しを描く（採用）。

## 理由

- サイドバーが上端まで伸びる構成は、macOS 26 のシステム設定と Xcode と同じで、利用者が見慣れている。
- 見出しをアプリが描けば、上端の領域を 32 pt のままにでき、項目のグループの左端にも揃えられる。
- `window.title` は隠すだけで、選んだセクションに合わせて変え続ける。VoiceOver とウインドウメニューが使うため、HIG の求め（`EVID-UI-003`）を満たしたままにできる。
- 描くのは見出しの文字だけで、ウインドウの枠やボタンは標準のものを使う（`SPEC-UI-005`）。

## 影響

- `SPEC-SET-001` のタイトルとサイドバーの配置を書き換える。
- 右側の最上段の高さによって、内容に使える高さが変わる。最も行の多いセクションが収まるかは `HYP-UI-004` で確かめる。

## 覆す条件

- 標準のツールバーで、上端の高さとサイドバーの余白を崩さずにタイトルを項目の左端へ揃えられると分かったら、ツールバーのタイトルに戻す。
