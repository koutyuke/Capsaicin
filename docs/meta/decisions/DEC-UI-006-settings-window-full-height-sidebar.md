# DEC-UI-006 設定ウインドウは全幅のタイトルバーを置かず、サイドバーを上端まで伸ばす

## 結論

設定ウインドウの上端に、全幅のタイトルバーの帯を置かない。サイドバーはウインドウの上端から下端まで伸ばし、閉じるボタンなどはサイドバーの上に重ねる。上端は、項目を置かない標準のツールバー（`.unified`）にし、選んだセクション名をツールバーの標準のタイトルとして出す。Xcode の設定ウインドウから、戻る・進むのボタンをなくした形である。サイドバーの下の2項目（「ヘルパー」と「このアプリについて」）は、サイドバーの下端に寄せる。寸法と配置は `SPEC-SET-001` にある。

## 背景

オーナーが実機で見たところ、全幅のタイトルバーの帯がサイドバーと右側の上をまたいで横切り、違和感があった。また、下の2項目がサイドバーの下端から浮いていた。下の2項目の位置は、サイドバーの高さから固定の値を引いて決めていたため、行の高さと合っていなかった。

オーナーは、Xcode、Dropover、AltTab の設定ウインドウを参考に挙げた。いずれも、サイドバーがウインドウの上端まで伸び、閉じるボタンなどがサイドバーの上に乗っている。

## 選択肢

- 全幅のタイトルバーを残す（不採用。違和感の元である）。
- システムのタイトルをそのまま右側の最上段に出す（不採用）。実機で見ると、13 pt の灰色の文字で、項目のグループの左端より 7 pt 左にずれる。標準の仕組みでは位置を動かせない。
- 標準のツールバー（`.unified`）を付け、ツールバーのタイトルとして出す（採用）。タイトルは 15 pt の太字で、項目の左端に揃う。閉じるボタンなどは、Xcode と同じく上端から 26 pt の位置に乗る。
- Dropover や AltTab のように、右側の内容の先頭に大きな見出しを置く（不採用）。内容の縦の余裕が減る。
- システムのタイトルを隠し、閉じるボタンなどと同じ行に、アプリが見出しを描く（一度採用し、取りやめた）。上端の行が 32 pt のままなので、閉じるボタンなどと見出しの周りが詰まって見えた。

## 理由

- サイドバーが上端まで伸びる構成は、macOS 26 のシステム設定と Xcode と同じで、利用者が見慣れている。
- オーナーは、上端に Xcode と同じゆとりを求めた。標準のツールバーなら、その高さとタイトルの位置を独自の部品なしで得られる（`SPEC-UI-005`）。
- ウインドウのタイトルは選んだセクションに合わせて変わるため、HIG の求め（`EVID-UI-003`）を満たしたままにできる。

## 影響

- `SPEC-SET-001` のタイトルとサイドバーの配置を書き換える。
- ツールバーの表示方式は「アイコンのみ」（`.iconOnly`）にする。既定の表示方式ではラベルの行の分だけ上端が 66 pt に広がり、中身が Xcode より 14 pt 下がる。「アイコンのみ」なら Xcode と同じ 52 pt になる。
- ツールバーがあると、SwiftUI の `List` がスクロールの内容の高さにツールバー由来の余白（42 pt）を含める。そのため、下の2項目を下端に寄せる空きの高さは、`List` の裏の `NSTableView` から実際の行の高さを読んで決める。`contentMargins` では余白を変えられなかった。
- 右側の最上段の高さによって、内容に使える高さが変わる。最も行の多いセクションが収まるかは `HYP-UI-004` で確かめる。

## 覆す条件

- macOS の更新で `List` が `NSTableView` で描かれなくなり、下端寄せが働かなくなったら、下の2項目の置き方を見直す。
