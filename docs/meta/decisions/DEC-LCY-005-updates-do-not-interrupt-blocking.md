# DEC-LCY-005 更新のインストールで抑止を黙って止めず、更新後に再開もしない

## 結論

- 自動のインストールを選んでいる場合、ダウンロードした版は、抑止を止めていて設定ウインドウを開いていないときにインストールし、アプリを起動し直す。抑止中や設定ウインドウを開いている間は待ち、その状態が終わったときにインストールする。
- 利用者が抑止中にインストールを選んだら、インストールすると抑止を解除することを確かめる。続けたら、いつもの終了の後片付けをしてインストールする。取り消したら、今はインストールしない。
- 更新のための終了に、新しい終了の理由を足さない。`DEC-LCY-004` のとおり判定できない終了として後片付けし、更新した版は抑止を再開しない。
- 抑止の再開用の記録と設定の保存形式は、版をまたいで読めるようにする。形式を変える版は、前の形式を読めるようにする。
- 自動のインストールを待っている間にアプリがクラッシュすると、launchd による起動し直しとインストールが重なることがある。この組み合わせはまれなので、特別な処理を足さずに受け入れる。

## 背景

Sparkle は、インストールの前にアプリを終了させ、入れ替えた後に起動し直す（`DEC-SYS-019`）。抑止中に終了すると、後片付けで抑止が解除される。

Sparkle の既定では、自動でダウンロードした版はアプリの終了時にインストールし、1週間終了しなければインストールを促す。Capsaicin はメニューバーに常駐し、ログアウトや再起動まで終了しないことが多い。

Sparkle が終了させるときの quit イベントには、終了の理由が付かないと見込まれる。その場合、Capsaicin は判定できない終了として扱う（`DEC-LCY-004`、`HYP-LCY-005`）。

## 選択肢

- Sparkle の既定に任せ、終了時にインストールする。常駐するアプリではほとんどインストールされず、1週間後に促す画面が出る。終了がログアウトと重なると、旧版が書いた再開用の記録を新版が読む（不採用）。
- 抑止中でもすぐインストールし、更新の後に抑止を再開する。新しい終了の理由と再開の規則（`SPEC-LCY-004`）が要り、終了が取り消されたときの扱いも増える。得られるのは抑止の途切れが数秒短くなることだけである（不採用）。
- 抑止を止めているときにインストールし、抑止中は待つ（採用）。

## 理由

- 抑止は利用者が意図して始めたもので、更新のために黙って止めると、処理や作業を中断させる（`REQ-BLK-001`）。
- 抑止を止めている間に起動し直しても、利用者が失うものはない。メニューバーのアイコンが一瞬消えるだけである。
- 終了の理由を偽らない規則（`DEC-LCY-004`）をそのまま保て、再開の規則も増えない。

## 影響

- 自動のインストールの説明は「次に終了したとき」ではなく「抑止を止めているとき」になる。
- 更新の仕組みが、抑止の状態と設定ウインドウの表示の変化を知る必要がある。
- 抑止中に手動でインストールするときに、確認が1回増える。
- 保存形式を変える変更に、前の形式を読むことが加わる。

## 覆す条件

- `HYP-LCY-005` か `HYP-SYS-002` で、Sparkle による終了が利用者の終了やセッションの終了として判定されると分かったとき。
- 抑止を止めている間の起動し直しが、利用者に気づかれて邪魔になると分かったとき。
- 自動のインストールを待っている間のクラッシュと起動し直しの重なりで、実際に不具合が起きたとき。
