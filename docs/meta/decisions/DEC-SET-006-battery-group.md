# DEC-SET-006 「スリープ」のバッテリー残量の条件を、時間の自動解除とは別のグループ「バッテリー」にする

## 結論

`DEC-SET-005` のうち、グループの分け方とバッテリー残量のスイッチの項目名を改める。ほかの決定（セクション名「スリープ」、「ディスプレイを閉じたとき」のポップアップ、(i) を置く範囲、`DEC-SET-004` から引き継いだカード・アイコン・子の行の字下げ・スクロール）はそのまま引き継ぐ。

- 「スリープ」のグループを次の3つにする。
  - 「スリープとディスプレイ」: 今の2項目。
  - 「スリープ防止の自動解除」: タイマーと指定時刻。
  - 「バッテリー」: バッテリー残量の条件のスイッチ、しきい値、電源アダプタ接続中は残量でオフにしない。
- バッテリー残量の条件のスイッチの項目名を、何がオンになるかが分かる言い切りの文にする（例: 「残量が少なくなったらオフにする」）。

## 背景

オーナーは、バッテリー残量の条件を自動解除の条件ではなく安全策と位置づけた（`DEC-MENU-005`）。メニューを実機で見たオーナーから、設定画面ではタイマー・指定時刻・バッテリー残量が同じ「スリープ防止の自動解除」に並ぶのにメニューでは分かれて見えること、バッテリーは時間・時刻と違って開始の条件ではなくオプションに感じることが挙がった。

仕様の上でも、タイマー・指定時刻とバッテリー残量の条件は振る舞いが違う。タイマーと指定時刻は「スリープ防止をオンにする」で使う既定値で、メニューや CLI の時間の指定で置き換えられ、スリープ防止中に変えてもいまのスリープ防止には効かない（`SPEC-BLK-003`、`SPEC-BLK-009`）。バッテリー残量の条件は開始の方法によらず働き、スリープ防止中に変えるとその場で反映し、成り立っていれば開始を拒否する（`SPEC-BLK-006`、`SPEC-BLK-009`）。

## 選択肢

- バッテリー残量の条件を別のグループにする（採用）。設定画面の分け方が振る舞いの違いと一致し、メニューの見出しも設定画面と同じ文言のまま分けられる。
- 設定画面は今のままにし、メニューでだけ別の見出しにする。変更は小さいが、設定画面とメニューで同じ項目の分け方が食い違う。

アドバイザーの2人（Codex と Claude）は、どちらも別のグループにする案を推した。

## 理由

- 時間の自動解除は開始のときに選ぶもの、バッテリー残量の条件はいつも働く安全策、という区別を、設定画面とメニューで同じ形で見せられる。
- グループの見出しが「バッテリー」になると、スイッチの項目名「バッテリー残量」では何がオンになるかが分からない。言い切りの文にすると、チェックやスイッチが「それが有効」を示す形にそろう。

## 影響

- `SPEC-SET-002` の表、`SPEC-SET-006` のハードウェアによる出し分け、手順書の設定画面の確認を直す。
- バッテリー残量のスイッチの文言を変える。保存の形と振る舞いは変えない。
- グループが1つ増える。

## 覆す条件

- バッテリー残量の条件が、タイマーや指定時刻と同じく開始のときに選ぶものになる。
- 3つのグループで「スリープ」の見通しが悪くなったという報告が続く。
