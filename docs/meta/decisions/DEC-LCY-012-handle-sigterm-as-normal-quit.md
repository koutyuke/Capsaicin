# DEC-LCY-012 SIGTERM を通常の終了として扱い、後片付けしてから終了する

## 結論

- アプリは `SIGTERM` を受けたら、利用者の終了ではない終了として、`SPEC-LCY-002` の終了時の後片付けを行ってから終了する。合わせられない制御が残ってもダイアログを出さず、ログに残す。HUD は出さない。
- バックグラウンドの項目のオフでは、macOS がアプリを終了させることを通常の振る舞いとする。デーモンの後片付けは `DEC-LCY-010` のとおり。
- アプリが終了させられずに動き続けた場合の扱い（`DEC-LCY-010` の、切断と承認待ちを検知して解除し HUD で知らせる処理）は残す。

## 背景

`EVID-HLP-016` ではアプリが動き続けたが、`EVID-HLP-017` では抑止の有無・ヘルパー・「ログイン時に起動」によらず `SIGTERM` で終了させられた。`SIGTERM` の既定の動作では即座に終わるので、LED の点灯と「明るさを0」の輝度が、次に開くまで残っていた（`SPEC-LCY-003` と同じ状態）。

## 選択肢

1. 何もしない: 項目をオフにするたびに LED と輝度が残る。
2. `SIGTERM` を通常の終了の経路に流す（採用）: 今ある後片付けをそのまま使い、新しい仕組みを作らない。`kill` やログアウトで届く `SIGTERM` も同じく後片付けする。
3. 終了する前に HUD を出す: HUD は約 2.1 秒かかり、その間終了を遅らせると `SIGKILL` で後片付けごと打ち切られるおそれが増える。`SIGTERM` の送り主（項目のオフ、`kill`、ログアウト）を確実には見分けられず、BTM の更新と終了の要求は同時に起きる。

動き続けた場合の扱いを削る案も検討した。`EVID-HLP-016` の状態では実際に通る経路で、実装と実機の確認が済んでいるので残す。

## 理由

項目のオフで終了させられるのは、利用者の Mac での通常の振る舞いである。そのたびに LED と輝度が残る状態は放置しない。今ある終了の経路に流せば、後片付けの中身と順序（`SPEC-LCY-002`）を1か所に保てる。

## 影響

- 仕様: `SPEC-LCY-002`、`SPEC-LCY-003`、`SPEC-HLP-004` と、その項目のオフを扱う受け入れ例（settings、hud、blocking）。
- 実装: `AppDelegate` に `SIGTERM` の監視を足す。

## 覆す条件

- `HYP-LCY-010` が外れ、後片付けの前に `SIGKILL` を受けると分かったとき。
- macOS が項目のオフでアプリを終了させなくなったとき。
