# DEC-MENU-003 メニューバーのアイコンは動かさずに替える

## 結論

抑止の状態が変わったら、メニューバーのアイコンを `NSStatusBarButton` の `image` に入れ替えるだけにし、置き換えの動きを付けない。これは、`DEC-MENU-002` の「影響」にあった、HUD と同じ置き換えの動きを付けるという方針をやめるものである。輪郭と塗りつぶしの使い分けは `DEC-MENU-002` のまま変えない。

## 背景

ディスプレイを2枚つないでいると、フォーカスのないディスプレイのメニューバーのアイコンが前の状態のまま残った。ほかのディスプレイのアイコンは AppKit が描いた画像の複製で、置き換えの動きの途中で描かれた画像が残る（`EVID-MENU-001`）。抑止中なのに輪郭のアイコンが出続けるので、`REQ-MENU-004` の「抑止中かどうかをアイコンの見た目で示す」を満たさない。

## 選択肢

- 動かさずに `button.image` に入れる（採用）。どのディスプレイでもすぐに正しいアイコンになる。ボタンに重ねた画像ビューと、ボタンの幅を測る手順が要らなくなる。
- 今の置き換えの動きを残し、少し後にボタンを描き直させて複製を更新する。フォーカスのあるディスプレイでは動きが残るが、ほかのディスプレイでは1秒ほど前の状態が残る。動きの終わりを知る API がないので待ち時間を決め打ちすることになり、短すぎると動きの途中の画像が残る。
- 画像は動かさずに入れ、動きは Core Animation のアニメーションで別に付ける。複製用の画像はアニメーションを含まずに描かれるので、フォーカスのあるディスプレイだけが動き、ほかは瞬時に切り替わる。OS の Bluetooth などのアイコンと同じ見え方になる。代わりに、SF Symbols の置き換えではなく似せた動きを自分で作って調整し、2枚のディスプレイで確かめ続けることになる。HUD の動きとも揃わない。

## 理由

- どのディスプレイでも抑止の状態を正しく示すことが、動きより優先する。この案は、それを一番少ないコードで満たし、今よりコードを減らす。
- `button.image` はステータス項目の標準の描き方なので、メニューバーの明暗での色、メニューを開いたときの強調、複製の更新を AppKit に任せられる。
- 動きは状態が変わった瞬間に1回だけ付ける飾りで、なくても状態の伝わり方は変わらない。オーナーも、似せた動きを作り込むほどの効果はないと判断した。

## 影響

- `SPEC-MENU-005` と `SPEC-UI-006` から、メニューバーのアイコンの置き換えの動きを除く。
- 「視差効果を減らす」に合わせた分岐が、メニューバーのアイコンでは要らなくなる。
- HUD のアイコンの置き換えの動き（`SPEC-HUD-006`）は変えない。メニューバーと HUD で、切り替わり方が揃わなくなる。

## 覆す条件

- 公開 API で、フォーカスのあるディスプレイだけを動かし、ほかのディスプレイを正しい状態にできる手段が出る。
- 切り替わりに動きがないため、利用者が状態の変化に気づかないという声が出る。
