# DEC-UI-011 画面の文言はスリープとディスプレイについて macOS のシステム設定の言い方に合わせ、アプリの動作は動詞句で書く

## 結論

画面に出す日本語の文言では、スリープとディスプレイを macOS のシステム設定と同じ言葉で書く。

| 指すもの | 書き方 | 例 |
| --- | --- | --- |
| Mac 全体のスリープ | 「スリープ」 | 「ディスプレイを閉じてもスリープさせない」 |
| ディスプレイだけが眠ること | 「ディスプレイをオフにする」 | 「ディスプレイを自動でオフにしない」 |
| ディスプレイをスリープさせず輝度を 0 にすること | 「明るさを0にする」 | （追加の判断は `DEC-BLK-007`） |

そのほかの言い方は次のとおりにする。

- 「システムスリープ」「ディスプレイスリープ」は画面に出さない。
- アプリ自身が何をするかは、「スリープさせない」「オフにしない」「スリープを止める」のような動詞句で書く。「防止」「制限」「抑止」を新しい文言に使わない。既存の機能名「スリープ防止」の扱いは `Q-UI-002` で決める。
- 設定画面の (i) で、Capsaicin が止めている間のことを書くときは「Capsaicinがオンの間は」で始める。
- 装置としての画面と、その状態（オフ、閉じる、明るさ）は「ディスプレイ」と書く。「画面」は、設定画面、ロック画面のような表示の内容や機能を指すときだけに使う。
- ノートブックの蓋と、それを閉じる操作は「ディスプレイ」「ディスプレイを閉じる」と書く。「蓋」は画面に出さない。
- 「消灯」「点灯」は Caps Lock の LED だけに使う。
- 「手動スリープ」は画面に出さない。アップルメニューの「スリープ」などの操作で書く。
- 「スクリーンセーバ」「電源アダプタ」は語尾を伸ばさない。

文書の中の呼び名（`specs/blocking.md` の「手動スリープ」「ディスプレイスリープ」など）は、この判断の対象にしない。

## 背景

`DEC-UI-009` は、止まるものを名前で区別するため「システムスリープ」「ディスプレイスリープ」を画面に出すとしていた。実装してみると、オーナーは macOS のシステム設定と言い方がずれることを嫌い、システム設定に合わせる方針に改めた。macOS の今の日本語 UI は、ディスプレイスリープを「ディスプレイをオフにする」と書く（[Mac の「ロック画面」設定を変更する](https://support.apple.com/ja-jp/guide/mac-help/mh11784/mac)）。

あわせてオーナーは、「防止」という言葉に違和感を示した。「防止」は防ぐ対象を「起きては困ること」と評価する語で、外からアプリを分類するラベル（「スリープ防止アプリ」）には合うが、アプリが自分の動作を言うには合わない。「制限」は「限度を設けて一部を許す」「相手の自由を縛る」含みがあり、選んだ種類のスリープを止める動作と合わない。

## 選択肢

- `DEC-UI-009` のまま「システムスリープ」「ディスプレイスリープ」で区別する。名前だけで何が止まるかが分かるが、システム設定と言い方が違う。
- システム設定の言い方に合わせる（採用）。なじみがあり、システム設定と見比べやすい。何が止まるかは、項目名の動詞句と (i) で補う。

## 理由

- 利用者はシステム設定のスリープとディスプレイの設定と見比べて使う。言い方が同じなら、どの設定に対応するかを迷わない。
- 「スリープ」と「ディスプレイをオフにする」は対象（Mac とディスプレイ）が違う言葉なので、名前を作らなくても区別できる。
- 動詞句は、スリープを良い悪いと評価せずに、アプリが何をするかだけを言える。

## 影響

設定画面、ヘルパーの確認ダイアログ、CLI の文言を、この規則に合わせる。メニュー、HUD、CLI に残る機能名「スリープ防止」は `Q-UI-002` を決めるまで変えない。

## 覆す条件

- 「スリープ」だけでは Mac 全体のスリープか分からないという報告が続く。
- macOS の日本語 UI が、スリープとディスプレイについて別の言い方に変わる。
