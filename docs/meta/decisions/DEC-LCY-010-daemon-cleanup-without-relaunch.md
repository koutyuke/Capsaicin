# DEC-LCY-010 クラッシュ時の再起動と抑止の再開をやめ、disablesleep の後片付けをデーモンに任せる

## 結論

アプリをクラッシュ時に起動し直す agent と、抑止の再開をやめる。アプリが後片付けをできずに終わったときに残る `disablesleep` は、ヘルパーのデーモンが戻す。

- **agent をやめる**: `SMAppService.agent` の登録、バンドルの `Contents/Library/LaunchAgents/` の plist、`launchctl kickstart` による引き渡しをなくす。直接起動したアプリが、そのまま動き続ける。「ログイン時に起動」は `SMAppService.mainApp` のまま残す。agent を登録した版から移ったアプリは、起動時に agent の登録を一度外す処理を持たない（開発機に残る Debug の登録は手作業で外す。利用者の Mac には agent を配布していない）。
- **再開をやめる**: 「スリープ防止の再開」の設定、起動の理由の判定、連続クラッシュの上限、再開用の記録の抑止のセッション・実行中の印・終了の理由・クラッシュ後の起動の時刻をなくす。アプリはどう起動しても停止中で始まる。
- **デーモンが後片付けする**: アプリは、ヘルパーの `on` を送った接続を、抑止中に `disablesleep` が要る間は保つ。デーモンは `on` を受けた接続に後片付けの役目を持たせる。その接続から `off` を受けたら役目を外し、`off` を受けずに接続が切れたら（アプリの終了やクラッシュ）`off` を実行する。launchd から `SIGTERM` を受けたとき（システム設定でバックグラウンドの項目をオフにしたときなど）も、役目を持つ接続があれば `off` を実行してから終了する。役目を持つ接続がある間は、アイドルでも終了しない。受け付ける要求は `on` と `off` のままである。
- **デーモンが落ちたら**: アプリは接続の中断を受けたら、接続を張り直して `on` を送り直し、役目を戻す。送り直せなければ、合わせられていない制御として扱う。
- **バックグラウンドの項目がオフになったら**: 接続が切れ、デーモンの状態が承認待ちになったら、アプリはヘルパーが要る抑止を解除し、HUD でそのことを知らせる。
- **所有はメモリーだけに持つ**: Capsaicin が `disablesleep` を立てたかは、アプリのメモリーだけに持ち、保存しない。起動時は「立てていない」から始め、そのとき `SleepDisabled` が 1 なら外部のものとして扱う。`kern.boottime` で Mac の起動をまたいだかを判定する処理をなくす。
- **保存する記録**: 保存するのは「明るさを0」で暗くする前の輝度の記録だけにする。記録を保存できなくても、抑止の開始は拒否しない。保存できないことを警告で示す。「明るさを0」は、輝度の記録を保存できたときだけ暗くする。
- **起動時の輝度**: 起動時に輝度の記録があれば、いまの輝度が 0 のときだけ記録した値を書き、それ以外は記録を消すだけにする。ディスプレイを開いたときと解除のときは、これまでどおりいまの輝度によらず記録した値を書く。
- **LED**: アプリが後片付けをできずに終わると、LED は点いたまま残る（`EVID-LCY-007`）。次の起動で通常の連動に戻す。
- **終了の扱い**: 終了は、どの種類でも停止中のあるべき状態に合わせる。合わせられないときにエラーのダイアログを出すのは利用者の終了だけで、それ以外の終了では出さない。

## 背景

Developer ID で署名してから、手元の `just restart` のビルド、PR の Debug ビルド、試作のビルドが同じ bundle ID の agent を取り合い、Debug アプリを確実に終了・起動できない状態が多発した。登録し直しを版の番号だけで判定していることが直接の原因だが、そもそも agent がクラッシュ時の再起動と再開のためだけにある。

クラッシュや Mac の再起動は利用者にも分かる出来事である。クラッシュすれば macOS がそのことを示し、Mac の再起動は利用者が自分で行う。どちらの後も抑止が自動で戻らなくても、利用者は自分で開始し直せる。一方、`disablesleep` が残ると Mac がスリープしなくなり、利用者は原因に気づきにくい。後片付けだけは誰かが確実に行う必要がある。

## 選択肢

1. agent の登録し直しの判定を直し、再起動と再開を残す: 同じ bundle ID の複数のコピーが登録を取り合う構造は残る。どのコピーの登録かの判定、移動したアプリの扱い、ビルドごとの識別子など、開発のための仕組みが製品に増える。
2. agent をやめ、再開も含めて後片付けをデーモンに任せる（採用）: デーモンは root で常に `off` を実行でき、アプリの終了を XPC の切断で受け取れる。再開がなくなるので、記録と起動時の処理が大きく減る。
3. agent をやめ、後片付けは次の起動に任せる: 利用者が開き直すまで `disablesleep` が残る。

## 理由

実機で、アプリを `SIGKILL` と `SIGSEGV` で終了させてもデーモンが切断を受けて1秒以内に `off` を実行すること（`EVID-HLP-010`）、バックグラウンドの項目をオフにしても `SIGTERM` で `off` を実行し、アプリがそれを検知できること（`EVID-HLP-012`）、デーモンが落ちてもアプリが `on` を送り直せること（`EVID-HLP-013`）を確かめた。`disablesleep` の後片付けに agent は要らない。

再起動がなくなると残るのは LED と輝度である。LED は次の起動で戻せ（`EVID-LCY-007`）、輝度は 0 のままでも開いた画面は見え、輝度のキーで戻せる（`EVID-BLK-015`）。どちらも利用者が気づけて自分で戻せるので、既知の制約として受け入れる。

所有を保存しなくてよくなるのは、Capsaicin が立てた `disablesleep` をアプリの終了時にデーモンが必ず戻すからである。次の起動の時点で 1 なら、それは外部のものか、デーモンが戻せなかったものである。後者は Mac の起動時の後片付け（`SPEC-HLP-003`）が戻す。

起動時の輝度を、いまの輝度が 0 のときだけ戻すのは、クラッシュの後に利用者が自分で戻した輝度を上書きしないためである。実機では、開いた後に利用者が上げた輝度を、起動時の処理が記録の値に戻した（`EVID-BLK-015`）。

## 影響

- 要件: `REQ-LCY-003` を「後片付けをできずに終わっても `disablesleep` を残さない」に書き換え、再開を選べる要件と、どう起動してもクラッシュ時に再起動される要件を削除する。単一インスタンスの要件は `DEC-LCY-011` で足す。
- 仕様: lifecycle の後片付け・起動時の処理・更新の仕様を書き直し、再開、launchd の管理下で動くこと、再開用の記録の仕様を削除する。輝度の記録は blocking に移す。helper の `SPEC-HLP-002`（後片付けの役目）、`SPEC-HLP-004`（項目をオフにしたとき）、`SPEC-HLP-005`（所有をメモリーに持つ）、`SPEC-HLP-007`（agent の登録し直しをなくす）、blocking の `SPEC-BLK-013` と `SPEC-BLK-007`、settings の「スリープ防止の再開」と「一般」の警告、menu と cli の状態を保存できないときの扱い、HUD を直す。
- 実装: agent の plist とその登録・引き渡し、`ResumeRecord` の再開のための値、起動の理由の判定、再開の処理と設定を削る。デーモンに接続ごとの後片付けの役目と `SIGTERM` の処理を足す。アプリに接続の保持と送り直し、項目のオフの検知を足す。
- 開発: justfile の `app` グループ、`scripts/debug-app.sh`、`AGENTS.md`、`DEC-SYS-024`、`DEC-SYS-026` の agent に関する記述を直す。開発機に残った Debug の agent の登録は手作業で外す（`docs/manual/verification/prepare.md`）。
- 代償: クラッシュの後、利用者が開き直すまで LED は点いたままで、「明るさを0」の画面は暗いままである。抑止は自動で戻らない。デーモンの後片付けは root の C のコードを、接続ごとの役目の管理と `SIGTERM` の処理の分だけ増やす（root で行う処理は `on` と `off` のまま）。

## 覆す条件

- デーモンが XPC の切断や `SIGTERM` を受け取れず、`off` を実行できない環境が見つかったとき。
- クラッシュの後に抑止が戻らないことや、LED と輝度が残ることで、利用者が困る報告が続いたとき。
- 同じ bundle ID の複数のコピーを区別せずに agent を扱える方法が見つかり、再起動の価値が代償を上回ると分かったとき。
