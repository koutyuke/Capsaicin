# DEC-LED-006 LED は実機のキーボードだけに書き、仮想キーボードがあるときは LED が点かないことがあると案内する

## 結論

`DEC-LED-001` を補い、次のようにする。API の呼び方、書き込みの対象、取り合わないことは `DEC-LED-005` から変えていない。変えたのは案内の条件と内容である。

- **API の呼び方:** SDK の公開ヘッダーにある `IOHIDEventSystemClient` と `IOHIDServiceClient` の関数で呼べるなら、それを使う。公開されていない関数が要る場合は、小さな C のモジュールに宣言を閉じ込め、弱いリンク（weak import）にする。`dlsym` と関数の型の手作業の変換は使わない。関数がないときの振る舞いは `SPEC-LED-006` にある。
- **書き込みの対象:** 実機のキーボードだけに書く。キー配列を変えるアプリが作る仮想キーボードには書かない。
- **ほかのアプリとの関係:** 取り合わない。ほかのアプリが LED を管理するキーボードでは、抑止中も LED が点かないことを受け入れる。
- **案内の条件:** 仮想キーボードがあるときに案内を出す。仮想キーボードの見分け方は、書き込みの対象から外すものと同じにする。アプリの名前やプロセスでは判定しない。
- **案内の内容:** キー配列を変更するアプリが動作していることと、そのアプリが LED を制御している場合は抑止中も LED が点灯しないことがあることだけを伝える（`SPEC-LED-005`）。特定のアプリの名前、設定、避け方は書かない。

## 背景

`DEC-LED-005` は、Karabiner-Elements のプロセスを検出したら、LED が点かないことと「Manipulate caps lock LED」をオフにする避け方を案内すると決めていた。案内を、LED に影響するときだけに絞る方法を `TASK-055` で調べ、次のことが分かった。

- Karabiner-Elements のアプリを終了しても常駐プロセスは残るので、プロセスの検出では案内が出続ける。仮想キーボードは、アプリの終了で消える（`EVID-LED-009`）。
- キーボードの占有の印（`DebugState`）で、アプリの終了と「Modify events」のオフは見分けられる。ただし、デバッグ用の値で、「Manipulate caps lock LED」をオフにしても印は残る（`EVID-LED-009`、`HYP-LED-008`）。
- 「Manipulate caps lock LED」のオン・オフは、Karabiner-Elements の設定ファイルを読まない限り分からない。

オーナーは、案内を「点かないことがある」という可能性の提示にとどめ、Karabiner-Elements に限らない形にすると決めた。

## 選択肢

- Karabiner-Elements のプロセスの検出を続け、文面だけを「点かないことがある」に寄せる。最も安いが、アプリを終了しても案内が出続け、Karabiner-Elements にしか効かない（不採用）。
- 占有の印で判定する。デバッグ用の値に頼り、LED の管理をオフにしても案内が残る（不採用）。
- 占有の印と Karabiner-Elements の設定ファイルで判定する。ほかのアプリの設定の形式、既定値、保存先に追従し続ける必要がある（不採用）。
- 仮想キーボードの有無で判定し、可能性だけを伝える（採用）。
- 光らせるキーボードを「すべて」「内蔵のみ」「外付けのみ」から選べるようにする。Karabiner-Elements は既定で内蔵と外付けの両方を管理するので、この問題を避けられない。案内とは別の機能なので、要望が出るまで作らない（不採用）。

## 理由

- 書き込みの対象から仮想キーボードを外す判定と同じルールで済み、アプリの名前に頼らない。
- Karabiner-Elements では、アプリを終了すれば仮想キーボードが消え、案内も消える。
- 仮想キーボードの有無は、LED が消されることを確かに示すものではない。仮想キーボードを作らずに入力を変えるアプリ、`Transport` を名乗る仮想キーボード、キー配列と関係のない仮想キーボードは見分けられない。文面を「点灯しないことがある」にとどめれば、誤って出たときや出なかったときの害は小さい。
- 特定のアプリの設定名を書くと、そのアプリの変更に追従が要る。「入力機能には影響ありません」は Karabiner-Elements でしか確かめていないので、一般的な案内には書けない。

## 影響

- Karabiner-Elements が既定の設定で占有するキーボードでは、抑止中も LED が点かない。Karabiner-Elements の利用者は、避け方を自分で探す必要がある。
- 案内は、Karabiner-Elements 以外のアプリの仮想キーボードでも出る。仮想キーボードが残っている間は、「Manipulate caps lock LED」をオフにした後も出る。
- `SPEC-LED-002` の対象から仮想キーボードを外す。実機と仮想の見分け方は `HYP-LED-007` で確かめる。案内の条件も同じ見分け方に頼る。
- 案内の判定に `DebugState` と Karabiner-Elements の設定ファイルは使わない。

## 覆す条件

- 公開ヘッダーの関数だけで `HIDCapsLockLED` を書けないと分かったら、呼び方を見直す。
- Karabiner-Elements が、仮想キーボードの LED を Caps Lock の状態として使わなくなった、または LED だけを点ける連携の手段を用意したら、対象と案内を見直す。
- 実機と仮想を見分けられないと分かったら（`HYP-LED-007`）、対象の決め方と案内の条件を見直す。
- 仮想キーボードがないのに LED が消される事例や、LED に影響しない仮想キーボードで案内が出続ける事例が多いと分かったら、案内の条件を見直す。
