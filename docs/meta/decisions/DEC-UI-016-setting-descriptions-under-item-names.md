# DEC-UI-016 設定の説明は (i) をやめ、項目名の下に説明文として出す

## 結論

- 設定の行の説明は、項目名の横の (i) とポップオーバーをやめ、macOS のシステム設定と同じく、項目名の下に説明文として常に出す。VoiceOver では、説明文をその行のコントロールのヒントとして読む。説明文の中のリンクは押せるようにする。
- 説明文は、その行で知っておくべきことだけを短く書く。説明を置く行の基準（項目名から分からない連動や制約がある行だけに置く。`DEC-SET-005` で決め、`DEC-SET-008` まで引き継いだもの）は変えない。この基準に照らし、項目名とコントロールで足りる「ディスプレイを閉じたとき」「スリープ防止の切り替え」「コマンドの場所」「自動アップデート」には説明を置かない。

## 背景

オーナーは、システム設定のように項目名の下に説明を出したいとした。(i) は開くまで中身が読めず、注意の記号が出ている行でも、理由を読むのに操作が要った。

## 選択肢

- (i) を押すとポップオーバーで開き、ツールチップも付ける（これまで。`DEC-UI-002`）。行はすっきりするが、読むのに操作が要る。
- 項目名の下に説明文を常に出す（採用）。システム設定と同じ形で、操作なしで読める。行が高くなる。

## 理由

- 説明を読むのに操作が要らない。注意の記号が出ている行では、理由もそのまま読める。
- 説明文をコントロールのヒントにすれば、キーボードと VoiceOver でもコントロールに移るだけで読める（`REQ-UI-003`）。`DEC-UI-002` が無効の行でも (i) を押せるようにした理由（無効の理由を読む手段を残す）も、常に出ていれば満たせる。
- 行が高くなる分、説明文を短くし、項目名とコントロールで足りる行からは説明をなくす。

## 影響

- `REQ-SET-003` の文と、`SPEC-SET-002`、`SPEC-SET-003`、`SPEC-SET-005`、`SPEC-SET-006`、`SPEC-SET-007`、`SPEC-UI-001`、`SPEC-UI-002`、`SPEC-UI-007`、`SPEC-HLP-001`、`SPEC-HLP-004` の (i) の記述を説明文に改める。
- 採用中の判断が (i) で伝えるとしている内容は、説明文を置く行ではその説明文で伝える。説明をなくした行の内容は画面では伝えない。たとえば、シェルから使うためのリンクやエイリアスの作り方（`DEC-CLI-001`）、ホットキーで開始したときに設定の解除条件を使うことである。
- 「ディスプレイを閉じたとき」でヘルパーが要ることは、選んだときの設置の確認（`SPEC-HLP-001`）で伝える。

## 覆す条件

- 説明文で行が高くなり、ページの見通しが悪いという報告が続く。または、スクロールせずに収まるはずのページが収まらなくなる（`HYP-UI-004`）。
- 説明をなくした行について、意味が分からないという報告が続く。
