# DEC-SYS-030 文書が指す手元のファイルは、Git で追跡しているものに限る

## 結論

文書（根拠の `sources` と本文を含む）が資料として指してよい手元のファイルは、リポジトリで Git が追跡しているファイルと、`develop` の履歴にあるコミットのファイルだけにする。OS や SDK に入っている資料は、どの Mac でも同じものが読めるので例外として絶対パスで指してよい。ホームの作業フォルダー、`~/Library` のアプリのデータ、`/var/log` のログ、Git が無視する生成物は指さない。

実機で取ったログや画面写真は、リポジトリに入れず参照もしない。結論に要る値（時刻、読み取った値、ログの行）は根拠の本文に書く。文書の検査で `sources` の形を確かめる。

## 背景

根拠26件の `sources` と本文が、実機の確認で作ったホームのフォルダー14個（`~/Capsaicin-verification.*` など、動画を含めて約 200MB）を記録の所在として指していた。確認が終わってもフォルダーを片付けると参照先がなくなるので、消せなかった。ほかにも、`~/Library` の再開記録、`/var/log` の Karabiner のログ、Git が無視する生成物の `Package.resolved`、削除したファイルを今のパスで指す `sources` があった。

これらは記録を書いた Mac でしか読めない。委譲先の worktree、ほかの Mac、CI からは読めず、検査でも存在を確かめられない。根拠の本文には読み取った値がすでに書かれており、生の記録がなくても結論は読める。

## 選択肢

- ホームのフォルダーを残し、今のまま指す。片付けられず、書いた Mac の外では読めないことは変わらない。
- 生の記録をリポジトリに入れる。動画を含めると大きく、ログには機器の識別子や利用者名が入る。結論に要らない行がほとんどで、読み手が探す手間も増える。
- 追跡しているファイルだけを指し、結論に要る値を本文に書く（採用）。

## 理由

- 文書の読み手が誰でも、どの worktree でも、同じ資料を引ける。
- 検査が `sources` の存在を確かめられるので、参照切れに気づける。
- 実機の記録を、確認が終われば気兼ねなく片付けられる。

## 影響

- `documentation-management.md` の `sources` の規則を、この判断に合わせる。
- 既存の根拠から、追跡していないファイルへの参照を外す。生の記録から確かめ直すことはできなくなる。
- 実機の確認の手順書は、記録を手元のフォルダーに残してよい。根拠を書くときに、要る値を本文へ移す。

## 覆す条件

- 生の記録を確かめ直す必要が繰り返し出たら、結論に要る抜粋をリポジトリに置くことを考える。
- 根拠の結論が、本文に書ききれない量のデータに依存するようになったら、データの置き場所を決め直す。
