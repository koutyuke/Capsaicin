# DEC-SYS-020 実機確認の操作は just のレシピにし、手順書のシェル変数は退避先だけにする

## 結論

- 実機確認で Debug アプリを操作する入口は、justfile の `manual` グループのレシピ（`start`、`stop`、`restart`、`status`）にする。`scripts/manual/verify.sh` は削除する。レシピはオーナーだけが実行し、エージェントは実行しない。
- `stop` と `status` は、どのチェックアウトの Debug ビルドも対象にする。`start` は、Debug アプリが動いていないことを確かめ、LaunchAgent のジョブを外してから、このチェックアウトのビルドを開く。
- 手順書 `docs/manual/verification.md` が持つシェル変数は、検証ごとの退避先 `B` だけにする。`B` は1節で作り、再ログインの後はメモした絶対パスを貼り直す。試験対象の CLI のパスは、使う節の冒頭で定義する。そのほかのパスと bundle ID はリテラルで書く。
- 検証用の変数は `.envrc` にも devShell にも置かない。
- レシピの出力は英語にする。

## 背景

`verify.sh` は、操作（restart、stop、status）と、手順書の11個の変数を出す `env` を1つのスクリプトにまとめていた。オーナーは、操作を just のほかのレシピと同じ形で呼びたいと考えた。

`env` が出す変数の多くは、固定のパスに名前を付けただけだった。手順書はログアウトや再起動をはさむので、貼り付けるコマンドが変数に依存すると、入れ直し忘れが起きやすい。`env` は退避先を「いちばん新しい `~/Capsaicin-verification.*`」として推測していたが、mtime は古い退避先に書き足しただけで変わる。また、`B` が空のまま `sudo /bin/mv "$RULE" "$B/…"` を実行すると、root 権限でファイルシステムのルートに移動する。

Debug ビルドは、すべての worktree で bundle ID と LaunchAgent を共有する。`verify.sh` の `stop` は、このチェックアウトのパスに一致するプロセスしか探さなかったので、別の worktree のビルドが動いていると「動いていない」と判断して終了した。アプリは起動時に plist を書き直して `bootstrap` と `kickstart` を行うが（`DEC-LCY-002`）、ジョブが読み込まれたままだと `bootstrap` が失敗し、読み込み済みの古いビルドが起動する。

## 選択肢

- `verify.sh` を残し、just のレシピから呼ぶ。入口は増えるが、操作が2か所に分かれたままになる（不採用）。
- 変数を `.envrc` や devShell の `shellHook` で配る。direnv は任意であり、検証ごと・チェックアウトごとに変わる値を開発者全員とエージェントの環境に入れることになる。`nix develop --command` のサブシェルからは対話シェルに値が届かない（不採用）。
- 頻繁に使う長いパス（`JOB`、`PLIST`、`RECORD`、`APP`、`CLI`）を略記として残す。行は短くなるが、貼り付けるたびに変数の入れ直しが前提になる（不採用）。
- 変数を退避先だけにし、状態の確認と起動・停止を just に寄せる（採用）。

## 理由

- 退避先は検証ごとに変わり、ほかに代わりがない。それ以外は、リテラルで書けば新しいシェルにそのまま貼れ、`sudo` や `trash` の対象もその場で見える。
- 手順書で変数を使っていた箇所の多くは状態の確認だったので、`just status` にまとめられる。
- 共有する LaunchAgent が別のチェックアウトのビルドを指していても、`start` で確実にこのチェックアウトのビルドを起動できる。

## 影響

- `AGENTS.md` の「`scripts/manual/` はオーナー専用」を、`manual` グループのレシピの記述に置き換える。
- `start` のジョブの取り外しは、plist を消さない一時的な操作である。オーナーだけが実行する。
- shellcheck は justfile のレシピを検査しないので、レシピは小さく保つ。
- 手順書のリテラルは、bundle ID やヘルパーの配置先を変えたら合わせて直す。

## 覆す条件

- 手順書のリテラルが実装とずれる事故が起きたら、パスを一か所で定義する方法を考え直す。
- エージェントが `manual` グループのレシピを誤って実行したら、`[confirm]` などの歯止めを足す。
