# DEC-SET-007 ヘルパーを使えない行に短い状態の文を出し、承認を待つ間の選び直しはアラートで許可を案内する

## 結論

`DEC-SET-006` が引き継いだ「(i) を置く範囲」の規則（各項目に説明文を付けない）に、ヘルパーの注意だけの例外を設ける。あわせて、システム設定での許可を待つ間の選び直しの扱いを改める。

- ヘルパーが要る行が、ヘルパーを使えないための注意の記号を出している間（承認を待つ間に選んだ値を保留しているとき、ヘルパーが要る設定が保存されているのにヘルパーを使えないとき）は、項目名の下に「ヘルパーが有効になっていません」程度の短い状態の文を出す。理由と直し方は、これまでどおり (i) で伝える。
- ヘルパーが承認待ちのときに、設定でヘルパーが要る値を選んだら、システム設定を直接開かずに、許可を案内するアラートを出す。システム設定は、利用者がアラートで開くと選んだときだけ開く。取り消したら、選んだ値を捨てて保存値に対応する表示に戻す。

## 背景

PR の Debug ビルドでヘルパーを確かめたオーナー（`EVID-HLP-006`）から、次の2つが挙がった。

- 許可を待つ間、行の注意の記号だけでは、何が起きていて設定が効いていないのかが分からない。(i) を開くまで理由が読めない。
- 承認待ちのときに選び直すと、何の説明もなくシステム設定が開く。設置の確認を見たのは前の操作で、今回の操作との結び付きが分からない。

## 選択肢

- 状態の文: 行の下に短い文を出し、詳しい説明は (i) に残す（採用）。注意の記号を見た時点で、設定が効いていないことが読める。
- 状態の文: (i) だけにする（これまで）。行がすっきりするが、記号の意味を知るのに操作が要る。
- 選び直し: アラートで案内し、利用者が選んだらシステム設定を開く（採用）。
- 選び直し: 確認なしでシステム設定を開く（これまで）。手数は少ないが、別のアプリの画面が突然前面に出る。

## 理由

- 状態の文は項目の説明ではなく、いまその設定が効いていないという状態の表示なので、説明文を付けない規則の目的（項目名だけで内容が伝わる画面）と両立する。対象を、ヘルパーの注意の記号を出している行に限る。
- システム設定は別のアプリなので、開く前に何をすればよいかを伝える方が、利用者が許可の操作に迷わない。

## 影響

- `SPEC-SET-003` に状態の文の例外を足し、`SPEC-SET-005` に状態の文を、`SPEC-HLP-001` と `SPEC-HLP-006` に承認待ちのときの案内のアラートを足す。
- 「ヘルパー」セクションの「システム設定を開く」ボタンは、これまでどおり確認なしで開く。利用者がその操作を選んでいるからである。
- 「明るさを0」を使えないことの注意（`SPEC-SET-005`）には状態の文を出さない。

## 覆す条件

- 状態の文を出す行が増え、画面の見通しが悪くなる。
- 承認待ちのときの選び直しで、アラートの手数が邪魔だという報告が続く。
