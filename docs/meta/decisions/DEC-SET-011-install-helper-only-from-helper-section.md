# DEC-SET-011 ヘルパーの設置は「ヘルパー」からだけ始め、ほかの場所ではヘルパーが要る選択肢を選べなくする

## 結論

ヘルパーの設置を始める場所を、設定の「ヘルパー」の「インストール…」だけにする。システム設定は、利用者が「システム設定を開く」を押したときだけ開く。

- 「インストール…」の確認で「インストール」を押したら、登録だけを行う。承認待ちになっても、システム設定を自動で開かない。許可の手順と「システム設定を開く」は、「ヘルパー」の状態の行と管理の行が示す（`DEC-SET-010`）。
- 設置の確認の本文では、システム設定が開くことを予告しない。何をするかと、設定の「ヘルパー」から削除できることだけを伝える。
- ヘルパーが使えない間（未インストール、承認待ち、このビルドでは使えない）は、「スリープ」とメニューのクイック設定で、ヘルパーが要る選択肢を選べなくする（グレー）。ヘルパーの要らない値へ戻す操作（「Macをスリープ（標準）」を選ぶ、「Appleメニューからのスリープも防ぐ」をオフにする）は、いつでもできるようにする。設定やメニューから設置の確認や許可の案内のアラートを出さず、選んだ値を許可まで保留することもしない。
- 「スリープ」では、選べない理由を、その行の説明文の先頭に、選べるようにする条件として1文で出す。MacBook では「「Macをスリープ（標準）」以外を選ぶには、ヘルパーを有効にする必要があります。」、MacBook 以外の Mac では「「Appleメニューからのスリープも防ぐ」をオンにするには、ヘルパーを有効にする必要があります。」とし、ヘルパーの状態によらず同じ文にする。「ヘルパー」へのリンクは置かない。メニューのクイック設定では、選べない項目をグレーにするだけで、理由を出さない。
- ヘルパーが要る設定が保存されたままヘルパーが使えないときは、`DEC-SET-009` の注意（注意の記号と「ヘルパーが有効になっていないため、設定を反映できません。」）だけを出し、選べるようにする条件の文は出さない。メニューでも、この注意は保存値の項目に出す。
- `DEC-SET-009` が `DEC-SET-007` から引き継いだ、承認待ちのときの選び直しをアラートで案内することはやめる。

## 背景

設置の確認で「インストール」を押すと、登録の後にシステム設定が自動で開いていた。オーナーは、システム設定を開くボタンを押していないのに開くのは、押したボタンと起きることが合っていないとした。確認の本文で予告していたが、利用者はアラートの本文をほとんど読まないので届かず、本文を増やしたくもない。

また、設置の確認と許可の案内は、「スリープ」のポップアップとスイッチ、メニューのクイック設定からも出ていた。メニューから出るときは、設定ウインドウを前面に出してシートを開いていた。オーナーは、スリープの動作を選ぶ場所からヘルパーの設置やシステム設定での許可まで求めるのは違うとした。

## 選択肢

- 今のまま、登録の後にシステム設定を自動で開く。手順は最も少ないが、ボタンと結果が合わないままで、本文の予告では解決しない。
- 自動で開くのをやめ、設定やメニューから始めたときは、登録の後に許可の案内のアラートを続けて出す。要件は変えずに済み、選んだ値も許可の後に保存されるが、スリープの動作を選ぶ場所からアラートが出ることは残り、初めての設置では2枚続く。
- 設定やメニューでヘルパーが要る値を選んだら、「ヘルパー」で設置するよう OK だけのアラートで伝える。OK を押しても目的に近づかず、選んだ値も失われる。
- 初回の起動でヘルパーを登録しておき、システム設定での許可だけで有効にする。使わない利用者のシステム設定にも項目が出て、「削除…」しても次の起動で登録し直すことになり、`REQ-HLP-001` の理由（root 権限が要る機能を使う利用者だけに求める）とぶつかる。
- 設置は「ヘルパー」からだけ始め、ほかの場所ではヘルパーが要る選択肢を選べなくする（採用）。
- 「スリープ」で選べない理由を出す場所: 行の説明文（採用）、ポップアップの中の見出し、グループのフッター。説明文に「ヘルパーのインストールが必要です。」と出すと、「Macをスリープ（標準）」を選んでいるときに、その値にヘルパーが要るように読めたが、ヘルパーが要る選択肢を名指しする文にすれば誤読されない。フッターは行から離れた部品をこの場合のためだけに足すことになる。ポップアップの中の見出しは、ポップアップを閉じていると見えず、メニューの見出しとも入れ子になる。
- 理由に添えるもの: 何も添えない（採用）、「ヘルパー」へ切り替えるリンク。リンクがあれば「ヘルパー」を探さずに済むが、システム設定にもこうしたほかの画面へのリンクはほとんどなく、「ヘルパー」はサイドバーにいつも見えている。
- 理由の文: 状態ごとに書き分ける、「ヘルパーのインストールが必要です。」の1文、選べるようにする条件を「有効にする」で書く1文（採用）。書き分けると、この行にヘルパーの状態を持たせることになる。「インストールが必要」は、承認待ちのときに事実と合わない。
- メニューの選べない項目に添えるもの: 何も添えない（採用）、最初の選べない項目にだけ文を出す、すべての選べない項目に文を出す。最初の項目にだけ出すと、その選択肢だけにヘルパーが要ると読める。すべてに出すと同じ文が最大3回並び、サブメニューを開いてすぐ切り替えるクイック設定が縦に長くなる。

独立した2人のアドバイザー（Claude Opus と Codex Astra）に、どちらも案を伏せて2回検討を頼んだ。1回目は、自動で開く案、許可の案内を続ける案、OK だけのアラートの案、初回に登録する案を比べ、2人とも許可の案内を続ける案を推した。2回目に、許可の案内を続ける案と採用した案を比べ、2人とも採用した案を推した。

## 理由

- システム設定が開くのは「システム設定を開く」を押したときだけになり、押したボタンと結果が一致する。本文で予告する必要がなくなる。Service Management の案内は、承認待ちを確かめ、利用者が同意したらシステム設定を開く形を示している。
- 設置の入口が1つになり、スリープの動作を選ぶ場所からアラートが出なくなる。HIG のメニューは使えない項目を隠さず薄く表示することを、アラートは控えめに使うことを勧めている。
- 選んだ値を許可まで保留する処理と、メニューから確認を出すために設定ウインドウを前面に出す処理が要らなくなる。
- 選べない理由は、ほかの説明と同じく行の説明文に置く。システム設定も、操作できない項目の説明文に、操作できるようにする条件を書いている。
- 理由の文は、何ができないかではなく、何をすればできるかを伝える。「有効にする」は「ヘルパー」の状態名「有効」と揃い、未インストール、承認待ち、このビルドでは使えない、のどれでも事実どおりの1文になる。ヘルパーの状態は「ヘルパー」が示すもので、この行には持たせない。
- メニューで理由を添えないのは、macOS のメニューでは使えない項目を薄く表示するだけにするのが通例で、クイック設定は設定画面への近道だからである。理由と直し方は「スリープ」の行が示す。

## 影響

- `REQ-HLP-001` の本文から、ヘルパーが要る設定を初めてオンにしたときに設置できることを外す。題と理由は変えない。
- `SPEC-HLP-001` の設置の入口、登録の結果の扱い、受け入れ例を直す。`SPEC-HLP-006` から設定から始める設置の確認と許可の案内を外し、設置の確認の本文と既定のボタンの扱いを直す。
- `SPEC-SET-005` の、ポップアップを無効にしない規則、設定から設置する流れ、選べない理由と注意の文の扱いを直す。`SPEC-SET-003` の説明文の受け入れ例に、ヘルパーが使える前提を足す。`SPEC-MENU-008` の設置と注意の扱いを直す。手順書を合わせて直す。
- MacBook 以外の Mac でメニューだけを見る利用者には、「Appleメニューからのスリープも防ぐ」を選べない理由が分からない。
- 初めて設置する利用者は、「ヘルパー」で設置して許可した後、「スリープ」に戻って値を選び直す。

## 覆す条件

- 選べるようにする条件の文を見ても「ヘルパー」にたどり着けない、または設置の後に値を選び直さずに離れてしまうという報告が続く。
- 条件の文が読まれず、選択肢を選べない理由が分からないという報告が続く。
