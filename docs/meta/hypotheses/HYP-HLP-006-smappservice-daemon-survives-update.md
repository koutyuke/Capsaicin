# HYP-HLP-006 同じ Team ID と署名識別子の版へ入れ替えて登録し直しても、デーモンの承認は保たれ、新しい版に XPC でつながる

## 主張

`SMAppService.daemon` を許可したアプリを、同じ Team ID と署名識別子で、デーモンの実行ファイルの内容が違う新しい版に入れ替える。新しい版のアプリが、デーモンを unregister し、その完了を待ってから register すると、次のすべてが成り立つ。

1. 状態は `.enabled` のままで、管理者の再承認を求められない。
2. 登録し直した直後から、XPC の接続先は新しい版のデーモンになる。古い版のデーモンは残らない。
3. 入れ替えを、Sparkle と同じくアプリのバンドルを別の inode に置き換える方法で行っても、手で `/Applications` にコピーし直しても、1 と 2 が成り立つ。
4. unregister の完了の直後の register が EPERM で失敗しても、少し待って試し直せば成功する。

## 外れたときに起きること

1 が外れ、更新のたびに承認を求められるなら、`DEC-HLP-004` の (c) は利用者の体験を悪くする。(b) に戻すかを比べ直す。2〜4 が外れたら、更新後の登録し直しの手順を設計し直す。

## 確かめ方

オーナーが、試作のアプリの2つの版（`TASK-103`）と、その手順書で確かめる。macOS のバージョンを記録する。登録の後片付けは `HYP-HLP-005` と同じである。
