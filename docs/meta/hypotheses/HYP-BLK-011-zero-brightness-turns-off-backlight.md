# HYP-BLK-011 DisplayServices で輝度を 0 にすると、ディスプレイスリープせずにバックライトが消え、画面の取り込みは続く

## 主張

一般ユーザーの権限で、DisplayServices で内蔵ディスプレイの輝度を 0 にすると、次のようになる。

- 内蔵ディスプレイのバックライトが消え、画面は目で見て真っ暗になる。
- 内蔵ディスプレイは `CGDisplayIsAsleep` が `0` のままで、ディスプレイスリープしない。したがって「ディスプレイがオフになったあとにパスワードを要求」によるロックはかからない。
- 画面収録や画面共有で取り込む内容は暗くならず、描画も止まらない。

## 外れたときに起きること

DisplayServices の輝度では `DEC-BLK-007` の目的（ロックさせずに続け、光漏れと電力を抑える）を満たせない。バックライトが消えなければ光漏れと電力を抑えられず、ディスプレイスリープするならロックを避けられず、取り込みが暗くなるなら画面収録や Computer Use に使えない。「明るさを0」を残すなら別の方式を探す。

## 確かめ方

`docs/manual/lid-close-dimming-verification.md` の C1、C3、C4 で確かめる。

1. 環境: 対応環境の MacBook。外部ディスプレイなし。Capsaicin で抑止し、「ディスプレイを自動でオフにしない」をオンにする。
2. 蓋を開けたまま、動く時計を画面収録しながら輝度を 0 にする。暗い部屋で画面を見て、`CGDisplayIsAsleep` を読む。
3. 蓋を閉じて輝度を 0 にし、暗い部屋で蓋の隙間から光が漏れるかを見る。パスワードを要求するまでの時間を過ぎるまで待つ。離れた場所から画面共有か `screencapture` で画面を取り込み、蓋を開けてロック画面が出るかを見る。
4. 成功: 画面が真っ暗になり、閉じた蓋の隙間から光が漏れず、`CGDisplayIsAsleep` が `0` のままで、収録と取り込みには時計が動いて写り、蓋を開けてもロック画面が出ない。失敗: いずれかが成り立たない。

永続的なシステム変更は伴わない。輝度は試験の後に元の値に戻す。

## 結果

支持された。輝度 0 で閉じたまま11分置いても、`CGDisplayIsAsleep` は `0` のままで、パスワードの要求が「すぐに」でもロックされず、画面収録には時計が進んで写り続けた（`EVID-BLK-011`）。輝度 0 で閉じた蓋の隙間からは、暗い部屋でも光が見えなかった（`EVID-BLK-012`）。

確かめていないのは、蓋を開けたまま輝度 0 にしたときの見た目（C1）と、画面共有と Computer Use での取り込みである。取り込みは画面収録と同じく描画された画面を読むので同じ結果になると見込むが、作った後の確認で確かめる。
