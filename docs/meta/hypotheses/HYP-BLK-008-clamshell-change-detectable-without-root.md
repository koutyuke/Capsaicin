# HYP-BLK-008 一般ユーザーの権限でディスプレイの開閉の変化を検知できる

## 主張

一般ユーザーの権限で動くアプリが、IOKit の `AppleClamshellState` の変化を、ディスプレイを閉じてから数秒以内に検知できる。ディスプレイを閉じたときのスリープを止めている状態でも検知できる。

## 外れたときに起きること

ディスプレイを閉じたら画面を消す処理を、アプリだけでは実現できない。`DEC-BLK-002` の方式を見直し、`SPEC-BLK-002` が変わる。

## 確かめ方

1. 環境: 対応環境の MacBook。値を一般ユーザーの権限で読めることは `EVID-BLK-003` で確かめてある。ここでは変化の検知を確かめる。
2. 一般ユーザーの権限で動く試作プログラムで、IOKit の通知を使って `AppleClamshellState` の変化を記録する。
3. ディスプレイを閉じたときのスリープを止めた状態（`HYP-BLK-006` の手順）で、ディスプレイを閉じて開く。
4. 成功: 閉じたときと開けたときの変化が、それぞれ数秒以内に記録される。失敗: 記録されない、または権限のエラーになる。

ディスプレイを閉じたときのスリープを止めるために `disablesleep` を使う場合は、永続的なシステム変更を伴う。始める前に `pmset -g` の `SleepDisabled` の値を記録し、終わったら `sudo pmset -a disablesleep <記録した値>` で元に戻す。

## 結果

支持された（`EVID-BLK-010`）。ディスプレイを閉じたときのスリープを止めた状態で、一般ユーザーの権限で動く補助が、8回の開閉のすべてで閉じた通知と開いた通知の両方を受け取った。10秒ごとの読み取りが通知より先に新しい状態を示したことはなく、開いた直後に輝度が戻ったことを目で確かめた。ディスプレイを動かしてから通知が届くまでの秒数は、別の時計で測っていない。
