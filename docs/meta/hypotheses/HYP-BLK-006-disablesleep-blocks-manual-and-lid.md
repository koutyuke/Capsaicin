# HYP-BLK-006 disablesleep 1 は手動スリープと蓋閉じスリープの両方を止め、片方だけは指定できない

## 主張

次の2つを主張する。確かめ方と判定は別にする。

1. 実測の主張: `pmset -a disablesleep 1` の状態では、Apple メニューからのスリープも、電源アダプター接続時の蓋閉じスリープも起きない。
2. 仕組みの主張: `disablesleep` は、手動スリープと蓋閉じスリープを区別しない1つの値であり、片方だけを止めるように指定する手段を持たない。

## 外れたときに起きること

- 主張1が外れた（どちらかでスリープする）場合: `DEC-BLK-001` の手動スリープと蓋閉じスリープの方式を見直し、`REQ-BLK-003` か `REQ-BLK-004` を満たす別の方式が要る。
- 主張2が外れた（片方だけを指定できる）場合: まとめた項目を設ける判断（`DEC-BLK-006`）を見直す。

## 確かめ方

主張1:

1. 環境: 対応環境の MacBook。電源アダプターを接続し、外部ディスプレイを外す。
2. `pmset -g` の `SleepDisabled` の値を記録し、`sudo pmset -a disablesleep 1` を実行する。
3. Apple メニューから「スリープ」を選び、画面と別の端末からの ping でスリープしないことを確かめる。
4. 蓋を閉じ、1 分後に ping が通ることを確かめる。
5. 成功: 手順 3 と 4 でスリープしない。失敗: どちらかでスリープする。

主張2:

1. `disablesleep` を受け取るカーネルの処理を、ソースで確かめる。値が手動・蓋閉じ・自動を区別するか、1つの真偽値でスリープの要求をまとめて止めるかを読む。
2. 成功: 1つの真偽値で、スリープの理由を区別せずに止めている。失敗: 理由ごとに止めるかどうかを分ける値や引数がある。
3. 文書に記載がないことは、判定に使わない。`disablesleep` そのものが `pmset` の man ページに載っていないため（`EVID-BLK-002`）である。

主張1は、`pmset -a disablesleep` を使うので永続的なシステム変更を伴う（`HYP-BLK-007`）。承認を得た実機でだけ行い、終わったら `sudo pmset -a disablesleep <記録した値>` で元に戻し、`pmset -g` で戻ったことを確かめる。主張2はソースを読むだけで、システムを変えない。

## 結果

- 主張1: 未確認。
- 主張2: xnu の main ブランチのソースでは、`SleepDisabled` は `userDisabledAllSleep` という1つの真偽値になり、スリープの要求を理由で区別せずに止める（`EVID-BLK-005`）。対応する macOS のバージョンのカーネルと同じかは確かめていない。
