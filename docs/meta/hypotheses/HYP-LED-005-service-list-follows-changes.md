# HYP-LED-005 Capsaicin が持ち続ける LED のクライアントは、作成後に追加・削除されたキーボードのサービスを一覧に反映しない

## 主張

`CapsLockLEDController` は、最初の書き込みで作った Passive のクライアントを持ち続け、書き込みのたびにその一覧（`IOHIDEventSystemClientCopyServices`）を引く。このクライアントの一覧には、作成後に現れたサービスが入らず、作成後に消えたサービスは残る。その結果、次の2つが起きる。

- 抑止中に接続したキーボードや、作り直された仮想キーボードに、`"On"` も `"Auto"` も書かれない。
- 消えたサービスへの書き込みが失敗し、LED 全体が失敗として扱われる。抑止中なら LED が合わせられていない制御として記録され、解除時に HUD が「一部を戻せません」を出す。

## 外れたときに起きること

一覧は追従していることになる。`EVID-LED-005` で作り直されたサービスに書かれなかった理由と、11-06 の「一部を戻せません」の原因を別に探す。

当たっていれば、`SPEC-LED-002` の「抑止中にキーボードが接続されたとき……設定し直す」を満たしていない。一覧の取り方を直す（クライアントを書き込みのたびに作る、サービスの追加・削除の通知を受けるなど）。合わせられていない制御の扱い（`SPEC-BLK-007`）は、消えたサービスを失敗に数えない形に直す。

## 確かめ方

`docs/manual/led-remapper-verification.md` の B2 で確かめる。

1. 外付けキーボードを外し、Capsaicin を起動して抑止を始める（LED で知らせるをオン）。
2. 外付けキーボードを接続する。`ioreg` でそのサービスの `HIDCapsLockLED` を読み、LED を目視する。
3. Karabiner-Elements が動いている状態で抑止を始め、Mac をスリープさせて復帰させる。仮想キーボードの登録 ID が変わったかと、新しい仮想キーボードの `HIDCapsLockLED` を読む。解除して HUD の表示を見る。
4. 対照として、2・3 の後に Capsaicin を終了・起動し直してから抑止を始め、同じものを読む。

成功（主張どおり）: 2・3 で新しいサービスが `"Auto"` のまま、または LED が点かず、4 では書かれる。3 の解除で「一部を戻せません」が出る。失敗: 2・3 でも新しいサービスに書かれる。
