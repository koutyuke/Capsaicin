# HYP-HLP-011 SMAppService のデーモンを登録したアプリのコピーを消すか動かすと、BTM のデーモンの項目は親を失い、以後の登録ではヘルパーが起動しない

## 主張

同じ bundle ID のアプリのコピー A と B があるとき、次のすべてが成り立つ。

1. A から `SMAppService.daemon` を登録すると、BTM のデーモンの項目は親にアプリの項目を持ち、ヘルパーは起動する。
2. A を消す（ゴミ箱に入れて空にする）か、別の場所へ動かすと、デーモンの項目は親を失う（`sfltool dumpbtm` の `Parent Identifier` が `Unknown Developer` になる）。
3. 親を失った後に B から登録すると、BTM は同じ項目を使い直し、launchd は `Invalid path (108)` でヘルパーを起動できない（`EVID-HLP-007`）。
4. アプリからの unregister では、親を失った項目は消えない。

## 外れたときに起きること

2 が成り立つなら、利用者がアプリを消して入れ直したり、別の場所へ動かしたりしただけで、ヘルパーが二度と起動しなくなりうる。アプリは「登録済みなのに起動しない」状態を見分けて示し、直し方を案内する必要がある（`SPEC-HLP-004`）。開発では、同じ bundle ID の Debug のコピーを増やしたり消したりしない規則が要る。

2 が外れる（消しても動かしても親を失わない）なら、`EVID-HLP-007` の状態は別の操作（試作の agent の unregister など）で生じた。その操作を探す。

## 確かめ方

オーナーが、ヘルパーのラベルをビルドごとに変えられる試作（`TASK-117`）と、その手順書（`TASK-118`）で確かめる。既存の親のない項目に邪魔されないよう、実験ごとに未使用のラベルを使う。各段階で `sfltool dumpbtm` のデーモンの項目の親と、`launchctl print` と launchd のログを見る。ヘルパーの登録は永続的なシステム変更で、実験で作った項目が親を失って消せなくなることがある。

## 結果

外れた（`EVID-HLP-008`）。主張1は成り立った。主張2は成り立たず、登録したコピーを消しても動かしても、デーモンの項目は親を保ち、別のコピーからヘルパーが起動した。主張3と4は、親を失った項目を作れなかったので判定できなかった。親のない項目は、UID -2 の記録からアプリの項目がなくなった状態で生じていたと見られ、その条件は `HYP-HLP-012` で確かめる。
