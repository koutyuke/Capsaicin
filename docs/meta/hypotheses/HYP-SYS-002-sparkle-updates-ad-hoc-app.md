# HYP-SYS-002 Sparkle 2 は、ad-hoc 署名で launchd の管理下にある Capsaicin を、利用者の追加の操作なしに更新できる

## 主張

ad-hoc 署名で公証していない Capsaicin を、Sparkle 2 で同じく ad-hoc 署名の新しいビルドへ更新すると、次のすべてが成り立つ。

1. EdDSA の署名が通る更新を受け入れ、署名を1バイトでも変えたアーカイブ、別の鍵で署名したアーカイブ、署名のない appcast を拒否する。
2. インストールの後、新しい版が Gatekeeper の「このまま開く」を求めずに起動する。新しい版に `com.apple.quarantine` が残らない。
3. 起動し直した新しい版は、Capsaicin の LaunchAgent の管理下で1つだけ動く。インストールの途中で、launchd が古い版を起動し直さない。
4. Mac を再起動してログインした後も、LaunchAgent から新しい版が起動する。ログイン項目やバックグラウンド項目が重複せず、利用者が無効にしていた状態も変わらない。
5. Sparkle による終了は、利用者の終了やセッションの終了ではなく、判定できない終了として扱われる（`DEC-LCY-004`）。

## 外れたときに起きること

- 1 が外れたら、`DEC-SYS-019` の署名と検証の設定を見直す。
- 2 から 4 のどれかが外れたら、更新のたびに利用者の操作が要る。`DEC-SYS-019` を見直し、更新を知らせてリリースのページを開くだけの方式に戻すかを決める。
- 5 が外れたら、`DEC-LCY-005` の終了の扱いを見直す。

## 確かめ方

オーナーが手で行う。`launchctl` を使うので、エージェントは実行しない。本番の v0.1.0 と鍵を使わないよう、Debug 構成（bundle ID `io.github.koutyuke.capsaicin.debug`）の2つのビルドと、使い捨ての鍵と、手元の HTTP サーバーで試す。詳しい手順は、Sparkle を組み込んだ後に作業として渡す。

1. 使い捨ての EdDSA の鍵を、ログインキーチェーンを使わずに作業用のフォルダーに作る。
2. 同じソースから、版とビルド番号だけを変えた A と B の2つのビルドを作る。appcast の URL と公開鍵はビルドの設定で渡し、`http://127.0.0.1:<port>/appcast.xml` を指す。
3. B の zip から appcast を作って署名し、そのフォルダーを `127.0.0.1` だけで待ち受ける HTTP サーバーで配信する。
4. A を、ブラウザでダウンロードした zip から入れ、「このまま開く」で起動する。前もって、`.debug` の LaunchAgent がほかのビルドを指していないことを確かめる。
5. 「このアプリについて」から確認してインストールし、主張の 2、3、5 を確かめる。再起動とログインをして、主張の 4 を確かめる。
6. 改ざんしたアーカイブ、別の鍵で署名したアーカイブ、署名のない appcast を配信し、主張の 1 を確かめる。
7. 後片付けとして、サーバーを止め、試験のアプリ、鍵、zip を消し、`.debug` の LaunchAgent を元に戻す。

成功の判定は、主張の 1 から 5 がすべて成り立つことである。どれかが成り立たなければ、何が起きたか（ダイアログ、ログ、`launchctl print` と `pgrep` の結果）を記録する。
