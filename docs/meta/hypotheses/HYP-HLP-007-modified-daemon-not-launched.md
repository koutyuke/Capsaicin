# HYP-HLP-007 バンドルの中のデーモンの実行ファイルを書き換えると、launchd はそれを起動しない

## 主張

`SMAppService.daemon` を許可した後に、`/Applications` のアプリのバンドルの中にあるデーモンの実行ファイルを、管理者でない利用者が書き換えて署名を壊す。すると、launchd はそのデーモンを root で起動しないか、起動しても接続を受けられずに終わる。書き換えたファイルが root として動くことはない。

## 外れたときに起きること

利用者が書き込める場所にあるファイルが root で動くことになり、`DEC-HLP-004` の (c) の安全性の前提が崩れる。(c) を採るかを比べ直す。

## 確かめ方

オーナーが、試作のアプリ（ブランチ `spike/smappservice-probe`）で確かめる。試作のデーモンの実行ファイルの末尾に1バイトを足し、Mach サービスに接続して、応答の有無と、`log show --predicate 'subsystem == "com.apple.xpc.launchd"' --last 5m` などの記録を見る。成功: 応答がなく、署名の検証の失敗の記録がある。失敗: 書き換えたデーモンが応答する。

終わったら、試作のアプリを入れ直すか、`HYP-HLP-005` と同じ方法で片付ける。

## 結果

支持された（`EVID-HLP-005`）。ただし、「確かめ方」に書いた末尾に1バイト足す方法は、署名の範囲を変えないので試験にならなかった（デーモンは普通に起動した）。代わりに、署名の範囲の1バイトを書き換えた場合と、同じ識別子の ad-hoc 署名の実行ファイルに差し替えた場合を確かめた。どちらも、カーネルの起動の制約で exec の段階で止まり、差し替えたコードは動かなかった。壊れている間、保留中の接続があると、launchd は10秒おきに起動を試し続けた。
