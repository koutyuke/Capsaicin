# HYP-LCY-005 セッションの終了による終了を、利用者の終了と区別できる

## 主張

ログアウト、再起動、システム終了によってアプリが終了するとき、アプリは終了の処理の中で、それが利用者の終了（メニューの「終了」など）ではなくセッションの終了によるものだと判定できる。判定に使える手段は、`NSWorkspace.willPowerOffNotification` か、終了の Apple Event の理由（`kAEQuitReason`）である。

また、終了の処理が間に合わずに強制終了された場合も、次の起動で `SPEC-LCY-007` の判定が成り立つ。再起動を伴えば「Mac の再起動・ログアウトの後」、伴わなければ「クラッシュ後」になる。

## 外れたときに起きること

セッションの終了を利用者の終了と取り違え、「アプリと Mac の再起動時」でも再起動やログアウトの後に再開しない。または、利用者の終了をセッションの終了と取り違え、利用者が止めた抑止を次の起動で再開する。`SPEC-LCY-002` の終了の扱いと `SPEC-LCY-007` の判定、`DEC-LCY-003` を見直す。

## 確かめ方

1. 環境: 対応環境の Mac。終了の理由を記録する試作アプリを、LaunchAgent から起動する。
2. メニューからの終了、`Command-Q`、ログアウト、Apple メニューからの再起動、システム終了で、それぞれアプリを終了させ、`NSWorkspace.willPowerOffNotification` を受けたかと、終了の Apple Event の `kAEQuitReason` の値を記録する。
3. ログアウトの確認ダイアログで取り消した場合と、終了の処理を長引かせて強制終了された場合も記録し、次の起動での判定を見る。
4. 成功: ログアウト、再起動、システム終了だけが、どちらかの手段でセッションの終了と判定でき、強制終了された場合の次の起動の判定が上の主張と一致する。失敗: どれかを区別できない。

LaunchAgent の登録は永続的なシステム変更なので、承認を得た実機でだけ行い、終わったら `launchctl bootout` で外し、plist を削除する。

## 結果

未確認。理由を判定できない場合の扱いは `DEC-LCY-004` に従う。この方針の採用は、OS で理由を取得できることの検証結果ではない。
