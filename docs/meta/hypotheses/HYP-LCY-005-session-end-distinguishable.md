# HYP-LCY-005 セッションの終了による終了を、利用者の終了と区別できる

## 主張

ログアウト、再起動、システム終了によってアプリが終了するとき、アプリは終了の処理の中で、それが利用者の終了（メニューの「Capsaicinを終了」など）ではなくセッションの終了によるものだと判定できる。判定に使える手段は、`NSWorkspace.willPowerOffNotification` か、終了の Apple Event の理由（`kAEQuitReason`）である。

## 外れたときに起きること

セッションの終了を利用者の終了と取り違えると、後片付けの失敗時に、終了を妨げるダイアログを出すおそれがある。判定不能なら利用者の終了以外として扱う `SPEC-LCY-002` の規則で、この誤表示を避けられるかを確かめる。

## 確かめ方

1. 環境: 対応環境の Mac。終了の理由を記録する試作アプリを直接起動する。
2. メニューからの終了、`Command-Q`、ログアウト、Apple メニューからの再起動、システム終了で、それぞれアプリを終了させ、`NSWorkspace.willPowerOffNotification` を受けたかと、終了の Apple Event の `kAEQuitReason` の値を記録する。
3. ログアウトの確認ダイアログで取り消した場合も記録する。
4. 成功: ログアウト、再起動、システム終了だけが、どちらかの手段でセッションの終了と判定できる。失敗: どれかを区別できない。

ログアウト、再起動、システム終了を伴うので、未保存の作業を保存し、承認を得た実機でだけ行う。

## 結果

未確認。理由を判定できない場合の扱いは `DEC-LCY-010` に従う。この方針の採用は、OS で理由を取得できることの検証結果ではない。
