# HYP-HLP-012 Mac の起動のとき、BTM は URL にアプリのない UID -2 のアプリの項目を消し、そのデーモンの項目は親を失う

## 主張

SMAppService でデーモンを登録したアプリの、UID -2 の記録のアプリの項目の URL が、存在しない場所（消したかゴミ箱へ移したコピー）を指したまま Mac を再起動すると、次のすべてが成り立つ。

1. 起動の後、UID -2 の記録から、そのアプリの項目がなくなる。
2. そのアプリが内包していたデーモンの項目は残り、`Parent Identifier` が `Unknown Developer` になる（`EVID-HLP-007` の状態）。
3. その後、同じラベルを登録すると、親のない項目が使い直され、launchd は `Invalid path (108)` でヘルパーを起動できない。
4. 別のラベルのデーモンを登録すると、UID -2 にアプリの項目が作り直され、親のない項目は消える（`EVID-HLP-008`）。その後は、元のラベルを登録してもヘルパーが起動する。

## 外れたときに起きること

1 と 2 が成り立つなら、正式版の利用者でも、アプリを消すかゴミ箱へ入れたまま Mac を再起動し、その後に入れ直すと、ヘルパーが起動しなくなりうる。アプリは「登録済みなのに起動しない」状態を見分けて示し、直し方を案内する必要がある。4 が成り立つなら、直し方の候補になる。

1 か 2 が外れたら、`EVID-HLP-007` の状態は別の操作で生じた。試作が起動時に行った agent の unregister などを調べる。

## 確かめ方

今の Mac は、`EVID-HLP-008` の最後の時点で、UID -2 のアプリの項目の URL がゴミ箱へ移した試作のコピーを指し、試験用の2つのデーモンの項目が親を持っている。オーナーが Mac を再起動し、ログインした後に `sfltool dumpbtm` を保存する。再起動の前に、同じ bundle ID の Debug のアプリを起動しない。読み取りだけなので、システムの変更は再起動だけである。3 と 4 は、1 と 2 が成り立ったときに、試作のビルドで確かめる。
