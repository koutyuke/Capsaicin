# TASK-021 HUD の内容を置き換えるとき、中央を保って伸び縮みし、文字をぼかして切り替える

## 目的

HUD の表示中に、幅の違う内容へ置き換えると（例: 「スリープ防止 オン」→「スリープ防止 オフ · 一部を戻せません」）、オーナーの実機で次のように見えた。

1. 置き換えた直後に、ガラスが元の幅のまま、新しい幅の左端まで一気に横へ移る。
2. その後、ガラスが右へだけ伸びる。中央の位置が保たれない（`SPEC-HUD-006` に反する）。
3. 新しい文字は、最初から最終の位置に全部の幅で出る。伸びきる前のガラスからはみ出す。
4. 古い文字と新しい文字がクロスフェードで重なり、両方が読める状態が見える。

PM の見立て（コードと画像からの推定。実験では確かめていない）:

- ガラスは `NSViewRepresentable` の `NSGlassEffectView` である。SwiftUI は、このビューの枠を補間しない。枠は最終値に一度で変わり、AppKit のレイヤーの暗黙のアニメーションが、左下を基準に大きさだけを動かす。1 と 2 はこれで説明できる。
- 文字はカプセルの中央に置かれ、幅は即座に最終値になる。このため 3 が起きる。

あるべき動きは、更新後の `docs/specs/hud.md` の `SPEC-HUD-004`、`SPEC-HUD-006`、`SPEC-HUD-008` と、`DEC-UI-007` にある。要点は次のとおりである。

- カプセルは中央を保ち、左右へ 0.20 秒（`timingCurve(0.2, 0, 0, 1)`）で伸び縮みする。
- アイコンと文字は1行として左端を揃え、カプセルの左端の動きに合わせて横へ移る。カプセルからはみ出して見えない。
- 止まっているときは、今と同じ見た目にする。内容が最小幅 200 pt より狭いときは、内容をカプセルの中央に置く。
- 文字は、古い文字をぼかしながら消し、新しい文字をぼかした状態から現す。新旧の文字が両方読める瞬間を作らない。
- アイコンは今の `.contentTransition(.symbolEffect(.replace))`（視差効果を減らすときは `.opacity`）のままにする。

## 作るもの

1. ガラスを SwiftUI の `glassEffect(.regular, in: Capsule())`（macOS 26 以降）で描き、`HUDGlass`（`NSViewRepresentable`）を消す。
   - 「透明度を下げる」のときの不透明な背景と枠線、「コントラストを上げる」のときの枠線は、今の挙動を保つ。
2. 幅の変化を SwiftUI の中で補間させ、カプセルの中央を保つ。
3. アイコンと文字の行を、カプセルの左端の動きに合わせて横へ移す。
   - 文字は、伸び縮みの途中でもカプセルの外に見えないようにする（カプセルで切り抜くなど）。
   - 内容が最小幅より狭いときは、止まった状態で中央に置く。
4. 文字（状態・区切り・解除の条件）を、ぼかしと不透明度で切り替える。
   - 時間とカーブは幅と同じ 0.20 秒・`timingCurve(0.2, 0, 0, 1)`。ぼかしの半径は 4〜6 pt 程度。
   - 拡大・縮小は加えない（左揃えの行が中央を基準に縮むと揺れて見えるため）。
   - 置き換え用の小さな `Transition` を自作してよい。5〜10 行に収める。
5. 出入り（`SPEC-HUD-005`）と、出る途中からの戻り（`SPEC-HUD-006`）は変えない。

## 守ること

- 短く素直に書く（`TASK-010` を参照）。上の 1〜5 以外を変えない。`DispatchQueue.main.async` の重ね掛け、タイマーでの手動補間、`.id` によるビュー全体の作り直しのような、更新の順序やタイミングに頼る仕掛けは避ける。文字の切り替えのために文字の部分だけに `.id` を付けるのはよい。
- アイコンの系統が変わったときの特別な切り替えは作らない。HUD が使うアイコンは `capslock` と `capslock.fill` だけである。
- テストでパネルを画面に出さない。アプリを起動しない。`scripts/manual/` を実行しない。`launchctl`・`sudo`・`pmset` の設定変更を実行しない。ScreenCaptureKit や `screencapture` を使わない。
- 本番コードに `REQ-*` と `SPEC-*` を書かない。`git commit` をしない。

## レビュー

PM が差分を読んでレビューし、次を直した。

- Codex は、行を幅 0 の枠に入れて `offset(x: -width / 2)` で左端へ寄せ、行自身にも最小・最大の幅（160〜380 pt）を持たせていた。PM が仕掛けを外し、カプセルの中央に置く元の形に戻して `cacheDisplay` のコマを書き出し直したところ、各コマは同じだった。仕掛けは不要で、幅の上下限も `HUDPresentation.replace` と二重になるため、外した。
  - 行はカプセルの中央に置いたまま、行の枠を幅と一緒に補間させる。止まっているときは中央に置かれ、伸びるときは行の左端がカプセルの左端に近づきながら左へ移る。
- アイコンにだけ付いていた 0.15 秒の別のアニメーションを外し、行全体の 0.20 秒に揃えた。
- `cacheDisplay` は、ぼかしとガラスを写さず、途中のコマの位置も実際の画面と同じかどうか分からなかった。このため、判定を持たない画像の書き出しテストと、外した最小・最大の幅を確かめるテストを消した。

残った変更は次のとおりである。

- ガラスを `Color.clear.glassEffect(.regular, in: Capsule())` の背景にした。文字にガラスの前景効果がかからないよう、背景に置いている。
- 行をカプセルの形で切り抜き、伸びきる前のガラスから文字がはみ出さないようにした。
- 文字の部分だけに内容の `.id` を付け、ぼかし（5 pt）と不透明度の `Transition` で切り替える。視差効果を減らすときは、ぼかしを使わず不透明度だけにする。

`just check` と `just build` が通った。動きの見え方（中央が保たれること、文字が重なって読めないこと、`glassEffect` がパネルの上で正しく描かれること）は、オーナーが実機で確かめる。
