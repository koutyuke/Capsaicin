# TASK-019 設定ウインドウのタイトルバーの帯をなくし、下の2項目をサイドバーの下端に寄せる

## 目的

オーナーが実機で設定ウインドウを見たところ、次の2点に違和感があった（`DEC-UI-006`）。

1. ウインドウの上端に、全幅のタイトルバーの帯（左に閉じるボタンなど、続けて「一般」のタイトル）があり、サイドバーと右側の上をまたいで横切っている。
2. 「ヘルパー」と「このアプリについて」が、サイドバーの下端から 40 pt 以上浮いている。原因は、`SettingsView` が下の2項目の上に置く空きの高さを `geometry.size.height - 280` という固定の値で決めていて、実際の行の高さと合っていないことにある。

Xcode 27 の設定ウインドウ（macOS 26 のシステム設定も同じ）のように、サイドバーをウインドウの上端まで伸ばし、閉じるボタンなどをサイドバーの上に乗せ、選んだセクション名を右側の最上段に出す。仕様は `SPEC-SET-001` にある。

## 範囲

書いてよい:

- `Sources/Capsaicin/Settings/SettingsView.swift`
- `Sources/Capsaicin/Settings/SettingsWindowController.swift`
- `Tests/CapsaicinTests/Settings/SettingsTests.swift`

触らない: ほかのすべてのファイル（`docs/`、`project.yml`、String Catalog を含む）。

## 作るもの

1. 全幅のタイトルバーの帯をなくす。
   - サイドバーはウインドウの上端から下端まで伸び、閉じる・最小化・ズームのボタンがサイドバーの上に乗る。
   - 選んだセクション名は、右側の列の最上段（閉じるボタンなどと同じ高さ）に、左寄せのウインドウのタイトルとして出る。Xcode の設定ウインドウと同じ見た目である。右側の内容の中に見出しを足すのではない。
   - 標準の仕組みだけで作る。例: ウインドウの `.fullSizeContentView`、`NSHostingView.sceneBridgingOptions`、`navigationTitle`、`NSToolbar` と `toolbarStyle`。どれを使うかは描画を見て決めてよい。独自のタイトルの部品を描かない。
   - `window.title` は今のとおり選んだセクションに合わせて変える（VoiceOver とウインドウメニューが使う）。
   - サイドバーの開閉ボタンは今のとおり出さない。最小化とズームのボタンは今のとおり無効にする。
2. 「ヘルパー」と「このアプリについて」をサイドバーの下端に寄せる。
   - 下端との間は、上の5つの最初の行と、その上にある閉じるボタンなどの下端との間と同じ程度（サイドバーの既定の余白）にする。
   - 固定の値（今の `280`）で行の高さを見積もらない。行の高さやウインドウの高さが変わっても下端に寄るようにする。
   - 7 項目は1つの `List` のままにし、選択の表示と ↑↓ での移動を 7 項目を通して連続させる。
   - 下の2項目の上の空きは、選べず、VoiceOver にも読まれないままにする。
3. テストを今の挙動に合わせる。
   - `SettingsTests` の `render` は、`SettingsWindowController` が作るウインドウと同じ設定のウインドウで描く。テストの中にウインドウの設定を書き写さず、本番のウインドウの作り方を共有する。描いた PNG を `.build/settings/` に書く挙動は今のままにする。
   - ウインドウの寸法と最小化のボタンを確かめるテストに、帯をなくすための設定（例: `.fullSizeContentView`）の確認を足す。

## 守ること

- 短く素直に書く（`TASK-010` を参照）。上の 1〜3 以外を変えない。行の高さ、角丸、余白はシステム既定のままにする。
- 標準の部品の見た目を描き直さない（`SPEC-UI-005`）。
- テストでアプリを起動しない。`launchctl`・`sudo`・`pmset` の設定変更を実行しない。
- 本番コードに `REQ-*` と `SPEC-*` を書かない。`git commit` をしない。

## レビュー

PM が差分と `.build/settings/` の PNG を見てレビューした。帯がなくなり、サイドバーが上端まで伸び、右側の最上段に選んだセクション名が出る。下の2項目は下端に寄り、「解除の条件」はスクロールせずに収まる。

実装者は、描画テストで ScreenCaptureKit によるウインドウの撮影を始めていた。この方式は画面収録の許可とロックの解除に依存し、`just check` が環境しだいで落ちる。そのため、元の `cacheDisplay` に戻させた。

PM が次を直した。

- 下端寄せの実装を差し替えた。実装者の版は、`List` の裏の `NSTableView` を `NSViewRepresentable` からたどり、`DispatchQueue.main.async` で測っていた。これを、SwiftUI 標準の `onScrollGeometryChange` で余った高さを空きに足す形にした。行の高さはシステム設定の「サイドバーのアイコンのサイズ」で変わるため、固定の値には戻さない。
- タイトルの出し方を `window.title` の1系統にした。`navigationTitle`、`sceneBridgingOptions = [.toolbars]`、`toolbarStyle = .unifiedCompact` は、外しても描画とテストの結果が変わらなかったので外した。

`just check` と `just build` が通った。`cacheDisplay` の PNG では、選択行が黒く潰れ、ガラスの質感も描かれない。そのため、実機の選択色と質感は `docs/manual/verification.md` の 8.2 で確かめる。

### 実機での確認の後

オーナーが実機で見たところ、システムのタイトル「一般」が小さく灰色で、項目のグループの左端からずれていた。PM が寸法を比べた。ツールバーなしではタイトルの左端が 213 pt、項目の左端が 220 pt である。標準のツールバー（`.unified`）を付けると揃うが、上端の領域が 66 pt に広がって中身が下がり、下の2項目も下端から浮いた（オーナーの実機の画像でも確かめた）。そこで、オーナーの選択により、システムのタイトルを隠し、閉じるボタンなどと同じ行にアプリが見出しを描く形にした（`DEC-UI-006`）。見出しの位置を決めるタイトルバーの高さは、固定値ではなく安全領域から読む。見出しは描画の PNG で確かめた。見出しの位置を確かめるテストは足していない。SwiftUI の `Text` は AppKit のビューとしてたどれないためである。
