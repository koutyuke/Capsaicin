# TASK-029 HUD の文字を、新旧を重ねたまま長めのぼかしで切り替える

## 目的

`TASK-026` で、古い文字を消してから新しい文字を現す形にした。オーナーが実機で見たところ、文字が消えて空になる間に明るいガラスだけが見え、眩しく感じられた。新旧を重ねて入れ替える形に戻し、チラつきの原因だった短さは、時間とカーブで補う。

## 範囲

書いてよい:

- `Sources/Capsaicin/HUD/HUDView.swift`
- `docs/specs/hud.md`（`SPEC-HUD-006`）
- `docs/meta/decisions/DEC-UI-007-hud-glass-and-replacement-motion.md`（結論と選択肢の補足）

## 完了条件

- 表示中の置き換えで、古い文字が消えるのと同時に新しい文字が現れる。時間は 0.40 秒の ease-in-out、ぼかしの半径は最大 8 pt である。
- 消えている状態から出すときは、文字は遅れずに HUD と一緒に現れる。
- 幅とアイコンの動き（0.20 秒）は変えない。
- `nix develop --command just check` と `nix develop --command just build` が通る。

## 検証

- `nix develop --command just check`
- `nix develop --command just build`
- 画面外で描いた途中のコマで、文字の濃さの移り変わりを確かめる（一時的なテストで行い、リポジトリには残さない）。
- 見た目は、オーナーが実機で確かめる。

## レビュー

PM が実装した。文字のトランジションを、消えるときも現れるときも同じ ease-in-out にした。消えている間の置き換えで動きを止める仕組み（`TASK-026`）はそのまま使う。

最初は 0.30 秒で実装し、途中のコマ（2x の画素で、文字の最も濃い画素の明るさ。39 が不透明、255 が背景）は次のとおりだった。

- 表示中の置き換え: 0 ms で 39、75 ms で 50、150 ms で 82、225 ms で 70、300 ms で 41、400 ms で 39。文字が消えて空になる瞬間はない（`TASK-026` では 140〜200 ms に 226〜254 の空白があった）。
- 消えている状態から出すとき: 文字は HUD のフェードインと一緒に現れ、200 ms で 39 になった。

その後、オーナーの依頼で 0.40 秒に延ばした。重ねて入れ替える仕組みは同じなので、途中のコマは測り直していない。

ぼかしは `cacheDisplay` に写らない。見た目はオーナーが確かめる。
