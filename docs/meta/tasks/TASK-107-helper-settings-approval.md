# TASK-107 設定画面のヘルパーを承認待ちに対応させ、起動時に登録を今の版に合わせる

## 目的

`TASK-106` で、ヘルパーは SMAppService のデーモンになり、状態は「未インストール / 承認待ち / 使える / このビルドでは使えない」の4つになった。設定画面、メニュー、ダイアログは、まだ古い3つの状態と管理者パスワードを前提にした見た目と文言のままである。これを仕様に合わせて作り直し、起動時の登録し直しを組み込む。

振る舞いの正は次の仕様である。

- `docs/specs/helper.md`: 「状態」、`SPEC-HLP-001`（設置と承認待ちの間の選択の扱い）、`SPEC-HLP-004`（状態の表示と削除）、`SPEC-HLP-006`（ダイアログ）、`SPEC-HLP-007`（登録し直し）
- `docs/specs/settings.md`: `SPEC-SET-002` の表のヘルパーが要る行の (i)、`SPEC-SET-005`
- `docs/specs/menu.md`: ヘルパーが原因の警告と副題（「修復」ではなく「直せる」）

## 範囲

変更してよいもの: `Sources/Capsaicin/Settings/`、`Sources/Capsaicin/MenuBar/`（ヘルパーに関わる文言と表示だけ）、`Sources/Capsaicin/App/`、`Packages/CapsaicinKit/Sources/CapsaicinPlatform/Helper/HelperRegistration.swift`（必要なときだけ）、対応するテスト。

触らないもの: `docs/`（このチケットを除く）、`Sources/capsaicin-helper/`、`project.yml`、LaunchAgent とライフサイクルの登録（後続のチケット）、`justfile`。

## やること

1. 「ヘルパー」セクションを `SPEC-HLP-004` の表に合わせる。状態の行の値とシンボル、管理の行のボタン（未インストール: インストール、承認待ち: システム設定を開く と 削除、使える: 削除、このビルドでは使えない: なし）、状態の行の (i) の内容。
2. 設置の流れを `SPEC-HLP-001` に合わせる。
   - 承認待ちなら、確認を出さずにシステム設定を開く。
   - このビルドでは使えない、App Translocation された場所で動いている、の2つは、登録せずにエラーのダイアログで伝える。
   - 設定から始めて承認待ちになったときは、選んだ値を保留する。保留している間、その行は選んだ値を表示し、注意の記号と、システム設定で許可すると有効になることを (i) で示す。保存値は変えない。
   - 状態は、設定ウインドウが前面に来たときと、保留している間は 2 秒ごとに読み直す。「使える」になったら、保留した値を保存して合わせ直しを試みる。
   - 設定ウインドウを閉じた、その設定を別の値に変えた、アプリが終了した、のどれかで保留を捨て、保存値に対応する表示に戻す。
3. `SPEC-SET-005` の注意の表示を、4つの状態に合わせる。(i) の先頭に、使えない理由と直し方（未インストールなら「ヘルパー」セクションで設置する、承認待ちならシステム設定で Capsaicin の項目を許可する）を示す。
4. ダイアログを `SPEC-HLP-006` に合わせる。設置の確認の本文はシステム設定での許可を伝え、管理者パスワードには触れない。削除の確認の本文から管理者パスワードの記述を除く。新しいエラー（このビルドでは使えない、App Translocation、`disablesleep` を戻せないので削除しない）の文言を足す。
5. メニューの警告と副題の「修復」を、仕様の「直せる」に合わせる。
6. 起動時に、`model.launch()`（`SPEC-LCY-006` の起動時の処理）の前に `HelperRegistration.reregisterIfNeeded()` を呼ぶ（`SPEC-HLP-007`）。ダイアログは出さない。
7. 使われなくなった文言のキー（古い状態、修復、管理者パスワード）を String Catalog から消す。

## 守ること

- `AGENTS.md` を読んでから始める。アプリを起動しない。`sudo`、`launchctl`、`sfltool` を実行しない。
- String Catalog は機能フォルダーごとのテーブルを使い、すべてのキーに英語と日本語を持たせる。Xcode の書式（`"key" : value`、末尾の改行なし）に合わせる。`stale` のキーを残さない。
- 日本語の文言は `~/.claude/skills/yomiyasu/SKILL.md` に従って推敲する。既存の文言の語調に合わせ、「蓋」という語は使わない（「ディスプレイを閉じる」と書く）。英語の文言は macOS の標準の言い回しに合わせる（システム設定の「Login Items & Extensions」など）。
- 保留は設定画面の状態として持ち、保存値や再開用の記録に書かない。
- 本番のコードに `REQ-*` と `SPEC-*` を書かない。テスト名で仕様と対応させる。
- `git commit` と `git push` をしない。

## 完了条件

- 上の 1〜7 を満たし、承認待ちの間の保留（保存しない、使えるになったら保存する、閉じたら捨てる）と、起動時の登録し直しの呼び出しの順序をテストで確かめている。
- `nix develop --command just check` が通る。

## 検証

- 実機（オーナー）: PR の Debug ビルドで、設置（許可の前後）、承認待ちの間の表示、システム設定で項目をオフにしたときの表示、削除、アプリの入れ替えの後の登録し直しを確かめる。
