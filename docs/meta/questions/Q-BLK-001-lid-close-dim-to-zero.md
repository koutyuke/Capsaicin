# Q-BLK-001 ディスプレイを閉じたときの動作に「明るさを0」を加えるか

## 問い

「ディスプレイを閉じたとき」のポップアップ（`DEC-SET-005`）に、「スリープ（標準）」「ディスプレイをオフ」「オンのまま」に加えて、内蔵ディスプレイの明るさを 0 にし、ディスプレイを開けたら元に戻す「明るさを0」を加えるか。

## 目的

オーナーがこの選択肢に求めるのは、次の2つを同時に満たすことである。

- 蓋を閉じたまま、画面をロックさせずに、画面収録・Computer Use・画面共有などを続ける。「ディスプレイをオフ」はディスプレイスリープさせるので、パスワードの設定によってはロックされる。
- 閉じた蓋の中で画面が光り続けることによる光漏れ、電力、発熱を抑える。「オンのまま」では光り続けると見込んでいる（`HYP-BLK-010`）。

## 選択肢と帰結

- 加える。暗くする方式は DisplayServices の輝度にする。
  - ほかの方式は目的に合わない。ガンマで画素を黒くする方式はバックライトを消さないので、光漏れと電力を抑えられない。内蔵ディスプレイを無効にする方式は、取り込む画面そのものがなくなり、ウインドウの配置も変わる。黒いウインドウで覆う方式は、取り込む画面も黒くなる。CoreDisplay の輝度は読み取りがレジストリの値と食い違い、IOKit の経路はこの Mac で使えない（`EVID-BLK-007`）。
  - 非公開の DisplayServices に頼るので、macOS の更新で使えなくなりうる。成功を返しても効かなくなる変化は、アプリから見分けにくい。
  - 元の輝度を戻す処理が要る。蓋を開けたとき、抑止を解除したとき（閉じたままの解除でスリープする前）、閉じたまま落ちた後の起動時である。ディスプレイスリープを止めるアサーションと違い、プロセスが終わっても輝度は自動では戻らない。
  - 閉じた蓋の中で描画は続くので、発熱と電力は「ディスプレイをオフ」より不利である。
  - 暗い画面はロックされているように見えるが、ロックされていない。蓋を開けた人はすぐに操作でき、画面収録も止まらない。
  - 「ディスプレイを自動でオフにしない」をオフにしていると、時間が来てディスプレイスリープし、ロックされうる。
- 加えない。非公開の依存と復旧の処理が増えない。ロックさせずに続けたいときは「オンのまま」を選び、光漏れと発熱を受け入れる。

## 加える場合に決めること

- DisplayServices が使えない、または輝度を変えられなかったときの扱い。「オンのまま」と同じく明るいままにすれば、ロックさせないという目的を守る。「ディスプレイをオフ」に切り替えれば、閉じた蓋の中で光り続けることを避けるが、選んだ動作と違う結果になる。
- 「ディスプレイを自動でオフにしない」と連動させるか。連動させると、項目が別の項目を含意する関係（`DEC-BLK-006` でなくしたもの）が戻る。連動させなければ、(i) で関係を伝える。
- 蓋を閉じている間に利用者や macOS が輝度を変えたとき、開けたときに元の輝度へ戻すか。

## 決めるのに必要な情報

分かったこと:

- 「オンのまま」の最大輝度で蓋を閉じると、隙間から光が漏れる（`EVID-BLK-009`）。
- 輝度 0 で閉じたままパスワードの要求とディスプレイの消灯の時間を過ぎても、ディスプレイスリープせず、ロックされず、画面収録が続く（`EVID-BLK-011`）。
- 自動輝度調節のオンとオフのどちらでも、閉じている間は輝度 0 のままで、開けたときに元の輝度へ戻せる。開閉の通知は一般ユーザーの権限で届く（`EVID-BLK-010`、`EVID-BLK-012`、`HYP-BLK-008`）。
- 輝度 0 で閉じた蓋の隙間からは、光が見えない（`EVID-BLK-012`）。
- 蓋を閉じたままでも、元の輝度へ書き戻せる（`EVID-BLK-012`）。

まだ分からないこと:

- 「オンのまま」で見えた光が内蔵ディスプレイのものか（`HYP-BLK-010`）。キーボードのバックライトなどの光なら、この選択肢では光漏れを抑えられず、要らない。
- 抑止を閉じたまま解除したとき、スリープより先に輝度を戻せるか。
- 蓋を閉じている間の電力が、輝度 0 で「オンのまま」よりどれだけ下がるか。
- 輝度 0 のままアプリが落ちたときと、そのまま Mac を再起動したときに、画面とログイン画面が暗いまま残るか。
